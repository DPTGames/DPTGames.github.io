Zone Variation & Palette System

VCCoreシェーダー向けインスタンス単位のカラーバリエーション

このシステムでは、GPUインスタンシングを維持したまま、個別に配置された各プロップへ独自のカラーバリエーションを与えられます。MaterialPropertyBlockやオブジェクトごとの個別Materialは使用しません。代わりに、各インスタンスで選択したカラーを共有Master Palette Textureと照合し、VCCoreシェーダーがレンダリング時に読み取る単一のインスタンス別データへパックします。システムは3つの要素で構成されています。各インスタンスへ追加するDPT_ZoneVariationコンポーネント、カラーからインデックスへの検索を行うDPT_PaletteMatcherユーティリティ、そしてMaster Palette Texture自体を生成するDPT_PaletteGenerator Editorツールです。

なぜRaw ColorではなくPalette Indexを使うのか？ インスタンスごとに生のRGB値を格納するより、共有Palette内の小さなIndexを格納する方が必要なbit数を抑えられます。またPaletteをIndex参照することで、すべてのインスタンスが同じ有限のカラーセットからバリエーションを取得できます。これによりUnityのGPU Resident Drawerによるインスタンシング経路を維持できます。MaterialPropertyBlockはこのBatchingを崩すため、このシステムでは意図的に使用していません。

DPT_ZoneVariation コンポーネント

VCCoreシェーダーを使用する任意のプロップインスタンスへDPT_ZoneVariationを追加すると、そのインスタンス独自のカラーバリエーションを設定できます。4つのZone Colorフィールド（Zone 0–3）と、オブジェクト全体に適用される1つのEmissive強度スライダーを使用できます。

  • Zone 0–3 Colors: 各カラーはオブジェクトのMaster Palette Texture内で最も近い色へ照合され、6-bit Indexとしてパックされます（下記のPacking Referenceを参照）。Zone 0は、シェーダーが認識できないZone IDに対するFallback Colorとしても使用されます。
  • Emissive: 0–1の単一の強度値を、そのインスタンスの4つすべてのZoneへ一様に適用します。
  • Update Every Frame: デフォルトではオフです。Runtime中にZone Colorを変更する場合（例: ダメージ状態による色変化）だけ有効にしてください。静的なプロップでは、変化しない値を毎Frame確認するCPU Overheadが増えるだけなので、通常はオフのままにします。

このコンポーネントは制御対象のRenderer（子オブジェクトを含む）を自動的に検出し、Inspectorで値を変更したとき（OnValidate）やオブジェクトが有効化されたときに再適用します。Play ModeでUpdate Every Frameがオフの場合、Start時に値を1度適用した後、自身を無効化します。つまり、何もする必要がない状態で毎Frame処理を続けることはありません。

VCCoreシェーダーが必要です: DPT_ZoneVariationは、対象Rendererのいずれかが_ZonesPaletteプロパティを持つMaterialを使用しているか確認します。該当するMaterialがない場合、Runtimeで警告を1度だけ出力し、コンポーネントによる見た目の変化は発生しません。パックした値を読み取るシェーダー側の受け口が存在しないためです。

Editorでのクリーンアップ

Editor上（Play Mode以外）でコンポーネントを削除または破棄すると、そのインスタンスのPacked Valueは0へリセットされます。これにより、コンポーネント削除後もRendererに古いVariationが残って表示されることを防ぎます。

Palette Matchingの仕組み

DPT_PaletteMatcher.FindNearestIndexはTarget ColorとPalette Textureを受け取り、そのPalette内で最も近い色のIndexを返します。距離の計算には単純なEuclidean Distanceではなく、Rec.601のLuma Weight（R/G/B = 0.299 / 0.587 / 0.114）によるChannel Differenceを使用します。そのため、人間の知覚上より近い色が優先されます。このWeightingはVCCoreパイプライン内のLuminance計算でも使用されています。

PaletteのPixel Dataは最初のLookup後、Texture単位でCacheされます。そのため、同じPaletteに対して繰り返し照合する場合（例: 1つのインスタンスで4つのZone Colorを照合する場合）でも、毎回Textureを読み直すことはありません。Palette TextureのImport SettingsでRead/Write Enabledが無効になっている場合は、エラーにする代わりにGPU Blit + ReadbackへFallbackしてPixel Dataを取得します。

Cacheの無効化: Palette Textureを再生成または再Importした場合は、DPT_PaletteMatcher.ClearCache()を呼び出してください（特定のTextureを渡すことも可能です）。これにより、以降の照合では古いCacheではなく更新後のPaletteが使用されます。

Master Paletteの生成

Tools → DPTTools → Tools → Generate PaletteからGeneratorを開きます。これはColor Space上を1本のGradientとして通過するのではなく、R/G/B全体に広がるFull-Gamut Latticeとして64色のMaster Paletteを構築します。そのため、生成されるPaletteはColor Cube全体をカバーします。

  • Red / Green / Blue Weight sliders: 合計6bitのIndexのうち、各Channelへ何bit相当を割り当てるかを制御します。Weightを高くすると、そのChannelで使用できるShade Levelが増える代わりに、他のChannelへ割り当てられる範囲が減ります。
  • Reset to VCCore Luma Weights: Weightを0.299 / 0.587 / 0.114へ設定します。Palette / Matchingパイプライン全体で使用されている知覚ベースのWeightingと一致します。
  • Reset to Uniform: 3つのWeightを同じ値へ設定し、知覚上の重要度に関係なく各Channelへ同数のShade Levelを割り当てます。
  • Bake to PNG: 現在の64色Stripを、指定したFile NameでProjectのAssetsフォルダーへPNGとして保存します。

Weight Sliderを調整すると、Preview Stripと「Resulting levels per channel」の表示がリアルタイムで更新されます。Bakeする前に、各Channelへ何段階のShadeが割り当てられているか正確に確認できます。

RSUV Packing リファレンス

各インスタンスの4つのZone IndexとEmissive Intensityは、GPU Resident DrawerのPer-Instance User Value（RSUV）へ書き込まれる単一の32-bit値にパックされます。これにより、MaterialPropertyBlockを使用せずにシステム全体をインスタンシング対応にしています。

Bits Field 内容
0–5 Zone 0 Index 64色Master Paletteを参照する6-bit Index（0–63）。
6–11 Zone 1 Index 6-bit Palette Index。
12–17 Zone 2 Index 6-bit Palette Index。
18–23 Zone 3 Index 6-bit Palette Index。
24–31 Emissive 8-bit Intensity（0–255）。最下位bitは常に1へ強制されます。
なぜPacked Valueが0にならないのか: Emissive Byteの最下位bitは常に1へ強制され、全体のPacked Valueが完全に0になる場合も1へ補正されます。これにより、すべてデフォルトのインスタンス（Zone 0、Emissionなし）と、Per-Instance Value自体が設定されていないインスタンスを区別できます。

Canvas Blending & Replacement Controls（Tint vs. Recolor）

VCCoreシェーダーにはカスタマイズ可能なBlend Strengthがあり、インスタンスVariationがベースとなるSurface Canvas（Bake済みVertex ColorやAmbient Occlusionなど）とどのように組み合わされるかを制御できます。

  • Tint Replacement Strength (_Tint_Blend): Material InspectorのShader Variation Controlsから設定します。0では通常のShader VariationがMultiplierとして動作し、元のVertex ColorへTintを掛けながらBake済みShadowを保持します。1ではVertex Color CanvasをFlat White Baseへ完全に置き換え、完全なRecolorを行います。
  • Zone Replacement Strength (_Zone_Blend): Zones Palette & Controls Foldout内で設定します。Zone Variationを元のBake済みVertex ShadowへTintとして重ねるか（0）、Clean White Canvasで完全に上書きしてFlatなPalette Swatchとして使用するか（1）を制御します。

ScriptによるVariationを使用していないオブジェクトや、デフォルト値のままのインスタンスでは、これらのBlend処理は自動的にBypassされ、元のアセットデータがそのまま維持されます。

トラブルシューティング & FAQ

DPT_ZoneVariationのカラーがゲーム内で反映されません。
Consoleに「no renderer using the custom VCCore shader」という警告が出ていないか確認してください。これは、そのオブジェクト配下のRendererが_ZonesPaletteプロパティを持つMaterialを1つも使用していないことを意味します。VCCore Materialを割り当てると解決します。
Paletteを再生成したら、すべてのZone Colorがおかしくなりました。
Palette Indexは、照合時に使用した特定のPalette Textureに対してのみ意味を持ちます。Paletteを再生成すると各Indexに割り当てられる色が変わるため、既存のすべてのDPT_ZoneVariationインスタンスは新しいLayoutに対して再解決されます。Paletteを差し替えた後はZone Colorを再選択するか、ApplyVariationを再実行してください。また、新しいTexture Assetを作成せず同じAssetを置き換えた場合は、DPT_PaletteMatcher.ClearCache()も呼び出してください。
「Update Every Frame」はオンにするべきですか？
Gameplay中にZone Colorが実際に変化する場合（Damage State、Faction Recoloringなど）だけオンにしてください。静的なSet Dressing用プロップではオフのままで問題ありません。Editor上で値を編集した場合は、コンポーネントが自動的に再適用します。
