Zone Variation & Palette System

VCCore 셰이더용 인스턴스별 컬러 변형

이 시스템은 GPU Instancing을 유지하면서 개별 배치된 프롭마다 독립적인 컬러 변형을 제공합니다. MaterialPropertyBlock이나 오브젝트별 Material은 사용하지 않습니다. 대신 각 인스턴스의 색상 선택을 공유 Master Palette Texture와 매칭하고, VCCore 셰이더가 렌더링 시 읽는 하나의 Per-Instance 값으로 패킹합니다. 시스템은 세 가지 요소로 구성됩니다. 각 인스턴스에 추가하는 DPT_ZoneVariation 컴포넌트, Color-to-Index 검색을 수행하는 DPT_PaletteMatcher 유틸리티, 그리고 Master Palette Texture 자체를 생성하는 DPT_PaletteGenerator Editor Tool입니다.

Raw Color 대신 Palette Index를 사용하는 이유 인스턴스마다 Raw RGB를 패킹하는 것보다 공유 Palette의 작은 Index를 패킹하는 편이 더 적은 Bit를 사용합니다. 또한 모든 인스턴스가 정확히 동일한 제한된 색상 집합을 참조하므로 Unity의 GPU Resident Drawer Instancing 경로를 그대로 사용할 수 있습니다. MaterialPropertyBlock은 이 Batching을 깨뜨리기 때문에 이 시스템에서는 의도적으로 사용하지 않습니다.

DPT_ZoneVariation 컴포넌트

VCCore 셰이더를 사용하는 프롭 인스턴스에 DPT_ZoneVariation을 추가하면 독립적인 컬러 변형을 적용할 수 있습니다. 4개의 Zone Color 필드(Zone 0–3)와 오브젝트 전체에 적용되는 하나의 Emissive 강도 슬라이더를 제공합니다.

  • Zone 0–3 Colors: 각 색상은 오브젝트의 Master Palette Texture에서 가장 가까운 항목과 매칭되고 6-bit Index로 패킹됩니다. 아래 Packing Reference를 참고하세요. Zone 0은 셰이더가 인식하지 못하는 Zone ID에 대한 Fallback Color로도 사용됩니다.
  • Emissive: 해당 인스턴스의 4개 Zone 전체에 동일하게 적용되는 0–1 강도 값입니다.
  • Update Every Frame: 기본값은 Off입니다. Runtime 중 Zone Color가 실제로 변경되는 경우, 예를 들어 Damage State에 따라 색상이 바뀌는 경우에만 켜세요. 정적 프롭에서는 바뀌지 않는 값을 계속 확인하는 CPU Overhead만 추가되므로 꺼두는 것이 좋습니다.

컴포넌트는 제어할 Renderer와 Child Renderer를 자동으로 찾으며, Inspector에서 값을 수정할 때(OnValidate) 또는 오브젝트가 Enable될 때 값을 다시 적용합니다. Play Mode에서 Update Every Frame이 Off라면 Start에서 한 번 값을 적용한 뒤 스스로 비활성화됩니다. 따라서 아무 작업도 하지 않으면서 매 Frame Tick하지 않습니다.

VCCore 셰이더가 필요합니다: DPT_ZoneVariation은 대상 Renderer 중 하나라도 _ZonesPalette 프로퍼티가 있는 Material을 사용하는지 확인합니다. 하나도 없다면 Runtime에서 한 번 경고를 출력하며, 패킹된 값을 읽을 셰이더가 없기 때문에 시각적인 효과도 없습니다.

Editor 정리

Editor에서 Play Mode가 아닌 상태로 컴포넌트를 제거하거나 삭제하면 인스턴스의 Packed Value를 0으로 되돌려, 컴포넌트가 사라진 뒤에도 이전 Variation이 Renderer에 남아 표시되는 것을 방지합니다.

Palette Matching 작동 방식

DPT_PaletteMatcher.FindNearestIndex는 Target Color와 Palette Texture를 받아 Palette에서 가장 가까운 색상의 Index를 반환합니다. 거리 계산에는 단순 Euclidean Distance가 아니라 Rec.601 Luma Weight의 Channel Difference(R/G/B = 0.299 / 0.587 / 0.114)를 사용하므로 지각적으로 더 가까운 색상이 우선됩니다. 이는 VCCore 파이프라인의 Luminance 계산과 동일한 Weighting입니다.

Palette Pixel Data는 첫 Lookup 이후 Texture별로 Cache됩니다. 따라서 동일한 Palette에 반복적으로 매칭할 때, 예를 들어 하나의 인스턴스에서 4개의 Zone Color를 매칭할 때마다 Texture를 다시 읽지 않습니다. Palette Texture의 Import Settings에서 Read/Write Enabled가 활성화되지 않은 경우에도 실패하지 않고 GPU Blit + Readback 방식으로 Pixel Data를 가져옵니다.

Cache 무효화: Palette Texture를 재생성하거나 다시 Import한 경우 DPT_PaletteMatcher.ClearCache() 를 호출하거나 특정 Texture를 전달해 이후 매칭이 오래된 Cache 대신 업데이트된 Palette를 읽도록 하세요.

Master Palette 생성

Generator는 Tools → DPTTools → Tools → Generate Palette 메뉴에서 엽니다. 64색 Master Palette를 Color Space를 가로지르는 단일 Gradient 경로가 아니라 R/G/B 전체에 분포된 Full-Gamut Lattice로 생성합니다. 따라서 결과 Palette는 한 줄이 아니라 Color Cube 전체를 실제로 커버합니다.

  • Red / Green / Blue Weight sliders: 총 6개의 Index Bit 중 각 Channel에 얼마만큼 할당할지 제어합니다. Weight가 높을수록 해당 Channel의 Shade Level은 늘어나지만 다른 Channel에 할당되는 범위는 줄어듭니다.
  • Reset to VCCore Luma Weights: Weight를 0.299 / 0.587 / 0.114로 설정해 Palette/Matching 파이프라인의 지각 기반 Weighting과 일치시킵니다.
  • Reset to Uniform: 세 Weight를 동일하게 설정해 지각적 중요도와 관계없이 각 Channel에 같은 수의 Shade Level을 제공합니다.
  • Bake to PNG: 현재 64색 Strip을 지정한 파일 이름으로 Project의 Assets 폴더에 저장합니다.

Weight Slider를 조절하면 Preview Strip과 "Resulting levels per channel" 표시가 실시간으로 갱신되어 Bake 전에 각 Channel에 몇 단계의 Shade가 할당되는지 정확히 확인할 수 있습니다.

RSUV Packing 레퍼런스

각 인스턴스의 4개 Zone Index와 Emissive Intensity는 GPU Resident Drawer의 Per-Instance User Value(RSUV)에 기록되는 하나의 32-bit 값으로 패킹됩니다. 이것이 MaterialPropertyBlock 없이 전체 시스템을 Instancing 호환으로 만드는 핵심입니다.

Bits Field 내용
0–5 Zone 0 Index 64색 Master Palette를 참조하는 6-bit Index(0–63).
6–11 Zone 1 Index 6-bit Palette Index.
12–17 Zone 2 Index 6-bit Palette Index.
18–23 Zone 3 Index 6-bit Palette Index.
24–31 Emissive 8-bit Intensity(0–255). 최하위 Bit는 항상 1로 강제됩니다.
Packed Value가 0이 될 수 없는 이유: Emissive Byte의 최하위 Bit는 항상 1로 강제되며 전체 Packed Value가 정확히 0이 되는 경우에도 1로 보정됩니다. 이를 통해 모든 값이 기본 상태인 인스턴스(Zone 0, Emission 없음)와 Per-Instance Value 자체가 설정되지 않은 인스턴스를 구분할 수 있습니다.

Canvas Blending & Replacement Controls (Tint vs. Recolor)

VCCore 셰이더에는 인스턴스 Variation이 Bake된 Vertex Color나 Ambient Occlusion 같은 기본 Surface Canvas와 어떻게 결합되는지 제어하는 Blend Strength가 있습니다.

  • Tint Replacement Strength (_Tint_Blend): Material Inspector의 Shader Variation Controls에서 설정합니다. 0에서는 일반 Shader Variation이 Multiplier로 작동해 원본 Vertex Color에 Tint를 적용하면서 Bake된 Shadow를 유지합니다. 1에서는 Vertex Color Canvas를 Flat White Base로 완전히 대체해 완전한 Recolor를 수행합니다.
  • Zone Replacement Strength (_Zone_Blend): Zones Palette & Controls Foldout에서 설정합니다. 0에서는 Zone Variation이 원래 Bake된 Vertex Shadow 위에 Tint로 적용되고, 1에서는 Clean White Canvas로 완전히 덮어 Flat Palette Swatch처럼 사용합니다.

Scripted Variation을 사용하지 않거나 기본값으로 남아 있는 인스턴스는 이러한 Blend를 자동으로 우회해 원본 Asset Data를 그대로 유지합니다.

문제 해결 & FAQ

게임에서 DPT_ZoneVariation 색상이 적용되지 않습니다.
Console에 "no renderer using the custom VCCore shader" 경고가 있는지 확인하세요. 해당 오브젝트 아래의 Renderer가 _ZonesPalette 프로퍼티가 있는 Material을 하나도 사용하지 않는다는 의미입니다. VCCore Material을 할당하면 해결됩니다.
Palette를 다시 생성한 뒤 모든 Zone Color가 잘못 보입니다.
Palette Index는 매칭에 사용한 정확한 Palette Texture를 기준으로만 의미가 있습니다. Palette를 다시 생성하면 각 Index의 색상이 바뀌므로 기존 DPT_ZoneVariation 인스턴스가 새 Layout을 기준으로 다시 해석됩니다. Palette를 교체한 뒤 Zone Color를 다시 선택하거나 ApplyVariation을 다시 실행하세요. 새 Texture Asset을 만들지 않고 기존 Asset을 교체했다면 DPT_PaletteMatcher.ClearCache()도 호출해야 합니다.
"Update Every Frame"을 켜야 하나요?
Gameplay 중 Zone Color가 실제로 변경되는 경우, 예를 들어 Damage State나 Faction Recoloring이 있을 때만 켜세요. 정적인 Set Dressing 프롭에서는 끄는 것이 좋습니다. Editor에서 값을 수정하면 컴포넌트가 자동으로 다시 적용합니다.
