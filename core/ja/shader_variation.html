DPT_ShaderVariation コンポーネント

DPT_ShaderVariation は、シーン内のアセットに対するインスタンスごとの色の変更を管理します。DPT Prefab Painter で配置した場合は自動的に動作しますが、カスタム GameObject、空のルート親オブジェクト、モジュラー Prefab に手動で追加して、低負荷で色を調整することもできます。

基本アーキテクチャ

指定した色を読み込み、RGB チャンネルを正規化して 24 ビットの色相精度を保ち、残り 8 ビットを独立した輝度倍率としてエンコードします。このベクトルパッキング方式では色の歪みを抑えながら、最大 2.0 倍の HDR 明るさに対応します。生成した値は単一の符号なし 32 ビット整数（uint）に圧縮され、Renderer Shader User Value（RSUV）経由で GPU のインスタンシングバッファーに渡されます。

色のバリエーションは GPU 側で SetShaderUserValue により処理されるため、共有マテリアルを複製、変更することはありません。異なる色のオブジェクトが多数あっても統合されたハードウェアドローコールで扱え、VRAM へのマテリアル複製による負荷を防ぎます。

コンポーネントの Inspector 項目

Hierarchy から DPT_ShaderVariation が付いたオブジェクトを選んで設定します。

項目説明
Instance Colorこのオブジェクトの GPU ストリームに渡す色合いと明るさの倍率。白（1,1,1,1）が中立です。暗い値ではオブジェクトが暗くなり、色の大きさが高い値では HDR の明るさになります。発光オブジェクトでは Alpha チャンネルが発光強度を直接制御します。 プロパティを介して直接制御するか、フィールド変更を追跡できます。
Color Property Name標準マテリアルへのフォールバック時に使用するシェーダー変数名です。通常の URP シェーダーでは _BaseColor などを指定します。DPT マテリアルを検出した場合はこの項目がロックされ、編集できません。 非 DPT マテリアル専用です。
Update Every Frame性能に関する注意：色の動的変更を追跡するために毎フレーム Update() を実行します。ダメージ時の点滅や発光の脈動など、ゲーム中に色が変化する場合だけ有効にしてください。通常の小道具では無効にして CPU 負荷をなくします。旧称は Is Animated です。
コンポーネントは空のルート親にも追加できます。階層内の Renderer をフィルター付きで収集するため、LOD0、LOD1、破壊された破片などの子メッシュにも色を適用でき、破壊可能なオブジェクトとも互換性があります。

高度なアーキテクチャ機能

1. 動的な色更新（Update Every Frame）

Unity Animator がスクリプトフィールドをアニメーションさせたり、外部スクリプトが値を変更したりすると、シリアライズされたバッキングフィールド（instanceColor）が直接変更されます。通常の C# プロパティセッター（InstanceColor）を通らないため、一般的な実装では GPU に更新を送る必要があると検知できません。

これを低負荷で解決するため、Update Every Frame を有効にすると内部の監視ループが動作します。

void Update()
{
    if (instanceColor != lastInstanceColor)
    {
        lastInstanceColor = instanceColor;
        ApplyVariation();
    }
}
  • 動的な小道具（大砲の導火線、被ダメージの点滅など）：Update Every Frame を有効にすると、Animator や外部スクリプトによる変更をそのフレームで検知し、更新値を GPU へ送信します。Alpha チャンネルのアニメーションによる発光の脈動やフェードにも対応します。
  • 通常の背景オブジェクト（樽、岩など）：無効の場合は初期化時に一度だけ送信し、その後コンポーネント自身の動作を停止（enabled = false）します。多数のオブジェクトで発生する Unity とマネージコード間のライフサイクル負荷を防ぎ、CPU のフレーム処理への影響をなくします。

2. アロケーションのない初期化

実行時に大量の小道具を生成する際のガベージコレクション（GC）スパイクを避けるため、初期化中の配列アロケーションを回避しています。事前確保した非シリアライズの汎用リスト（tempRendererList、filteredRenderers）を使って階層を走査し、Renderer キャッシュを構築します。

3. 入れ子階層の保護

点火した導火線を子孫に持つ攻城兵器のような複雑な Prefab では、GetComponentsInChildren<Renderer>() のような通常の再帰検索を使うと、親コンポーネントが子の Renderer まで管理し、それぞれの色を上書きしてしまう場合があります。

DPT_ShaderVariation はキャッシュ構築時に、階層の下から適切な管理者を確認するフィルターを使用します。

for (int i = 0; i < tempRendererList.Count; i++)
{
    Renderer rend = tempRendererList[i];
    if (rend != null && rend.GetComponentInParent<DPT_ShaderVariation>() == this)
    {
        filteredRenderers.Add(rend);
    }
}

親が子 Renderer を検索するとき、最も近くに存在する Variation 管理コンポーネントが自分自身かを確認します。導火線などの子オブジェクトに別の DPT_ShaderVariation があれば、親はその Renderer に干渉しません。これにより、主構造の色を親で管理しつつ、子ユニットの色を独立して制御できます。

性能と最適化への互換性

各レンダリング方式との互換性は以下のとおりです。

レンダリング方式対応注意事項
GPU Resident Drawer（Unity 6+）VCCore が必要DPT VCCore マテリアル、または RSUV に対応したカスタムシェーダーの場合にのみ完全対応します。URP Default Lit などの通常マテリアルでは Material Property Block が必要となり、そのオブジェクトは GPU Resident Drawer から除外されます。
SRP Batcher（URP / HDRP）対応共有シェーダーキーワード間の CPU ドローコールをまとめられます。
GPU Instancing対応すべてのインスタンスが同一のマテリアルを使うため、通常の GPU インスタンシングを維持できます。
Static Batching非対応GPU 駆動の処理との併用には適していません。オブジェクトに Batching Static を設定しないでください。メッシュの結合によって GPU Resident Drawer でのインスタンス処理が妨げられます。

MaterialPropertyBlock による動的フォールバック

VCCore の代わりに URP Default Lit などの Unity 標準マテリアルを使う場合、コンポーネントは自動的にフォールバックします。Color Property Name の編集を許可し、_BaseColor や _Color などの一般的な色プロパティを検出して、MaterialPropertyBlock（MPB）経由でインスタンスごとの色を更新します。

重要なパイプライン上の注意：MPB フォールバックはマテリアルの複製を避けるためメモリ効率は維持できますが、Material Property Block を使うと GPU Resident Drawer と SRP Batcher の両方が無効になります。 Unity 6 以降の大量インスタンスを使うゲームでは、提供される VCCore マテリアルを使用して最適な経路を維持してください。

トラブルシューティング

Inspector では色が変わるのにメッシュに反映されない

メッシュに Batching Static が設定されていないことを確認してください。また、シェーダーが unity_RendererUserValue に対応しているか、標準マテリアルへのフォールバック時は Color Property Name で指定した名前と一致しているかを確認してください。

Animator やスクリプトが色を変更しても画面が変わらない

Inspector の Update Every Frame を確認します。無効なら、コンポーネントは初期化後に自分自身を停止するため、Animator や外部スクリプトによるフィールド変更を検出しません。

親コンポーネントが子の色アニメーションを上書きしてしまう

子オブジェクト自身に DPT_ShaderVariation を追加してください。入れ子階層の保護機能は、子が独自の管理コンポーネントを持つことを前提にしています。
