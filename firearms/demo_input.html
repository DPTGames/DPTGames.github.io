Camera-only Demo Controller

Optional demo component · Mouse aim, ADS camera poses, hip-fire reticle, visual recoil and debug rays

Playable demonstration without a character controller

The camera-only demo rotates a stationary firearm from mouse input, positions the camera at hip-fire or ADS pose markers, shows a hip-fire crosshair and routes fire/reload input to the runtime component. It does not require a player model, locomotion or an Animator.

Quick Setup

  1. Add DPT_FirearmDemoInput to the firearm root. It requires DPT_Firearm on the same object.
  2. Assign the Main Camera or let the script locate it automatically. Keep the camera outside the firearm hierarchy.
  3. Optionally assign DPT_FirearmProceduralBolt. It is found on the firearm GameObject if present.
  4. Create and assign ADS Camera Pose under Aim Root at the intended iron-sight eye position. Optionally create a separate Hip Camera Pose.
  5. Enter Play Mode. The demo captures the cursor and rotates the rifle from mouse input; Escape releases the cursor.

Camera Pose Markers

  • Hip Camera Pose: optional empty Transform beneath the rifle’s Aim Root. Overrides numerical Hip Camera Offset.
  • ADS Camera Pose: optional empty beneath Aim Root, placed behind the rear notch with its +Z towards the muzzle. Overrides ADS Camera Offset.
  • A pose’s world position and rotation are used for the destination, with smooth interpolation controlled by Aim Responsiveness.
  • The camera is moved independently each frame. Do not parent Main Camera to SMLE_MkIII_Complete or another disabled/moving firearm child.

Aiming & Sight Calibration

  1. Set Spread Degrees = 0 and temporarily use Hitscan for a baseline test.
  2. Assign the ADS pose behind the rear sight and align its rotation so the top of the front blade corresponds to the centre of the screen.
  3. Enable Converge Shots To Crosshair to aim the muzzle towards the target beneath the current camera centre.
  4. Enable Show Aim Debug Rays to compare the green camera ray with the yellow muzzle ray in Scene view.
  5. Test at both near and far distances. If bullets land high relative to the front blade but hip-fire is accurate, lower the ADS Camera Pose slightly.
  6. Switch back to Swept Projectile and re-enable gravity. Any remaining drop/rise at range is then a ballistic alignment matter, not necessarily an input timing fault.
Update order: In the revised demo, the camera pose is updated before muzzle convergence and trigger processing. This avoids using the previous frame’s camera position for shots during mouse movement or ADS transitions.

Use in a Full Game

The demo script is intentionally not a general player controller. Production projects can remove it and invoke DPT_Firearm.TriggerDown(), TriggerUp(), Reload(), CycleAction() and optional bayonet APIs from their own player, AI or networking systems.
Input System assembly reference: DPT.Firearms.Demo.Runtime must reference DPT.Firearms.Runtime. If the Input System package is installed and enabled, also reference Unity.InputSystem in the demo asmdef.
