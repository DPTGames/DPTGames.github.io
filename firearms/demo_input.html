DPT Firearm Demo Input

Optional Sample Controller
The DPT_FirearmDemoInput component supplies minimal mouse and keyboard controls for testing the firearm in Play Mode. It is intentionally independent of character movement, possession and camera systems.

Quick Setup

  1. Add DPT_FirearmDemoInput to the firearm root for the quickest setup. It auto-finds DPT_Firearm on the same GameObject if the Inspector slot is unassigned.
  2. Alternatively, put the component on another GameObject and assign the firearm component manually.
  3. Ensure the project uses either Unity's new Input System or the Legacy Input Manager and the firearm is set up with a muzzle and a valid selected shot type.
  4. Enter Play Mode and use the controls below.

Default Controls

InputAction
Left Mouse ButtonPress to call TriggerDown(); release to call TriggerUp().
BCalls CycleAction() for an instant bolt cycle.
RCalls Reload() to start the timed magazine reload.
For animated bolt cycling: This demo script calls CycleAction() directly. If you want the cycle to wait for eject/chamber animation events, adapt the demo input to call RequestCycleAnimation() instead.

Input System Compatibility

When ENABLE_INPUT_SYSTEM is set, the script reads Mouse.current and Keyboard.current from the new Input System. Otherwise, when ENABLE_LEGACY_INPUT_MANAGER is set, it uses the corresponding Input methods.

Unlike the siege weapon's separate possession controller, this component does not expose configurable InputActionReference fields. Keys are hardcoded for demonstration, and no player PlayerInput action map is required by the sample itself.

Scope & Limitations

  • This is a demonstration input driver, not a full player controller.
  • It doesn't manage aiming, weapon sway, recoil, crosshairs, ADS, camera parenting or weapon pickup.
  • It doesn't create an Animator Controller or assign the three bolt animation events.
  • It releases the firearm trigger automatically when the component is disabled.
  • Production projects can call DPT_Firearm from their own input handlers without retaining this component.
Production use: Keep the firearm logic as the reusable weapon component and implement input independently for your player controller or AI. The firearm public API provides the required methods.
