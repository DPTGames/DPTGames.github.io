DPT Firearm Damage Integration

Interface & Relay Guide
The IDPT_FirearmDamageable interface and DPT_FirearmDamageRelay provide hit events for health systems, custom gameplay and external destruction tools without requiring the siege weapon framework.

Damage Architecture

Both hitscan and swept projectile hits look for IDPT_FirearmDamageable on the struck Collider's GameObject or one of its parents. The weapon passes the damage amount, hit point, incoming direction and source GameObject to ReceiveFirearmHit().

namespace DPT.Firearms
{
    public interface IDPT_FirearmDamageable
    {
        void ReceiveFirearmHit(float damage, Vector3 point,
            Vector3 direction, GameObject source);
    }
}
Decoupled by design: The firearm does not assume a particular health component, character controller or destruction package. It sends hit information through a small interface and lets the receiving system decide what to do.

DPT_FirearmDamageRelay

  1. On a target with a Collider, add DPT_FirearmDamageRelay to the same object or a parent.
  2. In the Inspector, connect On Damage to a UnityEvent listener accepting a float if the target has a compatible damage method.
  3. Use On Hit for simple parameterless reactions such as sound, particle effects or animation triggers.
  4. For more detailed hit logic, subscribe to the C# Hit event or read LastHitPoint, LastHitDirection and LastSource.

Implementing a Custom Damage Receiver

You can implement the interface directly on your own health or hit-reaction component. The firearm will find it through the hit Collider's parent hierarchy.

using UnityEngine;
using DPT.Firearms;

public class ExampleFirearmHealth : MonoBehaviour, IDPT_FirearmDamageable
{
    [SerializeField] private float health = 100f;

    public void ReceiveFirearmHit(float damage, Vector3 point,
        Vector3 direction, GameObject source)
    {
        health = Mathf.Max(0f, health - damage);
    }
}
Damaging child Colliders: When a character has multiple hitboxes, keep the interface on a shared parent if all hits should reduce the same health pool. Use separate receivers on children only when you intentionally require distinct hit handling.

Runtime Mesh Destruction Integration

The scripts don't directly call DPT_Cuttable. To use them with a runtime mesh destruction system, add an adapter implementing IDPT_FirearmDamageable and translate point, direction and damage into that system's actual hit method.

This design keeps the firearm package usable without additional dependencies. It also means the demonstration must include a specific adapter before bullet hits can cut geometry. A direct adapter cannot be documented accurately without the destruction API version in use.

Troubleshooting

SymptomCheck
Projectile hits but no damage event firesCheck that the hit Collider or a parent has an enabled component implementing IDPT_FirearmDamageable.
UnityEvent receives a value but no mesh damage occursThe relay merely broadcasts hits. Wire it to damage logic or supply an adapter for the mesh destruction component.
Only some hitboxes register damageCheck object hierarchies, Collider layers and whether another Collider intercepts the raycast.
Hit object is unaffected physicallyThe impulse settings are separate from the damage interface, and require a non-kinematic Rigidbody for force application.
