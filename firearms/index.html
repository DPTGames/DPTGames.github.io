A reusable firearms system, demonstrated with the SMLE Mk III

Configure firearm behaviour, ammunition, firing modes, projectiles, casing ejection, procedural bolt operation, reload visuals, bayonet attacks and gameplay events. The included SMLE setup is a working example, not a requirement or limitation of the runtime components.

Use the SMLE as a template, then replace the meshes, ammo parameters, muzzle/ejection markers, sounds and action logic for another weapon.

Quick Start

  1. Add DPT_Firearm and an AudioSource to the root GameObject. The component works independently of any character controller or third-party destruction system.
  2. Add an empty Muzzle_Point at the barrel tip with its blue +Z axis pointing forwards. Assign it under Projectile → Muzzle Point.
  3. Add an empty Ejection_Point beside the receiver and assign it under Casing Ejection → Ejection Point. Keep it outside moving bolt parts.
  4. Choose Shot Type: Hitscan for an immediate raycast or Swept Projectile for a bullet that moves using raycast segments.
  5. Assign projectile, casing, visual and audio references where needed. Configure magazine capacity, chamber state and firing mode.
  6. For a bolt-action example, add DPT_FirearmProceduralBolt and assign its bolt Transform. For an existing player controller, call the public API instead.
  7. For standalone testing, add the optional DPT_FirearmDemoInput in the demo assembly and keep Main Camera outside the rifle hierarchy.

Assembly Definitions & C# Namespaces

The current package uses two assemblies and two namespaces. An asmdef name and C# namespace are related by convention but are not the same thing. Keep both consistent with your installed package.

DPT.Firearms.Demo.RuntimeDPT.Firearms.Demo.RuntimeCamera-only demo input, optional bayonet demo input and example moving targets.

using DPT.Firearms.Runtime;
using UnityEngine;

public class ExampleWeaponInput : MonoBehaviour
{
    [SerializeField] private DPT_Firearm firearm;

    public void PressTrigger() => firearm.TriggerDown();
    public void ReleaseTrigger() => firearm.TriggerUp();
    public void ReloadWeapon() => firearm.Reload();
}

Reload Types and Loading Visuals

The core DPT_Firearm owns ammunition, reload operations, the loading prefab and its spawn Transform. Weapon-specific animation components can present those operations without duplicating prefab references. The optional DPT_FirearmProceduralBolt provides bolt-action motion and three loading visual modes:

Visual modeBehaviour
Whole ObjectInserts an entire prefab, such as a detachable magazine.
Contents OnlySeats a loading device then moves only its selected cartridge group into the weapon. Use for SMLE chargers.
Individual RoundsSpawns one loading visual per round for a one-at-a-time reload.
Single source of visual configuration: Assign Loading Prefab and Loading Spawn Point on the firearm. The bolt's Loading Contents is a Transform reference to a child of that prefab asset. It is not a string name lookup and does not require a separate loading visual MonoBehaviour.

For a working charger example, see SMLE charger prefab setup. For timing, animation modes and troubleshooting, see Procedural Bolt & Loading Animations.

Audio and Visual Effects

  • Use Shot Sounds, Reload Sounds, Bolt Sounds and Empty Sounds for the core firearm. Bolt Sounds are initiated on BeginCycle().
  • Muzzle Flash Prefab spawns a temporary GameObject at the muzzle. It is independent of a scene Light.
  • Muzzle Flash Light accepts an existing Light component and pulses its intensity. It can start inactive or with intensity zero. For most muzzle-flash lighting, a short-range Point Light with shadows off is a useful starting point.
  • Reload Bolt Close Sounds on the procedural bolt component play at the beginning of its closing phase.

Common Troubleshooting

SymptomCheck
Casings appear at the trigger/rootReassign the Ejection Point field. Inspect the casing prefab root and mesh offset; test with Ejection Speed = 0.
Bullets do not line up with sightsEnsure Muzzle Point +Z is forward. Calibrate ADS Camera Pose first; compare hitscan with spread 0 before diagnosing gravity.
Bolt never cycles after the first shotEnable Auto Cycle After Shot, set Manual Action on and assign the Bolt Transform.
Camera points backwardsChoose Root To Muzzle or set Reverse View Direction; ensure Main Camera is not a child of the rifle.
Muzzle light never flashesAssign the actual scene Light to Muzzle Flash Light, not only the Muzzle Flash Prefab slot.
Shot hits but target does nothingTarget needs a Collider and a damage receiver implementing IDPT_FirearmDamageable or a relay.
Loading visual doesn't animate its cartridgesUse Contents Only on the procedural bolt and assign Loading Contents to the cartridge group Transform from the same prefab asset referenced by the firearm.
Scripts cannot find firearm typesVerify demo asmdef references runtime asmdef and code imports DPT.Firearms.Runtime.
