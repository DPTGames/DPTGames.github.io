このツールでできること

Material Optimizer & Texture Atlas Creator は、1つ以上のモデルからマテリアルの入力を収集し、対応するテクスチャを共有アトラスに配置して、メッシュのUVを更新します。互換性のある元マテリアルは、共有の出力マテリアルに集約されます。モデルを個別に書き出す、1つの親プレハブにまとめる、選択した互換メッシュを結合する、という方法から選択できます。

処理変更される内容実際の用途
テクスチャアトラス作成テクスチャ配置とUV0座標。複数モデルが同じテクスチャを参照できます。1つのメッシュにする必要はありません。
マテリアル集約マテリアル参照と互換性のあるサブメッシュのスロット。モデルを個別に保ったまま、マテリアルやスロット数を減らせます。
任意のメッシュ結合選択した互換レンダラーとジオメトリ。レンダラー数を減らせます。結合した部品は表示状態とカリングを共有します。

このガイドは、メタリックワークフローを使用する URP Lit マテリアルを対象としています。最適化処理は Unity Editor 内で実行され、生成アセットに最適化ツール専用のランタイムコンポーネントは不要です。ただし、出力プレハブは元のスクリプト、アニメーションクリップ、アバター、コライダー用アセットに依存する場合があります。

導入、起動、言語の選択

Material Optimizer と一緒に DPT_Core をインポートしてください。エディターウィンドウは DPT.Core.Editor の共通ヘッダー、ドキュメントボタン、セクションスタイル、ボタン色を使用します。DPT Package Exporter では Material_Optimizer と DPT_Core の両方を選び、System Marker Overrides で DPT_Marker_MaterialOptimizer.cs を有効にしてください。

  1. URP プロジェクトにパッケージをインポートし、Unity のインポートとコンパイルが完了するまで待ちます。プロジェクトにコンパイルエラーがある場合は、先に解消してください。
  2. Tools > DPT Games > Material Optimizer を開きます。Tools メニューの製品名は、どの言語でも英語のままです。
  3. ウィンドウ上部の English、 日本語、 한국어 から選択します。選択した言語は記憶されます。アセット名、シェーダープロパティの識別子、出力ファイル名は翻訳されません。
  4. Edit Mode で操作します。Play Mode への移行中や実行中は、アトラスの操作が無効になります。設定欄とプレビューを表示できる広さを確保してください。最小ウィンドウサイズは 1020 × 650 です。

このツールは独自の Editor アセンブリを使用し、DPT Core、Color Swapper、DPT シェーダーを必要としません。対応 Unity バージョンはパッケージの製品ページを確認してください。

ヘルプを非表示 (Hide Help Boxes) は、書き出し欄の情報メッセージを含む任意のガイダンスを非表示にします。ツールチップ、警告、エラー、重要な処理状況は引き続き表示されます。プレビュー完成時の専用メッセージは表示しません。アトラスサイズの概要行にカーソルを合わせると、共有カラーピクセルに集約した三角形数を確認できます。メモリ比較表は結果のデータなので表示を維持します。

Hierarchyから開く

モデルのルートを1つ以上選び、右クリックしてDPT Games > Material Optimizerを選びます。選択した入力を読み込み、スキャンします。選択されていないオブジェクトを右クリックした場合は、そのオブジェクトを読み込みます。親子の重複と対応メッシュのない空の入力は除去します。ベイク、書き出し、シーンの変更は行いません。対応メッシュを含むオブジェクトに対してEdit Modeで利用できます。

最初のアトラスを作成する

  1. 1. ソースオブジェクト (1. Source objects) にシーンオブジェクト、モデルアセット、プレハブを1つ以上ドロップします。Unity で選択して 選択を追加 (Add Selection) を押す方法もあります。最初は結果を確認しやすい小さな構成で試してください。
  2. ソースをスキャン (Scan Sources) を押し、レンダラー、マテリアル、スロット、三角形の数を確認します。続行する前に警告を確認してください。
  3. 既定ではすべての詳細を保持 (Preserve All Details)が有効です。単色領域を1ピクセルのスウォッチに集約するには、すべて自動集約 (Auto Fold All)、または個別マテリアルの均一色を確認して集約 (Fold Verified Colours)を選択します。多くのマテリアルは 標準 (Normal priority) のままで構いません。
  4. URP Lit の マテリアルテンプレート (Material Template) を指定するか、空欄にして現在のパイプラインの標準 Lit シェーダーを使用します。最大サイズに自動調整 (Auto Fit to Maximum Size) を有効にしておきます。アトラスの最大サイズ (Maximum Atlas Size) の初期値は 4096 です。
  5. 緑色の アトラスプレビューを作成 (Create Atlas Preview) を押します。アトラスの各チャンネルと モデルの変更前 / 変更後 (Before / after model) を確認します。重要な面のディテールが不足する場合は ディテール優先度 (Detail Priority) を上げて、プレビューを再作成します。
  6. アトラスアセットを共有する独立モデルとして書き出す場合は 個別のプレハブ (Separate Prefabs) のままにします。グループ化やメッシュ結合が必要な場合に メッシュ出力 (Mesh Output) を変更します。
  7. 出力名 (Output Name) と、現在のプロジェクトの Assets 内にある 出力フォルダー (Output Folder) を指定し、青色の 保存してエクスポート (Save & Export) を押します。最新のプレビューは再利用します。ソースやベイク設定が変わった場合は、書き出し前に再作成します。
  8. 新しい出力フォルダーを開き、Prefabs サブフォルダー内のプレハブを使用します。生成プレハブをシーンに配置し、実際の照明とアニメーションで確認します。作業後にシーンを保存してください。

最初の練習には、テーブル、単色のマグカップ、印刷模様のある本、ガラス瓶などが適しています。まず個別プレハブで書き出します。次に、移動可能な小物とガラスを独立させたまま、テーブルの構造部分だけを結合した出力と比較します。これは、ご自身のアセットを使った練習例です。

同梱デモのテクスチャ: 最適化済みデモのアトラスは、元の4Kマテリアルテクスチャからベイクしています。パッケージ容量を抑えるため、入力用には1K-2Kの縮小コピーを同梱し、AOには現在のUVに対応したマップを使用しています。シーンのメモリ表示は同梱アセットの測定値です。縮小コピーから再ベイクした結果は、同梱アトラスと異なる場合があります。

再利用可能な設定プロファイル

ソース一覧の上にある設定プロファイルを展開します。名前を付けて保存...で、名前付きのプロジェクトアセットを作成します。既存の設定プロファイルを選択して読み込みで適用し、保存で更新します。アトラス設定、メッシュ出力オプション、出力名と出力先、一致するマテリアルアセットの個別設定を保存します。読み込んでも、現在のソースオブジェクト、レンダラーごとの結合選択、アタッチメントボーンは維持されます。ソースマテリアルは変更しません。シーン内だけのマテリアルの個別設定は保存しません。マテリアルテンプレートにはプロジェクトアセットが必要です。設定をリセットはアトラス、マテリアル、メッシュ出力を既定値に戻し、ソースオブジェクト、出力名、出力先を維持します。読み込んだ設定は独立したコピーなので、再び保存するまで変更は保存済みプロファイルに反映されません。

入力の選択とスキャン結果

入力はルート GameObject です。スキャンには、その配下にある対応レンダラー、非アクティブなオブジェクト、すべてのメッシュ LOD が含まれます。親と子の両方を指定しても、子は別の入力として重複計上されません。個別プレハブモードでは、入力ルートごとに1つのプレハブが生成されます。

操作・数値意味

ソースをスキャン (Scan Sources)現在の入力を再確認します。同じマテリアルの設定とレンダラーの結合選択は引き継がれます。
X / クリア (Clear)X は1つの入力を削除します。Clear は入力、マテリアル、結合選択をクリアします。

スキンモデルでは、参照されるすべてのボーンとルートボーンが含まれるよう、キャラクターの完全なルートを選択してください。複数モデルの配置や、書き出し前の取り付け部品の位置調整には、シーン上のインスタンスが便利です。テクスチャはマテリアル参照から読み取るため、元テクスチャを1つのフォルダーにまとめる必要はありません。

自動設定と元に戻す操作

ソースを追加したら、入力操作の下にある自動設定（Auto Configure）を押します。テクスチャの寸法、タイリング、フィルター、シェーダーの互換性を確認します。ピクセルのベイクや書き出しは行いません。設定の詳細（Configuration Details）を開くと選択理由を確認できます。推奨値を出発点として、プレビューと想定カメラ距離に合わせて優先度を調整してください。

アトラスには自動サイズ設定を選び、最大値を256～4096ピクセルで推定します。自動調整、形状を考慮した配置、自動余白、ソース解像度の上限を有効にし、アップスケールは無効にします。8Kや固定サイズは手動で選択できます。テクスチャのない標準マテリアルには検証済みの1ピクセル集約を使用します。ミップマップのないポイント入力にはポイントフィルター、ミップマップなし、非圧縮を設定します。詳細な入力には滑らかなフィルター、ミップマップ、高品質圧縮を設定します。テクスチャ付きマテリアルの既存の配置設定は保持します。カスタムシェーダー、テクスチャ配列、スペキュラーワークフロー、検出したディテール・視差効果では、マテリアルを保持するメッシュのみのモードを選びます。

ソース解析で結合可能なグループがある場合に、静的または共有リグの結合を推奨します。これは推定であり、最終的なUV構成や書き出し互換性により結果は変わる場合があります。既存のメッシュのみのモードは保持します。アトラスに対応する場合はアトラスとメッシュのみの出力設定も保持します。マテリアルの割り当て、優先度、レンダラーの除外、アタッチメントボーン、LODの個別設定、出力先は維持されます。

設定を元に戻す（Undo Configure）は、直前の自動設定前の設定とマテリアル配置設定を復元します。現在のソース選択とウィンドウのセッション内で利用できます。ベイクに影響する変更では既存プレビューが更新待ちになり、自動更新に従って再生成します。最適化モードを変えるとプレビューを解放します。書き出し・結合設定だけの変更は既存アトラスと手動配置を保持します。元に戻せるのは設定であり、再生成で失われた手動配置ではありません。

マイクロテクスチャと詳細領域

均一色を確認して集約 (Fold Verified Colours)は、各三角形がすべてのマッピングされたチャンネルで一定の値をサンプリングするか確認します。UVが変化する領域ではフィルタリング用の余白も確認します。UVがすべて同じパレット位置を指す面は、バイリニアフィルタリングで周囲の色が異なっていても一定です。対象領域は余白付きの1ピクセルスウォッチになります。異なるモデルやマテリアルでも、一致する検証済みスウォッチは同じピクセルを使えます。

ベースカラーが単色でも、法線、メタリック、スムースネス、オクルージョン、不透明度、発光のディテールは削除されません。対応チャンネルのいずれかに変化があれば、詳細領域として保持します。グラデーションや描き込まれた陰影も保持します。判定が曖昧な領域や検査負荷が高い領域は、安全のため詳細のまま残します。画風の名前ではなく、実際のテクスチャデータで判定します。

集約できる場合でもマテリアルを詳細領域として残したいときは、ディテールを保持 (Preserve Details) を選びます。すべて自動集約 (Auto Fold All) はすべてのスキャン済みマテリアルを均一色の検査対象にし、すべての詳細を保持 (Preserve All Details) はすべてを詳細保持に切り替えます。単色スウォッチと詳細領域は同じアトラス内に共存できます。集約で変わるのはテクスチャ参照であり、モデルの形状や三角形数ではありません。

同じ色や近い単色を共有する

すべて自動集約 (Auto Fold All)、または個別の均一色を確認して集約を有効にします。配置ボタンの下の色の許容差 (Colour Tolerance)は0～400で、既定値の0は完全一致です。Color Swapperと同じ8ビットRGB差の合計を使います。(100, 110, 120)と(102, 110, 120)の差は2です。

許容差を上げると、近い色の検証済み単色領域は、最も近い既存の代表スウォッチを共有できます。色が少し変わる場合があります。グラデーションやノイズのある詳細領域を単色と見なす設定ではありません。透明度、法線、メタリック、スムーズネス、AO、発光は完全一致が必要です。色だけの一致で他の表面差を消しません。プロファイルに保存され、自動設定でも維持します。設定のリセットで0に戻ります。

UVの重なり: 自動では、AOも一致する検証済み単色スウォッチを共有できます。詳細なAO領域はソースメッシュ間で分離します。許可でも共有でき、禁止ではレンダラーごとのスウォッチを分けます。不透明・透明キャンバスを分離した場合、両者は独立します。

入力チャンネルと URP のマッピング

2. パッキングと入力チャンネル (2. Packing & source channels) でマテリアルを展開すると、入力プロパティを確認できます。URP Lit のメタリック形式は自動検出されます。プロパティ欄には、テクスチャのファイル名ではなく _BaseMap などのシェーダー識別子を指定します。カスタムシェーダーでは、プレビュー作成前にマッピングを確認してください。

チャンネルURP の標準プロパティ出力形式
ベースカラー・不透明度_BaseMapRGB に色、A に不透明度。sRGB サンプリングの PNG。
接空間法線_BumpMap法線マップとしてインポートする PNG。
メタリック・スムースネス_MetallicGlossMapリニア PNG。R にメタリック、A にスムースネス。
アンビエントオクルージョン_OcclusionMapリニア PNG。G にオクルージョン。

すべての対応チャンネルは、同じ領域配置と更新後の UV0 を共有します。対応する元の色補正や一般的な表面係数はマップに焼き込まれ、出力側では二重適用を避けるため中立値に設定されます。省略可能なマップがない場合は、対応するマテリアル値を使用できます。任意のシェーダーコードを自動変換する機能ではありません。

タイリングとカスタムシェーダー

URP Lit では ベースのタイリングを共有 (Share Base Map Tiling) を有効にします。ベーステクスチャの変換を各チャンネルで共有します。各プロパティに独立したスケールとオフセットを使用する、対応カスタムシェーダーの場合にのみ無効にしてください。対応する Repeat、Mirror、MirrorOnce、Clamp のサンプリングと負のタイリングは、詳細領域に焼き込まれます。

有効な全チャンネルで正確な繰り返し周期が一致する場合は、1つの領域を再利用できます。ただし、1枚の三角形が多数の繰り返しをまたぐ場合は、依然として大きな領域が必要になります。要求サイズは元画像の寸法と同じとは限りません。カスタム出力シェーダーでは 出力テクスチャのプロパティ設定 (Output texture property mappings) を確認し、テンプレート選択後に テンプレートから検出 (Detect From Template) を使用します。このガイドの URP ワークフローでは、Metallic Smoothness のパック形式を使用してください。

テクスチャプロパティの選択: 入力チャンネルと出力プロパティは、選択したシェーダーのTexture2Dプロパティを表示名と識別子で一覧表示します。なし（テクスチャを省略）でテクスチャ入力を除外できます。保存済みのプロパティが見つからない場合は、その値を選択したまま警告を表示し、既存の割り当てを自動変更しません。テクスチャ配列とキューブマップは対象外です。各プロパティは既存の色、法線、メタリック／マスク、AO、発光の意味で処理され、任意のプロシージャル効果を自動ベイクする機能ではありません。

アトラス解像度、自動調整、余白

プレビューにはアトラスサイズの概要を1行で表示し、縮小領域がある場合はその数も示します。この行にカーソルを合わせると、ソース解像度の上限、密度目標、余白、集約した三角形数、UV重複の保護、回転の判断を確認できます。再構築待ちの間も、表示中のプレビューを説明します。

余白を自動設定は自動サイズと固定サイズの両方で既定で有効です。各キャンバスの生成サイズに合わせ、小さな非圧縮・ミップマップなしのアトラスでは1ピクセル、8Kでは16ピクセルになります。圧縮またはミップマップ使用時は4ピクセル以上です。不透明と透明で別の余白を使用できます。オフにすると余白を手動設定できます。実際の値はアトラスサイズのツールチップと書き出し解像度レポートに表示されます。API設定はAtlasSettings.automaticPaddingです。

高度なアトラス設定のアトラスのサイズ設定は、既定で自動です。自動では、要求されたディテールが収まる最小のキャンバスを最大アトラスサイズの範囲内で選択します。固定を選ぶと、固定アトラスサイズが幅と高さの正確な寸法になります。たとえば要求されたディテールが4096 x 4096に収まっても8192 x 8192を使用できます。固定では正方形を使用し、長方形のサイズ選択と非2の累乗サイズへの切り詰めを行いません。自動に戻すと元の設定が再び適用されます。空き領域をディテールに使用で各領域に空き領域を配分し、「元の解像度を超える拡大を許可」するとソース解像度またはワールド空間の目標を超えて拡大できます。固定を選んでも、これらのオプションは自動で有効にならず、入力に存在しないディテールは復元されません。透明アトラスを分離する場合は、各キャンバスに固定サイズを使用します。出力の解像度レポートにもサイズ設定が記録されます。

Atlas Shape の既定値は Square（正方形）です。Rectangular（長方形）は別に選択できます。2の累乗以外の寸法は個別に有効にします。

Allow Non-Power-of-Two Dimensions は既定でオフです。既定の出力は2の累乗の正方形です。Atlas Shape を Rectangular にすると、1024 x 2048 など各辺が2の累乗の長方形も使用できます。有効にすると4ピクセル単位でさらに切り詰めます。元のマテリアルを展開すると、割り当てたテクスチャ名、パス、インポート後の寸法と画像ファイルの寸法を確認できます。解像度の上限は現在割り当てられたインポート済みテクスチャと各UV領域の範囲です。未割り当ての4K元画像や以前のベイクの元画像は読み込まれません。

形状に基づくパッキングと長方形アトラス: アイランドの空き領域を再利用し、テクセルと余白を重ねずに配置します。外接矩形が重なる場合があります。ベイクは割り当てた形状と周囲の余白に元テクスチャの対応ピクセルをコピーし、アイランド端の色を引き伸ばしません。形状外の隙間は別のチャートで使用でき、手動サイズ合わせの再ベイクでも元の周辺ディテールを保持します。幅と高さは圧縮ブロックに合わせて個別に選びます。空き領域で元の解像度までディテールを復元できます。元の解像度を超える拡大には明示的な設定が必要です。プレビューにはテクスチャ全体の枠と、余白を含む使用率・空き領域の割合を表示します。

設定初期値・範囲使い方
アトラスの最大サイズ (Maximum Atlas Size)初期値 4096。256、512、1024、2048、4096、8192 から選択。出力の固定サイズではなく上限です。収まる場合は、より小さい2の累乗の正方形アトラスを使用できます。
最大サイズに自動調整 (Auto Fit to Maximum Size)有効。まず要求されたディテールで配置を試み、必要に応じて詳細領域を縮小して内容と余白を収めます。
ディテール倍率 (%) (Detail Scale (%))初期値 100%。範囲 5～100%。自動調整前のソース解像度またはワールド空間の目標に倍率を適用します。空き領域の活用では、この初期目標を超えて元のソース解像度まで復元できます。
エッジの余白 (Edge Padding)既定は自動。手動の範囲は1～16ピクセル。すべてのマップで各領域の周囲に余白を追加します。自動設定では生成サイズに合わせ、ミップマップまたは圧縮を使用すると4ピクセル以上になります。自動設定をオフにすると手動で指定できます。余白もアトラスの面積を使用します。

自動調整でディテールが減る場合は、プレビューに通知が表示され、各詳細マテリアルに要求サイズと出力ピクセル寸法が表示されます。書き出した Atlas_Resolution.txt にも記録されます。元テクスチャやそのインポート設定は変更されません。

4096 のテクスチャなのに 4092 × 4088 と表示される理由：領域寸法は、メッシュの UV が使用する範囲を表しています。画像端に未使用部分があると、元画像より少し小さくなります。その外側に余白を追加するため、約4Kの領域でも、厳密モードでは4Kアトラスに収まらない場合があります。

要求密度を自動縮小せずに維持したい場合にのみ、自動調整を無効にします。このとき優先度は無効になります。配置に失敗した場合は、自動調整を有効にする、最大サイズを上げる、入力ディテール上限を下げる方法があります。自動調整でも、余白付きの1ピクセル領域を無制限には配置できません。最小構成が収まらない場合は、入力を分割する、余白を減らす、最大サイズを上げるなどの対応が必要です。

テクセル密度の基準

テクセル密度 (Texel Density)の既定値はソース解像度 (Source Resolution)で、インポートされたテクスチャの寸法とタイリングを使用します。ワールド空間 (World Space)は、オブジェクトのスケールを含むUV方向のメッシュ寸法から、同じ大きさの面に近い密度を割り当てます。Unity単位あたりのピクセル数 (Pixels Per Unity Unit)は既定で512、スライダー範囲は64～2048です。自動調整で目標値が下がる場合があります。ワールド空間は詳細領域をレンダラーごとに配置するため、繰り返しオブジェクトでも必要な領域が増える場合があります。

配置処理の時間を抑えるため、キャンバスごとの領域が256を超えると余白を使った拡大を行いません。形状、余白、詳細上限によっても空きが残ります。最大サイズの変更や拡大の許可で、完全に埋まるとは限りません。

自動UV共有と手動スタック

UVの重なり (UV Overlap)の既定値は自動 (Auto)で、AOまたはHDRPマスクを使う異なるソースメッシュの詳細領域を分離します。検証済み単色スウォッチは各チャンネルが一致すれば共有でき、許容差は基本色RGBだけに適用します。許可 (Allow)は同じソースマテリアルの詳細領域をレンダラー間で再利用できますが、テクスチャを共有する全マテリアルを自動で重ねる機能ではありません。禁止 (Prevent)はレンダラーと分離したUVシェルを別領域にし、単色スウォッチも分けます。接続されたソースシェル内の既存の重なりは自動修復できません。形状を考慮した配置では、使用ピクセルと余白を分離したまま外接矩形が重なる場合があります。手動スタックには別の共有テクスチャ判定を使用します。

重要なマテリアルにディテールを割り当てる

優先度: 標準は、すべてのソースマテリアルを標準に設定します。優先度は相対的なため、すべてを同じ優先度にしても密度のバランスは変わりません。空き領域をディテールに使用は、共通の密度倍率で各領域をまとめて拡大し、自動フィットが有効な場合はマテリアルの優先度も維持します。アップスケールが無効な場合、ソース解像度またはワールド空間の目標が拡大の上限になります。アトラスの寸法は変わりません。アイランドの形状やパディングによって空き領域が残る場合があります。

ディテール優先度 (Detail Priority) は、自動調整で詳細領域を縮小する必要があるときの相対的な優先度です。通常のマテリアルは標準のままにし、重要なものだけ上げます。複数のマテリアルを高または最高に設定できます。すべてのマテリアルに割合を指定したり、チャンネルごとに調整したりする必要はありません。

優先度相対的な要求面積用途例
低 (Low priority)標準の 0.5 倍単純な面や目立ちにくい面。
標準 (Normal priority)1 倍。初期値。大半のマテリアル。
高 (High priority)標準の 2 倍印刷ラベル、布模様、顔、鎖帷子など。
最優先 (Very high priority)標準の 4 倍特に重要な少数の詳細マテリアル。

これらは相対面積の配分であり、アトラスの固定占有率や、縦横の寸法をその倍率にする指定ではありません。元のサイズ、UV 範囲、余白、配置形状にも影響されます。空き領域の活用では、初期のディテール目標を超えて元のソース解像度まで復元できます。ソースのサンプル数を超えて拡大するには、元の解像度を超える拡大を許可する設定が必要です。すでにすべて収まる場合は、優先度を上げても他のマテリアルを不要に縮小しません。集約済みの単色スウォッチは1ピクセルのままです。

例：木材、革、単純な金属を標準のままにし、鎖帷子と顔の両方を高に設定して、プレビューを再作成します。必要な場合は自動調整で詳細領域を再配分します。ベースカラー、法線、その他の対応チャンネルは常に同じ領域を使用します。優先度だけで特定の解像度になるとは考えず、実際の出力寸法を確認してください。

フィルタリング、ミップマップ、インポート設定

ツール更新後、既存のウィンドウでは新しい初期設定を反映するため、ミップマップを一度だけ有効にします。その後の手動変更は維持します。既存プロファイルを読み込むと、保存されたミップマップ設定を復元します。

ポイントフィルタリング (Point Filtering) は初期状態で無効です。ミップマップなしではバイリニア、ありではトライリニアフィルタリングを使います。パレットやピクセル表現をくっきり見せたい場合は、必要に応じて有効にします。ミップマップを生成 (Generate Mip Maps) は通常の元マテリアルに合わせて遠距離のハイライトを安定させるため、初期状態で有効です。既存プロファイルの保存設定は維持します。無効にすると、細かい金属や法線の模様が元画像より鮮明に見えたり、ちらついたりすることがあります。小さなミップレベルでは隣接するアトラス領域が混ざり、特に小さな単色スウォッチで目立つことがあります。詳細アセットでは遠距離のサンプリングに役立つため、余白を増やして実際の使用距離で確認してください。

出力アトラスは Clamp、選択した Export Compression、Read/Write 無効でインポートされます。対応する元のラップ動作は、各領域にすでに焼き込まれています。圧縮は小さなスウォッチやデータチャンネルに影響するため、変更後は結果を確認してください。共有アトラスではフィルタリングとインポート方針も共有されます。1つの出力セットで、モデルごとに異なるフィルタリングを同時に使うことはできません。

出力圧縮 (Export Compression)の既定値は高品質 (High Quality)です。バランス (Balanced)と非圧縮 (Uncompressed)も選べます。実際のGPU形式はプラットフォームとテクスチャの種類に依存します。見た目の差が圧縮によるものか調べる場合は、非圧縮を使用してください。

不透明、カットアウト、透明マテリアル

アトラスを共有しても、すべての面で必ず1つのマテリアルを使えるわけではありません。不透明、アルファクリップ、ブレンド透明では、互換性のある出力状態が必要です。ブレンド、しきい値、カリング、深度、描画キュー、対応する照明設定の違いにより、グループが分かれる場合があります。ツールには予定グループ数が表示され、透明な入力がある場合は通知されます。

透明度を維持する場合は 透明サーフェスを不透明にする (Make Transparent Surfaces Opaque) を無効のままにします。ガラスなどのブレンド透明面を意図的に不透明にする場合にのみ有効にしてください。ウィンドウに警告が表示されます。アルファクリップのカットアウトは維持されます。元マテリアルは変更されず、他の状態の違いによっては複数の出力マテリアルが必要です。

例：不透明な家具とガラス瓶は、同じアトラステクスチャを参照しながら、不透明用と透明用のマテリアルを使えます。プレハブは個別のまま書き出せます。メッシュ結合時も透明部分は描画順序を保つため、独立したレンダラーとして残ります。

透明アトラスの共有と分離

透明アトラス (Transparent Atlas)の既定値は自動 (Auto)です。不透明とブレンド透明の両方がある場合、分離後の合計推定テクスチャメモリが共有時より10%を超えて少なくなるか、分離時だけ配置に成功すると、別キャンバスを使います。共有 (Shared)は1枚を使い、分離 (Separate)は両方の種類がある場合に必ず分けます。各キャンバスの寸法や余白が異なる場合があります。固定サイズは各キャンバスに指定した正方形サイズを使うため、メモリが増える場合があります。出力マテリアルはそれぞれの描画状態を保持します。

アトラスとモデルのプレビューを確認する

詳細領域の縮小時は、出力1ピクセルが覆う元画像の面積を平均します。色、不透明度、法線、メタリック、スムーズネス、AO、発光と手動でのアイランドサイズ変更に適用します。法線は方向を平均してから正規化し、各チャンネルの元画像サイズとタイリングを使います。元画像の Filter Mode が Point なら最近傍サンプリングを維持し、検証済みの単色スウォッチは変えません。通常出力はミップマップありでトライリニア、なしでバイリニア補間を使います。Point Filtering は出力サンプリングの設定です。既存アトラスに適用するにはプレビューを再作成し、再エクスポートします。

自動更新はプレビュー作成ボタンの横にあります。モデルカメラは表示モデルの範囲とペインの縦横比に合わせます。スクロールで初期距離の5%まで近づけ、クリップ面もモデルの大きさに合わせます。ビューをリセットすると全体表示に戻ります。

縦の仕切りをドラッグして設定パネルの幅を変更します。ダブルクリックで既定の幅に戻り、Escapeで幅の変更を取り消します。アトラス領域をドラッグせずにクリックすると、設定パネル内のソースマテリアルを展開して強調表示し、そこへスクロールします。選択されたマテリアルの領域をシアンの枠で表示します。折り畳まれた色を複数のマテリアルが共有している場合は、すべての所有元を強調表示します。空き領域をクリックすると選択を解除します。ドラッグによる移動、修飾キー付きのドラッグ、ダブルクリックによる全体表示も引き続き利用できます。選択にはチャートマスクを使用し、かみ合った領域や表示中の透明アトラスを正しく区別します。選択操作でUVや出力テクスチャは変更されません。

手動アイランド配置（詳細）

アトラスプレビューの手動アトラス配置（詳細）を開き、編集を有効にします。左ドラッグでアイランド全体を移動します。全体のUV表示がオフでも、移動中のUV辺は表示されます。自由 / X / Yで移動軸を選びます。Xは横移動でYを固定します。ドラッグ中にXまたはYを押すと軸を制限し、同じキーでもう一度押すと解除します。Escでキャンセルします。Shiftを押しながら横移動（Y固定）、Ctrl（macOSではCommand）を押しながら縦移動（X固定）ができます。離すと選択中の軸モードに戻り、両方を押すと位置を保持します。中央・右ドラッグで表示移動、スクロールでズーム、ダブルクリックでテクスチャ全体表示に戻ります。スナップは1、4、8、16、32ピクセル単位です。左下基準のX/Y座標入力にも軸の固定が適用されます。固定により誤移動を防げます。

コンパクトな手動配置バーには、編集、スナップ、自由/X/Y、固定、X/Y座標、移動、元に戻す、リセットを1行にまとめています。元に戻すとリセットはツールチップ付きアイコンです。UVの重なりを許可すると同じ行にサイズ一致を表示します。配置の状態はアトラス下部に表示します。ボタンは任意で使えるDPT_CoreGUI.ButtonStyles APIを使用し、既存のコアスタイルは変更しません。

他の領域を並べ替える間、アイランドをテクスチャ枠の外へ退避できます。UV輪郭は表示され、退避したアイランドへ移動できるよう表示移動の範囲も広がります。サンプルを保持するため、戻してもマップのデータは失われません。すべてのアイランドと余白が枠内に戻るまで書き出しは無効です。極端な座標を防ぐため、退避範囲は各方向にアトラスの長辺の8倍までです。

UVの重なり: 許可では、同じ入力テクスチャセットを使うアイランドを手動で重ねられます。同じテクスチャを共有する別マテリアルも対象です。入力のUV範囲、サイズ、向きは異なっていても構いません。有効なカラー、法線、メタリック・マスク、AO、発光の入力テクスチャがすべて一致する必要があります。他のマップが異なる場合、ベースマップだけの一致では重ねられません。テクスチャなしの領域は同じ入力マテリアル、または全チャンネルが同一の単色領域なら共有できます。異なるテクスチャセットの重なりは拒否します。重なりは全マップのベイク済みピクセルを共有し、最後に移動したアイランドのピクセルを使用する編集です。異なるUV範囲や色補正を重ねると見た目が変わる場合があります。Alt＋クリックで重なったアイランドを切り替えます。元のサンプルは保持され、重なりを解くと復元されます。自動と防止では余白を含む形状の重なりを拒否します。不透明と透明のキャンバスは独立しています。元に戻す操作はサイズ変更と表示順を含め最大20回を復元します。配置リセットは元の配置と寸法に戻し、固定と履歴を解除します。手動配置は現在のプレビュー専用で、設定プロファイルには保存されません。再構築、スクリプト再読み込み、ウィンドウを閉じる操作で解除されます。配置を保持するには現在のプレビューを書き出してください。

重ねるときにサイズを合わせるは初期状態で有効です。自由移動中、小さいアイランドの中心を同じテクスチャを使う大きい領域に置くと、小さい側の寸法と位置を合わせます。ドラッグの輪郭で結果を確認でき、ドロップすると全マップとミップマップを入力テクスチャから新しいサイズで再ベイクします。入力に残る細部を回復できますが、入力解像度を超えても細部は増えません。無効にするとサイズを保持して部分的に重ねられます。X/Yの軸固定中はサイズを合わせません。重なりを解いても新しいサイズを保持し、元に戻す操作で以前の寸法に戻せます。拡大するのはドラッグした小さい側だけで、大きい側を移動しても静止した小さい領域は変わりません。

アトラス表示コントロールの下にあるUVワイヤーフレーム、領域の枠、テクスチャの枠の色フィールドを直接使います。モデルプレビューの照明コントロールの横には両ペイン共通の背景ピッカーがあります。選択・移動中のUV辺にも同じ色を使い、無効な移動は赤色で表示します。設定は再構築やEditor再起動後も保持されます。シーンカメラ、元マテリアル、出力テクスチャは変更しません。

表示・操作確認する内容
アトラステクスチャ (Atlas textures)チャンネル選択から生成マップを切り替え、色、法線、PBR データを個別に確認します。
領域の輪郭 (Region outlines)枠は配置した領域を示します。「色」で枠の色を変更できます。領域にカーソルを合わせると入力、寸法、三角形数を確認できます。
モデルの変更前 / 変更後 (Before / after model)元のマテリアル (Original materials) と アトラスマテリアル (Atlas materials) を比較します。左ドラッグで回転、スクロールでズームします。
数値と通知アトラス寸法、領域数、スロット数、出力マテリアル数、自動解像度低下を確認します。

スキンメッシュは元のスケルトンとブレンドシェイプのウェイトを使って表示されます。左右のプレビューは同じポーズを使用します。無効なレンダラーと非アクティブなオブジェクトは表示されません。元のポーズや表示状態を変更した場合は、プレビューを作成し直してください。プレビューは元の階層を使ってアトラス適用前後の見た目を比較するもので、最終的な結合ジオメトリやアニメーション再生は表示しません。書き出したプレハブをシーンで確認し、変形、取り付け部品、透明度、LOD、ゲーム内動作を検証してください。

配置やアトラス設定を変更するとプレビューが更新待ちになります。自動更新が有効な場合は、設定が落ち着いてから再生成します。入力や階層の変更でも再生成が必要になることがあります。保存してエクスポート (Save & Export)は必要な場合に再構築し、それ以外はサイズ合わせを含む現在の手動配置を保持して書き出します。ウィンドウを閉じる、スクリプトを再読み込みする、Play Mode を切り替えると、一時プレビューは解放されます。処理が長い場合は Unity の進捗ダイアログから中止し、入力を調整して再実行できます。

どちらのプレビューでも、スクロールで少しずつズームできます。アトラスはカーソル位置を中心にズームします。全体表示 (Fit) またはアトラスのダブルクリックで、ズームとパンをリセットできます。

メモリと書き出しの統計

アトラスとメッシュのみの両モードで、プレビューの詳細ドロップダウンを常時表示のメモリ比較（Memory Comparison）表に置き換えました。変更前、適用後プレビュー、推定変化の列で、有効なレンダラー、重複しないマテリアル、三角形、頂点、メッシュVRAM、テクスチャVRAM、強調表示された合計を比較します。減少は緑、増加は赤で、符号付きの量と割合を表示します。各行の集計範囲はツールチップで確認できます。形状の数は全LODと有効なメッシュの各使用箇所を含み、UV変換で頂点が増える場合があります。最終的な結合は書き出し時に行います。

メモリは、非アクティブな入力、ミップマップ、テクスチャ配列を含め、選択範囲内で参照される各メッシュ・テクスチャリソースを1回だけ数えます。メッシュVRAMは頂点配列をコピーせず、保存された頂点構成から頂点・インデックスバッファを推定します。CPU読み取り用コピー、ブレンドシェイプ格納領域、追加スキニングバッファ、エンジンの管理領域は含みません。ソーステクスチャはインポート形式、アトラス出力は既存のプラットフォーム依存の圧縮推定値を使用します。KB・MBは10進数で、ディスクサイズやEditorのプロセスメモリではなくリソースの推定値です。フレーム時間の予測値でもありません。計算結果はキャッシュされ、プレビューの再生成、メッシュ・マテリアルの置換、出力圧縮・ミップ設定の変更時に更新します。

書き出し成功後、書き出し操作付近の前回の書き出しを開くと、実際のレンダラー、マテリアル、スロット、ジオメトリの数を確認できます。プレビュー生成と書き出しの処理時間は別々です。選択したルート内で有効なジオメトリを全LODレベルを含めて数え、結合後に無効のまま保持された元レンダラーは除きます。頂点と三角形はメッシュの各使用箇所を数え、メッシュアセット数は重複を除きます。ドローコールやフレーム時間の実測値ではありません。

すべての書き出しモードでAtlas_Statistics.txtを作成します。統計レポートを開くから最新レポートを開けます。Raw Atlases & Meshes出力では、非アクティブな入力も含む全ソースメッシュと保存したUV変換済みメッシュを比較します。レンダラーとマテリアルは作成しません。前回の統計は、次の書き出しが成功するまでその時点の記録として残り、ソースの選択が変わると非表示になります。

Atlas_Statistics.txtは形状の数と処理時間を記録します。アトラス出力のAtlas_Resolution.txtは推定テクスチャメモリと、現在のEditorプラットフォームで実際にインポートされた形式、ミップ数、サイズを記録します。レポートのソースメモリはマッピングされた入力のみを対象にします。比較表はマテリアルが参照する全テクスチャを含むため、ソース合計値が異なる場合があります。

書き出しモードと生成ファイル

UnityのProjectウィンドウからフォルダーを出力フォルダーに直接ドロップするか、その横の参照...で既存の保存先を選択します。現在のフォルダーが存在する場合は、そこから参照を開始します。選択したパスはAssetsからの相対パスになります。ファイル、複数フォルダーの同時ドロップ、このプロジェクトのAssets外のフォルダーは選択できません。新しいAssets内のパスを手入力すると、エクスポーターがそのフォルダーを作成します。保存先を変更しても、アトラスは再構築されません。

メッシュ出力 (Mesh Output)結果適した用途
個別のプレハブ (Separate Prefabs)入力ルートごとに1つのプレハブ。出力アトラスと互換マテリアルを共有します。独立モデルや再利用する小物が必要な場合。初期設定です。
グループ化したプレハブ (Grouped Prefab)入力階層を個別の子として含む1つの親プレハブ。メッシュは結合しません。配置全体をまとめて置く場合や、複数入力がリグを共有する場合。
選択したメッシュを結合 (Merge Selected Meshes)選択した互換静的メッシュや共有リグのメッシュを結合した1つのプレハブ。不適合・除外部分は独立します。レンダラー数を減らしつつ、独立させる部分を選びたい場合。
Raw Atlases & Meshesマップ、UV変換済みメッシュ、割り当てレポートのみ。マテリアルとプレハブは生成しません。出力マテリアルとメッシュの割り当てを独自に設定する場合。

出力名 (Output Name) の初期値は Optimized_Model、出力フォルダー (Output Folder) は Assets/DPTGames/Material_Optimizer/Generated です。参照... (Choose Output Folder) で現在のプロジェクトの Assets 内を選択します。書き出しごとに固有のフォルダーが作成され、既存の出力や元アセットは上書きされません。個別プレハブのファイル名には入力名を使用し、同名の場合は固有パスが付けられます。

出力フォルダー内の場所内容
Meshes/UV 更新後のメッシュ、結合メッシュ、必要に応じて独立した透明部分のメッシュ。
Textures/生成アトラスマップ。
Materials/互換性のある共有出力マテリアルのグループ。
Prefabs/シーンに配置するプレハブ。
Animations/ブレンドシェイプの参照先を変更する場合の、複製したアニメーションクリップとオーバーライドコントローラー。
Atlas_Resolution.txtアトラスサイズ、余白、詳細領域の要求寸法と出力寸法。
Atlas_Statistics.txtジオメトリ、レンダラー、マテリアルの実測数と、個別のプレビュー生成・書き出し処理時間。全出力モードで作成します。
Atlas_Merge.txt結合モードで作成。結合した入力数、剛体部品数、独立して残した理由を記録します。

書き出し後、Unity は生成プレハブを選択し、最初のプレハブを強調表示します。ステータスには保存先が表示されます。結果が見つからない場合は、そのフォルダーの Prefabs を開いてください。対応するシーン入力を置き換える場合は、書き出し後にシーンオブジェクトを置換を有効にします。オフの場合は生成プレハブを手動で配置してください。移動するときは Unity の Project ウィンドウで、生成アセット一式をまとめて移動してください。元アセットの削除や出力の配布前には、スクリプト、アバター、アニメーションクリップ、コライダーメッシュなどの依存関係を確認してください。

シーンの置換: 書き出し後にシーンオブジェクトを置換を有効にすると、成功後に入力インスタンスを出力プレハブへ置き換えます。1回のUndoで元に戻せます。個別出力は親と変換を保持し、グループ出力は配置を新しいルート内に保持します。同じ通常シーンの入力のみ対応し、プロジェクトアセットとプレハブ編集ステージは対象外です。削除したシーンオブジェクトへの参照は確認が必要です。Undo後も出力ファイルは残り、シーンは自動保存しません。

アトラスとUV変換済みメッシュのみの書き出し

Mesh Output: Raw Atlases & Meshesを選び、アトラスとメッシュを書き出すを押します。Textures/、Meshes/、Atlas_Raw.txt、Atlas_Resolution.txt、Atlas_Statistics.txtを保存します。マテリアルやプレハブの生成、メッシュ結合、シーン置換は行いません。割り当てレポートには、元のレンダラー、出力サブメッシュ、使用するアトラスと互換マテリアルグループ、基本的な描画設定が記載されます。独自のマテリアルを作成し、レポートに従ってマップとメッシュを割り当ててください。対応する色とサーフェス値はすでにベイクされているため、色などの乗算値はニュートラル、タイリングは1にします。スキンメッシュでは元のスケルトン、ボーン順、ブレンドシェイプのウェイトを維持してください。使用するのは既存のチャンネル構成で、任意の追加マップやプロシージャル効果は対象外です。

Editor API: AtlasExporter.ExportRaw(build, parentFolder, outputName)、またはAtlasExportMode.RawAtlasesAndMeshesを設定してExportAllを使用します。結果のprefabsは空で、materialsFolderとprefabsFolderは空文字列です。プレハブを返すExportは、アセット作成前にこのモードを拒否します。

アトラスを作らずにメッシュを結合する

設定パネル上部の最適化モード > メッシュ結合のみを選択します。完全な入力オブジェクトを追加し、結合する静的メッシュ、共有リグのメッシュ、取り付け部品を選択して、結合プレビューを作成をクリックします。予測レンダラー数を確認し、結合して書き出すをクリックします。

このモードは元のプロジェクトマテリアル、シェーダー、テクスチャ配列、キーワード、シェーダープロパティを保持します。テクスチャのサンプリング、アトラスのベイク、UVの再マッピング、異なるマテリアルの統合は行いません。頂点カラーとすべての元のUVチャンネルは、VCCoreなどのシェーダーで引き続き使用できます。UV0のないメッシュにも対応します。プレビューでは元の外観と保持されるマテリアルを比較し、メッシュの結合は書き出し時に行います。

書き出しではプレハブ、メッシュアセット、Atlas_Merge.txt、Atlas_Statistics.txtを作成します。アトラステクスチャや解像度レポートは生成しません。既存のプロジェクトマテリアルは直接参照します。メモリ上だけに存在するマテリアルは新しいアセットとして保存されますが、そのテクスチャは事前に保存してください。異なるマテリアルは別々のスロットを保持するため、レンダラー数の削減が必ずしも描画呼び出し数の削減になるとは限りません。元のアセットとインポート設定は保持されます。

このモードでは、UV1座標の変更を避けるため、ベイク済みライトマップを使用するレンダラーは個別に保持します。透明面、個別にアニメーションする部品、互換性のない描画設定に関する既存の結合制限は引き続き適用されます。各オブジェクトのローカル座標、ピボット、スケールに依存するカスタムシェーダーは、結合後の外観を確認してください。テクスチャアトラスに戻すとアトラス設定が再表示されます。選択したモードは設定プロファイルに保存されます。

var settings = new AtlasSettings { mergeMeshesOnly = true };
var scan = AtlasScan.Create(sourceObjects, preserveMaterials: true);
using (var build = AtlasBuilder.Build(scan, settings))
{
    AtlasExporter.ExportAll(build, "Assets/Optimized", "Merged_Model");
}

詳細選択と静的メッシュの結合

最新のアトラスプレビューを作成すると、メッシュ結合セクションにソースのメッシュレンダラー数と出力予測数を表示します。結合スイッチ、レンダラーの選択、アタッチメントボーンを変更すると予測を更新します。パーツを分離して保持する理由を展開すると、除外、LOD、互換性のないレンダラー設定、リグ、アニメーションの制限、透明部分を確認できます。不透明と透明が混在するメッシュでは、結合後も透明部分のレンダラーが残るため、レンダラー数が増える場合があります。これはレンダラー数の予測です。描画コール数はレンダリングパスやバッチ処理に依存します。最終結果はエクスポート時に記録します。解析はモデルを複製せず、ソースデータの読み取りだけを行います。

4. メッシュ結合 (Mesh Merging) は出力設定の前に独立して表示されます。メッシュ出力 (Mesh Output) で結合を選び、直下の静的メッシュと同一リグの切り替えを設定します。部品や取り付け先ボーンは レンダラー選択と取り付け (Renderer Selection & Attachments) で選択します。保存先は 5. モデルを出力 で設定します。

  1. 選択したメッシュを結合 (Merge Selected Meshes) を選び、レンダラー選択と取り付け (Renderer Selection & Attachments) を開きます。静的結合には 静的メッシュを結合 (Merge Static Meshes) を有効にします。リグ付きメッシュ用の切り替えは別にあります。
  2. 含めるレンダラーにチェックを入れます。すべて選択 (Select All) または すべて個別に維持 (Keep All Separate) で初期選択をまとめて変更できます。同名の項目は入力番号と階層パスで区別します。チェックを外したレンダラーにもアトラスは適用されます。
  3. 書き出して Atlas_Merge.txt を確認します。結合グループには、少なくとも2つの選択済み互換レンダラーが必要です。レンダラー設定が異なる場合は、複数の結合レンダラーに分かれることがあります。

固定された家具部品、建物の構造、機械の外装、常に一緒に表示・移動する小物などが適しています。互換性には、レイヤー、影、プローブ、描画順序、モーションベクトル、その他の対応レンダラー設定が含まれます。静的結合では、対応するベイク済みライトマップの UV 変換も適用されます。

ドア、引き出し、着脱装備、個別に移動・非表示にする部品など、独立レンダラーに依存する部分は結合しないでください。元の Transform とコライダーは保持されますが、完全に結合へ取り込まれたレンダラーは無効になります。元の Transform を動かしても、結合済み静的メッシュ内の形状は個別には動きません。

既存のLODレベル内でメッシュを結合する

Merge Selected Meshesまたはメッシュ結合のみでは、互換性のある静的メッシュと共有リグのスキンメッシュを、既存のLODGroupと一致するレベル構成の範囲内で結合します。例えば、互換性のある2つのLOD0部品を1つのLOD0レンダラーにまとめ、LOD1部品は別のLOD1レンダラーにまとめます。独立したLODGroupは個別に保持されます。既存のLOD所属がない選択済みの小物は、結合書き出し時に互換グループへ自動割り当てされます。

書き出しではLODのレンダラーリストを生成したメッシュに更新します。レベル数、画面相対の切り替えしきい値、フェード幅、フェードモード、アニメーションするクロスフェード、グループの有効状態、ローカル基準点、グループサイズを保持します。LOD境界の再計算や簡略化ジオメトリの生成は行いません。除外した部品、残った透明面、互換性のない部品は元のレベルに残ります。結合したブレンドシェイプのレンダラーも同じLOD所属を維持します。

複数のレベルで再利用されるレンダラーは、所属する全レベルが一致するレンダラーとのみ結合できます。複数のLODGroupで共有されるレンダラーは個別に保持されます。完全なグループルートと参照先レンダラーをすべて選択してください。入力ルート間の参照にはGrouped PrefabまたはMerge Selected Meshesが必要です。Separate Prefabごとに完全なLOD構成を含めてください。

レンダラー数の予測にも書き出しと同じLOD制限を適用します。数値は、その瞬間に表示されるレベルだけでなく、スキャンした全レベルを含みます。Atlas_Merge.txtには更新したLODGroup数を記録します。Editor APIではAtlasExportResult.mergedLODGroupsから取得できます。モデルプレビューは最上位の有効なレベルを表示します。切り替えとクロスフェードは、書き出したプレハブをシーンで確認してください。

小物のLOD: 同じ階層、同じ入力オブジェクト、近くの互換グループの順に選びます。グループに対する小物のサイズ比と各切り替えしきい値から画面上の高さを推定します。次のレベルへ進むときの既定値は画面の高さの3%です。LOD0には必ず含まれます。小さい塩入れはLOD0のみ、椅子はLOD0–2に残る場合があります。複数レベルで同じレンダラーを参照するためジオメトリは複製されず、グループのカリングとともに非表示になります。

LOD詳細設定で自動割り当てとしきい値を変更し、小物ごとに対象グループと自動 / 全レベル / LOD0のみ / 最終レベルを指定 / 独立を選べます。既存のLOD所属は保持します。除外、独立したスクリプト、アニメーション、物理制御の部品は自動割り当てしません。手動指定では未結合や除外の小物もグループで表示制御できます。レポートに割り当てを記録し、AtlasExportResult.assignedLooseLODRenderersから件数を取得できます。低ポリゴンLODメッシュの生成は行いません。

Editor API: AtlasSettings.automaticLODForLooseObjectsの既定値はtrueです。lodMinimumScreenSizeは比率で保存し、既定値は0.03fです（UIは%表示）。AtlasMergeSelectionにはlodMode（AtlasLooseLODMode）、任意のlodGroupとlodLastLevelがあります。自動割り当てがオフでも手動表示指定は有効です。シーン置換では、元の入れ子の子ではなく完全なプレハブインスタンスルートを選択してください。

共有リグと剛体部品の取り付け

4. メッシュ結合 (Mesh Merging) で 同一リグのメッシュと装備を結合 (Merge Shared-Rig Meshes & Attachments) を有効にすると、実際に同じスケルトンを参照する互換 Skinned Mesh Renderer を結合できます。ボーン名が同じだけでは共有リグとは判定されません。同じボーン名を持つキャラクターの別インスタンスは、別スケルトンとして独立したまま残ります。

同じリグにスキニングされたメッシュを結合する

  1. キャラクターの完全なルートと、そのボーンをすでに参照している別のスキン入力を含めます。参照される全ボーンとルートボーンが、選択した入力内に必要です。
  2. レンダラーを分けたまま内部のボーン参照を共有する場合は グループ化したプレハブ (Grouped Prefab)、互換部品を結合する場合は 選択したメッシュを結合 (Merge Selected Meshes) を使用します。個別プレハブでは、各入力に完全なリグが必要です。
  3. 書き出して、シーン内でアニメーションを確認します。結合可能なスキンでは、ボーン参照、補正されたバインドポーズ、可変数のボーンウェイトが保持されます。通常のボーンアニメーションに対応し、結合時にブレンドシェイプのカーブを変更できます。それ以外のレンダラープロパティのアニメーションを持つ部分は個別に保持します。

未スキニングの剛体部品を取り付ける

  1. 剛体部品とキャラクターの完全なリグを含め、書き出し前に部品を必要な位置に配置します。装備だけでなく、道具、パネル、機械部品、アクセサリーなどの剛体ジオメトリにも使用できます。
  2. 剛体レンダラーにチェックを入れます。取り付け先ボーン (Attachment Bone) が 自動 (Automatic) の場合、既存の親ボーンを自動検出します。別入力の場合は、含まれるモデルのボーンやソケットをポップアップから選択します。プレハブやモデルアセットでも選択できます。
  3. リグ付き結合を有効にして、結合モードで書き出します。部品は現在の配置を保ち、全頂点が選択ボーンに100%のウェイトで追従します。剛体としての追従であり、変形用ウェイトの自動生成や手への自動スナップではありません。

取り付け専用のランタイムスクリプトは不要です。結合した部品は、出力スキンメッシュと表示状態を共有します。個別の非表示、交換、取り外し、位置オフセットのアニメーションが必要な場合は、独立させてください。共通のキャラクタールートにある Rigidbody は互換になり得ますが、独立して動く物理部品は結合しません。移動するスキン出力には、ライトマップ付き部品を結合しません。

ブレンドシェイプを持つメッシュの結合

共有リグの結合の下にあるブレンドシェイプメッシュを結合は既定で有効です。互換性のあるスキンメッシュの全フレーム、フレームのウェイト、現在のウェイトを保持します。固有名は維持し、重複名には元の部品名を付けて区別します。Animatorの該当クリップをAnimations/へ複製し、書き出したAnimator Override Controllerで新しい参照先に変更します。既存のオーバーライドとLegacy Animationにも対応します。元のクリップやコントローラーは変更せず、追加のランタイムコンポーネントも不要です。残った透明面用に元のカーブも保持します。

選択ソース内のシリアライズ済みスクリプトが直接参照するレンダラーは個別に保持します。表示状態やマテリアルのアニメーション、互換性のない設定も結合対象外です。外部スクリプト、インデックスによる制御、動的に読み込むクリップ、Playables、書き出す階層にないアニメーションシステムは参照先を確認してください。任意の参照を自動変更する機能ではありません。オフにすると以前と同様に個別レンダラーを保持します。レポートには結合したシェイプと変更したクリップ数を記録します。API: AtlasSettings.mergeBlendShapes、AtlasExportResult.mergedBlendShapes、remappedAnimationClips。

効果的な最適化と検証

代表的なシーンで最適化前後を測定します。Unity のプロファイリングツールで、マテリアルスロット、レンダラー数、ドローコール、テクスチャメモリ、フレーム時間を比較してください。個別モデル間でマテリアルを共有しても、すべてが自動的に1ドローコールになるわけではありません。透明度、パス、照明、バッチング、レンダラー設定も影響します。

大きな結合メッシュは、一部分だけが画面に見える場合でも表示対象になることがあります。通常一緒に表示され、移動するものをまとめてください。大きなアトラスは、無関係なテクスチャを同時に読み込む原因にもなります。用途に合わせてサイズ、チャンネル数、グループを選んでください。元の高解像度画像を同梱したままでは、出力アトラスを小さくしてもパッケージ内の元画像サイズは減りません。

  • 同じシーン照明とカメラ距離で、出力プレハブと元モデルを比較します。
  • 変形、ブレンドシェイプ、LOD 切り替え、透明度、コライダー、個別レンダラーを参照するスクリプトをテストします。
  • 両方のレポートを確認し、出力の依存関係と動作を検証するまで元アセットを保持します。

対応する入力と制限

以下のテクスチャサンプリング制限はテクスチャアトラスモードに適用されます。メッシュ結合のみは、頂点カラーやテクスチャ配列を含む元のシェーダーとマテリアルの入力を保持します。メッシュと結合の互換性制限は引き続き適用されます。

ベイクと結合はUnity Editorで実行します。ランタイムベイク、ランタイムメッシュ結合、ゲームのビルド前に自動で結合する機能はありません。
