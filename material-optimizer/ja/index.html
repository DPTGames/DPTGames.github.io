このツールでできること

Scene Material Optimizer, Texture Atlas Creator & Mesh Merger は、1つ以上のモデルからマテリアルの入力を収集し、対応するテクスチャを共有アトラスに配置して、メッシュのUVを更新します。互換性のある元マテリアルは、共有の出力マテリアルに集約されます。モデルを個別に書き出す、1つの親プレハブにまとめる、選択した互換メッシュを結合する、という方法から選択できます。

処理変更される内容実際の用途
テクスチャアトラス作成テクスチャ配置とUV0座標。複数モデルが同じテクスチャを参照できます。1つのメッシュにする必要はありません。
マテリアル集約マテリアル参照と互換性のあるサブメッシュのスロット。モデルを個別に保ったまま、マテリアルやスロット数を減らせます。
任意のメッシュ結合選択した互換レンダラーとジオメトリ。レンダラー数を減らせます。結合した部品は表示状態とカリングを共有します。

このガイドは、メタリックワークフローを使用する URP Lit マテリアルを対象としています。最適化処理は Unity Editor 内で実行され、生成アセットに最適化ツール専用のランタイムコンポーネントは不要です。ただし、出力プレハブは元のスクリプト、アニメーションクリップ、アバター、コライダー用アセットに依存する場合があります。

導入、起動、言語の選択

Scene_Material_Optimizer と同梱の DPT_Core を含め、パッケージ全体をインポートしてください。DPT Core は共通のエディターUIを提供します。対応するアトラス処理は標準の URP Lit マテリアルを使用し、独自シェーダーやシェーダーの編集は不要です。URP を設定した Unity 6.3 または Unity 7 で使用してください。

  1. URP プロジェクトにパッケージをインポートし、Unity のインポートとコンパイルが完了するまで待ちます。プロジェクトにコンパイルエラーがある場合は、先に解消してください。
  2. Tools > DPT Games > Scene Material Optimizer を開きます。Tools メニューの製品名は、どの言語でも英語のままです。
  3. ウィンドウ上部の English、 日本語、 한국어 から選択します。選択した言語は記憶されます。アセット名、シェーダープロパティの識別子、出力ファイル名は翻訳されません。
  4. Edit Mode で操作します。Play Mode への移行中や実行中は、アトラスの操作が無効になります。設定欄とプレビューを表示できる広さを確保してください。最小ウィンドウサイズは 1020 × 650 です。

ヘルプを非表示 は、書き出し欄の情報メッセージを含む任意のガイダンスを非表示にします。ツールチップ、警告、エラー、重要な処理状況は引き続き表示されます。プレビュー完成時の専用メッセージは表示しません。アトラスサイズの概要行にカーソルを合わせると、共有カラーピクセルに集約した三角形数を確認できます。メモリ比較表は「ヘルプを非表示」とは独立して、見出しから折りたためます。

Hierarchyから開く

モデルのルートを1つ以上選び、右クリックしてDPT Games > Scene Material Optimizerを選びます。選択した入力を読み込み、スキャンします。選択されていないオブジェクトを右クリックした場合は、そのオブジェクトを読み込みます。親子の重複と対応メッシュのない空の入力は除去します。ベイク、書き出し、シーンの変更は行いません。対応メッシュを含むオブジェクトに対してEdit Modeで利用できます。

最初のアトラスを作成する

  1. 1. ソースオブジェクト にシーンオブジェクト、モデルアセット、プレハブを1つ以上ドロップします。Unity で選択して 選択を追加 を押す方法もあります。最初は結果を確認しやすい小さな構成で試してください。
  2. ソースをスキャン を押し、レンダラー、マテリアル、スロット、三角形の数を確認します。続行する前に警告を確認してください。
  3. 既定ではすべての詳細を保持が有効です。単色領域を1ピクセルのスウォッチに集約するには、すべて自動集約、または個別マテリアルの均一色を確認して集約を選択します。多くのマテリアルは 標準 のままで構いません。
  4. URP Lit の マテリアルテンプレート を指定するか、空欄にして現在のパイプラインの標準 Lit シェーダーを使用します。最大サイズに自動調整 を有効にしておきます。アトラスの最大サイズ の初期値は 4096 です。
  5. 緑色の アトラスプレビューを作成 を押します。アトラスの各チャンネルと モデルの変更前 / 変更後 を確認します。重要な面のディテールが不足する場合は ディテール優先度 を上げて、プレビューを再作成します。
  6. アトラスアセットを共有する独立モデルとして書き出す場合は 個別のプレハブ のままにします。グループ化やメッシュ結合が必要な場合に メッシュ出力 を変更します。
  7. 出力名 と、現在のプロジェクトの Assets 内にある 出力フォルダー を指定し、青色の 保存してエクスポート を押します。最新のプレビューは再利用します。ソースやベイク設定が変わった場合は、書き出し前に再作成します。
  8. 新しい出力フォルダーを開き、Prefabs サブフォルダー内のプレハブを使用します。生成プレハブをシーンに配置し、実際の照明とアニメーションで確認します。作業後にシーンを保存してください。

最初の練習には、テーブル、単色のマグカップ、印刷模様のある本、ガラス瓶などが適しています。まず個別プレハブで書き出します。次に、移動可能な小物とガラスを独立させたまま、テーブルの構造部分だけを結合した出力と比較します。これは、ご自身のアセットを使った練習例です。

同梱デモのテクスチャ: 最適化済みデモのアトラスは、元の4Kマテリアルテクスチャからベイクしています。パッケージ容量を抑えるため、入力用には1K-2Kの縮小コピーを同梱し、AOには現在のUVに対応したマップを使用しています。シーンのメモリ表示は同梱アセットの測定値です。縮小コピーから再ベイクした結果は、同梱アトラスと異なる場合があります。

再利用可能な設定プロファイル

ソース一覧の上にある設定プロファイルを展開します。名前を付けて保存...で、名前付きのプロジェクトアセットを作成します。既存の設定プロファイルを選択して読み込みで適用し、保存で更新します。アトラス設定、メッシュ出力オプション、出力名と出力先、一致するマテリアルアセットの個別設定を保存します。読み込んでも、現在のソースオブジェクト、レンダラーごとの結合選択、アタッチメントボーンは維持されます。ソースマテリアルは変更しません。シーン内だけのマテリアルの個別設定は保存しません。マテリアルテンプレートにはプロジェクトアセットが必要です。設定をリセットはアトラス、マテリアル、メッシュ出力を既定値に戻し、ソースオブジェクト、出力名、出力先を維持します。読み込んだ設定は独立したコピーなので、再び保存するまで変更は保存済みプロファイルに反映されません。

シーン全体の最適化候補を確認する

シーンの自動アトラスは、テクスチャパレットを含め、マッピングされた全チャンネルの均一領域を検証します。完全に一定の領域はカラースウォッチを共有し、ノーマル、マスク、アルファなどの詳細がある領域は元の詳細を保持します。正確なセル索引と縮退UVの疎なサンプルで解析メモリを抑え、処理単位のキャッシュで分割時の再読み取りを減らします。完全に均一なチャンネルは必要なピクセル密度を増やしません。必要な出力チャンネルが近いマテリアル群をまとめます。

シーンのアトラスは、互換性のある不透明、カットアウト、透明マテリアルを対象とし、無効なレンダラーや非アクティブなオブジェクトも含みます。描画状態は別々に保持され、表示フラグは変更されません。各辺を2の累乗とする長方形レイアウトで圧縮を維持しながら空き領域を減らし、テクスチャのない一定値のマテリアルにはカラースウォッチを使用できます。各バッチの判定には元のシーン全体のテクスチャ予算とテクスチャ・メッシュ合計予算を使用します。他のバッチで容量が空いた場合、保留したマテリアル群をメッシュ結合前に再試行します。

Tools > DPT Games > Scene Material Optimizer を開き、同じウィンドウ内の モデルとアトラス / シーン最適化 ボタンでワークフローを切り替えます。一度に解析するのは読み込み済みの1シーンです。Prefab Mode を終了し、Edit Mode で使用してください。

  1. 対象シーン、最適化の優先度、出力画像の高さを設定します。プレイヤーが最も近づく距離を入力してください。参照カメラを指定すると画角または平行投影サイズを使用し、変更前後の参考画像も保存します。
  2. 保護するオブジェクトで対象と子孫を除外し、シーンを解析をクリックします。解析ではレンダラーやインポート設定を変更しません。
  3. マテリアル統合、テクスチャ解像度、アトラス、静的メッシュ結合、既存 LODGroup への小物の割り当て候補を確認します。各行に根拠、予想される効果、注意点が表示されます。ハイライトで対象を選択して表示範囲に収め、行を展開して詳細を確認できます。
  4. 初期状態で選択されるのはシリアライズされた設定が一致するマテリアル統合のみです。見た目や構造に影響する候補は確認して選択してください。解像度上限や最終表示 LOD を編集できます。このアトラスをプレビューで対象グループの変更前後を比較できます。
  5. 選択した最適化を適用すると Assets/DPTGames/Scene_Material_Optimizer/Generated 内に固有のフォルダーを作成します。Original_Backup.unity を保存し、隔離された追加読み込みの作業用シーンで処理して別の最適化済みシーンを保存します。元のシーンとアセットは保持され、シーンの未保存の変更もバックアップに含まれます。
  6. 最適化済みシーンを選択とレポートを開くで結果を確認します。出力シーンを別途開いて動作、ライティング、表示を確認し、対象デバイスで計測してください。

一時停止 / 再開 / キャンセル：解析、アトラス準備、適用は短いエディター更新に分割されます。一時停止中はシーン処理を進めませんが、アトラスのワーカースレッドは現在の計算を完了する場合があります。キャンセルすると一時リソースと未完成の出力を削除します。ウィンドウを閉じるか再コンパイルすると処理をキャンセルします。Unity のシーン保存、テクスチャインポート、画像エンコード、メッシュ処理は現在の処理単位が完了してから停止します。

慎重なグループ化：結合候補は近接する静的な兄弟オブジェクトで、レンダラー設定と既存 LOD の所属が一致するものに限定します。共有メッシュ、ベイク済みライトマップやオクルージョン、アニメーション、検出したスクリプト参照、プロパティの上書きを保護します。元の GameObject と Collider は保持し、元のレンダラーを無効化します。既存 LOD の形状と切替しきい値は維持します。小物の割り当ては親階層の LODGroup と境界を確認します。

テクスチャ推定：静的メッシュの UV 辺、テクスチャ縦横比、タイリングを出力高さと表示距離に照合します。読み取り専用の Editor メッシュスナップショットを使用し、Read/Write のインポート設定は変更しません。スキンメッシュ、大きすぎる入力、縮退 UV、非対応テクスチャは除外します。将来のカメラ移動や芸術的な重要度は判断できないため、文字、法線、アルファ境界を確認してください。選択したアトラスで全対象を処理する場合、重複する解像度削減は省略します。

レポートの範囲：有効なレンダラー、頂点、三角形、参照メッシュ、マテリアル、テクスチャと推定容量を比較します。すべての LOD レベルを含みます。結合後も無効化したレンダラーは元のアセット参照を保持するため、メッシュ容量が増える場合があります。これは描画回数、FPS、総 VRAM の実測や性能保証ではありません。参考画像は単一カメラの描画で、カメラスタックや独自描画とは異なる場合があります。

シーンや元アセットを変更した場合は再解析が必要です。実行時の検索や動的ロードも確認してください。複数シーンは個別に解析します。

LODの生成: シーン用ワークフローでは、既存のLODGroupを持たない末端のMesh RendererにLOD1とLOD2を生成できます。候補を展開して、目標三角形数、簡略化の強度（0〜2）、3段階の画面占有率を設定します。画面占有率の初期値は0.5、0.18、0.02です。LOD2のしきい値を下回ると描画されなくなります。最適化後のシーンでシルエット、シェーディング、切り替えを確認してください。元のメッシュアセットは変更されず、LOD0には確認対象のメッシュを使用します。

独立したLOD簡略化処理がこのパッケージに含まれており、Vertex 3D Terrainや共有のLODサービスは不要です。開いた境界、マテリアル境界、分割されたUVシームを保護し、サブメッシュと作成済みの頂点データを保持します。頂点カラーや補助UVを地形のバイオーム情報として解釈しません。同じ元メッシュと設定では生成したLODアセットを共有します。目標の削減率は保証されず、実際の三角形数をレポートに記録します。有効な削減ができない場合は不要なLODGroupを作成しません。

500三角形未満のメッシュ、子を持つレンダラー、既存のLODGroup、スキンメッシュ、ブレンドシェイプ、追加頂点ストリーム、透明・アルファクリップ・パララックスマテリアル、非対応シェーダー、ベイク済みライティング、検出された実行時参照は対象外です。上限は1メッシュ当たり200,000頂点、500,000三角形です。管理配列にコピーしたデータをバックグラウンドで処理し、一時停止とキャンセルを確認します。メッシュの作成と保存はエディタースレッドで行います。選択したアトラスの適用後にLODを生成できます。同じ対象の結合や小物のLOD割り当てはスキップされます。リソース合計には生成した全LODレベルと追加メモリも含まれます。

保存する各レベルは、直前に採用したレベルから10%以上かつ8三角形以上削減できる場合に限ります。効果の小さいレベルは省略され、LODGroupは2段階または3段階になります。同一座標の頂点は形状の接続判定でまとめますが、異なる頂点属性は分離したまま保持します。遠いLODほど形状誤差の許容範囲が広がります。

比較用のPNG画像は出力フォルダー内のSnapshots~/に保存され、プロジェクトのテクスチャとしてインポートされません。

シーンのアトラス候補は、親階層や距離に限定せず、互換性のあるマテリアルの使用先をまとめます。同じ静的メッシュと同じ順序のマテリアルスロットを持つインスタンスは、1つのUV配置と変換済みメッシュを共有します。異なるマテリアルの上書きは分離します。既存のLODGroup、オブジェクトの変換、コライダーは保持します。AOの元のサンプリングを保ち、同じ元マテリアルの使用先ではテクスチャ領域を再利用します。自動グループは読み戻しとメッシュ処理の作業メモリ見積もりで制限します。

URP Litの詳細ベイクは、Multiply x2とScaledのカラーブレンド、詳細マスクのアルファ、ベースと詳細UVのタイリングとオフセット、詳細法線の再配向合成に対応します。詳細キーワードが無効ならベースを変更しません。選択したアトラス解像度でベイクするため、細かい木目や法線をプレビューで確認してください。二重適用を防ぐため、出力の詳細レイヤーは無効にします。

元解像度のアトラスでは、同一の静的メッシュとマテリアル配置の変換済みジオメトリを再利用し、アイランド編集と出力後も共有します。ワールド空間密度では変換により必要密度が変わるため、インスタンスごとの配置を保持します。

シーンのアトラスは、必要な領域とチャンネルの元画像を順次読み戻し、チャンネル間で解放します。元画像の解像度は維持し、選択したアトラス解像度に合わせてサンプリングします。

テクスチャのディテール解析: テクスチャのディテールを解析 は既定でオフで、解析時間が増えます。低解像度の再構成画像をインポート済みの元画像と比較し、平均誤差と局所的な最大誤差を調べます。法線マップは角度誤差、マスクは対応マテリアルが実際に使用するチャンネルを評価します。アルファに敏感なテクスチャとポイントフィルターのテクスチャは元の解像度を維持します。優先度スライダーで保守的な誤差上限を調整し、表示距離やマテリアルの値によってさらに厳しい基準を使用します。出力圧縮前の推定であり、同じ見た目を保証するものではありません。提案と保存結果を確認してください。元の画像やインポート設定は変更しません。明示的に選択した内容ベースの縮小は、コピーしたテクスチャに適用してからアトラスを作成します。アトラスで完全に置き換える対象には、重複する距離ベースの縮小を適用しません。

UV領域とAOの共有: 参照画像、タイリング、色、関連する値が一致するサーフェスは、異なるマテリアルでもアトラス領域を共有できます。AOも比較対象です。異なるAOを重ねたり、ベイク済み照明で置き換えたりしません。対応する既存シェーダーを使用し、独自シェーダーやシェーダー編集は不要です。メタリックとスムースネスが一定なら、不要なマスク画像の代わりに標準マテリアル値を使用します。 アトラスの各マップは、必要なチャンネルのディテールと余白を保ちながら、異なるインポート解像度を使用できます。

エクスポート時の圧縮: シーンでも高品質、標準、非圧縮を選択できます。既定は高品質です。標準では不透明なベースカラーとAOの未使用アルファを省き、小さいRGB形式を使えます。カットアウトや透明なベースカラー、スムースネスのアルファは保持します。圧縮は木目やグラデーションに影響するため、保存結果を確認してください。見積もりと適用時のリソース確認には選択した形式を反映します。

シーンとは別にモデルを簡略化するには、モデルとアトラス > 最適化モード > LOD を生成 を使用します。元のマテリアルは保持されます。

シーン最適化ではアトラス最大サイズ（512～8192）とディテール解像度を指定できます。初期値は4096、元のテクスチャ密度の100%です。指定した密度で収まらない場合は、マテリアル構成ごとに分割するか元のテクスチャを保持します。最終的なマテリアル数は生成結果で確認してください。

パレットサイズを最適化は、Color Swapperと同様の単色モデル向けパレット変換です。ベースカラーとメタリック／スムーズネスの変化を、境界の補間色も含めて代表色に置き換えます。模様やグラデーションが失われる場合があるため、初期状態では無効です。アルファ、法線、AO、発光、ディテールマップの変化は保持します。モデルとアトラス、シーン最適化の両方で使用できます。

すべて自動集約は単色領域を検証し、テクスチャの詳細を保持するため、スウォッチと詳細領域が混在するアトラスにも使用できます。パレットサイズを最適化は単色アセット向けの代表色パレット変換とコンパクトな出力設定を追加し、すべてのマテリアルの折りたたみも有効にします。

スウォッチは、実際に出力するマップの値で照合します。ベースカラー、法線、メタリック／スムーズネス、AOは8ビット精度、発光は半精度浮動小数点を使用します。入力の浮動小数点が異なっても、出力ピクセルが同一ならスウォッチを共有します。出力しないチャンネルは重複を増やしません。出力チャンネルを変更するとプレビューを再構築します。

パレット変換では、同じソース領域のベースカラーとメタリック／スムーズネスを組として読み取ります。8ビットソースの読み取り値を正規化し、各色に対して少数の境界の組み合わせを整理しながら、小さい独立した色を保持します。パレットの許容差は、同一ソース内と異なるソース間の近い値をまとめます。0は出力値の完全一致です。正の値なら0.125と0.129など、8ビットの1段階の表面値差をまとめられます。値を上げると許容差も増えますが、各表面チャンネルの最大差は0.05未満です。アルファ、法線、AO、発光の変化は保護します。

パレットモードでは、詳細なアトラス設定を高度なアトラス設定内に折りたたみます。詳細領域が残っていない場合、優先度と回転のコントロールは非表示になります。概要はスウォッチ数とベースカラー数を別々に表示します。同じベースカラーでも、出力される表面値や保護されたUV割り当てが異なる場合は別のスウォッチが必要です。パレットの許容差はベースRGBと小さなメタリック／スムーズネスの差に適用されます。

すべての領域を折りたためる場合、自動サイズと自動エッジ余白を使用すると、各スウォッチを1ピクセルにし、ポイントフィルタリング、ミップマップなし、非圧縮、余白なしで出力します。小さいパレットは256ピクセル未満、8 × 8以下にも縮小できます。固定キャンバスと手動余白は指定した設定を維持します。詳細領域が残るアトラスには通常の設定を使用します。

マイクロテクスチャと詳細領域

テクスチャを自動的に非圧縮化は既定で有効です。単色の折りたたみを使用するマテリアルでは、圧縮や縮小によるノイズを避けるため、ソース解像度（最大8192ピクセル）の非圧縮一時コピーから検証します。保持する詳細領域はインポート済みテクスチャから読み取り、その解像度でサイズを決めます。元のファイルとインポート設定は変更されず、一時コピーは読み取り完了時またはキャンセル時に削除されます。

単色と確認された領域は、1 × 1ピクセルのスウォッチとパディングになります。自動サイズでは必要な最小キャンバスを選びます。固定サイズは指定した寸法を維持します。エッジにディテールが残る場合はUVアイランドを個別にパッキングを有効にすると、それらの領域を個別に詰められます。パレットの許容差は確認済みスウォッチの共有に使用され、実際のグラデーションや法線、マスク、AOのディテールは保持されます。

均一色を確認して集約は、各三角形がすべてのマッピングされたチャンネルで一定の値をサンプリングするか確認します。UVが変化する領域ではフィルタリング用の余白も確認します。UVがすべて同じパレット位置を指す面は、バイリニアフィルタリングで周囲の色が異なっていても一定です。対象領域は余白付きの1ピクセルスウォッチになります。異なるモデルやマテリアルでも、一致する検証済みスウォッチは同じピクセルを使えます。

ベースカラーが単色でも、法線、メタリック、スムースネス、オクルージョン、不透明度、発光のディテールは削除されません。対応チャンネルのいずれかに変化があれば、詳細領域として保持します。グラデーションや描き込まれた陰影も保持します。判定が曖昧な領域や検査負荷が高い領域は、安全のため詳細のまま残します。画風の名前ではなく、実際のテクスチャデータで判定します。

集約できる場合でもマテリアルを詳細領域として残したいときは、ディテールを保持 を選びます。すべて自動集約 はすべてのスキャン済みマテリアルを均一色の検査対象にし、すべての詳細を保持 はすべてを詳細保持に切り替えます。単色スウォッチと詳細領域は同じアトラス内に共存できます。集約で変わるのはテクスチャ参照であり、モデルの形状や三角形数ではありません。

すべて自動集約、または個別の均一色を確認して集約を有効にします。配置ボタンの下のパレットの許容差は0～400で、既定値の0は完全一致です。Color Swapperと同じ8ビットRGB差の合計を使います。(100, 110, 120)と(102, 110, 120)の差は2です。

有効な全チャンネルで正確な繰り返し周期が一致する場合は、1つの領域を再利用できます。ただし、1枚の三角形が多数の繰り返しをまたぐ場合は、依然として大きな領域が必要になります。要求サイズは元画像の寸法と同じとは限りません。カスタム出力シェーダーでは 出力テクスチャのプロパティ設定 を確認し、テンプレート選択後に テンプレートから検出 を使用します。このガイドの URP ワークフローでは、メタリック / スムースネス のパック形式を使用してください。

テクスチャプロパティの選択: 入力チャンネルと出力プロパティは、選択したシェーダーのTexture2Dプロパティを表示名と識別子で一覧表示します。なし（テクスチャを省略）でテクスチャ入力を除外できます。保存済みのプロパティが見つからない場合は、その値を選択したまま警告を表示し、既存の割り当てを自動変更しません。テクスチャ配列とキューブマップは対象外です。各プロパティは既存の色、法線、メタリック／マスク、AO、発光の意味で処理され、任意のプロシージャル効果を自動ベイクする機能ではありません。

アトラス解像度、自動調整、余白

アイランド形状に基づくパッキング は既定で有効です。アイランドの空き部分に他のアイランドを配置し、使用テクセルと余白の重なりを防ぎます。

プレビューにはアトラスサイズの概要を1行で表示し、縮小領域がある場合はその数も示します。この行にカーソルを合わせると、ソース解像度の上限、密度目標、余白、集約した三角形数、UV重複の保護、回転の判断を確認できます。再構築待ちの間も、表示中のプレビューを説明します。

余白を自動設定は自動サイズと固定サイズの両方で既定で有効です。各キャンバスの生成サイズに合わせ、小さな非圧縮・ミップマップなしのアトラスでは1ピクセル、8Kでは16ピクセルになります。圧縮またはミップマップ使用時は4ピクセル以上です。不透明と透明で別の余白を使用できます。オフにすると余白を手動設定できます。実際の値はアトラスサイズのツールチップと書き出し解像度レポートに表示されます。API設定はAtlasSettings.automaticPaddingです。

高度なアトラス設定のアトラスのサイズ設定は、既定で自動です。自動では、要求されたディテールが収まる最小のキャンバスを最大アトラスサイズの範囲内で選択します。固定を選ぶと、固定アトラスサイズが幅と高さの正確な寸法になります。たとえば要求されたディテールが4096 x 4096に収まっても8192 x 8192を使用できます。固定では正方形を使用し、長方形のサイズ選択と非2の累乗サイズへの切り詰めを行いません。自動に戻すと元の設定が再び適用されます。空き領域をディテールに使用で各領域に空き領域を配分し、「元の解像度を超える拡大を許可」するとソース解像度またはワールド空間の目標を超えて拡大できます。固定を選んでも、これらのオプションは自動で有効にならず、入力に存在しないディテールは復元されません。透明アトラスを分離する場合は、各キャンバスに固定サイズを使用します。出力の解像度レポートにもサイズ設定が記録されます。

アトラス形状は、高度なアトラス設定を展開し、アトラスのサイズ設定が自動の場合に表示されます。既定は正方形です。幅と高さを別々に選ぶことでメモリを節約できる場合は長方形を選択してください。固定サイズでは正方形のキャンバスを使用するため、この項目は表示されません。

2の累乗以外の寸法を許可も、高度なアトラス設定の自動サイズ設定で使用します。初期状態はオフです。アトラス形状: 長方形では、1024 x 2048など各辺が2の累乗となる長方形を使用できます。この設定を有効にすると、各辺を4ピクセル単位にさらに縮小できます。テクスチャのピクセル数を減らせますが、GPU性能の向上は保証されません。対象プラットフォームで確認してください。プレビュー、UV再配置、インポートサイズ、メモリ推定には最終的な幅と高さを反映します。

形状に基づくパッキングと長方形アトラス: アイランドの空き領域を再利用し、テクセルと余白を重ねずに配置します。外接矩形が重なる場合があります。ベイクは割り当てた形状と周囲の余白に元テクスチャの対応ピクセルをコピーし、アイランド端の色を引き伸ばしません。形状外の隙間は別のチャートで使用でき、手動サイズ合わせの再ベイクでも元の周辺ディテールを保持します。幅と高さは圧縮ブロックに合わせて個別に選びます。空き領域で元の解像度までディテールを復元できます。元の解像度を超える拡大には明示的な設定が必要です。プレビューにはテクスチャ全体の枠と、余白を含む使用率・空き領域の割合を表示します。

設定初期値・範囲使い方
アトラスの最大サイズ初期値 4096。256、512、1024、2048、4096、8192 から選択。出力の固定サイズではなく上限です。収まる場合は、より小さい2の累乗の正方形アトラスを使用できます。
最大サイズに自動調整有効。まず要求されたディテールで配置を試み、必要に応じて詳細領域を縮小して内容と余白を収めます。
ディテール倍率 (%)初期値 100%。範囲 5～100%。自動調整前のソース解像度またはワールド空間の目標に倍率を適用します。空き領域の活用では、この初期目標を超えて元のソース解像度まで復元できます。
エッジの余白既定は自動。手動の範囲は1～16ピクセル。すべてのマップで各領域の周囲に余白を追加します。自動設定では生成サイズに合わせ、ミップマップまたは圧縮を使用すると4ピクセル以上になります。自動設定をオフにすると手動で指定できます。余白もアトラスの面積を使用します。

自動調整でディテールが減る場合は、プレビューに通知が表示され、各詳細マテリアルに要求サイズと出力ピクセル寸法が表示されます。書き出した Atlas_Resolution.txt にも記録されます。元テクスチャやそのインポート設定は変更されません。

4096 のテクスチャなのに 4092 × 4088 と表示される理由：領域寸法は、メッシュの UV が使用する範囲を表しています。画像端に未使用部分があると、元画像より少し小さくなります。その外側に余白を追加するため、約4Kの領域でも、厳密モードでは4Kアトラスに収まらない場合があります。

要求密度を自動縮小せずに維持したい場合にのみ、自動調整を無効にします。このとき優先度は無効になります。配置に失敗した場合は、自動調整を有効にする、最大サイズを上げる、入力ディテール上限を下げる方法があります。自動調整でも、余白付きの1ピクセル領域を無制限には配置できません。最小構成が収まらない場合は、入力を分割する、余白を減らす、最大サイズを上げるなどの対応が必要です。

テクセル密度の基準

テクセル密度の既定値は元テクスチャ解像度で、インポートされたテクスチャの寸法とタイリングを使用します。ワールド空間は、オブジェクトのスケールを含むUV方向のメッシュ寸法から、同じ大きさの面に近い密度を割り当てます。Unity単位あたりのピクセル数は既定で512、スライダー範囲は64～2048です。自動調整で目標値が下がる場合があります。ワールド空間は詳細領域をレンダラーごとに配置するため、繰り返しオブジェクトでも必要な領域が増える場合があります。

配置処理の時間を抑えるため、キャンバスごとの領域が256を超えると余白を使った拡大を行いません。形状、余白、詳細上限によっても空きが残ります。最大サイズの変更や拡大の許可で、完全に埋まるとは限りません。

自動UV共有と手動スタック

UVの重なりの既定値は自動で、AOまたはHDRPマスクを使う異なるソースメッシュの詳細領域を分離します。検証済み単色スウォッチは各チャンネルが一致すれば共有でき、許容差は基本色RGBだけに適用します。許可は同じソースマテリアルの詳細領域をレンダラー間で再利用できますが、テクスチャを共有する全マテリアルを自動で重ねる機能ではありません。重なりを防止はレンダラーと分離したUVシェルを別領域にし、単色スウォッチも分けます。接続されたソースシェル内の既存の重なりは自動修復できません。形状を考慮した配置では、使用ピクセルと余白を分離したまま外接矩形が重なる場合があります。手動スタックには別の共有テクスチャ判定を使用します。

重要なマテリアルにディテールを割り当てる

優先度: 標準は、すべてのソースマテリアルを標準に設定します。優先度は相対的なため、すべてを同じ優先度にしても密度のバランスは変わりません。空き領域をディテールに使用は、共通の密度倍率で各領域をまとめて拡大し、自動フィットが有効な場合はマテリアルの優先度も維持します。アップスケールが無効な場合、ソース解像度またはワールド空間の目標が拡大の上限になります。アトラスの寸法は変わりません。アイランドの形状やパディングによって空き領域が残る場合があります。

ディテール優先度 は、自動調整で詳細領域を縮小する必要があるときの相対的な優先度です。通常のマテリアルは標準のままにし、重要なものだけ上げます。複数のマテリアルを高または最高に設定できます。すべてのマテリアルに割合を指定したり、チャンネルごとに調整したりする必要はありません。

優先度相対的な要求面積用途例
低標準の 0.5 倍単純な面や目立ちにくい面。
標準1 倍。初期値。大半のマテリアル。
高標準の 2 倍印刷ラベル、布模様、顔、鎖帷子など。
最優先標準の 4 倍特に重要な少数の詳細マテリアル。

これらは相対面積の配分であり、アトラスの固定占有率や、縦横の寸法をその倍率にする指定ではありません。元のサイズ、UV 範囲、余白、配置形状にも影響されます。空き領域の活用では、初期のディテール目標を超えて元のソース解像度まで復元できます。ソースのサンプル数を超えて拡大するには、元の解像度を超える拡大を許可する設定が必要です。すでにすべて収まる場合は、優先度を上げても他のマテリアルを不要に縮小しません。集約済みの単色スウォッチは1ピクセルのままです。

例：木材、革、単純な金属を標準のままにし、鎖帷子と顔の両方を高に設定して、プレビューを再作成します。必要な場合は自動調整で詳細領域を再配分します。ベースカラー、法線、その他の対応チャンネルは常に同じ領域を使用します。優先度だけで特定の解像度になるとは考えず、実際の出力寸法を確認してください。

フィルタリング、ミップマップ、インポート設定

テクスチャを自動的に非圧縮化は、単色の検証と集約用の読み取りにだけ使用します。ディテール領域はインポート済みテクスチャを使用し、一時コピーの繰り返しインポートを避けます。大きな領域のピクセルベイクはワーカースレッドで行い、インポート、読み取り準備、アップロードはエディター側で行います。ソースが変わらなければ設定変更時にスキャンを再利用します。フィルタリングと互換性のあるマテリアル変更ではアトラスを再利用します。現在の余白で足りる場合、ミップマップと圧縮の変更でも再ベイクせず、既存のベースレベルを再利用します。サイズ、配置、チャンネル、ディテール配分の変更には再配置や再ベイクが必要です。チェーンメイルなどの細かな表面は、ミップマップを生成を有効にして元のマテリアルと比較してください。

ツール更新後、既存のウィンドウでは新しい初期設定を反映するため、ミップマップを一度だけ有効にします。その後の手動変更は維持します。既存プロファイルを読み込むと、保存されたミップマップ設定を復元します。

ポイントフィルタリング は初期状態で無効です。ミップマップなしではバイリニア、ありではトライリニアフィルタリングを使います。パレットやピクセル表現をくっきり見せたい場合は、必要に応じて有効にします。ミップマップを生成 は通常の元マテリアルに合わせて遠距離のハイライトを安定させるため、初期状態で有効です。既存プロファイルの保存設定は維持します。無効にすると、細かい金属や法線の模様が元画像より鮮明に見えたり、ちらついたりすることがあります。小さなミップレベルでは隣接するアトラス領域が混ざり、特に小さな単色スウォッチで目立つことがあります。詳細アセットでは遠距離のサンプリングに役立つため、余白を増やして実際の使用距離で確認してください。

出力アトラスは Clamp、選択した エクスポート時の圧縮、Read/Write 無効でインポートされます。対応する元のラップ動作は、各領域にすでに焼き込まれています。圧縮は小さなスウォッチやデータチャンネルに影響するため、変更後は結果を確認してください。共有アトラスではフィルタリングとインポート方針も共有されます。1つの出力セットで、モデルごとに異なるフィルタリングを同時に使うことはできません。

エクスポート時の圧縮の既定値は高品質です。標準と非圧縮も選べます。実際のGPU形式はプラットフォームとテクスチャの種類に依存します。見た目の差が圧縮によるものか調べる場合は、非圧縮を使用してください。

不透明、カットアウト、透明マテリアル

アトラスを共有しても、すべての面を必ず1つのマテリアルに統合できるわけではありません。不透明、アルファクリップ、ブレンド透明のサーフェスには互換性のある描画状態が必要です。ブレンド方式、カットオフ、面カリング、深度設定、描画キュー、対応するライティング設定が異なると、マテリアルグループが分かれます。ツールは予定グループ数を表示し、透明またはアルファクリップされた入力を検出します。

透明度と切り抜き穴を保持する場合は、透明サーフェスを不透明にするを無効にしてください。有効にすると、ブレンド透明面とアルファクリップのカットアウト面の両方が完全に不透明な出力マテリアルになります。ガラスは不透明になり、切り抜き穴は埋まります。変換時は出力描画キューも不透明用に統一されます。元のマテリアルは変更されません。警告が表示され、その他の描画設定が異なる場合は複数の出力マテリアルが必要になることがあります。

不透明マテリアルの面カリングを統一（Unify Opaque Face Culling）は高度なアトラス設定内の独立したオプションです。面カリング設定だけが異なる不透明マテリアルは、出力を両面描画（Render Faces: Both）（_Cull = 0）に統一することで共有できます。透明サーフェスを不透明にするのオン・オフに関係なく使用できます。ただしフラグメント処理やオーバードローが増える場合があります。他の描画状態が異なる場合はマテリアルが引き続き分かれるため、必ず1つになるとは限りません。元の面カリングを保持したい場合はオフにしてください。

例：不透明な家具とガラス瓶は、同じアトラステクスチャを参照しながら、不透明用と透明用のマテリアルを使えます。プレハブは個別のまま書き出せます。メッシュ結合時も透明部分は描画順序を保つため、独立したレンダラーとして残ります。

透明アトラスの共有と分離

透明アトラスの既定値は自動です。不透明とブレンド透明の両方がある場合、分離後の合計推定テクスチャメモリが共有時より10%を超えて少なくなるか、分離時だけ配置に成功すると、別キャンバスを使います。共有は1枚を使い、分離は両方の種類がある場合に必ず分けます。各キャンバスの寸法や余白が異なる場合があります。固定サイズは各キャンバスに指定した正方形サイズを使うため、メモリが増える場合があります。出力マテリアルはそれぞれの描画状態を保持します。

アトラスとモデルのプレビューを確認する

表示をリセット でモデル全体を表示するカメラに戻します。アトラスの色設定 テクスチャの外枠 は、領域や UV の輪郭とは別に、テクスチャ全体の外枠の色を指定します。

表示中のアトラスが単一ピクセルに折り畳まれたスウォッチだけの場合、UVが点に集約されるため、UVの輪郭はグレー表示で無効になります。ディテールを保持する領域があれば利用できます。スウォッチの境界を確認するには領域の輪郭を使います。

詳細領域の縮小時は、出力1ピクセルが覆う元画像の面積を平均します。色、不透明度、法線、メタリック、スムーズネス、AO、発光と手動でのアイランドサイズ変更に適用します。法線は方向を平均してから正規化し、各チャンネルの元画像サイズとタイリングを使います。元画像の Filter Mode が Point なら最近傍サンプリングを維持し、検証済みの単色スウォッチは変えません。通常出力はミップマップありでトライリニア、なしでバイリニア補間を使います。ポイントフィルタリング は出力サンプリングの設定です。既存アトラスに適用するにはプレビューを再作成し、再エクスポートします。

自動更新はプレビュー作成ボタンの横にあります。モデルカメラは表示モデルの範囲とペインの縦横比に合わせます。スクロールで初期距離の5%まで近づけ、クリップ面もモデルの大きさに合わせます。ビューをリセットすると全体表示に戻ります。

縦の仕切りをドラッグして設定パネルの幅を変更します。ダブルクリックで既定の幅に戻り、Escapeで幅の変更を取り消します。アトラス領域をドラッグせずにクリックすると、設定パネル内のソースマテリアルを展開して強調表示し、そこへスクロールします。選択されたマテリアルの領域をシアンの枠で表示します。折り畳まれた色を複数のマテリアルが共有している場合は、すべての所有元を強調表示します。空き領域をクリックすると選択を解除します。ドラッグによる移動、修飾キー付きのドラッグ、ダブルクリックによる全体表示も引き続き利用できます。選択にはチャートマスクを使用し、かみ合った領域や表示中の透明アトラスを正しく区別します。選択操作でUVや出力テクスチャは変更されません。

手動アイランド配置（詳細）

単一ピクセルに折り畳まれたスウォッチも編集で移動できます。新しいコンパクトパレットはスナップ: 1 pxで開始するため、アトラス全体と同じ大きさのグリッドに移動量が丸められることはありません。空きセルへ移動するか、スウォッチを枠外に退避して並べ替えます。使用中のセルは誤った上書きから保護されます。スウォッチにカーソルを合わせると、ベースRGBAとマップされたサーフェス値を確認できます。同じベースカラーでも、スムーズネス、メタリックなどが異なる場合は別のピクセルを使用します。パレットの許容差はベースRGBと小さなメタリック／スムーズネスの差を変更します。

アトラスプレビューの手動アトラス配置（詳細）を開き、編集を有効にします。左ドラッグでアイランド全体を移動します。全体のUV表示がオフでも、移動中のUV辺は表示されます。自由 / X / Yで移動軸を選びます。Xは横移動でYを固定します。ドラッグ中にXまたはYを押すと軸を制限し、同じキーでもう一度押すと解除します。Escでキャンセルします。Shiftを押しながら横移動（Y固定）、Ctrl（macOSではCommand）を押しながら縦移動（X固定）ができます。離すと選択中の軸モードに戻り、両方を押すと位置を保持します。中央・右ドラッグで表示移動、スクロールでズーム、ダブルクリックでテクスチャ全体表示に戻ります。スナップは1、4、8、16、32ピクセル単位です。左下基準のX/Y座標入力にも軸の固定が適用されます。固定により誤移動を防げます。

コンパクトな手動配置バーには、編集、スナップ、自由/X/Y、固定、X/Y座標、移動、元に戻す、リセットを1行にまとめています。元に戻すとリセットはツールチップ付きアイコンです。UVの重なりを許可すると同じ行にサイズ一致を表示します。配置の状態はアトラス下部に表示します。ボタンは任意で使えるDPT_CoreGUI.ButtonStyles APIを使用し、既存のコアスタイルは変更しません。

他の領域を並べ替える間、アイランドをテクスチャ枠の外へ退避できます。UV輪郭は表示され、退避したアイランドへ移動できるよう表示移動の範囲も広がります。サンプルを保持するため、戻してもマップのデータは失われません。すべてのアイランドと余白が枠内に戻るまで書き出しは無効です。極端な座標を防ぐため、退避範囲は各方向にアトラスの長辺の8倍までです。

UVの重なり: 許可では、同じ入力テクスチャセットを使うアイランドを手動で重ねられます。同じテクスチャを共有する別マテリアルも対象です。入力のUV範囲、サイズ、向きは異なっていても構いません。有効なカラー、法線、メタリック・マスク、AO、発光の入力テクスチャがすべて一致する必要があります。他のマップが異なる場合、ベースマップだけの一致では重ねられません。テクスチャなしの領域は同じ入力マテリアル、または全チャンネルが同一の単色領域なら共有できます。異なるテクスチャセットの重なりは拒否します。重なりは全マップのベイク済みピクセルを共有し、最後に移動したアイランドのピクセルを使用する編集です。異なるUV範囲や色補正を重ねると見た目が変わる場合があります。Alt＋クリックで重なったアイランドを切り替えます。元のサンプルは保持され、重なりを解くと復元されます。自動と防止では余白を含む形状の重なりを拒否します。不透明と透明のキャンバスは独立しています。元に戻す操作はサイズ変更と表示順を含め最大20回を復元します。配置リセットは元の配置と寸法に戻し、固定と履歴を解除します。手動配置は現在のプレビュー専用で、設定プロファイルには保存されません。再構築、スクリプト再読み込み、ウィンドウを閉じる操作で解除されます。配置を保持するには現在のプレビューを書き出してください。

重ねるときにサイズを合わせるは初期状態で有効です。自由移動中、小さいアイランドの中心を同じテクスチャを使う大きい領域に置くと、小さい側の寸法と位置を合わせます。ドラッグの輪郭で結果を確認でき、ドロップすると全マップとミップマップを入力テクスチャから新しいサイズで再ベイクします。入力に残る細部を回復できますが、入力解像度を超えても細部は増えません。無効にするとサイズを保持して部分的に重ねられます。X/Yの軸固定中はサイズを合わせません。重なりを解いても新しいサイズを保持し、元に戻す操作で以前の寸法に戻せます。拡大するのはドラッグした小さい側だけで、大きい側を移動しても静止した小さい領域は変わりません。

アトラス表示コントロールの下にあるUVワイヤーフレーム、領域の枠、テクスチャの枠の色フィールドを直接使います。モデルプレビューの照明コントロールの横には両ペイン共通の背景ピッカーがあります。選択・移動中のUV辺にも同じ色を使い、無効な移動は赤色で表示します。設定は再構築やEditor再起動後も保持されます。シーンカメラ、元マテリアル、出力テクスチャは変更しません。

表示・操作確認する内容
アトラステクスチャチャンネル選択から生成マップを切り替え、色、法線、PBR データを個別に確認します。
領域の輪郭枠は配置した領域を示します。「色」で枠の色を変更できます。領域にカーソルを合わせると入力、寸法、三角形数を確認できます。
モデルの変更前 / 変更後元のマテリアル と アトラスマテリアル を比較します。左ドラッグで回転、スクロールでズームします。
数値と通知アトラス寸法、領域数、スロット数、出力マテリアル数、自動解像度低下を確認します。

スキンメッシュのプレビューは、作成時に取得した元のスケルトンのポーズとブレンドシェイプのウェイトを使用します。両側は同じポーズで、アニメーションは再生しません。無効なレンダラー、非アクティブなオブジェクト、forceRenderingOff が設定されたレンダラーは非表示です。有効な各 LODGroup では、レンダラーを持つ最上位のレベルのみを表示します。スキャンとリソース集計には全レベルを含みます。元のポーズや表示状態を変更した場合はプレビューを作成し直してください。アトラス適用前後の見た目を比較するもので、最終的な結合ジオメトリは表示しません。書き出したプレハブをシーンで確認し、変形、取り付け部品、透明度、LOD とゲーム内動作を検証してください。

配置やアトラス設定を変更するとプレビューが更新待ちになります。自動更新が有効な場合は、設定が落ち着いてから再生成します。入力や階層の変更でも再生成が必要になることがあります。保存してエクスポートは必要な場合に再構築し、それ以外はサイズ合わせを含む現在の手動配置を保持して書き出します。ウィンドウを閉じる、スクリプトを再読み込みする、Play Mode を切り替えると、一時プレビューは解放されます。プレビュー生成中は、プレビュー領域に処理段階、進捗バー、中止ボタンを表示します。解析とベイクは小分けに実行し、UVのグループ化とアトラス配置はバックグラウンドで処理します。新しい結果が完成するまで前の結果を保持します。中止すると前の結果を維持し、待機中の書き出しも中止します。生成中は設定と書き出し操作を無効にします。入力が途中で変更された場合は新しい結果を破棄します。必要な再生成が成功すると、保存してエクスポートを自動で続行します。対応環境では非同期GPU読み戻しを使用します。デバイスや形式が非対応の場合は従来の読み戻しに戻ります。テクスチャの確保・転送と個々のメッシュ処理は引き続きエディタースレッドで行うため、大きな入力では停止が発生する場合があります。ウィンドウを閉じる、スクリプトを再読み込みする、Play Modeを切り替えると、未完了の生成を中止して一時リソースを解放します。

どちらのプレビューでも、スクロールで少しずつズームできます。アトラスはカーソル位置を中心にズームします。全体表示 またはアトラスのダブルクリックで、ズームとパンをリセットできます。

メモリと書き出しの統計

推定変化 は変更前後の推定差を表示します。

アトラスとメッシュのみの両モードで、プレビューの詳細ドロップダウンを折りたたみ可能なメモリ比較表に置き換えました。見出しをクリックすると、表とプレビュー構築時間の表示を切り替えられます。この状態はツールを開き直しても保持されます。変更前、適用後プレビュー、推定変化の列で、有効なレンダラー、重複しないマテリアル、三角形、頂点、メッシュVRAM、テクスチャVRAM、強調表示された合計を比較します。減少は緑、増加は赤で、符号付きの量と割合を表示します。各行の集計範囲はツールチップで確認できます。形状の数は全LODと有効なメッシュの各使用箇所を含み、UV変換で頂点が増える場合があります。最終的な結合は書き出し時に行います。 現在のプレビューで選択したメッシュを結合を使用する場合、適用後 / 推定のレンダラー数には書き出し時の結合予測が反映されます。三角形数、頂点数、VRAMの値は結合前のプレビューを示し、実際の書き出し結果はレポートに記録されます。

メモリは、非アクティブな入力、ミップマップ、テクスチャ配列を含め、選択範囲内で参照される各メッシュ・テクスチャリソースを1回だけ数えます。メッシュVRAMは頂点配列をコピーせず、保存された頂点構成から頂点・インデックスバッファを推定します。CPU読み取り用コピー、ブレンドシェイプ格納領域、追加スキニングバッファ、エンジンの管理領域は含みません。ソーステクスチャはインポート形式、アトラス出力は既存のプラットフォーム依存の圧縮推定値を使用します。KB・MBは10進数で、ディスクサイズやEditorのプロセスメモリではなくリソースの推定値です。フレーム時間の予測値でもありません。計算結果はキャッシュされ、プレビューの再生成、メッシュ・マテリアルの置換、出力圧縮・ミップ設定の変更時に更新します。

書き出し成功後、書き出し操作付近の前回の書き出しを開くと、実際のレンダラー、マテリアル、スロット、ジオメトリの数を確認できます。プレビュー生成と書き出しの処理時間は別々です。選択したルート内で有効なジオメトリを全LODレベルを含めて数え、結合後に無効のまま保持された元レンダラーは除きます。頂点と三角形はメッシュの各使用箇所を数え、メッシュアセット数は重複を除きます。ドローコールやフレーム時間の実測値ではありません。

すべての書き出しモードでAtlas_Statistics.txtを作成します。統計レポートを開くから最新レポートを開けます。アトラスとメッシュのみ出力では、非アクティブな入力も含む全ソースメッシュと保存したUV変換済みメッシュを比較します。レンダラーとマテリアルは作成しません。前回の統計は、次の書き出しが成功するまでその時点の記録として残り、ソースの選択が変わると非表示になります。

Atlas_Statistics.txtは形状の数と処理時間を記録します。アトラス出力のAtlas_Resolution.txtは推定テクスチャメモリと、現在のEditorプラットフォームで実際にインポートされた形式、ミップ数、サイズを記録します。レポートのソースメモリはマッピングされた入力のみを対象にします。比較表はマテリアルが参照する全テクスチャを含むため、ソース合計値が異なる場合があります。

書き出しモードと生成ファイル

UnityのProjectウィンドウからフォルダーを出力フォルダーに直接ドロップするか、その横の参照...で既存の保存先を選択します。現在のフォルダーが存在する場合は、そこから参照を開始します。選択したパスはAssetsからの相対パスになります。ファイル、複数フォルダーの同時ドロップ、このプロジェクトのAssets外のフォルダーは選択できません。新しいAssets内のパスを手入力すると、エクスポーターがそのフォルダーを作成します。保存先を変更しても、アトラスは再構築されません。

メッシュ出力結果適した用途
個別のプレハブ入力ルートごとに1つのプレハブ。出力アトラスと互換マテリアルを共有します。独立モデルや再利用する小物が必要な場合。初期設定です。
グループ化したプレハブ入力階層を個別の子として含む1つの親プレハブ。メッシュは結合しません。配置全体をまとめて置く場合や、複数入力がリグを共有する場合。
選択したメッシュを結合選択した互換静的メッシュや共有リグのメッシュを結合した1つのプレハブ。不適合・除外部分は独立します。レンダラー数を減らしつつ、独立させる部分を選びたい場合。
アトラスとメッシュのみマップ、UV変換済みメッシュ、割り当てレポートのみ。マテリアルとプレハブは生成しません。出力マテリアルとメッシュの割り当てを独自に設定する場合。

出力名 の初期値は Optimized_Model、出力フォルダー は Assets/DPTGames/Scene_Material_Optimizer/Generated です。参照... で現在のプロジェクトの Assets 内を選択します。書き出しごとに固有のフォルダーが作成され、既存の出力や元アセットは上書きされません。個別プレハブのファイル名には入力名を使用し、同名の場合は固有パスが付けられます。

出力フォルダー内の場所内容
Meshes/UV 更新後のメッシュ、結合メッシュ、必要に応じて独立した透明部分のメッシュ。
Textures/生成アトラスマップ。
Materials/互換性のある共有出力マテリアルのグループ。
Prefabs/シーンに配置するプレハブ。
Animations/ブレンドシェイプの参照先を変更する場合の、複製したアニメーションクリップとオーバーライドコントローラー。
Atlas_Resolution.txtアトラスサイズ、余白、詳細領域の要求寸法と出力寸法。
Atlas_Statistics.txtジオメトリ、レンダラー、マテリアルの実測数と、個別のプレビュー生成・書き出し処理時間。全出力モードで作成します。
Atlas_Merge.txt結合モードで作成。結合した入力数、剛体部品数、独立して残した理由を記録します。

書き出し後、Unity は生成プレハブを選択し、最初のプレハブを強調表示します。ステータスには保存先が表示されます。結果が見つからない場合は、そのフォルダーの Prefabs を開いてください。対応するシーン入力を置き換える場合は、書き出し後にシーンオブジェクトを置換を有効にします。オフの場合は生成プレハブを手動で配置してください。移動するときは Unity の Project ウィンドウで、生成アセット一式をまとめて移動してください。元アセットの削除や出力の配布前には、スクリプト、アバター、アニメーションクリップ、コライダーメッシュなどの依存関係を確認してください。

シーンの置換: 書き出し後にシーンオブジェクトを置換を有効にすると、成功後に入力インスタンスを出力プレハブへ置き換えます。1回のUndoで元に戻せます。個別出力は親と変換を保持し、グループ出力は配置を新しいルート内に保持します。同じ通常シーンの入力のみ対応し、プロジェクトアセットとプレハブ編集ステージは対象外です。削除したシーンオブジェクトへの参照は確認が必要です。Undo後も出力ファイルは残り、シーンは自動保存しません。

アトラスとUV変換済みメッシュのみの書き出し

メッシュ出力: アトラスとメッシュのみを選び、アトラスとメッシュを書き出すを押します。Textures/、Meshes/、Atlas_Raw.txt、Atlas_Resolution.txt、Atlas_Statistics.txtを保存します。マテリアルやプレハブの生成、メッシュ結合、シーン置換は行いません。割り当てレポートには、元のレンダラー、出力サブメッシュ、使用するアトラスと互換マテリアルグループ、基本的な描画設定が記載されます。独自のマテリアルを作成し、レポートに従ってマップとメッシュを割り当ててください。対応する色とサーフェス値はすでにベイクされているため、色などの乗算値はニュートラル、タイリングは1にします。スキンメッシュでは元のスケルトン、ボーン順、ブレンドシェイプのウェイトを維持してください。使用するのは既存のチャンネル構成で、任意の追加マップやプロシージャル効果は対象外です。

Editor API: AtlasExporter.ExportRaw(build, parentFolder, outputName)、またはAtlasExportMode.RawAtlasesAndMeshesを設定してExportAllを使用します。結果のprefabsは空で、materialsFolderとprefabsFolderは空文字列です。プレハブを返すExportは、アセット作成前にこのモードを拒否します。

アトラスを作らずにメッシュを結合する

設定パネル上部の最適化モード > メッシュ結合のみを選択します。完全な入力オブジェクトを追加し、結合する静的メッシュ、共有リグのメッシュ、取り付け部品を選択して、結合プレビューを作成をクリックします。予測レンダラー数を確認し、結合して書き出すをクリックします。

このモードは元のプロジェクトマテリアル、シェーダー、テクスチャ配列、キーワード、シェーダープロパティを保持します。テクスチャのサンプリング、アトラスのベイク、UVの再マッピング、異なるマテリアルの統合は行いません。頂点カラーとすべての元のUVチャンネルは、VCCoreなどのシェーダーで引き続き使用できます。UV0のないメッシュにも対応します。プレビューでは元の外観と保持されるマテリアルを比較し、メッシュの結合は書き出し時に行います。

書き出しではプレハブ、メッシュアセット、Atlas_Merge.txt、Atlas_Statistics.txtを作成します。アトラステクスチャや解像度レポートは生成しません。既存のプロジェクトマテリアルは直接参照します。メモリ上だけに存在するマテリアルは新しいアセットとして保存されますが、そのテクスチャは事前に保存してください。異なるマテリアルは別々のスロットを保持するため、レンダラー数の削減が必ずしも描画呼び出し数の削減になるとは限りません。元のアセットとインポート設定は保持されます。

このモードでは、UV1座標の変更を避けるため、ベイク済みライトマップを使用するレンダラーは個別に保持します。透明面、個別にアニメーションする部品、互換性のない描画設定に関する既存の結合制限は引き続き適用されます。各オブジェクトのローカル座標、ピボット、スケールに依存するカスタムシェーダーは、結合後の外観を確認してください。テクスチャアトラスに戻すとアトラス設定が再表示されます。選択したモードは設定プロファイルに保存されます。

var settings = new AtlasSettings { mergeMeshesOnly = true };
var scan = AtlasScan.Create(sourceObjects, preserveMaterials: true);
using (var build = AtlasBuilder.Build(scan, settings))
{
    AtlasExporter.ExportAll(build, "Assets/Optimized", "Merged_Model");
}

詳細選択と静的メッシュの結合

最新のアトラスプレビューを作成すると、メッシュ結合セクションにソースのメッシュレンダラー数と出力予測数を表示します。結合スイッチ、レンダラーの選択、アタッチメントボーンを変更すると予測を更新します。パーツを分離して保持する理由を展開すると、除外、LOD、互換性のないレンダラー設定、リグ、アニメーションの制限、透明部分を確認できます。不透明と透明が混在するメッシュでは、結合後も透明部分のレンダラーが残るため、レンダラー数が増える場合があります。これはレンダラー数の予測です。描画コール数はレンダリングパスやバッチ処理に依存します。最終結果はエクスポート時に記録します。解析はモデルを複製せず、ソースデータの読み取りだけを行います。

4. メッシュ結合でメッシュ出力を選択したメッシュを結合に設定します。直下の静的メッシュを結合または同一リグのメッシュとアタッチメントを結合を有効にし、レンダラー選択と取り付けで個別のパーツやボーンを選択します。保存先は5. モデルを出力で指定します。

  1. 4. メッシュ結合で選択したメッシュを結合を選び、必要な静的メッシュまたは同一リグの結合スイッチを有効にします。レンダラー選択と取り付けを展開し、対象の部品とアタッチメントボーンを選びます。保存先は5. モデルを出力で指定します。
  2. 含めるレンダラーにチェックを入れます。すべて選択 または すべて個別に維持 で初期選択をまとめて変更できます。同名の項目は入力番号と階層パスで区別します。チェックを外したレンダラーにもアトラスは適用されます。
  3. 書き出して Atlas_Merge.txt を確認します。結合グループには、少なくとも2つの選択済み互換レンダラーが必要です。レンダラー設定が異なる場合は、複数の結合レンダラーに分かれることがあります。

レンダラー選択リストの初期の高さは340ピクセルです。リスト直下の小さなハンドルをドラッグすると、160～650ピクセルの範囲で変更できます。ハンドルをダブルクリックすると340ピクセルに戻ります。高さはエディターウィンドウに保存されます。リスト内をスクロールすると、他のレンダラーも確認できます。

固定された家具部品、建物の構造、機械の外装、常に一緒に表示・移動する小物などが適しています。互換性には、レイヤー、影、プローブ、描画順序、モーションベクトル、その他の対応レンダラー設定が含まれます。静的結合では、対応するベイク済みライトマップの UV 変換も適用されます。

ドア、引き出し、着脱装備、個別に移動・非表示にする部品など、独立レンダラーに依存する部分は結合しないでください。元の Transform とコライダーは保持されますが、完全に結合へ取り込まれたレンダラーは無効になります。元の Transform を動かしても、結合済み静的メッシュ内の形状は個別には動きません。

モデル LOD の生成

モデルとアトラス > 最適化モード > LOD を生成 を選び、モデル、プレハブ、またはシーンオブジェクトを追加します。最高詳細度を入力に使用し、既存の下位 LOD は生成対象から除外します。元のアセットは変更しません。

LOD1/LOD2 の三角形目標と強度を指定します。シーム簡略化距離 (%) は短い接続エッジを優先的に簡略化し、UV の分割を維持します。小さな独立パーツ (%) は削除可能な独立した微小形状の最大サイズです。距離は各メッシュのバウンズ対角線に対する割合で、パーツの削除は軽量化率と強度に応じて変化します。最大の構成要素は維持します。0 に設定すると各処理を無効化します。

メッシュと生成レベルを選んで確認します。比較元は常に元の LOD0 です。両画面で回転、パン、ズーム、照明を共有し、ワイヤーフレームと三角形数を表示できます。生成中は一時停止、再開、キャンセルが可能です。追加の効果がない重複レベルは書き出しません。

インポート済みの法線と接線の向きを維持し、滑らかなシェーディングや加重法線を保ちます。色の境界、UV の向き、テクスチャの伸び、形状誤差、トポロジーを確認します。短いシームやベベル面と小さな独立形状が削除される場合があるため、保存前に外観を確認してください。元のテクスチャは変更しません。

保存時は専用フォルダーに Meshes、Prefabs、LOD_Report.txt を作成し、LOD0 と元のマテリアルを維持します。書き出したコピー内の既存の下位レンダラーを無効化し、メッシュとマテリアル参照を解除します。元のアセットと開いているシーンを維持します。スキニング、ブレンドシェイプ、追加頂点ストリーム、マテリアルプロパティの上書きがない静的三角形メッシュが対象です。上限は 20 万頂点、50 万三角形で、UV0 は任意です。浮動小数点バッファや UV 分割によりメモリが増える場合があります。目標は保証値ではなく、FPS 測定値でもありません。設定はアトラスプロファイルと別に保存します。

既存のLODレベル内でメッシュを結合する

選択したメッシュを結合またはメッシュ結合のみでは、互換性のある静的メッシュと共有リグのスキンメッシュを、既存のLODGroupと一致するレベル構成の範囲内で結合します。例えば、互換性のある2つのLOD0部品を1つのLOD0レンダラーにまとめ、LOD1部品は別のLOD1レンダラーにまとめます。独立したLODGroupは個別に保持されます。既存のLOD所属がない選択済みの小物は、結合書き出し時に互換グループへ自動割り当てされます。

書き出しではLODのレンダラーリストを生成したメッシュに更新します。レベル数、画面相対の切り替えしきい値、フェード幅、フェードモード、アニメーションするクロスフェード、グループの有効状態、ローカル基準点、グループサイズを保持します。LOD境界の再計算や簡略化ジオメトリの生成は行いません。除外した部品、残った透明面、互換性のない部品は元のレベルに残ります。結合したブレンドシェイプのレンダラーも同じLOD所属を維持します。

複数のレベルで再利用されるレンダラーは、所属する全レベルが一致するレンダラーとのみ結合できます。複数のLODGroupで共有されるレンダラーは個別に保持されます。完全なグループルートと参照先レンダラーをすべて選択してください。入力ルート間の参照にはグループ化したプレハブまたは選択したメッシュを結合が必要です。個別のプレハブごとに完全なLOD構成を含めてください。

レンダラー数の予測にも書き出しと同じLOD制限を適用します。数値は、その瞬間に表示されるレベルだけでなく、スキャンした全レベルを含みます。Atlas_Merge.txtには更新したLODGroup数を記録します。Editor APIではAtlasExportResult.mergedLODGroupsから取得できます。モデルプレビューは最上位の有効なレベルを表示します。切り替えとクロスフェードは、書き出したプレハブをシーンで確認してください。

小物のLOD: 同じ階層、同じ入力オブジェクト、近くの互換グループの順に選びます。グループに対する小物のサイズ比と各切り替えしきい値から画面上の高さを推定します。次のレベルへ進むときの既定値は画面の高さの3%です。LOD0には必ず含まれます。小さい塩入れはLOD0のみ、椅子はLOD0–2に残る場合があります。複数レベルで同じレンダラーを参照するためジオメトリは複製されず、グループのカリングとともに非表示になります。

LOD詳細設定で自動割り当てとしきい値を変更し、小物ごとに対象グループと自動 / 全レベル / LOD0のみ / 最終レベルを指定 / 独立を選べます。既存のLOD所属は保持します。除外、独立したスクリプト、アニメーション、物理制御の部品は自動割り当てしません。手動指定では未結合や除外の小物もグループで表示制御できます。レポートに割り当てを記録し、AtlasExportResult.assignedLooseLODRenderersから件数を取得できます。この小物の割り当ては表示レベルのみを変更します。低ポリゴンメッシュを生成するには、LOD を生成 を使用してください。

Editor API: AtlasSettings.automaticLODForLooseObjectsの既定値はtrueです。lodMinimumScreenSizeは比率で保存し、既定値は0.03fです（UIは%表示）。AtlasMergeSelectionにはlodMode（AtlasLooseLODMode）、任意のlodGroupとlodLastLevelがあります。自動割り当てがオフでも手動表示指定は有効です。シーン置換では、元の入れ子の子ではなく完全なプレハブインスタンスルートを選択してください。

共有リグと剛体部品の取り付け

同一リグのメッシュと装備を結合 で 4. メッシュ結合 を有効にすると、実際に同じスケルトンを参照する互換 Skinned Mesh Renderer を結合できます。ボーン名が同じだけでは共有リグとは判定されません。同じボーン名を持つキャラクターの別インスタンスは、別スケルトンとして独立したまま残ります。

同じリグにスキニングされたメッシュを結合する

  1. キャラクターの完全なルートと、そのボーンをすでに参照している別のスキン入力を含めます。参照される全ボーンとルートボーンが、選択した入力内に必要です。
  2. レンダラーを分けたまま内部のボーン参照を共有する場合は グループ化したプレハブ、互換部品を結合する場合は 選択したメッシュを結合 を使用します。個別プレハブでは、各入力に完全なリグが必要です。
  3. 書き出して、シーン内でアニメーションを確認します。結合可能なスキンでは、ボーン参照、補正されたバインドポーズ、可変数のボーンウェイトが保持されます。通常のボーンアニメーションに対応し、結合時にブレンドシェイプのカーブを変更できます。それ以外のレンダラープロパティのアニメーションを持つ部分は個別に保持します。

未スキニングの剛体部品を取り付ける

  1. 剛体部品とキャラクターの完全なリグを含め、書き出し前に部品を必要な位置に配置します。装備だけでなく、道具、パネル、機械部品、アクセサリーなどの剛体ジオメトリにも使用できます。
  2. 剛体レンダラーにチェックを入れます。取り付け先ボーン が 自動 の場合、既存の親ボーンを自動検出します。別入力の場合は、含まれるモデルのボーンやソケットをポップアップから選択します。プレハブやモデルアセットでも選択できます。
  3. リグ付き結合を有効にして、結合モードで書き出します。部品は現在の配置を保ち、全頂点が選択ボーンに100%のウェイトで追従します。剛体としての追従であり、変形用ウェイトの自動生成や手への自動スナップではありません。

取り付け専用のランタイムスクリプトは不要です。結合した部品は、出力スキンメッシュと表示状態を共有します。個別の非表示、交換、取り外し、位置オフセットのアニメーションが必要な場合は、独立させてください。共通のキャラクタールートにある Rigidbody は互換になり得ますが、独立して動く物理部品は結合しません。移動するスキン出力には、ライトマップ付き部品を結合しません。

ブレンドシェイプを持つメッシュの結合

共有リグの結合の下にあるブレンドシェイプメッシュを結合は既定で有効です。互換性のあるスキンメッシュの全フレーム、フレームのウェイト、現在のウェイトを保持します。固有名は維持し、重複名には元の部品名を付けて区別します。Animatorの該当クリップをAnimations/へ複製し、書き出したAnimator Override Controllerで新しい参照先に変更します。既存のオーバーライドとLegacy Animationにも対応します。元のクリップやコントローラーは変更せず、追加のランタイムコンポーネントも不要です。残った透明面用に元のカーブも保持します。

選択ソース内のシリアライズ済みスクリプトが直接参照するレンダラーは個別に保持します。表示状態やマテリアルのアニメーション、互換性のない設定も結合対象外です。外部スクリプト、インデックスによる制御、動的に読み込むクリップ、Playables、書き出す階層にないアニメーションシステムは参照先を確認してください。任意の参照を自動変更する機能ではありません。オフにすると以前と同様に個別レンダラーを保持します。レポートには結合したシェイプと変更したクリップ数を記録します。API: AtlasSettings.mergeBlendShapes、AtlasExportResult.mergedBlendShapes、remappedAnimationClips。

効果的な最適化と検証

代表的なシーンで最適化前後を測定します。Unity のプロファイリングツールで、マテリアルスロット、レンダラー数、ドローコール、テクスチャメモリ、フレーム時間を比較してください。個別モデル間でマテリアルを共有しても、すべてが自動的に1ドローコールになるわけではありません。透明度、パス、照明、バッチング、レンダラー設定も影響します。

大きな結合メッシュは、一部分だけが画面に見える場合でも表示対象になることがあります。通常一緒に表示され、移動するものをまとめてください。大きなアトラスは、無関係なテクスチャを同時に読み込む原因にもなります。用途に合わせてサイズ、チャンネル数、グループを選んでください。元の高解像度画像を同梱したままでは、出力アトラスを小さくしてもパッケージ内の元画像サイズは減りません。

  • 同じシーン照明とカメラ距離で、出力プレハブと元モデルを比較します。
  • 変形、ブレンドシェイプ、LOD 切り替え、透明度、コライダー、個別レンダラーを参照するスクリプトをテストします。
  • 両方のレポートを確認し、出力の依存関係と動作を検証するまで元アセットを保持します。

追加頂点ストリーム適切な元メッシュに先に適用してください。無視して破棄することはありません。
ClothCloth のないコピーを使用してください。UV 分割で頂点インデックスが変わる可能性があり、Cloth 係数の再ベイクが必要です。
カスタムシェーダー入力マッピングと生成マテリアルの状態を確認してください。独自のパック形式や効果には、別途変換・検証が必要です。

出力がぼやける解像度低下の通知とマテリアルごとの寸法を確認します。重要なものの優先度を上げる、最大サイズを上げる、同時に処理するモデルを減らす方法があります。
優先度を変えても結果が変わらない優先度は自動調整が有効で、縮小が必要な場合に機能します。入力密度の上限や配置形状によっても差が制限されます。

遠距離で色がにじむ・変わるミップマップ、余白、圧縮、フィルタリングを確認します。厳密なパレット用途ではミップマップを無効にし、ポイントフィルタリングを検討します。まず非圧縮出力で比較してください。
法線・メタリック・発光がおかしい各チャンネルのプレビュー、プロパティ識別子、パック形式、ベースタイリング、元のワークフローを確認します。同じ照明で比較してください。独自効果は自動ベイクしません。
出力マテリアルが複数できる透明またはカットアウトの入力がある場合は、透明サーフェスを不透明にするを確認してください。不透明マテリアル2つの違いが面カリングだけなら、高度なアトラス設定 > 不透明マテリアルの面カリングを統一を有効にし、プレビューを再作成してから書き出します。その他の描画設定が異なる場合は、依然として別マテリアルが必要です。アトラスの共有だけでは出力マテリアルは必ずしも1つになりません。
ガラスが不透明になるガラスの透明度やアルファクリップの切り抜き穴を保持するには、透明サーフェスを不透明にするを無効にしてプレビューを作り直し、再出力してください。カスタム出力シェーダーのサーフェス設定も確認してください。
ボーンが入力範囲外と表示される参照される全ボーンとルートボーンを含むキャラクタールートを選びます。入力間で共有する場合は完全なリグも入力に含めます。
共有スキン部品を個別プレハブで出力できないグループ化または選択メッシュ結合を使用します。個別出力では入力ごとに完全な独立リグが必要です。
選択メッシュが結合されないAtlas_Merge.txt を読み、両結合スイッチ、選択、グループ数、リグの同一性、前述の除外条件を確認します。
取り付け部品の位置や追従ボーンが違う書き出し前の配置と選択したボーン・ソケットを確認します。現在の配置を保持するため、自動で姿勢調整やスナップはしません。

出力モデルが見つからないステータスの保存先を確認し、Prefabs フォルダーからシーンへ配置します。対応するシーン入力は、書き出し後にシーンオブジェクトを置換を有効にした場合に置換されます。
出力フォルダーを指定できない現在のプロジェクトの Assets 内を選びます。Assets 外や親フォルダーへの遡りを含むパスは使えません。
