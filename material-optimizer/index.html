What the tool does

Scene Material Optimizer, Texture Atlas Creator & Mesh Merger collects material inputs from one or more models, packs their supported textures into shared atlases and remaps the meshes to use them. Compatible source materials consolidate into shared output materials. You choose whether the exported models remain separate, share a parent prefab or merge selected compatible meshes.

OperationWhat changesWhat it means in practice
Texture atlas creationTexture layout and UV0 coordinates.Several models can sample the same texture assets without becoming one mesh.
Material consolidationMaterial references and compatible submesh slots.Fewer materials or slots can be used while retaining separate models.
Optional mesh mergingSelected compatible renderers and their geometry.Can reduce renderer counts. Merged parts share visibility and culling.

This guide covers URP Lit materials using the metallic workflow. The optimizer runs in the Unity Editor. Generated assets do not require an optimizer runtime component. Source scripts, animation clips, avatars and collider assets may still be dependencies of an exported prefab.

Install, open and choose a language

Import the complete package, including Scene_Material_Optimizer and the bundled DPT_Core folder. DPT Core supplies the shared editor interface. The supported atlas workflow uses stock URP Lit materials and does not require custom shaders or shader edits. Use Unity 6.3 or Unity 7 with URP.

  1. Import the package into a URP project and let Unity finish importing and compiling. Resolve project compilation errors before opening editor tools.
  2. Open Tools > DPT Games > Scene Material Optimizer. The Tools menu retains the English product name in every language.
  3. Use English, 日本語 or 한국어 at the top of the window. Unity remembers the selection. Asset names, shader property identifiers and export filenames are not translated.
  4. Work in Edit Mode. Atlas controls are disabled while entering or running Play Mode. Allow space for the settings column and preview; the window has a minimum size of 1020 × 650.

Hide Help Boxes hides optional guidance, including the informational notices under Export models. Tooltips, warnings, errors and important operation status remain available. A successful preview does not show a separate ready message; hover the atlas sizing line to see how many triangles were folded into shared colour pixels. The Memory Comparison table has its own collapsible heading, independent of Hide Help Boxes.

Open from the Hierarchy

Select one or more model roots and right-click DPT Games > Scene Material Optimizer. The shortcut loads and scans that selection. Right-clicking an unselected object loads that object instead. Nested duplicates and empty unsupported objects are removed. It does not bake, export or change the scene. The command is available in Edit Mode for objects containing supported meshes.

Create your first atlas

  1. Drop one or more scene objects, model assets or prefabs into 1. Source objects, or select them in Unity and click Add Selection. Start with a small collection you can inspect easily.
  2. Click Scan Sources. Check the renderer, material, slot and triangle counts. Read any warnings before continuing.
  3. Preserve All Details is enabled by default. Use Auto Fold All, or choose Fold Verified Colours for individual materials, to detect flat regions suitable for single-pixel swatches. Leave most materials at Normal priority.
  4. Use a URP Lit Material Template, or leave it empty to use the active pipeline’s default Lit shader. Keep Auto Fit to Maximum Size enabled. The default Maximum Atlas Size is 4096.
  5. Click the green Create Atlas Preview button. Inspect the atlas channels and Before / After Model view. If important surfaces lose too much detail, raise their Detail Priority and create the preview again.
  6. Keep Separate Prefabs to export independent models sharing atlas assets. Use 4. Mesh Merging to choose grouping or Merge Selected Meshes. The static and shared-rig switches are visible directly in this section.
  7. Set Output Name and an Output Folder inside this project’s Assets directory. Click the blue Save & Export button. An up-to-date preview is reused. Source or baking changes rebuild it before export.
  8. Open the new export folder and use the prefab assets in its Prefabs subfolder. Drag a generated prefab into your scene and check it under your own lighting and animation. Save the scene when finished.

First exercise: use a table, a flat colour mug, a printed book and a glass bottle. Export separate prefabs first. You can then compare a second export that merges the table’s structural pieces while keeping the movable props and glass separate. This is a suggested exercise using your own assets.

Bundled demo textures: The optimized demo atlas was baked from 4K material masters. Compact 1K-2K source copies are supplied to keep the package size down, with the current AO maps retained. The scene's memory figures measure the included assets. A rebake from those compact sources may differ from the supplied atlas.

Reusable settings profiles

Expand Settings Profiles above the source list. Save As... creates a named project asset. Select an existing Settings Profile and click Load to apply it, or Save to update it. Profiles store atlas settings, mesh-output options, output name and destination and overrides for matching material assets. Loading retains the current source objects, per-renderer merge choices and attachment bones. It does not modify source materials. Scene-only material overrides are not stored; a material template must be a project asset. Reset Settings restores atlas, material and mesh-output defaults while retaining source objects, output name and destination. Loaded settings are independent copies, so later edits do not change the saved profile until Save is clicked.

Review optimizations across a scene

Automatic scene atlases verify flat regions across all mapped channels, including texture-based palettes. Exactly constant regions share colour swatches; regions with normal, mask, alpha or other detail retain their texture data. Compact exact-cell indices and sparse samples for collapsed UVs bound analysis memory, and a per-operation cache avoids repeating full source readbacks when groups split. Exactly uniform source channels do not inflate required pixel density. Compatible material families are grouped by their required output channels to avoid unnecessary atlas maps.

Scene atlases include compatible opaque, cutout and transparent material users, including disabled renderers and inactive objects. Render states remain separate and existing visibility flags are preserved. Power-of-two rectangular layouts reduce empty atlas space while keeping texture compression. Texture-free constant materials can use colour swatches. Resource checks use the original scene texture and combined texture/mesh budgets across all atlas batches; deferred material families are retried before merging after other batches free storage. Material counts include all renderer types and retained asset references.

Open Tools > DPT Games > Scene Material Optimizer and use the Models & Atlases / Scene Optimization buttons to switch workflows within the same window. The scene workflow analyses one loaded scene at a time. It works in Edit Mode outside Prefab Mode.

  1. Choose the scene, optimization priority and target image height. Enter the closest distance from which players may view the objects. An optional reference camera supplies its field of view or orthographic scale and enables illustrative before/after snapshots.
  2. Use Protected objects to exclude objects and their descendants. Click Analyse Scene. Analysis reads the scene without changing its renderers or import settings.
  3. Review the suggested material consolidations, texture sizes, atlas groups, static merges and assignments of loose props to existing LOD groups. Each row explains its evidence, estimated benefit and trade-offs. Highlight selects and frames the affected objects. Expand a row to inspect its materials and object paths.
  4. Only exact serialized material matches are selected by default. Review and select visual or structural changes yourself. Edit proposed texture or atlas limits and the last visible LOD. Preview This Atlas builds a before/after model comparison for that group inside the scene workflow.
  5. Click Apply Selected Optimizations. The tool creates a unique output folder under Assets/DPTGames/Scene_Material_Optimizer/Generated, saves Original_Backup.unity, works in an isolated additive working scene and saves a separate optimized scene. Original scene objects and source assets are preserved, including unsaved scene changes in the backup.
  6. Use Select Optimized Scene to locate the output and Open Report to inspect resource totals. Open the optimized scene separately to check gameplay, lighting and visibility, then profile on your target device.

Pause / Resume / Cancel: analysis, atlas preparation and application advance across short editor updates. A paused job stops advancing its scene work; an atlas worker may finish its current calculation. Cancel releases temporary resources and removes incomplete output. Closing the window or recompiling cancels the active job. Individual native scene saves, texture imports, image encoding and mesh operations finish their current step before a pause or cancellation takes effect.

Conservative grouping: merge proposals require nearby static siblings, compatible renderer settings and matching existing LOD membership. Repeated mesh instances, baked lightmaps, baked occlusion, animation, detected script references and property overrides are protected. Original GameObjects and colliders remain after merging; their source renderers are disabled. Existing LOD geometry and transition thresholds are preserved. Loose-prop suggestions use an enclosing LODGroup and bounds checks, rather than assigning an unrelated nearest group.

Texture estimates: static-mesh UV edges, texture aspect ratio and material tiling are checked against the selected image height and viewing assumptions. Read-only Editor mesh snapshots avoid changing Read/Write import flags. Skinned or oversized inputs, degenerate UVs and unsupported texture types are skipped. The estimate cannot infer future camera movement or artistic importance, so inspect lettering, normal detail and alpha edges. Selected atlases suppress redundant distance-based texture reductions for fully covered objects. Explicitly selected content-based reductions apply to copied textures before atlas creation.

Use texture detail analysis: this optional setting is off by default and adds analysis time. It compares lower-resolution reconstructions with the imported source, checking average and worst local error so small features are not lost in an average. Normal maps use angular error; mask maps use the channels sampled by the supported material. Alpha-sensitive and point-filtered textures retain their resolution. The priority slider adjusts conservative error limits, while viewing assumptions and strong material values tighten them. Review the proposed rows and inspect the saved result: these estimates precede output compression and do not guarantee identical appearance. Original texture files and import settings remain unchanged.

Shared UV regions and AO: scene users of the same sampled surface can overlap in the atlas, including different materials whose sampled maps, tiling, tint and relevant values match. AO is part of that comparison; differing AO keeps regions separate. The optimizer does not replace authored AO with baked lighting. The supported atlas workflow uses stock URP Lit without requiring a custom shader or shader edits. When metallic and smoothness are constant across an output material, the stock material values replace an unnecessary mask map. Atlas maps can use different imported resolutions while retaining the required channel detail and padding.

Export Compression: scene atlases offer the same High Quality, Balanced and Uncompressed choices as Models & Atlases. High Quality is the default. Balanced can use smaller RGB compression for opaque base colour and AO maps; cutout/transparent base colour and metallic/smoothness retain their alpha data. Compression can affect grain, gradients and normal quality, so inspect the saved textures. Resource estimates reflect the selected desktop format and final imported resources are checked before an atlas is accepted.

Report limits: reports compare enabled renderer counts, vertices, triangles and unique renderer-referenced meshes, materials and textures, with estimated buffer/storage sizes. All existing LOD levels are counted. Disabled source renderers retain their asset references after merging, so referenced mesh memory may increase. These are resource totals, not measured draw calls, FPS, total VRAM or a performance guarantee. Optional snapshots are illustrative single-camera renders; camera stacks and custom rendering may differ.

Scene or source changes invalidate the reviewed plan. Analyse again before applying. Runtime lookups and dynamically loaded content still require review. Different loaded scenes are analysed separately.

To simplify a model independently of a scene, use Models & Atlases > Optimization Mode > Generate LODs. This workflow retains the original materials.

Generate LODs: the scene workflow can create LOD1 and LOD2 for eligible leaf Mesh Renderers without an existing LODGroup. Expand a suggestion to set triangle targets, LOD strength (0-2) and three screen-height thresholds. Defaults are 0.5, 0.18 and 0.02. Screen height is the fraction of the view occupied by the object; below the LOD2 threshold it is culled. Inspect the silhouette, shading and transitions in the optimized scene. Original mesh assets are unchanged and LOD0 uses the reviewed mesh.

The independent LOD reducer is included in this package. Vertex 3D Terrain and a shared LOD service are not required. It protects open borders, material boundaries and split UV seams, retains submeshes and authored vertex channels and does not interpret vertex colours or auxiliary UVs as terrain biome data. Repeated sources with identical settings share generated mesh assets. Targets are best effort; the report records achieved triangle counts. If protection limits prevent useful reduction, no redundant LODGroup is created.

LOD generation excludes meshes below 500 triangles, non-leaf renderers, existing LOD groups, skinned meshes, blend shapes, additional vertex streams, transparent or alpha-clipped materials, parallax materials, unsupported shaders, baked lighting and detected runtime references. Limits are 200,000 vertices and 500,000 triangles per mesh. Generation runs on managed snapshots in a background worker with pause and cancellation checkpoints; mesh creation and saving stay on the editor thread. Selected atlases can be applied before generation. Generation suppresses an overlapping merge or loose-prop assignment. Resource totals include every generated LOD level and its additional memory.

Each saved level must remove at least 10% and eight triangles from its previous accepted level. Ineffective levels are omitted, so a generated group can contain two or three levels. Exact coincident positions share geometric topology while distinct attribute samples remain separate. Coarser targets allow more geometric error.

Use model LODs: analysis also detects unused LOD0/LOD1/LOD2 meshes inside imported model assets. A suggestion requires unambiguous mesh names, matching model-space transforms, the same ordered material slots, decreasing triangle counts and matching vertex channels. It reuses those mesh assets with the current scene materials, including foliage and custom shaders. Expand the suggestion to review the meshes and adjust transition and culling screen heights. Defaults are 0.6, 0.25 and 0.005 and respect Quality LOD Bias. These objects are excluded from redundant LOD generation. Overlapping atlas suggestions are suppressed because remapped UVs would be incompatible with the existing lower meshes. Original model assets are unchanged.

Optional shadow detail: Use lowest LOD for shadows keeps the visible LOD geometry while a shadow-only renderer uses the lowest existing model LOD. It is off by default. This can change shadow shape and density, especially on alpha-clipped foliage. Review the saved scene at close range. Two-sided shadow casters retain their original shadows. No runtime helper script is required.

Fewer triangles do not guarantee faster frames. Different instances choosing different LOD meshes can split otherwise shared instancing groups and increase draw calls. Review the saved scene from representative camera positions and measure frame time on the target device.

Comparison PNGs are saved in Snapshots~/ inside the output folder and are not imported as project textures.

Scene atlas suggestions group compatible material users across the scene. Repeated static meshes with the same ordered material slots share one atlas UV layout and one remapped mesh. Different material overrides remain separate. Existing LODGroups, object transforms and colliders are retained. Materials keep their authored AO sampling; the scene workflow reuses the original material's texture regions across its users. The source readback and geometry working estimate bounds each automatic group.

URP Lit detail baking supports Multiply x2 and Scaled colour blending, the detail mask alpha channel, composed base/detail UV tiling and offsets and reoriented detail normals. Disabled detail keywords leave the base unchanged. Detail layers are baked at the selected atlas resolution, so inspect fine grain and normal detail in the preview. The output disables detail overlays to avoid applying them twice.

Source-resolution atlas builds reuse remapped geometry for identical static mesh/material layouts, including through island editing and export. World-space density keeps per-instance layouts because transforms can change the requested density.

Scene atlas baking streams the source images needed by each region and channel, releasing them between channels. It retains original source resolution and samples into the selected atlas resolution.

Scene mode now exposes Maximum atlas size (512–8192) and Atlas detail resolution. The default is 4096 and 100% source texture density. Packing must retain the chosen density; batches split by material layout or keep their original textures rather than silently shrinking further. Large or heavily tiled materials may stay separate. The material-count estimate is provisional until the final atlas groups are built.

Automatic scene atlases must reduce scene-wide material count without increasing texture storage or the combined texture and mesh buffer estimate. Textures still referenced by other renderers or serialized component fields remain in the calculation. Candidates are checked after packing and again using imported textures before any renderer is changed. Shared materials stay together across different material-slot layouts. Rejected groups split or retain their original resources. These resource checks do not prove a frame-rate improvement: compare CPU and GPU frame times using matching views and quality settings. LOD generation is a separate geometry-for-memory tradeoff.

Mesh Colliders: a Mesh Collider sharing the renderer mesh does not prevent visual mesh optimization. The collider keeps its original mesh asset. Retained collision meshes are included in atlas resource guards and scene mesh totals, so replacing visual geometry does not hide the memory cost of keeping collision geometry. Script references to the same mesh remain protected.

Choose sources and read the scan

A source is a root GameObject. The scan includes supported renderers in all its children, including inactive objects and every mesh LOD. If both a parent and its child are supplied, the child is not counted again as a separate source. Each source root becomes a separate prefab in Separate Prefabs mode.

Auto Configure and undo

After adding sources, click Auto Configure beneath the source controls. It scans texture dimensions, tiling, filtering and shader compatibility without baking pixels or exporting. Expand Configuration Details to see why each setting was chosen. These are starting recommendations; preview the result and adjust detail priorities for your intended camera distance.

For atlas inputs it selects Automatic sizing with an estimated maximum between 256 and 4096 pixels, Auto Fit, shape-aware packing, automatic padding and source-resolution limits. Upscaling is off. You can still select 8K or Fixed sizing manually. Untextured standard materials use verified single-pixel folding. Point-filtered sources without mipmaps receive point filtering, no mipmaps and no compression; detailed sources receive smooth filtering, mipmaps and high-quality compression. Existing packing choices on textured materials remain unchanged. Custom shaders, texture arrays, specular workflows and detected detail/parallax effects select Merge Meshes Only to retain their materials.

Compatible static and shared-rig merging is recommended only where the source analysis finds a mergeable group. This is an estimate; final UV layouts and export compatibility can affect the result. Existing mesh-only mode is retained. Raw atlas output is retained when atlasing remains compatible. Material mappings, priorities, renderer exclusions, attachment bones, LOD overrides and the output destination are kept.

Undo Configure restores the settings and material packing choices from before the most recent configuration. It is available for the current source selection in this window session. Changes that affect baking mark an existing preview for rebuilding, following Auto Update; changing optimization mode releases it. Changes only to export or merging settings preserve the existing atlas and manual layout. Undo restores settings, not a manual layout lost through rebuilding.

Micro textures and detailed regions

Auto-Uncompress Textures is enabled by default in Models & Atlases and Scene Optimization. Materials using Fold Verified Colours are checked through uncompressed temporary copies at source resolution, capped at 8192 pixels, so compression and downscaling artefacts do not block flat colour and PBR folding. Retained detailed regions are sampled from the imported textures and sized at their imported resolution. Source files and import settings stay unchanged; temporary assets are removed after sampling or cancellation. Native imports can pause the Editor. Disable this option to sample the imported compressed pixels instead.

Optimize Palette Size adds a palette conversion for flat-colour models, similar to Color Swapper. It replaces base-colour and metallic/smoothness variation, including blended border pixels, with representative palette colours. This option is off by default because it can remove patterns and gradients. Alpha, normal, AO, emission and detail-map variation remain protected. It is available in Models & Atlases and Scene Optimization.

Auto Fold All verifies flat regions while retaining texture detail, so it can create an atlas containing both swatches and detailed areas. Optimize Palette Size adds a representative palette conversion for flat-colour assets and configures compact output. It also enables folding for all materials.

Swatches match the values that will be written to the active output maps. Base colour, normals, metallic/smoothness and AO use 8-bit map precision. Emission uses half-float precision. Input floats that produce identical output pixels share a swatch. Channels omitted from the output do not create unused duplicates; changing an output channel rebuilds the preview.

Palette sampling pairs base colour with metallic/smoothness from the same source areas. It normalises 8-bit source readback, filters minor border combinations relative to each colour and retains small distinct colours. Palette Tolerance groups nearby values across source materials and within each source. Zero keeps exact encoded values. A positive value can bridge one 8-bit step of metallic or smoothness variation, such as 0.125 versus 0.129. Higher settings allow more variation, capped below 0.05 per surface channel. Alpha, normal, AO and emission variation remain protected.

In palette mode, detailed atlas controls are collapsed under Advanced Atlas Controls. Priority and rotation controls are hidden when there are no retained detailed regions. The summary reports swatches and base colours separately. Identical base colours can still need different swatches when exported surface values or protected UV assignments differ. Palette Tolerance controls base RGB and small metallic/smoothness differences.

When every region folds, Automatic sizing with Automatic Edge Padding uses one pixel per swatch, point filtering, no mipmaps, uncompressed textures and no padding. Small palettes can therefore export below 256 pixels, including 8 × 8 or smaller. Fixed canvases and manual padding retain your chosen output settings. Detailed and mixed atlases retain their normal filtering, compression and padding.

A single packing button shows Preserve All Details, Auto Fold All or Mixed Packing to match the individual material rows. New selections default to preserving detail. Click once to switch all materials to folding, or click again to preserve all details. Mixed selections switch to folding on the first click.

In Models & Atlases, enabling Optimize Palette Size applies the complete palette setup in one action: all materials switch to folding, clean source sampling is enabled, sizing and padding become automatic, UV sharing respects AO and output uses point filtering with uncompressed maps and no mipmaps. There is no need to adjust those controls separately. Switching back to Preserve All Details disables palette conversion.

Pack UV Islands Separately only affects detailed regions left after folding. It does not change single-pixel swatches. The control is disabled when the current output is entirely a compact palette.

Verified flat regions become 1 × 1 pixel swatches plus edge padding. Automatic atlas sizing then selects the smallest canvas that fits the resulting swatches and any retained detail. A fixed canvas keeps its selected dimensions. If filtered edge regions retain detail, enable Pack UV Islands Separately to compact them; otherwise each material keeps its remaining regions together. Palette Tolerance groups already verified swatches; it does not flatten real gradients or normal, mask or AO detail.

Fold Verified Colours checks that each triangle samples a constant value across every mapped channel, including a filtering margin where its UVs vary. A face whose UVs all point to one palette position is constant even with bilinear filtering and different neighbouring texels. Suitable regions become single-pixel swatches plus padding. Matching verified swatches can use the same pixel across different models and materials.

A flat base colour does not erase normal map, metallic, smoothness, occlusion, opacity or emission detail. If a mapped channel varies, the region remains detailed. Gradients and painted shading also remain detailed. Ambiguous or expensive footprints are retained conservatively. The tool checks texture data rather than detecting an art style by name.

Use Preserve Details to keep a material in detailed atlas regions even if folding might be possible. Auto Fold All applies verified folding to all scanned materials. Preserve All Details switches them all to detailed packing. Flat swatches and detailed regions can coexist in the same atlas. Folding changes texture sampling, not the model’s shape or triangle count.

Share exact or similar flat colours

Enable Auto Fold All or choose Fold Verified Colours for individual materials. The Palette Tolerance slider under the packing buttons ranges from 0 to 400 and defaults to 0 for exact matches. It uses the same sum of 8-bit RGB differences as Color Swapper: (100, 110, 120) and (102, 110, 120) differ by 2.

Increasing tolerance lets similar verified flat base colours and nearby metallic/smoothness values reuse an existing representative swatch. This changes only those folded colour and finish values, leaving detailed texture regions intact. Opacity, normals, AO and emission must still match at output precision. The active RGB and metallic/smoothness limits appear below the single slider. Profiles save the setting, Auto Configure retains it and Reset Settings restores zero. Scene Optimization uses the same control for atlas preview and application.

UV Overlap: Auto can share verified flat swatches with matching AO, while detailed AO regions remain isolated between source meshes. Allow also permits sharing. Prevent keeps renderer swatches separate. Opaque and transparent canvases remain independent when split.

Expand a material under 2. Packing & source channels to inspect its source properties. URP Lit metallic conventions are detected automatically. Property fields contain shader identifiers such as _BaseMap, not texture filenames. Verify custom shader mappings before creating the preview.

Tiling and custom shaders

Keep Share Base Map Tiling enabled for URP Lit. It uses the base texture transform across mapped channels. Disable it only for compatible custom shaders whose properties use independent scale and offset. Supported Repeat, Mirror, MirrorOnce and Clamp sampling is baked into detail regions, including negative tiling.

Exact repeating UV periods can reuse one region when all active channels support the same period. A triangle spanning many repeats can still require a large footprint. Large requested sizes are not necessarily the source image’s dimensions. For custom output shaders, inspect Output texture property mappings and use Detect From Template after choosing the template. For the documented URP workflow, use the Metallic Smoothness packed layout.

Texture property pickers: source channel mappings and output property mappings list the selected shader’s Texture2D properties by display name and identifier. Choose None (omit texture) to omit a texture input. A saved property that is missing from the shader remains selected and is labelled not found, so opening the picker does not silently change existing mappings. Texture arrays and cubemaps are not offered. The existing supported colour, normal, metallic/mask, occlusion and emission channel meanings still apply; selecting a custom property does not bake arbitrary procedural shading.

Atlas resolution, fitting and padding

The preview keeps one compact atlas sizing line, including any reduced-region count. Hover it for source-resolution limits, density targets, padding, folded triangles, UV-overlap protection and rotation decisions. It describes the displayed preview while a rebuild is pending.

Automatic Edge Padding is enabled by default in Automatic and Fixed sizing. Padding is chosen from the actual generated dimensions for each canvas, increasing from 1 pixel for small uncompressed atlases without mipmaps to 16 pixels at 8K. Compression or mipmaps enforce a minimum of 4 pixels. Separate opaque and transparent canvases can have different padding. Turn the option off to set Edge Padding manually. The effective values appear in the atlas sizing tooltip and the export resolution report. The API setting is AtlasSettings.automaticPadding.

Advanced Atlas Controls contains Atlas Sizing, which defaults to Automatic. Automatic chooses the smallest canvas that fits the requested detail, up to Maximum Atlas Size. Select Fixed to use Fixed Atlas Size as the exact width and height, for example 8192 x 8192 even when the requested detail fits in 4096 x 4096. Fixed uses a square canvas and skips rectangular sizing and NPOT trimming. Returning to Automatic restores those preferences. Use Spare Space for Detail distributes available room across the regions; Allow Upscaling Beyond Source permits growth beyond source or world-space targets. Fixed sizing does not enable either option or recover detail absent from the mapped inputs. With Separate transparent atlases, each canvas uses the fixed size. The export resolution report records the sizing mode.

Automatic padding follows the generated canvas size and uses at least 4 pixels with mipmaps or compression. Disable Automatic Edge Padding to choose a manual value. Padding consumes atlas space.

When fitting reduces detail, the preview displays a notice and each detailed material shows its requested and output pixel dimensions. The exported Atlas_Resolution.txt records the choices. Original textures and their import settings are not resized or changed.

Why can a 4096 texture request 4092 × 4088? Region dimensions describe the UV footprint used by the mesh. Unused image borders can make that footprint slightly smaller than the image. Padding is added outside the footprint, so even a nearly 4K region can fail to fit a 4K atlas in strict mode.

Turn Auto Fit off only when you require the requested density without automatic reduction. Detail priorities are then inactive. If strict packing fails, enable Auto Fit, raise the maximum size or lower the source detail limit. Even Auto Fit cannot fit an unlimited number of one pixel regions plus padding: split the sources, reduce padding or increase the limit when the minimum layout cannot fit.

Shape-aware Island Packing is enabled by default. It places charts inside unused cavities of other charts. Chart bounding rectangles can overlap while occupied texels and their filter gutters stay separate, including with UV Overlap set to Prevent. The bake copies original source pixels throughout each chart's allocated footprint, including the surrounding filter border. It preserves neighbouring source detail rather than stretching island-edge colours. Gaps outside that footprint remain available to other charts. This also applies when a manual stack resize rebakes the island. No additional mesh cuts or UV seams are introduced.

Atlas Shape is under Advanced Atlas Controls when Atlas Sizing is set to Automatic. It defaults to Square; choose Rectangular when different width and height can reduce atlas memory. It is unavailable in Fixed sizing, which always uses a square canvas.

Allow Non-Power-of-Two Dimensions is also under Advanced Atlas Controls for Automatic sizing and is off by default. With Atlas Shape: Rectangular, sizes such as 1024 x 2048 are possible while each dimension stays a power of two. Enable this option to trim each dimension to multiples of four pixels. This may reduce stored pixels but does not guarantee improved GPU performance. Test your target platforms. Preview, UV remapping, imported texture sizes and memory estimates use the final width and height.

Use Spare Space for Detail is enabled by default. Reduced regions can retain more of a 4K source within a 2K atlas by using available gaps. With Source Resolution density, a lower Detail Scale can also recover samples from the currently mapped imported textures. The atlas does not grow for this step. Allow Upscaling Beyond Source is off by default; enable it to enlarge past the original sampling density. Folded colour swatches remain one pixel.

Check the actual source resolution: expand a material under Packing & source channels to see each mapped texture asset, its project path, its imported dimensions and the dimensions of its source image file. The baker samples the imported texture. A 4K file imported at 1K supplies 1K samples; an already-baked atlas supplies its currently assigned pixels. A small UV chart uses only a fraction of those pixels. Unassigned 4K masters and textures used before a previous bake do not raise the source cap. The preview and exported resolution report identify source-capped regions.

The texture preview always draws a box around the complete texture edges, using the Texture border colour, independent of UV and region outlines. The status line shows occupied and unused percentages. Occupied includes chart padding and the conservative packing footprint; bounding rectangles are not counted as fully occupied.

Texel-density targets

Texel Density defaults to Source Resolution, using imported texture dimensions and tiling. World Space uses mesh dimensions along the UV directions, including object scale, for comparable detail on similarly sized surfaces. Pixels Per Unity Unit defaults to 512; its slider ranges from 64 to 2048. Auto Fit may reduce the target. Detailed regions are packed separately per renderer in World Space, so repeated objects can use more atlas space.

Spare-space growth is skipped above 256 regions per canvas to limit packing time. Chart shapes, padding and detail limits can also leave gaps; increasing the maximum size or allowing upscaling does not guarantee a filled atlas.

Automatic UV sharing and manual stacking

UV Overlap defaults to Auto, which separates detailed regions from source meshes using AO or HDRP mask maps. Verified flat swatches can still share when their mapped surface values match, with the selected tolerance applied only to base RGB. Allow can reuse detailed regions of the same source material across renderers; it does not automatically stack all materials sharing a texture. Prevent separates renderers and disconnected UV shells, including flat swatches. Existing overlap inside a connected source shell cannot be repaired automatically. Shape-aware chart rectangles can interlock while occupied pixels and padding stay separate. Manual stacking uses separate shared-texture checks.

Give important materials more detail

Priority: Normal sets every source material to Normal. Priorities are relative: assigning the same priority to every material keeps the same density balance. Use Spare Space for Detail grows regions together at a shared density scale while preserving material priorities when Auto Fit is enabled. Growth stops at the applicable source or world-space target unless upscaling is enabled. The atlas dimensions stay fixed, and island shapes and padding can still leave gaps.

Detail Priority is a relative preference used when Auto Fit needs to reduce detailed regions. Leave ordinary materials at Normal and raise the ones you care about. You can give several materials High or Very high priority. You do not need to assign percentages to every material or adjust each texture channel separately.

Filtering, mip maps and texture imports

Auto-Uncompress Textures is used only for folding analysis and folded colour samples. Retained detailed regions use imported texture data, avoiding repeated source-copy imports and matching the source material workflow. Large atlas patches bake their pixels on a worker thread; texture imports, readback setup and uploads stay on the Editor thread. Settings-only rebuilds reuse the source scan when the sources are unchanged. Filtering and compatible material changes reuse the current atlas. Mipmap changes reuse its existing base-level pixels when the current padding is sufficient; compression changes also avoid a rebuild when padding remains sufficient. Atlas dimensions, packing, channel mappings and detail allocation still require repacking or rebaking. For detailed surfaces such as chainmail, enable Generate Mip Maps to compare with source materials that use mipmaps.

After updating the tool, an existing editor window enables mipmaps once to pick up this corrected default. Later manual changes are retained. Loading an existing settings profile restores its stored mipmap choice.

Point Filtering is off by default. Smooth output uses bilinear filtering without mipmaps and trilinear filtering with mipmaps. Enable point filtering for crisp palette or pixel textures when appropriate. Generate Mip Maps is enabled by default to match typical source materials and keep distant highlights stable. Existing profiles retain their saved setting. Disabling mipmaps can make fine metallic or normal-map patterns appear sharper or sparkle compared with mipmapped originals. Lower mip levels eventually mix nearby atlas regions, which is especially visible with tiny palette swatches. For detailed assets, mip maps can improve distant sampling; increase padding and inspect the result at the distances you will use.

Exported atlases use Clamp wrapping, your selected Export Compression setting and Read/Write disabled. The atlas has already baked the supported source wrapping behaviour into its regions. Compression can damage tiny swatches and data channels; change it only after inspecting the result. Shared atlases also share their filtering and import policy. One output set cannot simultaneously use different filtering for each source model.

Export Compression defaults to High Quality; Balanced and Uncompressed are also available. Actual GPU formats depend on platform and texture type. Use Uncompressed to check whether compression causes an appearance difference.

Opaque, cutout and transparent materials

Atlas sharing does not mean every surface can use one material. Opaque, alpha-clipped and blended transparent surfaces need compatible output render states. Differences in blending, cutoff, face culling, depth settings, render queue or supported lighting switches can create additional groups. The tool reports the planned material group count and detects transparent or alpha-clipped source materials.

Leave Make Transparent Surfaces Opaque off to retain blended transparency and alpha-clipped holes. When enabled, it converts both blended transparent and alpha-clipped cutout surfaces to fully opaque output materials: glass becomes solid and cutout holes are filled. The output render queue is normalized for the opaque conversion. The original source materials are unchanged. A warning appears, and differences in other render settings can still require multiple output materials.

Unify Opaque Face Culling is a separate, optional switch inside Advanced Atlas Controls. It allows opaque source materials with different front-face/back-face culling settings to share an output material by setting Render Faces: Both (_Cull = 0) on the generated opaque material. It works whether Make Transparent Surfaces Opaque is on or off. This may increase fragment shading and overdraw. It does not override other material-state differences, so one output material is not guaranteed. Leave it off to retain the original face-culling behaviour.

Example: solid furniture and a glass bottle can share the atlas textures while using an opaque material and a transparent material. They can still be exported as independent prefabs. Transparent portions retain separate renderers during merging so they can keep their sorting behaviour.

Shared or separate transparent atlases

Transparent Atlas defaults to Auto. With opaque and blended transparent regions present, Auto splits canvases if their combined estimated texture memory is more than 10% lower than sharing, or if only separate packing succeeds. Shared uses one canvas; Separate forces a split when both surface types exist. Separate canvases may have different dimensions and padding. Fixed sizing gives each the selected square size, which can increase memory. Output materials retain their respective render states.

Inspect the atlas and model preview

UV outlines is greyed out when the displayed atlas contains only folded single-pixel swatches, because their UVs collapse to points. It remains available when that atlas contains detailed regions. Use Region outlines to inspect swatch boundaries.

When detailed regions are reduced, the bake averages the source texel area covered by each output pixel. This applies to colour, opacity, normal, metallic, smoothness, occlusion and emission data, including manual island resizing. Normal directions are averaged before normalization. Each channel uses its own texture dimensions and tiling. Point-filtered source textures retain their nearest-neighbour sampling; verified flat colour swatches remain exact. Smooth output uses trilinear filtering when mipmaps are enabled and bilinear filtering without mipmaps. Point Filtering controls output sampling. Recreate existing previews and export again to apply the improved reduction to earlier atlases.

Auto Update sits beside Create Atlas Preview (or Create Merge Preview). The model camera fits the visible model bounds and viewport proportions. Scroll to inspect details, down to 5% of the fitted camera distance; clipping planes adapt to model size. Reset view restores the fitted view.

Drag the vertical divider to resize the settings panel. Double-click the divider to restore its default width; Escape cancels a resize. Click an atlas region without dragging to expand, highlight and scroll to its source material in the settings panel. Click empty canvas to clear selection. Dragging still pans, modified drags still pan and double-click still fits the atlas. Manual island placement (advanced)

Folded single-pixel swatches can also be moved with Edit. A new compact palette starts with Snap: 1 px, so movement is not rounded to a grid as large as the atlas. Move into an empty cell or park a swatch outside the canvas while rearranging; occupied cells remain protected against accidental replacement. Hover a folded swatch to inspect its base RGBA and mapped surface values. Matching base colours may occupy different pixels because their smoothness, metallic or other mapped values differ. Palette Tolerance controls base RGB and small metallic/smoothness differences.

Expand Manual Atlas Layout (Advanced) in the atlas preview and enable Edit. Left-drag whole islands. The actual UV edges remain visible while moving even when the general UV overlay is off. Use Free / X / Y to constrain movement; X means horizontal movement with Y locked. During a drag, press X or Y to choose that axis and press it again to release the constraint. Escape cancels. Hold Shift for horizontal movement (Y locked) or Ctrl (Command on macOS) for vertical movement (X locked). Release to return to the selected axis mode; holding both keeps the current position. Middle/right-drag pans, scroll zooms and double-click fits the texture. Snap uses 1, 4, 8, 16 or 32 pixel movement increments. X/Y coordinate entry uses the lower-left corner and respects the selected axis lock. Pin island prevents accidental moves.

The compact manual-layout toolbar puts Edit, Snap, Free/X/Y, Pin, the X/Y pixel fields, Move, Undo and Reset on one line. Undo and Reset use icon buttons with tooltips. Match size appears on that same line when UV Overlap is Allow. Layout feedback is shown in the atlas footer.

Islands can be parked outside the texture box while rearranging other regions. Their UV outlines remain visible and the pan range expands to reach parked islands. Their samples are retained so they can be moved back without losing any map data. Export is disabled until every island and its padding is inside the atlas. Parking is limited to eight times the longer atlas dimension in each direction to reject extreme coordinates.

With UV Overlap: Allow, manual moves may overlap islands that use the same source texture set, including different materials sharing those textures. Different source areas, sizes and orientations are allowed. Colour, normal, metallic/mask, occlusion and emission texture identities must agree for active channels; sharing only a base map is insufficient when another map differs. Untextured regions can share the same source material or an identical folded swatch. Different texture sets are rejected. Overlapped regions intentionally share baked pixels across every map; the last moved island supplies those pixels, so overlapping different source areas or material tints can change their appearance. Alt-click cycles through stacked islands. Samples are retained and restored when unstacked. Auto and Prevent still reject overlapping padded footprints. Opaque and transparent canvases are independent. Undo Move restores up to 20 moves, including size changes and paint order. Reset Layout restores the original layout, dimensions and pins/history. Manual positions belong to this preview, are not stored in settings profiles and are cleared by rebuilding, script reload or closing the window. Export the current preview to keep its arrangement.

Match size when stacking is enabled by default. While moving freely, placing the centre of a smaller island inside a larger compatible island snaps the smaller island to its size and position. The drag outline previews the result; releasing the mouse rebakes that island from the original source textures at its new size, including all maps and mipmaps. Available source detail can improve; sizes beyond the source resolution add no new detail. Disable the toggle to keep the original size and allow partial overlap. X/Y axis locks keep size matching off. Moving the island away preserves its new size; Undo Move restores its previous dimensions. Only the dragged smaller island grows; dragging a larger island across a smaller one does not resize the stationary island.

Use the direct UV wireframe, Region boxes and Texture border colour fields underneath the atlas overlay controls. The model preview has its own Background picker beside its lighting controls, shared by both panes. The wireframe colour also applies to selected and moving edges; invalid moves remain red. Preferences persist across rebuilds and Editor sessions. These controls do not change scene cameras, source materials or exported textures.

Memory and export statistics

The collapsible Memory Comparison table replaces the preview Details dropdown in both atlas and mesh-only modes. Click its heading to show or hide the table and preview build time. The choice is remembered when reopening the tool. Before, After Preview and Est. Change columns compare enabled renderers, unique materials, triangles, vertices, mesh VRAM, texture VRAM and a highlighted total. Decreases are green and increases are red, with signed amounts and percentages. Hover a row for its scope. Geometry includes all authored LODs and counts each enabled mesh instance; UV remapping can add vertices. Final merging happens during export. When a current preview uses Merge Selected Meshes, the renderer count under After / Est. includes the planned export merge. Triangle, vertex and VRAM values still describe the unmerged preview; the export report records the measured result.

Memory counts unique referenced mesh and texture resources once across the selection, including inactive inputs, mipmaps and texture arrays. Mesh VRAM estimates vertex/index buffers from the stored vertex layout without copying vertex arrays. It excludes CPU-readable copies, blend-shape storage, additional skinning buffers and engine overhead. Source textures use imported formats; atlas output uses the existing platform-dependent compression estimate. Values use decimal KB/MB, describe resources rather than disk size or Editor process memory and do not predict frame time. The calculation is cached and refreshed for a rebuilt preview, replaced meshes/materials or changed output compression/mip settings.

After a successful export, expand Last export beside the export actions for measured renderer, material, slot and geometry counts. Preview build and export processing times are separate. Raw export compares all source mesh instances with the saved remapped meshes, including inactive inputs; it creates no renderers or materials. Last-export statistics remain a snapshot until the next successful export and are hidden if the source selection changes.

Atlas_Statistics.txt records geometry counts and processing times. For atlas exports, Atlas_Resolution.txt records estimated texture memory and actual imported atlas formats, mip levels and sizes on the current Editor platform. Its source-memory total covers mapped inputs; the comparison table includes all referenced material textures, so those source totals can differ.

Raw atlases and remapped meshes

Choose Mesh Output: Raw Atlases & Meshes, then Export Raw Atlases & Meshes. This saves Textures/, Meshes/, Atlas_Raw.txt, Atlas_Resolution.txt and Atlas_Statistics.txt. No materials, prefabs, mesh merging or scene replacement are created. The assignment report maps each source renderer and output submesh to its atlas canvas and compatible material group, with basic render-state settings. Create your own materials and assign the generated maps and meshes using that report. Supported tints and surface values are already baked, so use neutral material multipliers and unit tiling. For skinned meshes, retain the original skeleton, bone order and blend-shape weights. Raw export uses the existing supported channel layouts; it does not capture procedural shader effects or arbitrary extra maps.

Merge meshes without creating an atlas

Select Optimization Mode > Merge Meshes Only at the top of the settings panel. Add complete source objects, select the static meshes, shared-rig meshes and attachments to combine, then click Create Merge Preview. Check the renderer estimate and click Merge & Export.

This mode keeps the original project materials and shaders, including texture arrays, keywords and shader properties. It does not sample textures, bake an atlas, remap UVs or consolidate different materials. Vertex colours and all original UV channels remain available to shaders such as VCCore. Meshes without UV0 are supported. The preview compares the original appearance with the retained materials; mesh combination happens on export.

Export creates a prefab, mesh assets, Atlas_Merge.txt and Atlas_Statistics.txt. It creates no atlas textures or resolution report. Existing project materials are referenced directly. A material that exists only in memory is saved as a new material asset; its textures must already be saved. Different source materials remain separate material slots, so fewer renderers do not necessarily mean fewer draw calls. Source assets and import settings are preserved.

Baked lightmapped renderers stay separate in this mode so their UV1 coordinates are not rewritten. The existing merge restrictions still apply to transparent surfaces, independently animated parts and incompatible render settings. Custom shaders that depend on each original object's local position, pivot or scale need a visual check after merging. Switching back to Texture Atlas restores the atlas controls. Settings profiles save the selected mode.

Mesh merging and renderer selection

The mesh-merging section shows source mesh renderers and estimated output renderers before export, after an up-to-date atlas preview exists. The estimate refreshes when merge switches, renderer choices or attachment bones change. Expand Reasons for keeping parts separate to inspect exclusions, LODs, incompatible renderer settings, rigs, animation restrictions and transparency. Mixed opaque/transparent meshes can leave a transparent renderer alongside a merged renderer, so merging can increase the count. This is a renderer estimate; draw calls depend on rendering passes and batching. Export records the final result. Analysis reads source data without instantiating models or changing source objects.

  1. In 4. Mesh Merging, set Mesh Output to Merge Selected Meshes. Enable Merge Static Meshes or Merge Shared-Rig Meshes & Attachments directly below. Expand Renderer Selection & Attachments to choose individual parts and attachment bones. Set the destination in 5. Export models.
  2. Enable the renderer entries to include. Use Select All or Keep All Separate for a starting selection. Source numbers and hierarchy paths distinguish duplicate names. Excluded renderers still receive atlas materials.
  3. Export and read Atlas_Merge.txt. At least two compatible selected renderers are needed in a merge group. Different renderer settings can create several combined renderers.

Double-click the handle to reset it to 340 pixels. The height is saved with the editor window, and you can scroll within the list to reach additional renderers.

Good candidates include fixed furniture components, building structures, machinery housings and props that should always move and appear together. Compatibility includes layers, shadows, probes, sorting, motion vectors and other supported renderer settings. Compatible baked lightmap UV transforms are applied during static merging.

Keep doors, drawers, removable equipment and independently moving or hidden parts separate when their behaviour depends on individual renderers. The tool retains original transforms and colliders, but renderers fully incorporated into a combined mesh are disabled. Moving an old source transform does not move its geometry out of the combined static mesh.

Generate model LODs

Choose Models & Atlases > Optimization Mode > Generate LODs. Add a model asset, prefab or scene object. The highest detail renderers are the inputs. Existing lower levels are excluded from generation and original assets stay unchanged.

Choose LOD1 and LOD2 triangle targets and strength. Seam collapse distance (%) prioritises short connected edges such as small bevels and geometric seams while retaining separate UV samples. Small disconnected detail (%) sets the maximum relative size of tiny separate components that may be removed. Both distances use each mesh bounds diagonal. Detail removal scales with reduction and strength; the largest component is retained. Set either control to zero to disable it.

Use Inspect mesh to isolate a part and select LOD0, LOD1 or LOD2. The reference always shows the original LOD0. The preview panes share camera orbit, pan, zoom, framing and lighting. Wireframe and actual triangle counts help inspect the result. Generation runs in the background with Pause, Resume and Cancel controls. Duplicate ineffective output levels are omitted.

Imported shading normals and tangent handedness are retained to preserve smooth and weighted shading. Texture colour differences, UV orientation, texture stretch, geometry error and topology constrain collapses. Short seam edges may lose bevel faces while adjoining surfaces remain. Tiny component removal is a deliberate detail tradeoff; review the result before export. Source textures are unchanged.

Save LOD Meshes & Prefabs creates a unique folder with Meshes, Prefabs and LOD_Report.txt. LOD0 retains its original mesh and materials. Existing lower renderers in exported copies are disabled and their mesh/material references cleared before generated levels are assigned. Repeated meshes share output assets. Source assets and the open scene are preserved.

Supports static triangle meshes up to 200,000 vertices and 500,000 triangles, without skinning, blend shapes, additional vertex streams or material property overrides. UV0 is optional. Floating point output buffers and necessary UV splits can increase mesh memory even with fewer triangles. Custom shaders require visual review. Triangle targets are best effort and do not measure FPS. Settings are stored with the window separately from atlas profiles.

Merge meshes within existing LOD levels

In Merge Selected Meshes or Merge Meshes Only, compatible static meshes and shared-rig skinned meshes now combine within their existing LODGroup and matching level membership. For example, two compatible LOD0 parts can become one LOD0 renderer, while the LOD1 parts become a separate LOD1 renderer. Independent LODGroups stay independent. Selected loose props without authored LOD membership join a compatible group automatically on merge export.

The exporter updates the LOD renderer lists to the generated meshes. It preserves the number of levels, screen-relative transition heights, fade widths, fade mode, animated crossfading, group enabled state, local reference point and group size. It does not recalculate LOD bounds or create simplified geometry. Excluded parts, transparent remainders and incompatible parts remain assigned to their original levels. Compatible merged blend-shape renderers retain the same level membership.

A renderer reused by several levels can merge only with renderers having the same complete level membership. Renderers referenced by multiple LODGroups remain separate. Select the complete group root and all renderers it references. Cross-root references require Grouped Prefab or Merge Selected Meshes; each Separate Prefab must contain its own complete LOD setup.

The renderer estimate follows the same LOD restrictions as export. Counts include all scanned levels, not only the level visible at one moment. Atlas_Merge.txt reports the number of updated LODGroups; the Editor API exposes it as AtlasExportResult.mergedLODGroups. The model preview shows the highest populated level; inspect the exported prefab in a scene to review switching and crossfades.

Loose props and LODs: automatic assignment prefers a group in the same hierarchy, then the same source object, then the nearest compatible selected group. It estimates the prop's screen height from its size relative to the group and each transition threshold. The default cutoff is 3% of screen height when entering the next level. LOD0 always includes it: a small salt shaker may appear only in LOD0, while a chair remains through LOD0–2. Props retained in several levels share one renderer rather than duplicate geometry. They cull when that group culls.

Open Advanced LOD Controls to change the cutoff, disable automatic assignment or choose each loose prop's target group and Automatic / All Levels / LOD0 Only / Custom Last Level / Independent visibility. Existing authored membership is preserved. Excluded, independently scripted, animated or physics-controlled parts are not assigned automatically. Manual assignment can control an excluded or unmerged prop's LOD visibility. The report lists assignments; AtlasExportResult.assignedLooseLODRenderers gives their count. This loose-prop option changes visibility rather than polygon detail. Use Generate Model LODs in Models & Atlases, or a scene LOD suggestion, to create reduced geometry.

Editor API: AtlasSettings.automaticLODForLooseObjects defaults to true; lodMinimumScreenSize stores a fraction, default 0.03f (the UI displays percent). Each AtlasMergeSelection has lodMode (AtlasLooseLODMode), optional lodGroup and lodLastLevel. Manual visibility modes remain active when global automatic assignment is off. Scene replacement requires selecting a complete prefab instance root, rather than one of its original nested children.

Shared rigs and rigid attachments

Enable Merge Shared-Rig Meshes & Attachments in 4. Mesh Merging to combine compatible Skinned Mesh Renderers that reference the same actual skeleton. Bone names alone do not establish a shared rig. Two character instances with identically named bones still have separate skeletons and remain separate.

Combine meshes already skinned to the rig

  1. Include the complete character root and any separate skinned source objects that already reference its bones. All referenced bones and root bones must be inside the selected sources.
  2. Use Grouped Prefab to retain separate renderers with internal shared bone references, or Merge Selected Meshes to combine compatible selected parts. Separate Prefabs requires each source to contain its own complete rig.
  3. Export and check animation in a scene. Bone references, corrected bind poses and variable bone influences are retained for eligible merged skins. Normal bone animation is supported. Blend-shape curves can be remapped when merging; other animated renderer properties keep their renderers separate.

Attach an unskinned rigid part

  1. Include the rigid part and the complete character rig. Position the part where you want it before export. This workflow applies to tools, panels, mechanical parts, accessories and other rigid geometry as well as equipment.
  2. Tick the rigid renderer. Attachment Bone set to Automatic detects an existing rig bone parent. For a separate source, select a bone or socket from the included models using the popup. The picker also works with prefab and model assets.
  3. Export in merge mode with the rigged switch enabled. The part keeps its current placement and its vertices follow the chosen bone with full weight. This creates rigid following, not automatic deforming skin weights or an automatic snap to the hand.

No runtime attachment script is required. Merged attachments share the skinned output’s visibility. Keep a part separate if gameplay must hide, swap, detach or animate its offset independently. A shared character root Rigidbody can be compatible; independently moving physics parts remain separate. Moving skinned outputs do not merge lightmapped parts.

Merge meshes with blend shapes

Merge Blend Shape Meshes is enabled by default beneath shared-rig merging. Compatible skinned meshes retain every blend-shape frame, frame weight and current renderer weight. Unique names are retained; duplicate names receive independent source-name prefixes. Existing Animator clips that animate those shapes are copied into an Animations/ folder and assigned through an exported Animator Override Controller. Existing overrides are retained. Legacy Animation clips are also copied and remapped. Source clips and controllers are unchanged; no additional runtime component is required. Original shape curves remain available to transparent remainders.

Renderers directly referenced by serialized scripts inside the selected sources remain separate. Animated visibility, material changes and incompatible renderer settings also retain independent renderers. External scripts, index-based shape controls, dynamically loaded clips, Playables and animation systems not attached to the exported hierarchy require review; their arbitrary references cannot be rewritten automatically. Disable the option to retain the earlier separate-renderer behaviour. The merge report records merged shape and remapped clip counts. API: AtlasSettings.mergeBlendShapes, AtlasExportResult.mergedBlendShapes and remappedAnimationClips.

ConditionReason or result
Transparent surfacesKeep independent sorting. Mixed renderers can retain only their transparent portions.
Blend shape rendererCan merge with Merge Blend Shape Meshes enabled. Serialized script references and incompatible renderer animation can keep it separate. Blend-shape merging details.
Different LOD groups or level membershipMerge only within the same group and matching levels. Independent groups and mismatched level memberships stay separate. LOD merging details.
Inactive, disabled or forced off rendererRetains the original independent visibility state.
Mirrored or singular transformNeeds a separate mesh. Check negative or zero scale.
Different rig instancesActual skeleton references differ, even when bone names match.
Independent physics, movement or static objects controlled by scripts/animationPreserves independent behaviour.
Animated visibility, materials, renderer properties or attachment offsetsBindings need their original target renderers or transforms. Normal bone animation is supported.

Inclusion is a request to merge when compatible, not a command to discard incompatible behaviour. Read Atlas_Merge.txt for the retained path and reason. The atlas can still be successful when some or all meshes remain separate.

What is preserved and what changes

DataBehaviour
GeometryPositions, normals, tangents and vertex colours are retained. UV splitting can increase vertex count. The tool is not a polygon decimator.
UV channelsUV0 is remapped to the atlas. All eight UV channels are supported and the other channels retain their dimensions. Compatible static lightmap transforms can be applied during merging.
Skinning and blend shapesBone weights, bind poses and blend shape frames are retained during atlas remapping. Eligible shared rig merging retains bone references and weights and can preserve blend shapes with copied animation bindings.
Hierarchy, LODs and inactive stateOriginal hierarchies, bones, LODGroup references and inactive state are retained. Grouped and merged modes add a common prefab hierarchy.
Materials and texturesGenerated assets replace rendering references in the exported copies. Source assets and import settings remain intact.
Colliders and other componentsExisting components are retained. Collider geometry is not automatically simplified or reauthored. Some references can still point to original assets.

Example workflows

GoalSuggested setupReview before use
Several reusable propsAdd all props, create the atlas and export Separate Prefabs.Compatible materials and textures are shared; each prefab remains independent.
A single model with oversized texturesUse Auto Fit, lower the maximum atlas size and prioritise important materials.Compare small text, face detail and normal maps at the intended camera distance.
A table or fixed shop displayMerge compatible structural meshes, keep movable props and transparent glass separate.Check culling, interactions and colliders after export.
A modular character or machineInclude the full rig, use shared rig merging and assign rigid attachment bones where needed.Check animation, sockets and parts that need independent visibility.

Choose useful optimizations and verify them

Measure a representative scene before and after optimization. Compare material slots, renderer counts, draw calls, texture memory and frame time using Unity’s profiling tools. Sharing a material across separate models does not automatically make every object one draw call. Transparency, passes, lighting, batching and renderer settings still affect the result.

A large combined mesh can remain visible when only a small portion is on screen. Merge groups that are normally visible and move together. Large atlases can also keep unrelated textures loaded together. Match atlas size, channel count and grouping to your use case. A smaller exported atlas does not reduce the package size of original high resolution images that you still include.

  • Compare the exported prefab with the original under the same scene lighting and camera distance.
  • Test deformation, blend shapes, LOD switching, transparency, colliders and any scripts that address individual renderers.
  • Inspect the export reports and keep source assets until you have checked output dependencies and behaviour.

Supported inputs and practical limits

The texture-sampling restrictions below apply to Texture Atlas mode. Merge Meshes Only retains original shader and material inputs, including vertex colours and texture arrays; mesh and merge-compatibility restrictions still apply.

Baking and merging run in the Unity Editor. Runtime baking, runtime mesh merging and automatic merging before a game build are not included.

Input or featureRequirement or limit
MeshesMeshRenderer with MeshFilter, or SkinnedMeshRenderer. Triangle submeshes only. Textured meshes need UV0.
Material slotsEvery submesh must have a valid material and slot count must match submesh count. Fix missing shaders before scanning.
Textures and shader samplingTexture2D inputs and compatible UV0 sampling. Active URP Lit detail colour and detail normals are baked with their tiling, offsets, mask alpha and strengths. Texture arrays, procedural shading, vertex displacement, parallax and detail layers from other shader families are not automatically baked.
Specular workflowConvert to metallic workflow first. The tool rejects detected specular workflow materials.
MaterialPropertyBlockBake or remove overrides on a suitable source copy before atlasing. Detected overrides are rejected.
Additional vertex streamsApply the streams to a suitable source mesh first. They are not silently discarded.
ClothUse a copy without Cloth. UV splitting can change vertex indices, so Cloth coefficients require rebaking.
Custom shadersReview both input mappings and generated material states. Shader specific packed layouts and effects require their own conversion or verification.

Troubleshooting

SymptomWhat to check first
The window is unavailable or controls are disabledResolve Console compilation errors, wait for import/reload to finish and return to Edit Mode. Open the tool from the Tools menu.
No usable renderers are foundSelect roots containing supported mesh components. Particle, line and other renderer types are not atlas mesh inputs.
A region needs more pixels than the atlas allowsEnable Auto Fit. If already enabled, check extreme UV tiling, padding and the minimum number of regions. Raise the size or split the collection when needed.
The output is softer than expectedInspect the resolution reduction notice and per-material dimensions. Raise important material priorities, use a larger maximum size or export fewer models together.
Changing priority makes no differencePriorities apply only with Auto Fit and only when reduction is necessary. Source detail caps and packing shape can also limit differences.
A stylized material does not become a single pixelAnother mapped channel or a painted gradient can contain detail. Check the packing mode and source maps. Conservative retention protects uncertain regions.
Colours bleed or change at distanceCheck mip maps, padding, compression and filtering. For strict palettes, disable mip maps and consider point filtering. Compare the uncompressed export first.
Normals, metallic or emission look wrongInspect the individual channel preview, property identifiers, packed layout, base tiling and source workflow. Compare under the same lighting. Custom effects are not automatically baked.
More than one output material is generatedCheck Make Transparent Surfaces Opaque for transparent and cutout sources. If two opaque materials differ only in face culling, enable Advanced Atlas Controls > Unify Opaque Face Culling and rebuild the preview before exporting. Other render-state differences can still require separate materials. Sharing atlas textures does not guarantee a single output material.
Glass becomes solidDisable Make Transparent Surfaces Opaque and rebuild/export again if glass transparency or alpha-clipped cutout holes must remain visible. Also review custom output shader surface settings.
The tool says bones are outside the sourcesSelect the complete character root, including every referenced bone and root bone. For cross-source sharing, include the whole rig as a selected source.
Separate Prefabs rejects shared skinned partsUse Grouped Prefab or Merge Selected Meshes. Separate exports need a complete independent rig inside each source.
A selected mesh did not mergeRead Atlas_Merge.txt. Check both merge switches, selection, group size, rig identity and the exclusions described above.
An attachment is in the wrong place or follows the wrong boneCheck its placement before export and the selected attachment bone/socket. The tool keeps current placement; it does not automatically pose or snap the part.
The preview does not show the animation or merged resultSkinned previews capture the source pose and hierarchies when the model preview is first opened. Recreate the preview after changing the source pose or visibility. Check the generated prefab in a scene for animation and final merging.
The exported models seem to be missingRead the status folder, open its Prefabs subfolder and drag those assets into the scene. Scene instances are replaced only when Replace scene objects after export is enabled for supported scene inputs.
The export folder is rejectedChoose a path inside this project’s Assets directory. Paths outside Assets and traversal segments are not accepted.

Editor scripting reference

AtlasSettings.colourTolerance is an integer from 0 to 400, default 0. It compares the sum of 8-bit display RGB differences only for verified flat swatches; alpha and other mapped channels remain exact. It is included in settings snapshots and profiles.

DPT.TextureAtlasCreator.DPT_AtlasSettingsProfile: settings, materials, preserveAllDetails, outputFolder, outputName.

settings.atlasSizeMode = AtlasSizeMode.Fixed; settings.maxAtlasSize = 8192;

Advanced integrations use the public namespace DPT.TextureAtlasCreator in DPT.MaterialOptimizer.Editor. The assembly definition is Editor only, automatically referenced and depends on the included DPT.Core.Editor assembly. Put integrations in an Editor assembly and add a reference when your own assembly definition requires it. API identifiers retain their original names.

Entry point or dataPurpose
AtlasScan.CreateScans selected source roots, validates inputs and exposes renderer/material inputs.
AtlasSettingsAtlas size, padding, detailScale, autoFit, material mappings, transparency conversion and export/merge choices.
AtlasMaterialInput.priorityLow, Normal, High or VeryHigh. Default is Normal. Priorities operate with automatic fitting.
AtlasBuilder.BuildCreates an AtlasBuild with textures, remapped meshes, materials and renderer material groups. Dispose the build when finished.
AtlasExporter.ExportAllReturns AtlasExportResult with generated prefabs, folder paths, merge counts and notes. Export returns the first generated prefab.

Use the result’s meshesFolder, texturesFolder, materialsFolder and prefabsFolder rather than assuming all generated assets sit beside the prefab.

DPT_TextureAtlasCreatorWindow.OpenWithSources(IEnumerable<GameObject>) opens the window with supported roots loaded and scanned, without baking or exporting. Nested source duplicates are removed. It throws if no usable mesh sources are supplied.

AtlasBuild.sourceStatistics, previewStatistics and buildMilliseconds describe the preview. Each AtlasGeometryStatistics exposes renderers, uniqueMeshes, submeshes, materialSlots, materials, vertices and triangles. Statistics hold numbers, not owned Unity assets.

Terms used in this guide

TermMeaning
AtlasOne texture containing regions used by several source surfaces. Each mapped channel has its own corresponding atlas map.
UV0The primary texture coordinate channel. The optimizer remaps it to point at the new atlas regions.
Swatch / paddingA compact constant surface sample / the surrounding pixels that help separate regions when sampling.
Material group / material slotA compatible output rendering state / a renderer’s assignment of a material to a submesh.
Rig / bind poseThe actual bone hierarchy / the reference relationship between the mesh and its bones used for skinning.
Culling / draw callDeciding which geometry needs rendering / a rendering submission. One shared material does not guarantee one draw call.
