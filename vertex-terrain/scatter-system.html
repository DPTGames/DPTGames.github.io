The 3D Scatter system places instanced meshes and particle emission points directly from Terrain Atlas biome data. A scatter object contains one reusable set of placement rules, with mesh variants, particle layers and optional audio, or both. Instead of rebuilding the same grass setup for every biome, add several Target Biomes to that one object and optionally give each target its own density multiplier.

Scatter is intended for repeated surface detail such as grass, flowers, mushrooms, stones and small props. It does not edit the terrain mesh or turn every scattered mesh into a separate GameObject. Physics colliders are optional and can be limited by distance; the visible meshes remain GPU-instanced.

Understand the scatter library

Scatter authoring is global to the Terrain Atlas biome library rather than stored separately inside every biome inspector. Open the 3D Scatter section in the Vertex 3D Terrain window to create and edit the library.

Create your first scatter object

  1. Use the Terrain Atlas pipeline and make sure the terrain has painted biome data.
  2. Open 3D Scatter in the Vertex 3D Terrain window. If no profile exists, create the Scatter Library.
  3. Choose + Add Scatter Object and give it a clear name such as Meadow Grass.
  4. Under Target Biomes, choose one or more biomes from the current library.
  5. Start with Density Multiplier 1 on each target.
  6. Set the overall Density (clumps per square metre), Spacing, Coverage range, slope, scale and surface alignment.
  7. Keep Scatter Output on Meshes for this grass setup. Add a Mesh Variant, using the built-in Grass preset, an imported mesh or a prefab source. For particles, follow the particle setup below.
  8. Assign or confirm the material, enable GPU Instancing if prompted and use Rebuild Scatter after major changes if the preview has not already refreshed.

Example: create one Meadow Grass object, then target Lush Grass at ×1.0, Dry Meadow at ×0.65 and Forest Soil at ×0.25. The same grass mesh, colour ramp, roughness and wind setup is reused on all three surfaces.

Editing preview and terrain tool updates

Use Preview beside the 3D Scatter header to show scatter outside Play mode. It is off by default for new renderers and does not affect runtime rendering. When enabled, the joined Update After Stroke button appears and is on by default. It keeps the existing placements during a terrain tool operation, then updates affected sources when the operation finishes. Turning it off allows updates during the operation.

For Continuous particles, also enable the effect’s Preview Particles switch. In Scene view, turn on Effects and Particle Systems. The tool offers a fix when those view options hide enabled previews. Player Movement effects and audio are tested in Play mode. Animate Preview is a separate scatter setting for continuously refreshing wind and animated materials.

Target several biomes from one setup

A scatter object can target any number of Terrain Atlas biomes. The biome picker shows the current biome name and numeric ID. Use + Add Target Biome to extend the list.

ControlMeaningExample
BiomeThe Terrain Atlas biome on which this scatter object is allowed to appear.Grassland, Forest Soil or another current library entry.
Density Multiplier: 0–2Multiplies the scatter object’s base density only for this target biome.1 uses normal density, 0.5 gives half as much, 0 disables that target, 2 allows twice as much.

At a painted blend, the system evaluates the combined contribution of the scatter object’s targeted biomes. A reusable object can therefore continue across a Grass/Forest boundary instead of requiring separate duplicate definitions.

Accepted instances retain an owning biome based on the contributing target at their position. This is what allows a single reusable grass object to react differently when a live biome modifier affects only one of its target biomes.

Placement controls

Find Scatter Output: in the Vertex 3D Terrain window, expand 3D Scatter, then open a Scatter Object by clicking its name or arrow. Its Scatter Output dropdown is directly below Target Biomes and above Placement. Choose Meshes, Particles or Meshes + Particles there.

Under Placement, Biome Lock controls whether live biome changes affect this group, while Permanent preserves its saved layout between loads. Player Interaction enables the Bend Distance control for compatible meshes. See Biome Lock and Permanent for the distinction.

Biome Lock and Permanent: two different controls

Biome Lock keeps the scatter group independent of live biome changes and distant density thinning. It is for objects that should not disappear, thin or change colour when a live biome modifier adjusts the environment. This is the new name for the former Static Scatter setting.

Permanent saves the generated layout with the terrain scene so the same objects occupy the same positions after scene or game reloads. Changes made in the editor can update the saved layout. Use this for individual trees, rocks, landmarks or authored-looking distributions that should not reroll between loads.

The controls are independent: a Permanent group can still respond to live biome changes unless Biome Lock is also enabled. Similarly, Biome Lock does not on its own mean the exact placement layout is saved. Enable both when you want stable positions and independence from live biome changes.

Example: for a persistent forest, enable Permanent to retain the location of each tree. Enable Biome Lock as well only if the trees should ignore changes to the live biome density or colour. For seasonal grasses that can disappear during winter, leave Biome Lock off.

Place reeds only along a shoreline

  1. Create a Reeds scatter object and target Water only.
  2. Use a Coverage range such as 0.15–0.65 to allow reeds where Water blends into Mud, while excluding pure Water at 1.
  3. Adjust the painted transition width and range to position the band, then set Density and Spacing for the number and separation you want.

Coverage sums all targeted biomes. If you target both Water and Mud, their combined coverage can be 1 throughout that transition, so the same range will exclude it. Target only the biome whose partial coverage describes the edge you need. Coverage filters eligible surface; the per-biome Density Multiplier changes how many clumps appear there.

Built-in presets, custom meshes and prefabs

Mesh Source lets you use a built-in preset, a custom mesh or a prefab as the source for GPU-instanced scatter. Additional mesh variants are removed with the red Remove Mesh Variant button.

Each scatter object can contain several Mesh Variants. Relative Chance is a relative selection weight, not a percentage that must add to 100. Use different Shape Seed values for variations of a built-in mesh without changing the placement seed. Preset descriptions are available as tooltips.

Shading and surface properties

All built-in presets, including Crystals, have Smoothing Angle: 0–180°. At 0 the faces stay flat; at 180 all adjoining faces can blend their normals. Intermediate values smooth gentle joins while keeping sharper edges. This changes lighting, not the mesh silhouette or terrain’s global Smooth / Sharp setting.

The Vertex Colour Ramp is evaluated from bottom to top locally for each generated element. Smoothness runs from rough at 0 to polished at 1 and defaults to 0.2 for new variants. Metallic controls their metallic response from 0 to 1.

Generated meshes pack Metallic into UV3.R. UV3.G contains the DPT packed scale/roughness value derived from Smoothness, rather than raw smoothness. A custom shader must decode this DPT mesh data to use it correctly.

Emissive scatter

Enable Emissive on a built-in variant, then use HDR colours in its ramp for brightness and ramp alpha for glow coverage. DPT packs that coverage into vertex alpha in the same way as emissive biomes. HDR colour alone does not enable emission. The material’s emission controls still apply; visible bloom depends on the scene’s post-processing, and emission does not create a light source.

Custom meshes and prefab sources

Custom scatter variants accept an imported mesh or a prefab as their source. With an imported mesh, assign the 3D Mesh, optional submesh index, Material and optional Distant Mesh. With no Distant Mesh, the near mesh is reused.

When you assign a prefab, the scatter system extracts its meshes, materials and collider definitions for use with GPU-instanced rendering and optional physics. The prefab is a source of data: the system does not instantiate a complete copy of the prefab GameObject for every visible scatter instance. This allows trees and other multi-part imported assets to be used in the instanced scatter workflow without manually supplying an FBX mesh alone.

Custom meshes retain their authored normals, vertex colours and UV3 surface data; the built-in shading, metallic, smoothness and emissive controls do not rewrite them. Enabling supported DPT Scatter Wind prepares a runtime copy with wind/biome data and leaves the source asset unchanged.

Material choice matters. Scatter uses GPU instancing. Use materials compatible with the source mesh data and enable GPU Instancing when prompted. Leaving the variant material empty resolves the source terrain material where appropriate.

Optional scatter colliders

Scatter groups can now use optional colliders for physics interaction. Custom prefab sources can supply collider definitions automatically; configure whether collider support is used rather than assuming every visible instance needs physics. Collider distance settings let you limit how far from the relevant interaction area physics colliders are maintained, helping to control performance across large populations.

Use colliders for objects that need physical interaction, such as trees that block movement or large rocks. For small grass, flowers and visual ground cover, keep colliders disabled unless the project genuinely needs them. GPU instancing remains responsible for mesh rendering; collider support is a separate physics cost.

Example: use a tree prefab to supply mesh, material and collider information, enable colliders for nearby trees, then adjust the collider distance for the player’s expected interaction range. Keep distant trees rendered with instancing but avoid unnecessary distant physics.

Emit particles from scatter placements

Choose Particles or Meshes + Particles under Scatter Output, then expand Particle Effect 1. Built-in presets generate their particle systems, materials and mathematical shapes without imported sprites. Choose Custom for a ParticleSystem prefab. Footprints are configured on Player Surface Effects, not in the scatter preset list.

Triggers and emission points

Continuous emits from eligible placements near the viewing camera. Player Movement emits where a moving Player Surface Effects component with Enable Scatter Interaction passes near placements. It uses the interaction radius, height and strength and ignores teleports beyond Scatter Teleport Distance. Mesh bending is optional.

Meshes + Particles uses this Scatter Object’s mesh placements. Particles generates its own placement points without mesh variants. A separate Scatter Object has separate points; it does not automatically attach to another object’s grass. Emitter Fraction chooses a stable fraction of the object’s placements for each effect.

Start with a low emitter fraction and rate, tune Emission Offset/Rotation, then set the camera range and budgets. Continuous preview needs both the main Preview button and Preview Particles, plus Scene view Effects/Particle Systems. Preview is off by default and is not needed for Play-mode emission.

React to player movement

  1. Use Meshes + Particles on an existing grass object, or Particles for an effect without meshes.
  2. Choose Grass Flecks or Pollen and set Emission Trigger to Player Movement. Start with Emitter Fraction 0.2, Rate / Emitter 15 and Minimum Movement Speed 0.1, then lower budgets as needed.
  3. Add Player Surface Effects to the player and enable Enable Scatter Interaction. Position Interaction Origin/Offset near the roots and tune radius, height and strength.
  4. Move through the placements in Play mode. Standing still stops new emission. Enable Player Interaction and a positive Bend Distance separately if visible mesh bending is also wanted.

For effects beneath the player rather than at scatter roots, use biome surface effects. Particles, footprints and footstep audio can share one player entry with multiple biome targets.

Live response and particle lifetime

Live biome strength and Scatter Density multiply new particle emission. At zero, new emissions stop and living particles complete their lifetimes. Biome Lock keeps emission independent of those modifiers. Mesh Live Shrinking does not control particle transparency.

Each active layer uses a pooled generated effect or Custom prefab instance rather than one GameObject per placement. Simulation is in world space. Automatic prefab emission rates/bursts are disabled; the scatter emitter drives regular child systems per event and divides the layer budget across them.

Emission anchors follow placement transforms. Wind and shader bending do not move them to the deformed mesh tips. Changing presets/output or disabling the renderer releases unused effects. Procedural generation alone is not a frame-rate guarantee; large overlapping transparent particles can be costly.

Spatial audio from scatter placements

Expand Scatter Audio inside any Scatter Object. It can accompany Meshes, Particles or Meshes + Particles. Choose Audio Only for invisible sound placements driven by the same biome and placement rules. This does not require a mesh asset or particle prefab.

  1. Select Target Biomes and configure placement Density, coverage, slope and spacing.
  2. Enable Enable Audio and assign one or more Audio Clips. A non-null clip is selected randomly for each new voice.
  3. Choose Audio Trigger → Continuous for spatial loops, or Player Movement for one-shots when an enabled player interaction reaches the placements.
  4. Set volume, pitch, distances, Audio Emitter Fraction and source limits. For movement audio, tune Minimum Movement Speed and Sound Cooldown.
  5. Test in Play mode with an active Audio Listener. Audio has no edit-mode preview.

Audio sources are reused and bounded; distant or ineligible loops stop and can resume when eligible. Live biome density influences audio on groups without Biome Lock, while Biome Lock ignores live changes.

Use one Scatter Object when mesh, particle and audio effects should share placements. Their triggers and budgets remain independent. For actual footsteps, use Footstep Audio on the player; for marks beneath the player, use Footprints. There is no separate impact-speed/landing-audio setup.

A meadow: keep grass meshes, layer Grass Flecks and Pollen, and add Player Movement rustling clips under Scatter Audio. A water ambience: use Audio Only targeting the water biome, then choose Continuous with a low Audio Emitter Fraction and Source Limit.

Waterfall splash and mist

Use DPT_WaterfallSplashEmitter for a manually placed impact strip at the bottom of a waterfall. It emits a shared particle effect across the strip rather than requiring a scatter profile or a GameObject at every impact point.

The enabled component emits continuously during Play mode at Emission Rate while within camera range. It does not wait for water or a player to collide with it. Enable Preview Particles for editing; optional live biome and flow links can reduce or stop new emissions.

  1. Create a GameObject at the waterfall’s base and add DPT_WaterfallSplashEmitter through Add Component.
  2. Use the default procedural Waterfall Splash selection, choose another Particle Preset, or choose Custom to show Particle Prefab and assign your own effect.
  3. Adjust Splash Width and Splash Depth to cover the impact. The selected-object gizmo shows the strip.
  4. Leave Spray Direction at (0, 1, 0) for an upward spray, then tune Emission Rate and Particle Limit.
  5. Enable Preview Particles to see it while editing.
  6. Optionally link it to the water biome and flow speed as described below.

Place the impact effect yourself. The component does not detect waterfall bottoms or calculate impact forces. Waterfall Projection animates the water surface; this component supplies the visible splash and mist.

A linked splash also follows Scatter Density. If the water slot has Scatter Density at 0, it emits no new particles even with flow enabled. Use an unlinked emitter when you want its rate controlled independently.

For still water, choose Lake mode on the water material. A flow-linked waterfall splash stops emitting in Lake mode; an unlinked decorative effect can continue at its own configured rate.

Grass reacting to players

Enable Player Interaction on a compatible grass or plant scatter object and add DPT_PlayerSurfaceEffects to the player. Nearby mesh tips bend away while their roots stay anchored. This works independently of wind and does not require physics colliders for every grass clump.

The Player Collision & Interaction Guide covers setup, radius, height tolerance, bend limits, NPCs and physical collision. Use it when the player walks through grass and you want a visual response without individual grass colliders.

Per-group render distance and shadow overrides

Each scatter group can now override render distance and shadow settings independently of the shared Scatter Settings. Leave an override disabled to use the existing shared setting; enable it for groups that need different visibility or shadow behaviour.

Wind setup

DPT Scatter Wind uses material and Scatter Object controls, with optional camera-distance fading in Scatter Settings. The material decides whether the wind feature is active in the shader, while Enable Wind on the Scatter Object decides whether that particular scatter object uses the DPT Scatter Wind path. The Scatter Object control is only available when the assigned shader declares the _DPT_SCATTER_WIND Boolean Keyword, which lets Vertex 3D Terrain recognise that the shader supports this feature.

Using the Vertex Terrain material

  1. Open the material’s Wind section and turn on Enable Wind.
  2. Set a modest Wind Strength.
  3. Set Height To Tip close to the object-space height of the scatter mesh so the base stays anchored and the tip can reach full movement.
  4. Choose the Compass Heading and Vertical Pitch.
  5. Back in the 3D Scatter section, turn on Enable Wind for each Scatter Object that should use DPT Scatter Wind.
  6. If strongly animated tips disappear near the camera or frustum boundary, increase Wind Bounds in Scatter Settings.

Rigid scatter such as pebbles can share the same material while leaving the Scatter Object’s Enable Wind option off.

Fade and stop distant wind

  1. Open 3D Scatter → Scatter Settings → Distance & LOD.
  2. Set Wind Fade Start to the camera distance where movement should begin reducing.
  3. Set Wind Cutoff to a greater distance. Wind fades smoothly between these two values and stops at the cutoff.
  4. Set Wind Cutoff back to 0 to keep wind at every distance. Wind Fade Start has no effect while the cutoff is 0.

Example: Wind Fade Start 20 and Wind Cutoff 40 keep full wind within 20 metres, fade it between 20 and 40 metres, and stop it at 40 metres and beyond.

Distances are measured from the viewing camera to each scatter instance’s origin in world metres. Each clump fades as a whole. The setting applies to both near and far meshes and their matching shadows on supported DPT shaders, using either CPU or GPU scatter rendering.

This controls wind animation rather than the number of objects drawn. Continue using Draw Distance, Far Density and shadow settings to control rendering cost. Keep enough Wind Bounds for the strongest nearby movement.

Use the current supplied Vertex Terrain shader for distance fading. Custom shaders need compatible DPT wind-distance support; enabling a wind keyword alone does not add it. VCCORE and other authored wind systems keep their own material controls.

With motion blur or TAA, camera movement through the fade band can make reprojection less accurate because distance-fade changes are not included in previous-frame motion vectors.

VCCORE materials

VCCORE uses its own authored wind system, so the Scatter Object’s Enable Wind control is intentionally unavailable for VCCORE materials. This is expected. If wind was painted onto the model with Stylized Color Swapper & Material Optimizer, or the model came from a DPT pack with wind data already authored, no Scatter-specific wind setup is required. Use the VCCORE material’s own wind controls to enable or adjust that movement.

Add DPT Scatter Wind to your own Shader Graph

If your custom shader already has its own wind system, keep using that system. You only need the DPT setup below when you want a custom Shader Graph to use the same Scatter Wind feature as the Vertex Terrain shader.

Open SH_DPT_VCTerrain, copy the Scatter Wind block shown below and paste it into your own Shader Graph. Then add these Blackboard entries using the exact Reference names:

Live biome density and colour response

The same four Live Biome Modifier slots used by terrain surfaces can also control scatter belonging to their target biome IDs. This lets a seasonal system change the ground and the vegetation together.

Scatter Response controlMeaningNeutral value
Scatter Density: 0–1Multiplies how many already-generated instances are submitted for scatter owned by the targeted biome IDs.1. A value of 0 hides that biome’s scatter. Placement is retained during ordinary live changes; enable Live Shrinking to fade the changing population.
Colour MultiplierMultiplies the generated scatter colour for instances owned by the targeted biome IDs.White. HDR values can brighten as well as tint.

For example, a winter slot can increase snow dusting on a grass biome while reducing its Scatter Density and moving its Colour Multiplier toward a pale frosted colour. A reusable grass object can also target a forest biome; those forest-owned instances remain independent unless that biome ID is targeted by the live slot.

Seasonal example: leave summer Scatter Density at 1 and Colour Multiplier at white. At peak winter, try Density around 0.05–0.25 and a cool pale multiplier. The supplied Dynamic Biome Demo Controller contains an example winter animation that drives these values alongside dusting.

See Terrain Material Settings for the material controls and Demo & Runtime Guide for the example controller.

Shrink scatter during live changes

  1. Open 3D Scatter → Scatter Settings → Distance & LOD.
  2. Enable Live Shrinking and start with Fade Range at its default 0.15.
  3. Use the supplied DPT terrain material with scatter shrinking support and animate the live biome’s Strength or Scatter Density.
  4. Increase Fade Range for a softer shrink/regrow transition. Its value is part of the live density range, not seconds; duration and easing come from your controller.

Live Shrinking contracts mesh vertices toward the instance root as the live population decreases, then regrows them when density returns. It keeps placement positions and affects both the visible geometry and its matching shadow. This transition uses vertex shrinking rather than alpha-clipped crossfading.

The setting works with supported CPU and GPU scatter paths. Biome Lock ignores live biome changes. A custom material needs DPT scatter shrinking support; unsupported materials retain their existing visibility behaviour. Authored placement Density and rebuilding remain separate from live density animation.

Transition controls the stochastic near/far LOD band. Live Shrinking controls live biome population changes. Particle fading uses particle lifetimes, and mathematical footprints use their own Footprint Lifetime/Fade.

Seasonal snapshots and collapsible profiles

Use the Dynamic Biome Demo Controller to capture material appearances as Environment Profiles. Edit the material, then choose + Capture Current Settings as NEW Profile. Each profile is a saved snapshot; later material edits are saved only when you capture again.

Click a profile’s arrow or name to collapse or expand it. The header keeps its name and sequence position visible, with the first profile marked START. Newly captured profiles open automatically. Expand a profile to edit Name, Transition Seconds, easing and Channels to Animate, or to use its capture, apply, reorder and remove controls. Animate To Profile blends the checked channels from the current appearance and then holds the result.

Snapshot changeWhen it applies
Live modifier Target BiomesThe destination profile’s target list applies at the start of the transition, including added, replaced or removed IDs. Strength, density, colours and other numeric values continue to animate. Unchecked modifier slots retain their current settings.
Dusting Biome ID with no starting dustingThe destination dusting ID applies at the start when the starting Dusting Strength is 0, dusting is disabled or the modifier slot is inactive. Dusting Strength then animates using the destination ID.
Dusting Biome ID with visible starting dustingWhen the starting slot is active with dusting enabled and nonzero strength, its existing dusting ID stays until the transition ends.

These rules apply to sequence playback, Edit Mode Preview/scrubbing and Animate To Profile. Each Live Biome Modifier slot supports up to three target biome IDs; this is separate from a Scatter Object’s Target Biomes list, which can contain any number of biomes.

Spring → winter → spring → heatwave: capture spring with water Dusting Strength at 0, winter with Ice dusting, a return to spring with strength back at 0, then heatwave with Sand dusting. The heatwave transition selects Sand immediately, so sand grows as strength rises instead of ice growing first and switching at the end. If the dry-season snapshot also targets an additional biome, that biome joins the live modifier from the start of the transition.

When painting dusting in Scene view, the red dusting preview is drawn before the brush handle, so the selected brush handle colour remains visible over the highlight.

Runtime scatter and baked terrain data

Scatter placement is generated synchronously on the main thread, then cached for rendering. A readable terrain mesh supplies its placement geometry directly. A non-readable terrain mesh can use a matching DPT_TerrainSurfaceData asset with baked scatter geometry instead, so terrain Read/Write does not need to stay enabled for this runtime path.

  1. Assign the scatter profile before baking.
  2. While the terrain is available for editor authoring, use Bake Surface Data. With a scatter profile assigned, it includes placement vertices, normals, triangles and biome channels as well as gameplay surface information.
  3. Keep the baked asset assigned to DPT_TerrainSurfaceTarget on each source terrain and include it in your build.
  4. Rebake after terrain geometry, painting, biome IDs or topology change. A gameplay-only or stale bake is not sufficient for scatter placement.
  5. Test the built scene with terrain Read/Write disabled. If the renderer requests a scatter geometry bake, supply current data or keep that source mesh readable.

The baked placement arrays consume memory; disabling terrain Read/Write does not eliminate the scatter data itself. Generating or rebuilding a large population can still take main-thread time. This terrain-data option does not remove authored custom mesh requirements, including readable mesh channels when preparing a DPT wind copy.

Performance and practical limits

Audio uses reused, capped spatial sources rather than a voice for every placement. Tune Audio Emitter Fraction, Audio Distance, the group Source Limit and Shared Audio Source Limit. Player surface particles, footprints and footsteps share terrain detection and biome matching; footprints also use view/range culling, cached instanced data and GPU fading. Profile these effects with the actual game camera and resolution.

  • Scatter uses GPU-instanced draws rather than one GameObject per rendered instance, including when a prefab supplies the source meshes and materials.
  • Placement is generated from the terrain mesh and cached. Ordinary camera movement and live density changes do not rebuild the terrain scatter distribution.
  • Camera distance and frustum culling operate on scatter batches/cells. Cell Size therefore affects both grouping overhead and culling precision.
  • Far Density can reduce distant population for groups without Biome Lock in addition to using a cheaper distant mesh; per-group render distance overrides allow different visibility ranges for different scatter groups.
  • Per-group shadow overrides let you avoid paying for unnecessary shadows on dense decorative scatter.
  • Enable colliders only for groups that need physics, and tune collider distance independently of visual render distance.
  • Permanent retains the saved instance layout across loads; Biome Lock separately controls whether a group follows live biome changes.
  • Very high Density on a large terrain can reach the candidate or instance safety caps. Treat those limits as warnings to profile the setup, not targets to maximise.
  • Custom meshes should be suitable for instancing and should avoid unnecessary vertex/submesh/material complexity when they will appear thousands of times.

For particles, tune Emitter Fraction, Rate / Emitter, Particle Distance, Emitter Limit and Particle Limit separately from mesh LOD. Large transparent particles and overlapping mist can still be expensive even with a modest particle count. Particle simulation and vertex bending do not change the baked gameplay surface query.

Runtime Discovery is opt-in, so a stable terrain hierarchy does not need a full search every second during play. Built-in variant signatures are cached until the profile changes. Configured mesh caches retain meshes still used by active renderers and release obsolete entries after rebuilds; disabling the final renderer clears the shared scatter caches. Profile changes can still require regeneration.
