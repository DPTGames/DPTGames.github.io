작은 화면에서는 넓은 표를 좌우로 스크롤하여 모든 열을 확인할 수 있습니다.

Demo Component를 사용하면 Terrain을 검사하고 Live Material Effect를 시험하며 Physics Raycast가 어떤 Biome을 반환하는지 확인할 수 있습니다. 학습하고 수정할 수 있는 예제이며 완성된 Character Controller, Weather System 또는 Footstep Audio System을 제공하는 것은 아닙니다.

Demo를 시험하는 데는 코드를 작성할 필요가 없습니다. 이 페이지 뒤쪽의 Integration Example은 Surface 정보를 자신의 Gameplay에서 사용하려는 개발자를 위한 것입니다.

데모를 실행하고 구성 요소 확인하기

  1. Assets/DPTGames/Vertex_Terrain/VertexTerrain_Demo/VertexTerrain_DemoScene.unity를 엽니다.
  2. Terrain Renderer를 찾고 해당 Material과 Biome Library를 확인합니다. 그 Library에서 Surface ID를 확인합니다.
  3. Dynamic Biome Demo Controller를 찾습니다. Play Mode에 들어가기 전에 지정된 Material, Target ID 및 활성 Simulation을 확인합니다.
  4. Play Mode에 들어가 Demo Camera로 여러 Painted Surface를 살펴봅니다.
  5. 효과를 명확히 확인할 수 있도록 Material Simulation은 한 번에 하나씩 시험합니다.
  6. Surface Raycast Tester로 반환되는 ID와 Name을 확인합니다. Pure Patch와 Blend 경계 근처의 외형을 비교합니다.

Dynamic Biome Demo Controller

Object에 DPT → Dynamic Biome Demo Controller를 추가하고 Terrain Material을 지정합니다. 비워 두면 Component가 같은 Object의 Renderer에서 Shared Material을 찾을 수 있습니다. Renderer가 없는 Empty Object에는 명시적인 Material Reference가 필요합니다.

이 Controller는 지정된 Material을 직접 편집합니다. Private Material Instance를 자동으로 만들지는 않습니다. Terrain 하나만 독립적으로 변경하려면 별도 Material을 사용하십시오.

Pull과 Push Action은 Component의 Context Menu에서 사용할 수 있습니다. Runtime에서는 Simulation이 활성화되어 있는 동안 Demo가 계속 Push합니다. 모든 Simulation이 꺼져 있으면 자신의 Script에서 Field를 변경해도 매 Frame 자동 Push되지 않습니다. 변경 후 PushMaterialProperties()를 호출하십시오.

예측 가능한 편집 Workflow: Material Inspector에서 Setup을 완성하고 Component로 Pull한 다음, 이후에는 Material과 Component 중 어느 쪽이 편집을 구동할지 결정합니다. Simulation 또는 Edit-mode Sync가 한쪽을 덮어쓰는 동안 양쪽을 반복해서 편집하지 마십시오.

네 개의 Slot 설정하기

각 Slot은 최대 세 개의 Biome ID를 Target으로 할 수 있습니다. Slot 1은 두 개의 Demo Animation에서 사용하는 Slot일 뿐 항상 활성화되어야 하는 특별한 규칙은 없습니다. Component에 저장된 Example ID는 Demo 기본값이며 사용자의 Library에 같은 Surface가 존재한다는 보장은 없습니다.

Surface Raycast Tester

Raycast는 Unity에 “이 선을 따라 어떤 Collider가 있는가?”라고 묻습니다. Tester는 해당 Hit를 표시한 다음 Terrain의 Surface Target에 Biome을 요청합니다. 두 단계는 별개입니다. Collider에 Hit했다고 해서 Terrain Surface Data가 있다는 뜻은 아닙니다.

자신의 Terrain에 Probe 설정하기

  1. 작은 Painted Test Terrain을 완성하고 Mesh를 저장합니다.
  2. Bake하려는 Mesh와 Triangle Layout이 일치하는 MeshCollider를 지정합니다.
  3. Terrain Tool에서 Bake Surface Data를 사용합니다.
  4. 적절한 Terrain Object에 DPT → Terrain Surface Target이 있고 Bake된 Surface Data Asset이 지정되어 있는지 확인합니다. Renderer가 필요합니다.
  5. Terrain 위에 별도 Empty Object를 만들고 DPT → Surface Raycast Tester를 추가합니다.
  6. Downward Probe, 충분한 Max Ray Distance 및 Terrain Collider가 포함된 Layer Mask를 선택합니다.
  7. Scene Gizmos 또는 Game HUD를 활성화하고 Hit Object, Triangle Index, Biome ID 및 Name을 확인합니다. Probe를 서로 확실히 다른 두 Painted Area 사이로 이동합니다.

결과 읽기

Hit Object는 Ray를 가로챈 Collider입니다. Triangle Index는 Lookup에 사용된 Triangle을 식별합니다. Biome ID and Name은 Surface Query Result입니다. Hit Point, Normal and Distance는 물리적인 Intersection을 설명합니다.

Collider가 Hit했지만 Biome을 알 수 없다면 Surface Target과 Data를 확인합니다. Triangle 기반 Lookup에서 Box 또는 Sphere Collider는 일치하는 Terrain MeshCollider를 대체할 수 없습니다. Negative 또는 다른 유효하지 않은 Triangle Index를 정상적인 Terrain Query로 취급하지 마십시오.

검사용 Camera에 DPT → Terrain Demo Camera를 추가합니다. Free Movement와 Mouse Look을 제공합니다. Walking Physics, Collision Avoidance, Grounded Movement 또는 Planet Gravity는 제공하지 않습니다.

Gameplay에서 Surface Data 사용하기

의도된 흐름은 Terrain 페인트 → Surface Data Bake → Data를 Terrain에 연결 → 일치하는 Collider에 Raycast → Biome ID 읽기 → Gameplay Response 선택입니다.

Baked Asset은 Live Reweighting에 사용되는 Candidate ID와 Weight를 포함해 Triangle마다 대표적인 Biome 정보를 기록합니다. Surface Target은 해당 정보와 Terrain Material의 현재 Modifier를 읽습니다. Hit 하나에 대해 하나의 Biome ID를 반환하며 전체 Texture나 보이는 모든 Surface 목록을 반환하는 것은 아닙니다.

간단한 Integration Example

다음 코드를 TerrainSurfaceProbe.cs로 저장하고 Test Terrain 위의 Object에 추가합니다. Terrain Layer Mask와 Distance를 설정합니다. Component Context Menu의 Read Surface를 사용해 Query를 한 번 실행합니다. Console Message는 예시일 뿐입니다. Gameplay에 연결할 때는 자신의 Sound, Particle 또는 Movement Lookup으로 교체하십시오.

using UnityEngine;
using DPT.VertexTerrain;

public class TerrainSurfaceProbe : MonoBehaviour
{
    public LayerMask terrainLayers = ~0;
    public float distance = 2f;

    [ContextMenu("Read Surface")]
    public void ReadSurface()
    {
        if (!Physics.Raycast(transform.position, Vector3.down,
                out RaycastHit hit, distance, terrainLayers))
        {
            Debug.Log("No collider within the probe distance.");
            return;
        }

        if (hit.triangleIndex < 0)
        {
            Debug.Log("This collider has no usable terrain triangle index.");
            return;
        }

        if (DPT_TerrainSurfaceTarget.TryGetHitBiome(
                hit, out int biomeID, out string biomeName))
        {
            Debug.Log($"Surface: {biomeName} (ID {biomeID})");
            // Choose your project's response using biomeID.
        }
        else
        {
            Debug.Log("The hit has no linked terrain surface data.");
        }
    }
}

Footstep에서는 Footstep이 발생하는 시점에 적절한 Foot 또는 Character Position에서 Query를 호출합니다. 반환된 ID를 자신의 Audio/Effect Table에 연결합니다. Library 변경에 맞춰 해당 Table도 갱신하십시오. Biome Name은 Label로 유용하지만 Query가 반환하는 Numeric Value는 Library ID입니다.

Planet 또는 Custom Gravity System에서는 Example의 World-down Direction을 게임의 Local Gravity Direction으로 바꿉니다. 이 Script에서 Tool이 해당 방향을 자동으로 추론하지는 않습니다.

언제 다시 Bake해야 하나요?

  • Gameplay에서 Query할 영역을 다시 페인트한 뒤.
  • Biome 추가, 삭제 또는 재정렬로 Data에서 사용하는 ID가 변경된 뒤.
  • Subdivision, Deletion, Tunnel Creation, Simplification 또는 Triangle을 변경하는 다른 작업 뒤.
  • Bake 또는 대표 Surface 정보에 영향을 주는 다른 Geometry 변경 뒤.
  • Simplified LOD Collider를 포함해 다른 Collider Mesh로 전환할 때.

지원되는 일반 Live Material Multiplier는 Target이 Query 시점에 읽기 때문에 Terrain을 다시 페인트하거나 Triangle Data를 다시 만들지 않고 평가할 수 있습니다. 하지만 여전히 Bake된 Candidate를 사용하므로 오래된 Bake에서 새로 페인트된 정보를 복구할 수는 없습니다.

Query 결과는 화면과 얼마나 일치하나요?

제공되는 Query는 대표적인 Terrain Surface를 선택하는 데 유용하지만 Shader가 Render하는 결과를 Pixel-perfect하게 Sample하는 기능은 아닙니다. 모든 Edge 또는 Snow Patch가 Cursor 아래의 화면과 정확히 같은 결과를 반환한다고 가정하지 말고 자신의 Gameplay 요구사항에 맞춰 시험하십시오.

상황Query 동작Gameplay에 미치는 의미
하나의 Triangle에 여러 Biome대표 ID 하나를 반환합니다. Static Bake는 Coverage/Priority Rule을 사용하고 Live Reweighting은 저장된 Candidate Weight에서 선택합니다.아주 작은 Painted Patch 또는 Blend Edge에서는 모든 위치에서 다른 ID가 반환되지 않을 수 있습니다.
Height-blended Shader Detail모든 Per-pixel Height/Detail Blend를 재현하지 않습니다.보이는 Mixture가 국소적으로 Triangle의 대표 Surface와 다를 수 있습니다.
Live Weight 변경Material Slot Multiplier를 사용해 Bake된 Candidate Surface의 Weight를 다시 계산합니다.Bake에 없는 새로 Painted Candidate를 선택할 수 없습니다.
Dusting단순화된 World-up Slope/Strength Test를 사용합니다. Shader의 Painted Dusting Mask는 포함하지 않습니다.화면에는 Masked Overlay가 없는데 Query는 Overlay를 반환할 수 있습니다. Snow-specific Movement 또는 Footstep에 사용하기 전에 검증하십시오.
Tester의 Override Surface DataBaked Asset을 직접 읽습니다.Target의 Live Material Evaluation을 우회합니다. 일반 Live Path를 시험하려면 Override를 비우십시오.
다른 Collider TopologyHit Triangle Index는 보이는 Render Mesh가 아니라 Collider를 기준으로 합니다.Bake가 해당 Collider의 Triangle Order와 일치해야 합니다. Simplified LOD2 Collider에 관련 없는 Original-mesh Mapping을 안전하게 사용할 수 없습니다.

Gameplay에 정확한 Small Patch, Local-gravity-aware Snow 또는 Precise Per-pixel Coverage가 필요하다면 해당 규칙에 맞는 Query를 별도로 만들고 검증하십시오. 제공되는 Component는 위의 제한을 가진 출발점입니다.

Runtime 및 Demo 문제

증상확인할 항목
Demo Controller가 아무것도 하지 않습니다Terrain Material을 지정하고 Master Switch와 관련 Slot을 활성화하고 현재 Target ID를 사용한 뒤 설정을 Push합니다. 변경할 Source Contribution이 있는지도 확인하십시오.
Play Mode 진입 시 Component 설정이 바뀝니다Pull From Material On Play가 기존 Material Setup을 가져올 수 있습니다. Test 전에 어느 쪽이 Baseline을 제공할지 결정하십시오.
Material 편집이 즉시 되돌아갑니다Sync In Edit Mode와 활성 Runtime Simulation을 확인합니다. Setup 중에는 하나의 Driving Source만 사용하십시오.
Runtime Script가 Field를 바꾸지만 화면은 그대로입니다Simulation이 실행 중이 아니라면 Component 변경 후 PushMaterialProperties를 호출합니다. Material Reference도 확인하십시오.
Snowstorm Animation에 눈이 보이지 않습니다Slot 1 Active, 효과를 받을 Ground ID, Snow Overlay ID, Painted Dusting Mask 및 Slope Threshold를 확인합니다. Animation은 Dusting Strength를 순환시키면서 Slot 1 Scatter Response도 변경합니다.
Terrain은 눈으로 바뀌지만 Grass는 그대로입니다Grass Scatter Object가 Slot 1과 같은 Biome ID를 Target으로 하는지, Material에 Scatter-response Property가 있는지, Live-biome Master Switch가 활성화되어 있는지, Scatter Renderer가 해당 Material을 사용하는지 확인합니다. 3D Scatter 가이드를 참고하십시오.
River Level이 Water를 올리지 않습니다Slot 1의 Painted Weight Contribution을 변경합니다. Water Mesh를 이동하거나 실제 Level을 Simulation하지 않습니다.
Probe가 Hit을 보고하지만 Biome이 없습니다Collider Layer, Surface Target 및 지정된 Bake를 확인합니다. 일치하는 MeshCollider와 유효한 Triangle Index를 사용하십시오.
잘못된 Name 또는 ID가 반환됩니다부적절한 Override를 비우고 현재 Surface Data를 다시 Bake하고 Library ID를 다시 확인한 뒤 Collider Topology를 맞춥니다. Blend Boundary 전에 Pure Patch에서 비교하십시오.
Planet에서 Probe가 놓칩니다Downward Probe는 World-down입니다. Surface를 향한 Transform Forward 또는 게임의 Gravity를 기반으로 한 Ray를 사용하십시오.
여러 Terrain Object가 함께 바뀝니다Controller가 Shared Material을 편집하고 있을 수 있습니다. 별도 동작이 필요하면 독립 Material을 사용하십시오.
Demo Camera가 Bridge를 통과합니다Collision Controller가 없습니다. 자신의 Gameplay Character와 실제 Terrain Collider로 이동 가능 여부를 시험하십시오.
