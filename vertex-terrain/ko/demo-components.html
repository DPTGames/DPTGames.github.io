작은 화면에서는 넓은 표를 좌우로 스크롤하여 모든 열을 확인할 수 있습니다.

이 데모 컴포넌트로 Terrain을 확인하고, Environment Profile을 통해 Dynamic Biome과 Scatter 및 Lighting 변화를 시험하고, Physics Raycast가 반환하는 Biome을 검증할 수 있습니다. 학습 및 응용을 위한 예제이며 완성된 Character Controller, Weather System 또는 Footstep Audio System은 아닙니다.

데모를 시험하는 데 별도의 코드를 작성할 필요는 없습니다. 페이지 후반의 연동 예제는 Surface 정보를 자신의 Gameplay에 활용하려는 개발자를 위한 것입니다.

데모를 실행하고 구성 요소 확인하기

  1. Assets/DPTGames/Vertex_Terrain/VertexTerrain_Demo/VertexTerrain_DemoScene.unity를 엽니다.
  2. Terrain Material과 Ground Library를 확인합니다. 해당 Material을 Dynamic Biome Demo Controller의 Terrain Material에 지정합니다. 태양광도 전환하려면 Sun에 Directional Light를 지정합니다.
  3. Terrain Material Inspector에서 첫 번째 환경을 구성합니다. 데모 컨트롤러의 + Capture Current Settings as NEW Profile 버튼을 눌러 저장한 뒤 Spring 등으로 이름을 변경합니다.
  4. 실제 Material 설정을 수정하여 다음 환경을 구성합니다. 다시 캡처하여 Summer로 이름을 지정하고 같은 방법으로 Autumn, Winter 또는 다른 상태를 추가합니다.
  5. 저장된 상태를 다시 편집하려면 해당 프로파일의 Apply Profile To Material을 눌러 설정을 현재 Material에 불러옵니다. 수정한 결과를 프로파일에 저장하려면 Capture Profile From Material을 다시 누릅니다.
  6. 두 번째 프로파일부터 Transition Seconds를 지정하고 Run Sequence From Start로 전체 전환을 시험합니다. Edit Mode와 Play Mode에서 사용할 수 있습니다. Pause, Resume 및 Stop & Restore로 제어하며 Edit Mode에서는 타임라인을 직접 스크럽할 수도 있습니다.
  7. Play Mode 시작 시 자동 실행하려면 Play On Start를 활성화합니다. Demo Camera로 결과를 살펴보고 Surface Raycast Tester로 Painted Surface의 Biome ID를 확인합니다.

Dynamic Biome Demo Controller

컴포넌트 Inspector 맨 위의 Open Documentation 버튼이나 헤더의 Help 아이콘을 누르면 영어판 데모·런타임 가이드가 열립니다. 현재 페이지는 한국어판입니다.

GameObject에 DPT → Dynamic Biome Demo Controller를 추가합니다. Terrain Material을 지정하거나 같은 GameObject의 Renderer에서 Shared Material을 가져오도록 둘 수 있습니다. 방향광의 회전, 광도, 색상도 함께 변경하려면 Sun에 Light를 지정합니다.

환경의 원본 설정은 Terrain Material Inspector에서 직접 편집합니다. Dynamic Biome Slot, Target Biome ID, Dusting, Scatter Density / Colour, Surface Overrides 및 Flow 등을 Material에서 설정하십시오. 데모 컨트롤러는 이러한 Material 조절 항목을 중복 제공하지 않습니다. Capture 버튼을 누른 순간의 값만 프로파일에 저장됩니다.

동일한 Shared Material을 사용하는 Terrain Object는 함께 변경됩니다. 인접한 여러 Terrain Tile에 동일한 환경 변화를 적용할 때 유용합니다. 서로 다르게 제어하려면 별도 Material을 사용하십시오.

단일 스크립트 구성: Custom Inspector와 캡처 버튼은 DPT_DynamicBiomeDemoController.cs 내부의 Editor 전용 조건부 코드에 포함되어 있습니다. 별도의 Editor 스크립트는 필요하지 않습니다. 이전의 DPT_DynamicBiomeDemoControllerEditor.cs가 남아 있다면 Inspector 클래스 중복을 방지하기 위해 삭제하십시오.

프로파일에 저장되는 항목

각 프로파일에는 Modifier Slot 네 개의 활성 상태, 대상 Biome ID, Weight, Smoothness, Normal Strength, Parallax, Emission, Flow, Dusting 및 Scatter Response가 각각 독립적으로 저장됩니다. 지원되는 Stylized Lighting의 수치와 색상, 지정한 Sun의 회전, 광도, 색상도 함께 캡처됩니다.

프로파일은 Material의 현재 값에 연결되어 있지 않습니다. Winter를 만들려고 Material을 변경하더라도 이전에 캡처한 Autumn 스냅샷은 바뀌지 않습니다. 기존 프로파일을 갱신하려면 해당 프로파일의 캡처 버튼을 명시적으로 눌러야 합니다.

Apply Profile To Material은 저장된 설정을 현재 Shared Material과 선택적으로 Sun에 다시 적용합니다. 임시 타임라인 미리 보기가 아니라 실제 Material을 편집하는 동작입니다. 저장된 프로파일은 그대로 유지되므로 Material을 시각적으로 조정한 뒤 같은 프로파일에 다시 캡처할 수 있습니다. 적용 작업은 Unity Undo를 지원합니다.

Shader 설정의 자세한 내용은 Terrain Material 설정을, Scatter Response가 Instanced Vegetation에 적용되는 방식은 3D Scatter 가이드를 참고하십시오.

Environment Profiles 및 타임라인

Environment Profile은 봄·여름·가을·겨울뿐 아니라 가뭄, 홍수, 온도 변화 등 다양한 환경 상태의 연속 전환에 활용할 수 있습니다. 첫 번째 프로파일은 시작 화면의 상태입니다. 두 번째부터는 이전 상태에서 도달할 환경과 그 전환에 걸리는 시간을 지정합니다.

프로파일 시퀀스 캡처하기

  1. Spring: Material과 필요한 경우 Sun을 설정한 후 + Capture Current Settings as NEW Profile을 클릭합니다. 이름을 Spring으로 바꾸면 타임라인의 시작 상태가 됩니다.
  2. Summer: Material과 Light를 여름 모습으로 수정한 후 같은 버튼으로 캡처합니다. 이름을 Summer로 바꾸고 Transition Seconds에 봄에서 여름으로 바뀌는 시간을 설정합니다.
  3. Autumn: Dusting, Scatter 및 Lighting을 필요한 만큼 변경하고 세 번째 프로파일로 캡처합니다.
  4. Winter: 눈을 위한 Dusting, 감소한 식생 밀도, 차가운 Lighting 등을 설정한 후 네 번째 프로파일로 저장하고 전환 시간을 지정합니다.
  5. 새 프로파일을 캡처하면 이전에 도달한 상태와 비교하여 값이 달라진 Modifier Slot 또는 Lighting의 Channels to Animate이 자동으로 체크됩니다. 체크박스를 수동으로 조절할 수도 있으며, 체크하지 않은 채널은 이전 상태의 값을 유지합니다.
  6. Preview In Edit Mode와 Preview Normalized로 전환을 미리 본 뒤 Stop Preview & Restore Material을 클릭합니다. Loop가 활성화되어 있으면 마지막 상태에서 시작 상태로도 부드럽게 돌아갑니다.

기존 프로파일 수정: 편집할 프로파일에서 Apply Profile To Material을 눌러 저장 상태를 불러옵니다. Material 또는 Sun을 변경한 후 Capture Profile From Material을 누르고 확인 대화상자에서 승인하십시오. 선택한 프로파일만 덮어써집니다. 적용이나 캡처를 시작하기 전에는 재생과 미리 보기를 중지해야 합니다.

Lighting 및 전환의 제약 사항

  • Stylized Lighting은 선택 사항입니다. 미리 보기 또는 재생을 시작할 때 _STYLIZED_LIGHTING 키워드가 이미 활성화되어 있는 경우에만 수치와 색상을 전환합니다. 컨트롤러가 Shader Keyword를 켜거나 끄지는 않습니다. Sun 전환은 독립적으로 작동합니다.
  • 수치와 색상은 보간됩니다. Weight, Dusting Strength, Scatter Density / Colour, Flow Speed, Emission, 그림자 관련 값 및 Sun 회전 등을 설정한 시간에 따라 부드럽게 변경할 수 있습니다.
  • ID와 On/Off 설정은 연속적으로 보간되지 않습니다. Target Biome ID, Dusting Overlay Biome ID 및 Shader 기능 스위치 등은 단계적으로 바뀝니다. 자연스러운 전환을 위해 가능한 한 같은 대상 ID를 유지하고 Strength, Weight, Density를 변경하십시오.
  • Terrain Material에서 Dynamic Biomes가 활성화되어 있어야 합니다. 마스터 스위치가 꺼져 있으면 프로파일을 재생해도 Live Modifier의 효과가 나타나지 않습니다.
  • 미리 보기는 Shared Material을 임시로 변경합니다. 에셋을 저장하거나 Material을 다시 편집하기 전에 반드시 중지 및 복원하십시오. Editor의 예상치 못한 종료에 대비해 원본 Material을 저장해 두는 것이 좋습니다.

프로파일은 Terrain을 다시 페인트하거나 Scatter 배치를 재생성하지 않으며 Water Mesh의 높이를 물리적으로 변경하거나 실제 강수 시뮬레이션을 구현하지 않습니다. Live Weight는 이미 페인트된 Biome의 기여도에 적용되며, 눈 Dusting을 위해서는 적절한 Biome ID와 미리 페인트된 Dusting Mask가 필요합니다.

Surface Raycast Tester

Raycast는 Unity에 “이 선을 따라 어떤 Collider가 있는가?”라고 묻습니다. Tester는 해당 Hit를 표시한 다음 Terrain의 Surface Target에 Biome을 요청합니다. 두 단계는 별개입니다. Collider에 Hit했다고 해서 Terrain Surface Data가 있다는 뜻은 아닙니다.

자신의 Terrain에 Probe 설정하기

  1. 작은 Painted Test Terrain을 완성하고 Mesh를 저장합니다.
  2. Bake하려는 Mesh와 Triangle Layout이 일치하는 MeshCollider를 지정합니다.
  3. Terrain Tool에서 Bake Surface Data를 사용합니다.
  4. 적절한 Terrain Object에 DPT → Terrain Surface Target이 있고 Bake된 Surface Data Asset이 지정되어 있는지 확인합니다. Renderer가 필요합니다.
  5. Terrain 위에 별도 Empty Object를 만들고 DPT → Surface Raycast Tester를 추가합니다.
  6. Downward Probe, 충분한 Max Ray Distance 및 Terrain Collider가 포함된 Layer Mask를 선택합니다.
  7. Scene Gizmos 또는 Game HUD를 활성화하고 Hit Object, Triangle Index, Biome ID 및 Name을 확인합니다. Probe를 서로 확실히 다른 두 Painted Area 사이로 이동합니다.

결과 읽기

Hit Object는 Ray를 가로챈 Collider입니다. Triangle Index는 Lookup에 사용된 Triangle을 식별합니다. Biome ID and Name은 Surface Query Result입니다. Hit Point, Normal and Distance는 물리적인 Intersection을 설명합니다.

Collider가 Hit했지만 Biome을 알 수 없다면 Surface Target과 Data를 확인합니다. Triangle 기반 Lookup에서 Box 또는 Sphere Collider는 일치하는 Terrain MeshCollider를 대체할 수 없습니다. Negative 또는 다른 유효하지 않은 Triangle Index를 정상적인 Terrain Query로 취급하지 마십시오.

Gameplay에서 Surface Data 사용하기

의도된 흐름은 Terrain 페인트 → Surface Data Bake → Data를 Terrain에 연결 → 일치하는 Collider에 Raycast → Biome ID 읽기 → Gameplay Response 선택입니다.

Baked Asset은 Live Reweighting에 사용되는 Candidate ID와 Weight를 포함해 Triangle마다 대표적인 Biome 정보를 기록합니다. Surface Target은 해당 정보와 Terrain Material의 현재 Modifier를 읽습니다. Hit 하나에 대해 하나의 Biome ID를 반환하며 전체 Texture나 보이는 모든 Surface 목록을 반환하는 것은 아닙니다.

간단한 Integration Example

다음 코드를 TerrainSurfaceProbe.cs로 저장하고 Test Terrain 위의 Object에 추가합니다. Terrain Layer Mask와 Distance를 설정합니다. Component Context Menu의 Read Surface를 사용해 Query를 한 번 실행합니다. Console Message는 예시일 뿐입니다. Gameplay에 연결할 때는 자신의 Sound, Particle 또는 Movement Lookup으로 교체하십시오.

using UnityEngine;
using DPT.VertexTerrain;

public class TerrainSurfaceProbe : MonoBehaviour
{
    public LayerMask terrainLayers = ~0;
    public float distance = 2f;

    [ContextMenu("Read Surface")]
    public void ReadSurface()
    {
        if (!Physics.Raycast(transform.position, Vector3.down,
                out RaycastHit hit, distance, terrainLayers))
        {
            Debug.Log("No collider within the probe distance.");
            return;
        }

        if (hit.triangleIndex < 0)
        {
            Debug.Log("This collider has no usable terrain triangle index.");
            return;
        }

        if (DPT_TerrainSurfaceTarget.TryGetHitBiome(
                hit, out int biomeID, out string biomeName))
        {
            Debug.Log($"Surface: {biomeName} (ID {biomeID})");
            // Choose your project's response using biomeID.
        }
        else
        {
            Debug.Log("The hit has no linked terrain surface data.");
        }
    }
}

Footstep에서는 Footstep이 발생하는 시점에 적절한 Foot 또는 Character Position에서 Query를 호출합니다. 반환된 ID를 자신의 Audio/Effect Table에 연결합니다. Library 변경에 맞춰 해당 Table도 갱신하십시오. Biome Name은 Label로 유용하지만 Query가 반환하는 Numeric Value는 Library ID입니다.

Planet 또는 Custom Gravity System에서는 Example의 World-down Direction을 게임의 Local Gravity Direction으로 바꿉니다. 이 Script에서 Tool이 해당 방향을 자동으로 추론하지는 않습니다.

언제 다시 Bake해야 하나요?

  • Gameplay에서 Query할 영역을 다시 페인트한 뒤.
  • Biome 추가, 삭제 또는 재정렬로 Data에서 사용하는 ID가 변경된 뒤.
  • Subdivision, Deletion, Tunnel Creation, Simplification 또는 Triangle을 변경하는 다른 작업 뒤.
  • Bake 또는 대표 Surface 정보에 영향을 주는 다른 Geometry 변경 뒤.
  • Simplified LOD Collider를 포함해 다른 Collider Mesh로 전환할 때.

지원되는 일반 Live Material Multiplier는 Target이 Query 시점에 읽기 때문에 Terrain을 다시 페인트하거나 Triangle Data를 다시 만들지 않고 평가할 수 있습니다. 하지만 여전히 Bake된 Candidate를 사용하므로 오래된 Bake에서 새로 페인트된 정보를 복구할 수는 없습니다.

Query 결과는 화면과 얼마나 일치하나요?

제공되는 Query는 대표적인 Terrain Surface를 선택하는 데 유용하지만 Shader가 Render하는 결과를 Pixel-perfect하게 Sample하는 기능은 아닙니다. 모든 Edge 또는 Snow Patch가 Cursor 아래의 화면과 정확히 같은 결과를 반환한다고 가정하지 말고 자신의 Gameplay 요구사항에 맞춰 시험하십시오.

상황Query 동작Gameplay에 미치는 의미
하나의 Triangle에 여러 Biome대표 ID 하나를 반환합니다. Static Bake는 Coverage/Priority Rule을 사용하고 Live Reweighting은 저장된 Candidate Weight에서 선택합니다.아주 작은 Painted Patch 또는 Blend Edge에서는 모든 위치에서 다른 ID가 반환되지 않을 수 있습니다.
Height-blended Shader Detail모든 Per-pixel Height/Detail Blend를 재현하지 않습니다.보이는 Mixture가 국소적으로 Triangle의 대표 Surface와 다를 수 있습니다.
Live Weight 변경Material Slot Multiplier를 사용해 Bake된 Candidate Surface의 Weight를 다시 계산합니다.Bake에 없는 새로 Painted Candidate를 선택할 수 없습니다.
Dusting단순화된 World-up Slope/Strength Test를 사용합니다. Shader의 Painted Dusting Mask는 포함하지 않습니다.화면에는 Masked Overlay가 없는데 Query는 Overlay를 반환할 수 있습니다. Snow-specific Movement 또는 Footstep에 사용하기 전에 검증하십시오.
Tester의 Override Surface DataBaked Asset을 직접 읽습니다.Target의 Live Material Evaluation을 우회합니다. 일반 Live Path를 시험하려면 Override를 비우십시오.
다른 Collider TopologyHit Triangle Index는 보이는 Render Mesh가 아니라 Collider를 기준으로 합니다.Bake가 해당 Collider의 Triangle Order와 일치해야 합니다. Simplified LOD2 Collider에 관련 없는 Original-mesh Mapping을 안전하게 사용할 수 없습니다.

Gameplay에 정확한 Small Patch, Local-gravity-aware Snow 또는 Precise Per-pixel Coverage가 필요하다면 해당 규칙에 맞는 Query를 별도로 만들고 검증하십시오. 제공되는 Component는 위의 제한을 가진 출발점입니다.
