プレイヤーにPlayer Surface Effects（DPT_PlayerSurfaceEffects）を追加します。このコンポーネントの散布オブジェクトの反応を有効化スイッチは、近くのスキャッターの曲げ表現と、移動に反応するスキャッターパーティクル／オーディオを制御します。サーフェスエフェクトを有効化は、プレイヤーの足元の地形から発生するパーティクル、足音、足跡を制御します。どちらの機能も単独で使用できます。

植生と環境エフェクトの作成については3D スキャッターガイドを参照してください。このページでは、プレイヤー側の設定、接地判定、バイオームルール、足音のタイミングについて説明します。

用途に合ったエフェクトを選ぶ

実現したいこと必要な設定サーフェスデータのベイクは必要？
近くの草を曲げるプレイヤーでプレイヤーサーフェスエフェクト → 「散布オブジェクトの反応を有効化」を有効にし、スキャッターメッシュグループでもプレイヤーの影響を有効にします。スキャッターがすでに描画されていれば、ゲームプレイ用の追加サーフェスベイクは不要です。
植物の配置位置で葉片、花粉、葉擦れ音を発生させるスキャッターパーティクルエフェクトまたは散布オーディオ → プレイヤーの移動を選び、プレイヤーの「散布オブジェクトの反応を有効化」を有効にします。メッシュの曲げ表現は任意です。ゲームプレイ用の追加サーフェスベイクは不要です。
プレイヤーの足元で砂ぼこり、水しぶき、雪を発生させるプレイヤーサーフェスエフェクト → 「サーフェスエフェクトを有効化」を有効にし、パーティクルプリセットを持つバイオームエントリを設定します。必要です。ベイク済みサーフェスデータと、それに対応する地形の MeshCollider が必要です。
複数のバイオームで足音と足跡を切り替える1つのサーフェスエフェクトエントリに複数のバイオームを設定し、足音オーディオ、足跡、任意のパーティクルを組み合わせます。必要です。ベイク済みサーフェスデータと、それに対応する地形の MeshCollider が必要です。
木、岩、小道具でプレイヤーの移動を妨げるメッシュのスキャッターグループでスキャッターコライダーを有効にし、各バリアントのコライダー形状と、レンダラーのコライダー対象および有効範囲を設定します。プレイヤー用サーフェスエフェクトの追加ベイクは不要です。スキャッターの配置データを使用します。詳細はスキャッターコライダーの設定を参照してください。
地形上の配置位置で環境音を再生する散布オーディオ → 継続を選び、オーディオクリップを割り当てます。スキャッターの配置データを使用します。スキャッターガイドを参照してください。

内蔵パーティクルと足跡の輪郭はプロシージャル生成されます。内蔵の足跡形状にはデカール、インポートしたテクスチャ、専用メッシュアセットは必要ありません。カスタムの足跡では独自のマスク画像を使用します。オーディオには実際のオーディオクリップが必要です。また、カスタムパーティクルには独自の ParticleSystem プレハブが必要です。

見た目のインタラクションと物理衝突は別々に設定してください。草の曲げ表現と足跡は視覚エフェクトです。衝突判定が必要なメッシュの障害物ではスキャッターコライダーを有効にし、キャラクターの移動には独自のプレイヤーコントローラーを使用してください。草の曲げ表現も足跡も、地形の衝突面を変形させません。

プレイヤーの動きに草を反応させる

  1. Vertex 3D Terrain ウィンドウで3D スキャッターを開きます。草のスキャッターオブジェクトを展開し、ターゲットバイオームの下にあるスキャター出力でメッシュまたはメッシュ＋パーティクルを選択します。
  2. 配置でプレイヤーの影響を有効にし、曲げ距離を0より大きく設定します。一般的な草では、まず約0.35メートルから試してください。
  3. 対応するマテリアルを使用します。まずは付属のSH_DPT_VCTerrainシェーダーを試してください。
  4. プレイヤーにPlayer Surface Effectsを追加し、散布オブジェクトの反応を有効化を有効にします。
  5. 足の高さに置いたマーカーを反応位置の基準に割り当てるか、反応位置のオフセットを使って影響の中心を草の根元付近に移動させます。
  6. 最初は反応半径を1、反応する高さの範囲を0.75、反応の強さを1に設定します。Play モードで草の中を移動して確認してください。
  7. 移動時のパーティクルや葉擦れ音には、スキャッターエフェクト／オーディオのプレイヤーの移動を使用します。このトリガーにプレイヤーの影響や0より大きい曲げ距離は不要です。これらのメッシュ設定は、目に見える曲げ表現のためのものです。

3D スキャッターの見出し横にあるプレビューボタンを有効にすると、編集中もスキャッターの曲げ表現を確認できます。プレイヤーのサーフェスパーティクル、足音、足跡、スキャッターオーディオはPlay modeで再生されます。

スキャッターとのインタラクションだけが必要な場合は、サーフェスエフェクトを有効化をオフにして構いません。ただし、コンポーネント自体は有効にしておいてください。

歩行キャラクターの例：足元のマーカーを反応位置の基準に設定し、反応半径を0.8、反応する高さの範囲を0.5、反応の強さを1にします。草の曲げ距離は0.35にします。風による環境アニメーションは独立して制御できます。

植物に触れたときのパーティクルと音

草のスキャッターオブジェクトを開いてメッシュ＋パーティクルを選択し、パーティクルエフェクト 1を展開します。草の切れ端または花粉を選び、放出のトリガー → プレイヤーの移動に設定します。プレイヤーには「散布オブジェクトの反応を有効化」を有効にしたプレイヤーサーフェスエフェクトが必要です。草の可視曲げ表現は任意です。

同じ配置位置に複数のエフェクトを重ねるには、＋ パーティクルエフェクトを追加を使用します。例えば花粉と葉片を組み合わせられます。各エフェクトにはそれぞれプリセット、トリガー、色、ノイズ品質、風への反応、エミッター割合、発生率、オフセット、上限があります。親の共有パーティクル上限は、生存中のパーティクルの合計数を制限します。エフェクトを削除ボタンは赤色です。

葉擦れ音には、散布オーディオを展開してオーディオを有効にし、クリップを割り当ててプレイヤーの移動を選択します。最小移動速度と音声クールダウンを調整してください。環境ループ音には継続が利用できます。足音は代わりにプレイヤーのバイオームエントリで設定します。

パーティクルの色を設定するにはパーティクルの色を使用し、プリセットの色の維持、単色の指定、2色の間でランダムから選択します。色のアルファ値は元の不透明度に乗算され、寿命に伴うフェードも適用されます。変更は新しく発生するパーティクルに反映されます。

プレイヤーの移動は根元への近接と、移動経路を掃引したインタラクション領域を使用します。風だけでは発動しません。花粉や葉片を風で漂わせるには、スキャッターパーティクルエフェクト内の風に追従を有効にして風の影響を設定します。有効な DPT マテリアルの風に従って移動し、パーティクルを発生位置へ引き戻すことはありません。これはグループのメッシュ用風を有効化とも、足元のサーフェスパーティクルとも独立しています。編集時のパーティクルプレビューは継続放出のみ対応しています。メインの 3D スキャッタープレビューとエフェクトの「パーティクルをプレビュー」を有効にし、Scene ビューの Effects/Particle Systems も有効にしてください。

バイオーム別サーフェスエフェクトの設定

1つのサーフェスエフェクトエントリで複数のバイオームに対応し、パーティクル、足跡、オーディオを組み合わせられます。これらのエフェクトはスキャッターの配置とは独立しており、プレイヤーの足元でサンプリングした地形に従います。

  1. 編集が終わったらサーフェスデータをベイクを使用します。ベイク済みデータをDPT_TerrainSurfaceTargetに割り当て、地形のMeshColliderがベイク時の三角形構成と一致していることを確認してください。ジオメトリ、トポロジー、ペイントしたバイオームを変更した場合は再ベイクします。
  2. プレイヤーサーフェスエフェクトでサーフェスエフェクトを有効化を有効にします。足元の基準位置に足裏付近のマーカーを指定するか、足のオフセットを使用します。足元の基準位置を割り当てた場合、オフセットはそのポイントを基準にします。
  3. 設定項目のサーフェス検出を展開します。サーフェスレイヤーに地形を含め、プレイヤーは除外してください。最初は検出開始の高さを0.2、地面への到達距離を0.4メートルにします。足音と足跡には、既定で0.06メートルの足の接地距離以内の接地も必要です。
  4. まずシーンの地形データを読み込むをクリックすると、読み込まれたシーンのサーフェスターゲットから固有のベイク済みデータが追加されます。サーフェスデータソースは名前付きバイオームの候補と、メッシュに対応するフォールバックを提供します。ヒットした地形タイル自身のサーフェスターゲットが優先されます。
  5. 続いてサーフェスエフェクトを追加をクリックし、エントリ名を付けてバイオームを選択します。さらにバイオームを追加するにはバイオームを追加を使い、サーフェスデータソースに現在存在する名前付きバイオームすべてを追加するにはすべて追加を使います。すべて追加は未割り当てや重複した選択肢を除外します。これは保存される選択リストであり、将来追加されるバイオームを自動的に含むワイルドカードではありません。
  6. パーティクルプリセットを選択します。足跡とオーディオのみを使用する場合はなしを選びます。必要に応じて足跡や足音オーディオを有効にしてください。
  7. 最小移動速度と関連するエフェクト設定を調整し、Play モードで歩いて動作を確認します。エフェクトの上限と品質を展開すると、各種上限と表示レイヤーを調整できます。
設定項目内容／既定値
足元の基準位置 / 足のオフセット足裏付近のサンプリング位置です。オフセットは指定したポイントのローカル軸を使用し、未指定ならプレイヤーの Transform を基準にします。
サーフェスレイヤー地形判定に使用する物理レイヤーです。プレイヤーの子オブジェクトと Trigger コライダーは無視されます。手前にある通常のコライダーは、その背後の地形判定を遮ります。
検出開始の高さ／地面への到達距離レイは足元ポイントからプレイヤーのローカル上方向へ0.2メートル持ち上げた位置から始まり、下方向へ0.4メートル届きます。
足の接地距離足音と足跡に許される足と地面の最大間隔は0.06メートルです。パーティクルのサーフェスオフセットを増やしても、この距離より高い足元の位置は補正されません。
移動テレポート距離足元の位置が5メートルを超えて移動した場合は移動の軌跡を生成しません。散布反応のテレポート距離とは別の設定です。
バイオーム／すべて追加1つのエントリで複数のバイオーム ID を使用できます。未設定 は「すべてのバイオーム」を意味しません。すべて追加の前にデータを読み込んでください。
パーティクルプリセット内蔵プリセット、ParticleSystem プレハブを使用するカスタム、またはなしを選べます。最初に追加されるエントリの既定値は草の切れ端です。
最小移動速度エントリごとの移動速度のしきい値です。既定値は0.1メートル／秒で、移動パーティクルと自動の足跡／足音に適用されます。
メートルごとの放出数移動1メートルあたりのパーティクル発生イベント数です。既定値は8です。足音のタイミングをアニメーションイベントにしても、パーティクルの発生は移動距離ベースのままです。
サーフェスオフセット / スケールヒット面の法線に沿うパーティクル発生位置のオフセットとスケールです。既定値は0.03メートル／1です。足跡には独自のオフセットとサイズがあります。
パーティクルの色プリセットの色、単色、2色の間でランダムから選択します。エントリにパーティクル出力がある場合に使用できます。

最初に一致した有効なエントリは、パーティクル、足跡、オーディオそれぞれで独立して選択されます。足跡のみのエントリがあっても、後続の一致エントリにあるパーティクルやオーディオは妨げられません。同じバイオームを対象とする関連エフェクトは1つのエントリにまとめ、対象が重複するエントリは順序を意識して配置してください。

2つ目以降の新規エントリには、直前のエントリから足跡の形状、サイズ、色、寿命／フェード、移動速度、オーディオなどの設定がコピーされます。バイオームリストは未割り当てにリセットされます。コピー後の設定は独立しているため、新しいエントリを変更しても元のエントリは変わりません。削除するには赤いサーフェスエフェクトを削除ボタンを使用します。

ランタイムのバイオーム判定では、ヒットしたタイルの現在のライブバイオームと、十分に強いダスティングが考慮されます。雪や氷によって反応を変えたい場合は、そのダスティングのバイオームも対象に追加してください。放出が止まっても既存のパーティクルは寿命まで残り、足跡はそれぞれの寿命に従います。このコンポーネントは水深、浮力、衝突力を計算しません。

足跡、走行跡、カスタムマスク

  1. サーフェスエフェクトエントリで対象バイオームを選択し、パーティクルが不要ならパーティクルプリセット → なしを選びます。
  2. 独立した足跡スイッチを有効にして、足跡の形状を選びます。
  3. 下記の内蔵形状を選ぶか、カスタムを選択して独自の足跡マスクを割り当てます。
  4. 足跡サイズ、色、寿命、フェード、オフセットを設定します。足元の基準位置を地面付近に置き、対応するサーフェスデータがベイク済みであることを確認して、Play モードでテストしてください。
足跡の形状見た目／用途
靴丸いつま先と踵、つながった靴底、浅い土踏まずを持つ形状です。左右の足跡は交互に鏡像反転されます。
裸足丸い踵と足裏、内側の土踏まず、5つの足指の形状です。親指は内側に配置されます。
タイヤ跡選択した足音タイミングと間隔に従って、プロシージャルなタイヤのトレッド部分を押印します。連続した跡になるよう長さと 一歩の距離 を調整してください。車輪の接地をシミュレーションする機能ではありません。
肉球の足跡幅の広い肉球、4つの指球、小さな爪痕がある形状です。動物に合った幅と長さを設定してください。
カスタム靴底、タイヤの溝、動物の足跡、その他の地面の跡に、独自のマスクテクスチャを使用します。
ひづめの跡中央が開いた丸いひづめの縁と、踵側の端を表現します。四足歩行には明示的な接地イベントを使用してください。
足跡の設定内容／既定値
足跡サイズメートル単位の幅と長さです。通常の新規既定値は0.12 × 0.32です。その既定値から肉球の足跡を選ぶと0.24 × 0.26、ひづめの跡では0.13 × 0.15になります。以前に設定したサイズは維持されます。
足跡の色エントリごとの色と不透明度です。既定値はアルファ0.6の暗い茶色です。
足跡の持続時間 / 足跡のフェード合計寿命は20秒で、最後の5秒間にフェードします。フェード時間は寿命に含まれ、寿命終了後に追加されるものではありません。
足跡オフセットちらつきを減らすため、ヒット面の法線方向にわずかな間隔を設けます。既定値は0.003メートルです。大きすぎると浮いて見えることがあります。
足跡数の上限 / 足跡表示距離エフェクトの上限と品質にあります。既定値は128個、60メートルです。上限に達すると古い跡から削除されます。画面外や範囲外の跡は非表示になりますが、寿命のカウントは続きます。
表示レイヤープレイヤーの衝突レイヤーとは独立した、足跡とパーティクルの描画レイヤーです。既定値はレイヤー0です。ゲームカメラの Culling Mask に含めてください。

内蔵足跡は、共有プロシージャルパーティクルシェーダー内で生成したクアッドと数学的な輪郭を使用します。カスタム足跡も同じ描画経路でマスクテクスチャを使用します。足跡はサンプリングされたサーフェス上に配置され、URP では環境光とメインライトのリアルタイムシャドウを受けます。地面を削ったりへこませたりはしません。

寿命、フェード、サイズ、オフセット、色はサーフェスエフェクトエントリごとに設定します。これにより、雪の足跡を道路の足跡とは異なる速度で消せます。複数のバイオームで同じ足跡を共有するときは、1つのエントリにまとめます。新しいエントリには前の設定が独立した形でコピーされるため、差分だけ変更すれば済みます。

独自の足跡画像を使用する

  1. 跡の前方／つま先が画像の上方向を向くようにマスク画像を準備します。
  2. まず足跡の形状 → カスタムを選択し、インポートしたテクスチャを足跡マスクに割り当てます。テクスチャの Read/Write を有効にする必要はありません。
  3. 白黒画像の場合はマスクのアルファを使用をオフにします。赤チャンネルの白い部分が跡となり、黒い部分は地面が透けます。透過画像の場合はマスクのアルファを使用を有効にすると、アルファをマスクとして使用できます。
  4. 必要に応じて左足の足跡を反転で左右交互の左側の跡を反転させます。左右で同じタイヤ痕を使用する場合や、動物の跡を同じ向きにしたい場合はオフにします。
  5. マスクの向きは足跡の回転でサーフェス上のマスクを回転させ、足跡サイズと 色 を調整します。

カスタムエントリで足跡を生成するには足跡マスクが必要です。別のマスクを割り当てても、新しく押印される跡にのみ適用され、既存の跡は寿命が切れるまで元のマスクを保持します。マスクが輪郭を決め、足跡の色が表示色と不透明度を決めます。

左右一対のタイヤ痕：タイヤ跡またはカスタムのトレッドマスクを選び、足の間隔で左右の走行跡の位置を決め、移動距離を使います。一歩の距離 を足跡の長さの半分にすると、左右交互のセクションが各側でつながります。長さ0.4メートルの跡なら0.2メートルから試してください。実際の車輪位置を使う場合は車両コントローラーから明示的な接地を発行します。カスタムのタイヤ跡では左足の足跡を反転をオフにできます。

雪と道路：雪／氷のバイオームすべてを対象にする雪上の足跡エントリを作成し、パーティクルはなしまたは舞い上がる雪にして、足跡の寿命を短くします。次に路面の足跡エントリを追加して道路のバイオームを選び、足跡の色と寿命を変更します。コンポーネント共通のタイミングと上限は両方に適用されます。

足音のタイミングとオーディオ

パーティクルは移動距離に応じて発生します。足音のタイミングは、左右交互の足跡と足音の接地タイミングをまとめて制御します。コンポーネントの足音と足跡セクションで一度設定します。

設定項目内容／既定値
移動距離サーフェスに接地して移動している間、左右交互に自動ステップを生成します。一歩の距離 の既定値は0.6メートルです。キャラクターの歩幅に合わせて調整してください。
アニメーションイベント自動の距離ベースのステップは無効になります。アニメーション内で足が接地するたびにEmitFootstep()を呼び出します。配置位置は左右交互に切り替わります。コンポーネントを Animator のあるオブジェクトに追加するか、アニメーションスクリプトからイベントを転送してください。
足の間隔ヒット面上で、中央サンプル位置から交互の足までの距離です。既定値は0.09メートルです。EmitFootstepAt(contact) はこのオフセットを使用せず、指定された接地位置を使用します。
EmitFootstepAt(contact)足、ひづめ、車輪の Transform を渡して接地を明示する API です。その位置で地形の接地とバイオームルールを確認し、跡や音を生成します。足跡の向きはアクターの前方方向を使用します。
足音オーディオサーフェスエフェクトエントリで有効にし、オーディオクリップを割り当てます。新しい音ごとに null でないクリップを1つランダムに選択します。足音だけの場合はパーティクルをなしにし、足跡を無効にします。
音量／ピッチ範囲空間オーディオの音量とランダムなピッチです。既定値はそれぞれ0.5、0.95～1.05です。
近距離／音声距離最大音量となる距離と聞こえる最大距離です。既定値は1／25メートルで、距離に応じて線形減衰します。
足音数の上限プレイヤーあたりの同時再生数の上限です。既定値は8で、1～32の範囲で設定できます。すべて使用中の場合は新しい音をスキップします。

ゲームカメラで有効なAudio Listenerを使用し、Play モードで確認してください。オーディオクリップが必要です。このパッケージは足音の録音を合成しません。足音には対象のバイオームと、足の接地距離内にある足元の基準位置が必要です。

アニメーションイベントでは明示的にステップを要求しますが、地形への接地とバイオーム設定は引き続き確認されます。自動移動の速度しきい値は、明示的なイベントを妨げません。このワークフローには、着地／衝撃音専用コンポーネントや衝撃速度の設定はありません。

足、ひづめ、車輪ごとの接地タイミング

移動距離とEmitFootstep()は、2つの接地点を交互に使用します。四足動物では肉球の足跡またはひづめの跡を選び、足音のタイミング → アニメーションイベントに設定して、足またはひづめが地面に触れた瞬間に、その Transform を渡してEmitFootstepAt(contact)を呼び出します。歩容と接地の順序はアニメーションまたはコントローラー側で決定します。

// From your existing animation-event or locomotion code:
surfaceEffects.EmitFootstepAt(frontLeftHoof);
// Call for each other hoof at its own contact time.

各接地 Transform は足裏やひづめの接地点付近に配置してください。この呼び出しでは足の間隔と自動の移動速度しきい値を無視しますが、Play モード、コンポーネントの有効状態、サーフェスエフェクトを有効化、接地状態、バイオーム設定は確認されます。null の接地点や空中の接地点では跡は生成されません。脚の接地タイミングを推定したり、すべての足ボーンを自動監視したりする機能ではありません。

車輪の場合は、車両コントローラーが適切な移動間隔で接地イベントを発行できます。自動の足跡タイミングは押印パターンであり、タイヤやサスペンションのシミュレーションではありません。

マテリアルとカスタムメッシュ

マテリアルはDPT のスキャッターインタラクションをサポートしている必要があります。GPU Instancing だけでは不十分です。まず付属の SH_DPT_VCTerrain シェーダーを使って反応を確認し、その後でカスタムマテリアルに置き換えてください。

曲げ表現には、メッシュのバウンディング範囲内でのローカル Y 高さが使われます。最下部は固定され、先端に向かうほど変位が大きくなります。カスタムの草は根元から先端への方向をローカル +Y に合わせて作成し、ピボットとバウンディングを確認してください。横向きのメッシュや無関係なジオメトリが同じバウンディングに含まれると、予期しない曲げマスクになることがあります。

カスタムシェーダーには、通常のスキャッターインスタンシング設定に加え、DPT スキャッターの頂点インタラクション経路と対応プロパティが必要です。風の関数だけ追加してもプレイヤーによる曲げ表現は有効になりません。可視パスとシャドウパスで頂点処理を一致させてください。

風の調整には地形マテリアル設定を、バリアント、元メッシュ、マテリアルの設定にはカスタムメッシュの設定を参照してください。

プレイヤー、NPC、各種制限

スキャッターに影響を与えたい近くの各アクターに、「散布オブジェクトの反応を有効化」を有効にしたプレイヤーサーフェスエフェクトを追加します。プレイヤーと NPC のコンポーネントは同じ共有シェーダーデータを使用するため、視覚的な曲げ表現に Trigger コライダーや衝突コールバックは必要ありません。

システムは同時に最大8つの有効かつ強度が正のインタラクターを使用できます。これを超える場合は、現在のカメラ／参照位置に近いアクターが優先されます。大勢のキャラクターがいる場合は、必要なアクターだけを有効にしてください。この視覚的な反応の上限は、レンダラーのコライダー対象を中心とする物理衝突範囲とは別です。

複数のアクターが重なると、各アクターによる押し出しが合成されますが、スキャッターグループの曲げ距離は守られます。反応する高さの範囲を調整すると、橋、洞窟の床、積層された空間で反応を分離しやすくなります。

草の反応はアクターの現在位置に追従します。曲げ表現は通過した軌跡を保持せず、アクターが去った後のバネ状の復元アニメーションもシミュレーションしません。別機能の足跡では、一定時間残る跡を地形上に生成できます。

物理衝突とゲームプレイ

地形の衝突メッシュとプレイヤーの移動／衝突設定は、プレイヤーサーフェスエフェクトとは別に管理してください。インタラクターが提供するのは描画への影響であり、プレイヤーコントローラーではありません。キャラクターを地形上に立たせる機能もありません。

インスタンシングされたスキャッターには、内蔵プリセット、カスタムメッシュ、プレハブ向けの任意のプール式コライダーを使用できます。プレイヤーを妨げる必要のあるグループでスキャッターコライダーを有効にし、以下のように形状と範囲を設定します。可視メッシュはインスタンシングのままで、Play モード中に指定ターゲットの付近でコライダーオブジェクトが有効化されます。

任意のスキャッターコライダーを設定する

  1. まず3D スキャッターでスキャッターオブジェクトを開きます。メッシュまたはメッシュ＋パーティクルを選択してスキャッターコライダーを有効にします。既定ではオフです。グループのプレイヤーの影響やプレイヤーの散布オブジェクトの反応を有効化は必要ありません。
  2. グループのコライダー範囲をメートル単位で設定します。既定値は10です。ゲーム内の物理的なインタラクションを十分にカバーできる範囲を選択してください。
  3. 各メッシュバリアントを展開し、コライダー形状を選択します。まずは自動、または単純なボックス、カプセル、球体から試してください。
  4. カスタムソースでは、メッシュのソーススロットにプレハブも指定できます。メッシュの各パーツ、マテリアル、対応するコライダー定義をまとめて取得できます。必要に応じてプレハブのオーバーライドや別のコライダー形状を使用してください。
  5. 次にスキャッター設定 → スキャッターの衝突の下で、コライダー対象に有効化範囲の基準となるプレイヤー／キャラクターまたはカメラを指定します。空の場合は有効なメインカメラが使用されます。
  6. コライダー更新間隔、フレームごとのコライダー数、コライダーの物理レイヤーを確認します。Play モードで移動と実際の物理クエリをテストしてください。編集モードのスキャッタープレビューではこれらのコライダーは有効になりません。
コライダー形状動作
自動対応するプレハブコライダーがあればコピーし、なければ元のバウンディングを囲む低コストのボックスを1つ使用します。内蔵プリセットにもカスタムソースにも適しています。
ボックスコライダー中心とコライダーサイズを使用します。
カプセルコライダー中心、コライダー半径、コライダー高さを使用します。木の幹や直立する柱に適しています。
球体コライダー中心とコライダー半径を使用します。
メッシュコライダーメッシュを使用し、未設定ならスキャッターの近距離メッシュを使用します。凸型コライダー も利用できます。詳細な形状は単純なプリミティブより高コストになる場合があります。
プレハブプレハブの有効な子階層から、ボックス、球体、カプセル、メッシュコライダーをコピーします。相対 Transform、Trigger フラグ、物理マテリアルも含まれます。対応するコライダーがない場合は、バウンディングに合わせたボックスにフォールバックします。

物理マテリアルで、バリアントの生成コライダーに対する摩擦と反発を任意で上書きできます。空のままならプレハブコライダーのマテリアルを維持し、生成プリミティブでは既定のマテリアルを使用します。コピーされた Trigger は Trigger のままなので、移動を妨げる必要がある物体には通常のコライダーを指定してください。

スキャッターの衝突の設定項目内容／既定値
コライダー対象範囲判定に使うキャラクターまたはカメラの Transform です。空の場合は有効なメインカメラを使用します。スキャッターレンダラーごとに1つのターゲットがあります。
コライダー更新間隔距離の再評価間隔です。既定値は0.1秒です。ターゲットの移動に合わせ、近くの形状を確認してプールから利用します。
フレームごとのコライダー数1フレームに新たに有効化できるコライダーオブジェクトの最大数です。既定値は32です。増やすと新しい範囲を早く埋められますが、フレーム負荷が増加します。スキャン自体も段階的に実行されます。
コライダーレイヤーを上書き／コライダーレイヤー生成されるコライダー階層に使用する任意の物理レイヤーです。上書きしなければ元の地形のレイヤーを使用します。プレイヤーの衝突ルールと発射物のクエリマスクを適切に設定してください。

コライダー範囲は描画距離、LOD、グループの描画距離を上書きとは独立しています。遠くまで表示される木でも、近くの木だけにコライダーを有効化できます。逆に、物理範囲を描画範囲より広くすることも可能です。近接攻撃や接近移動では必要な範囲を確保し、遠距離武器では想定クエリ距離をカバーしてください。範囲を大きくすると有効な形状が大幅に増える場合があります。8つの視覚インタラクターが、8つの独立したコライダー範囲を作成するわけではありません。

コライダーはプールされ、フレームをまたいで有効化されます。高速移動、スポーン、新しい場所へのテレポートでは、十分な範囲と準備時間を確保してください。スキャッターの起動準備完了シグナルは配置とメッシュアップロードを対象とし、コライダーの有効化完了を保証しません。テレポート直後にプレイヤーの操作を開始したり物理クエリを発行したりする前に、必要な周囲の衝突判定が準備できていることを確認してください。

個々の障害物の位置をロード後も維持したい場合は固定配置を有効にしてシーンを保存します。バイオーム固定はライブの見た目の変化を別途制御します。物理衝突の範囲は、見た目の密度やフェードとは独立して設定してください。

衝突形状は、プレハブの完全なインスタンスではありません。コライダープロキシがコピーするのは、対応するコライダー定義と必要な Transform です。配置ごとにプレハブの Renderer、スクリプト、Rigidbody の動作を複製するわけではありません。動く物体、破壊できる物体、個別のスクリプトで制御する小道具には、独自のゲームプレイコードを持つ通常のシーンオブジェクト／プレハブを使用してください。

地形の検出と障害物の衝突を分離する

サーフェスレイヤーは、プレイヤーサーフェスエフェクトによる足元の地形クエリを制御します。プレイヤーコントローラー側の物理衝突ルールは別です。手前にある通常の非 Trigger コライダーは地形クエリを遮り、スキャッター障害物にはベイク済みバイオームデータが自動的に付くわけではありません。

障害物で移動は妨げたいものの、地形エフェクト用にサンプリングしたくない場合は、コライダーレイヤーを上書きで障害物を適切なレイヤーに配置します。そのレイヤーをコントローラーの衝突／クエリルールには含め、サーフェスレイヤーからは除外してください。これにより、プレイヤーは木に衝突しながら、足音用には本来の地形をサンプリングできます。

視覚的なマテリアル効果とゲームプレイ

流れ、湖 の波紋、ダスティング、スキャッターの曲げ表現は見た目を変化させる機能です。水の浮力、氷の摩擦、滑りやすい衝突、移動する水のボリュームを追加するものではありません。ゲームプレイ上の挙動は、独自のコントローラーまたはデモとランタイムガイドを使って実装してください。ベイク済みのサーフェスクエリは、曲がった草の頂点やパーティクルを測定しません。

パフォーマンスと制限

スキャッターインタラクションは、配置を再構築したり草1本ごとに GameObject を作成したりせず、対応する頂点シェーダーに処理を追加します。表示中の頂点数と有効なアクター数が負荷に影響します。スキャッターのカリング範囲には設定した曲げ距離が含まれますが、風のバウンディングは別です。

プレイヤー用のパーティクル、足音、足跡はサーフェス検出とバイオームルールの選択を共有します。ParticleSystem とオーディオソースはプールされます。足跡の描画では、インスタンシングバッチ、事前計算されたバウンディング、カメラの視錐台／距離カリング、ビューと足跡が変わらない場合の描画データキャッシュ、GPU による寿命フェードを使用します。

リソース上限既定値／調整方法
有効なスキャッターインタラクター強度が正の有効なアクターを最大8つ使用します。混雑時はカメラ／参照位置に近いものが優先されます。レンダラーの単一のコライダー対象とは独立しています。
パーティクルの距離 / パーティクル数の上限このプレイヤーのサーフェスエフェクト全体で40メートル／500個です。透明な大型パーティクルが多数重なると、依然として高コストになることがあります。
パーティクルノイズ高、中、低、オフから選びます。品質を下げるとプロシージャルな乱流処理を軽減できます。カスタムプレハブでは作成時のノイズ設定が維持されます。
足跡数の上限 / 足跡表示距離128個／60メートルです。密集した足跡では、上限、寿命、距離、足跡サイズを小さくしてください。
足音数の上限プレイヤーごとに8音です。スキャッターレンダラーの共有音源数の上限とは別です。
スキャッターコライダーの範囲／有効化グループごとに既定ではオフです。コライダー範囲を制限し、単純な形状を優先して、コライダー更新間隔とフレームごとのコライダー数を見た目の描画とは独立して調整してください。

設定されたパーティクルエフェクト、足音のクリップ／再生音声、足跡の容量は、初回使用時の処理を軽減するため段階的に事前準備されます。シェーダーの初回コンパイルや大規模なカスタムエフェクトには追加の準備が必要な場合があります。メッシュの準備についてはスキャッターの起動オプションを参照してください。この準備完了シグナルは、すべてのサーフェスエフェクトやコライダーを対象とするものではありません。

上限はリソース消費を抑えるためのもので、発生量を増やす設定ではありません。実際のゲームカメラ、ターゲット解像度、ターゲット端末でプロファイリングしてください。カリングとプーリングは不要な処理を減らしますが、特定のフレームレートを保証するものではありません。

プレイヤーエフェクトのトラブルシューティング

症状確認する順序
草が曲がらない可視メッシュ出力、プレイヤーの影響、0より大きい曲げ距離、対応するシェーダーを確認します。プレイヤーでは散布オブジェクトの反応を有効化をオンにし、反応位置の基準/オフセット、半径、高さ、強度を確認してください。
移動時のパーティクルや葉擦れ音が出ないプレイヤーの「散布オブジェクトの反応を有効化」を有効にし、対象のスキャッターエフェクトでプレイヤーの移動を選択します。移動速度のしきい値、配置対象、割合、発生率／クールダウン、カメラ／オーディオ範囲、各種上限を確認してください。メッシュの曲げ表現は任意です。
足元のパーティクルが出ない「サーフェスエフェクトを有効化」を有効にします。足元の基準位置/オフセット、サーフェスレイヤー、地面への到達距離、対応する MeshCollider、ベイク済みサーフェスターゲット／データ、選択したバイオーム ID を確認します。なし以外のプリセットを選び、Play モードで移動して発生率、パーティクルの距離、パーティクル数の上限を確認してください。
足跡や足音が出ないサーフェスエフェクトエントリを展開し、足跡や足音オーディオを有効にします。必要ならパーティクルはなしにします。足元の基準位置を足裏付近に置き、現在の 地面との間隔 が足の接地距離以内か確認します。移動距離を使うか、アニメーションイベントモードで EmitFootstep イベントを送ります。自動ステップの場合はバイオーム ID と最小移動速度を確認してください。
音は出るが足跡が表示されない足跡が有効か、色 のアルファ、サイズ、足跡数の上限/距離、オフセットを確認してください。カメラがプレイヤーレイヤーを非表示にしている場合でも、表示レイヤーをカメラの Culling Mask に含めてください。
カスタム足跡が出ない／四角形になるカスタムを選び足跡マスクを割り当てます。赤チャンネルのマスクでは白が跡、黒が透明領域です。透過画像ではマスクのアルファを使用を有効にします。アルファが全面不透明なら長方形が塗りつぶされます。サイズ、色のアルファ、接地、範囲、表示レイヤーも確認してください。
カスタムの走行跡が左右交互に反転する左右で同じ跡にする場合は左足の足跡を反転を無効にします。足跡の回転はカスタムマスクの向きを変え、回転が0のとき画像上方向が進行方向になります。
四足動物なのに2列の跡しか残らない移動距離と EmitFootstep は2つの位置を交互に使用します。アニメーションイベントに切り替え、各足／ひづめが接地した瞬間にその Transform を使って EmitFootstepAt を呼び出してください。明示的な呼び出しでは足の間隔を使いませんが、有効な地形への接地とバイオーム設定は引き続き必要です。
足跡が浮く／ちらつく足跡オフセットを0.003メートル程度の小さな値にし、地形のコライダーが可視サーフェスと一致しているか確認してください。足跡はコライダー法線に沿うため、シェーダーだけによる任意の変位には追従しません。
影の中で足跡が明るく見えるURP で最新の共有プロシージャルパーティクルシェーダーを使い、メインライトと影を落とすオブジェクトのリアルタイムシャドウを有効にしてください。足跡はメインライトの影を受けますが、色は別途設定されます。
プロシージャルエフェクトがピンク色になるUnity の Console でシェーダーコンパイルエラーを確認し、最新の DPT_ProceduralParticle シェーダーを使用します。シャドウ API の互換性はインストール済み URP ヘッダーに依存します。URP と Core パッケージのバージョンを揃えてください。
バイオームの候補がない／すべて追加を使用できないサーフェスデータをベイクを実行してシーンの地形データを読み込むをクリックするか、サーフェスデータソースを明示的に割り当ててください。すべて追加はこれらのソースに含まれる名前付きバイオーム ID を使用します。
サーフェスに不適切なエフェクトが出るエントリの順序と対象バイオームを確認します。パーティクル、足跡、オーディオは、それぞれ最初に一致した有効エントリを独立して選択します。ライブバイオームの変化や十分に強いダスティングにより別の ID が選ばれる場合があります。編集内容を変更した場合は再ベイクしてください。
オーディオが鳴らないnull でないオーディオクリップを割り当て、足音オーディオまたは散布オーディオを有効にし、音量、距離、ソースの上限、有効な Audio Listener を確認してください。オーディオは Play モードで動作します。
別の階の草が動く／一部のアクターが反応しない積層された床では反応する高さの範囲を小さくします。8つのインタラクター上限と、0より大きい反応の強さを確認してください。
プレイヤーがスキャッターの岩をすり抜けるメッシュグループのスキャッターコライダーを有効にし、適切な形状を指定してコライダー範囲/ターゲット、物理レイヤー、プレイヤーの衝突ルールを確認します。Play モードでテストし、近くのコライダーが有効になるのを考慮してください。コピーされたプレハブの Trigger は移動を妨げません。
テレポート後にコライダーの出現が遅れるターゲット、範囲、コライダー更新間隔、フレームごとのコライダー数を確認します。有効化は段階的で、配置が利用可能になってから始まります。スキャッターメッシュの準備完了はコライダーの完了を保証しません。ゲームプレイを再開する前に必要な物理衝突範囲を確認してください。
プレハブのコライダーは機能するが、スクリプトや Rigidbody は動かないスキャッターがコピーするのは対応する衝突形状であり、完全なゲームプレイオブジェクトではありません。移動、破壊、スクリプト制御が必要な障害物には通常のシーンオブジェクト／プレハブを使用してください。
スキャッターの障害物付近で足音が止まる最も近い物理ヒットが、有効な地形データを持たない障害物かどうか確認してください。プレイヤーコントローラーでは障害物との衝突を維持しつつ、生成コライダーのレイヤーをプレイヤーのサーフェスレイヤーから除外してください。

サポート

サポートが必要な場合は、Unity のバージョン、スキャッターオブジェクトとプレイヤーサーフェスエフェクトのスクリーンショット、使用中のメッシュとマテリアル、問題が Scene ビューと Play モードのどちらで発生するかを添えてください。高さの問題では、草の根元に対するプレイヤーの中心位置が分かる画像をご用意ください。
