3D Scatterシステムは、Terrain Atlasのバイオームデータからインスタンス化メッシュとパーティクル放出ポイントを直接配置します。1つの scatter object には、メッシュのバリエーション、パーティクルレイヤー、必要に応じたオーディオを含む再利用可能な配置ルールが保存されます。バイオームごとに草の設定を作り直す代わりに、同じオブジェクトに複数の Target Biomes を追加し、必要に応じてターゲットごとに密度倍率を設定できます。

Scatterは草、花、キノコ、石、小さな小道具など、繰り返し使用する地表のディテール向けです。地形メッシュを編集したり、描画用のScatterインスタンスごとにGameObjectを生成したりするものではありません。物理コライダーは必要な場合だけ有効にでき、距離によって適用範囲を制限できます。可視メッシュはGPUインスタンシングで描画されます。

Scatterライブラリの仕組み

Scatterの設定は各バイオームのInspector内に個別保存されるのではなく、Terrain Atlasのバイオームライブラリ全体で共有されます。Vertex 3D Terrainウィンドウの 3D Scatter セクションを開いてライブラリを作成・編集します。

要素役割重要なポイント
Scatter Object配置ルール、メッシュまたはプレハブのバリエーション、複数のパーティクルエフェクト、任意のコライダー・オーディオ、風・プレイヤーとの相互作用設定を保存します。一度設定すれば複数のバイオームに使用できます。必要に応じてBiome LockとPermanentを組み合わせます。
Target Biome選択したTerrain Atlasバイオームが存在する場所への配置を許可します。各ターゲットには0～2の個別のDensity Multiplierを設定できます。
Scatter OutputMeshes、Particles、Meshes + Particles、Audio Onlyから選択します。オーディオは独立して設定でき、どの出力にも追加できます。Audio Onlyは表示メッシュやパーティクルを使わず、音の配置ポイントを生成します。
Mesh Variant組み込みプリセット、インポートしたメッシュ、プレハブのいずれかと、相対的な選択確率を指定します。カスタムプレハブからメッシュ、マテリアル、コライダー情報を取得してGPUインスタンシングに利用できます。
Scatter Settingsシード、バッチ処理、距離、LOD切り替え、遠距離密度、安全上限を制御します。これらはオブジェクトごとではなく、Scatterライブラリ全体で共有されます。
Active Terrain Rendererプロファイルを選択した地形ルートに接続し、GPUインスタンシング描画を実行します。何千ものScene内GameObjectとしてインスタンスを表現することはありません。

最初のScatter Objectを作成する

  1. まず Terrain Atlas 方式を使用し、地形にバイオームがペイントされていることを確認します。
  2. Vertex 3D Terrainウィンドウで 3D Scatter を開きます。プロファイルがなければScatter Libraryを作成します。
  3. 次に + Add Scatter Object を選び、Meadow Grassなど分かりやすい名前を付けます。
  4. Target Biomesの下で、現在のライブラリから1つ以上のバイオームを選択します。
  5. 各ターゲットのDensity Multiplierは最初は1にします。
  6. 全体の Density （1平方メートルあたりの株数）、 Spacing、 Coverage の範囲、傾斜、スケール、地表への整列を設定します。
  7. この草の設定では Scatter Output を Meshes のままにします。組み込みGrassプリセット、インポートしたメッシュ、プレハブのいずれかを使ってMesh Variantを追加します。パーティクルについては後述の パーティクルの設定 を参照してください。
  8. マテリアルを割り当てるか確認し、求められた場合はGPU Instancingを有効にします。大きな変更後にプレビューが更新されていなければ、 Rebuild Scatter を実行します。

例： Meadow Grassを1つ作成し、Lush Grassに×1.0、Dry Meadowに×0.65、Forest Soilに×0.25で割り当てます。草メッシュ、カラーランプ、粗さ、風の設定が3種類の地表で再利用されます。

エディタープレビューと地形ツールの更新

Playモード以外でScatterを表示するには、 Preview の見出し横にある 3D Scatter を使用します。新しいレンダラーでは初期状態でオフになっており、ランタイム描画には影響しません。有効にすると、隣接する Update After Stroke ボタンが表示され、初期状態ではオンです。地形ツールの操作中は既存の配置を保持し、操作終了後に影響を受けたソースを更新します。オフにすると操作中に更新できます。

Continuousパーティクルの場合は、エフェクトの Preview Particles スイッチも有効にします。SceneビューではEffectsとParticle Systemsをオンにしてください。これらの表示設定でプレビューが隠れている場合、ツールは修正を提案します。Player MovementエフェクトとオーディオはPlayモードでテストします。 Animate Preview は風やアニメーション付きマテリアルを継続的に更新する別のScatter設定です。

1つの設定から複数のバイオームを対象にする

Scatter ObjectはいくつでもTerrain Atlasバイオームを対象にできます。バイオーム選択欄には現在の名前と数値IDが表示されます。 + Add Target Biome でリストを増やせます。

設定意味例
BiomeこのScatter Objectを配置できるTerrain Atlasバイオーム。Grassland、Forest Soilなど、現在のライブラリ内の項目。
Density Multiplier: 0–2このターゲットバイオームに限って、Scatter Objectの基本密度に倍率を掛けます。1は標準密度、0.5は半分、0はこのターゲットを無効、2は2倍の密度です。

ペイントされたブレンド領域では、対象バイオームの寄与度を合算して判定します。そのため、GrassとForestの境界をまたぐ場合も、定義を複製せず同じオブジェクトを連続して配置できます。

配置が確定したインスタンスは、配置地点で寄与したターゲットに基づく所属バイオームを保持します。これにより、ライブバイオームモディファイアが対象の一部だけに作用しても、同じ草オブジェクト内で反応を分けられます。

配置設定

Scatter Outputの場所： Vertex 3D Terrainウィンドウで 3D Scatterを展開し、名前または矢印をクリックしてScatter Objectを開きます。 Scatter Output のドロップダウンは Target Biomes のすぐ下、 Placementの上にあります。ここで Meshes、 Particles 、または Meshes + Particles を選びます。

Placement 内の Biome Lock はライブバイオームの変更への反応を制御し、Permanent はシーンやゲームの再読み込み後も保存済みの配置を維持します。Player Interaction を有効にすると、対応メッシュの Bend Distance を設定できます。2つの固定設定の違いは Biome LockとPermanent を参照してください。

設定意味設定の目安
Scatter OutputMeshesは設定したバリエーションを描画し、Particlesはメッシュバリエーションなしで放出ポイントを生成し、Meshes + Particlesは両方を組み合わせます。既存のScatter Objectの初期出力はMeshesです。Meshes + Particlesではメッシュバリエーションを使って配置を決定します。
Biome Lockライブバイオームによる密度・色の変更を無視し、遠距離での密度間引きも適用しません。環境のライブ変更によって表示、密度、色を変えたくない植生や小道具に使用します。配置位置の保存はPermanentとは別です。
PermanentScatterグループの配置レイアウトを地形シーンとともに保存し、シーンやゲームの再読み込み後も同じ位置を維持します。樹木や岩など、個々の配置を固定したいオブジェクトに使用します。エディターでの変更に応じて保存レイアウトを更新できます。
Player Interaction / Bend DistanceScatter Interactionを有効にした近くのPlayer Surface Effectsコンポーネントから、対応メッシュの先端を遠ざけるように曲げます。Bend Distanceはワールド単位メートルで先端の最大変位を制限します。草や柔らかい植物に使用します。詳しくは プレイヤーの衝突とインタラクションガイドを参照してください。パーティクルのみの出力には、このメッシュ設定は表示されません。
Density: 0～100株/m²Target Biome倍率とランタイムのライブ密度が適用される前の基準インスタンス密度です。低めから始め、インスタンス数と遠景の被覆状況を見ながら増やしてください。
Coverage Min / Max: 0–1すべてのTarget Biomesの合計被覆率が指定範囲内にある場所だけに配置します。Minを上げると薄いブレンドを除外します。Maxを1未満にすると単一バイオームの内部を除外します。Maxが1なら通常どおり内部にも配置します。
SpacingこのScatter Objectの株の中心間の最小ワールド距離です。地形タイルの境界をまたいでも適用されます。0では間隔制限がありません。密集や重なりを減らすには大きくします。最終インスタンス数がDensity設定より少なくなる場合があります。中心間を測るため、大きなメッシュは重なることがあります。
Max Slope: 0–90°設定角度より急な面を除外します。草は岩や崖の破片より小さい上限が適することが多いです。
Scale Min / Max採用されたインスタンスに適用するランダムな均一スケールの範囲です。目立つサイズ変化を避け、自然なばらつきになる控えめな範囲を使用してください。
Alignment: 0–1指定したUp Modeと地形法線の間で整列方向を補間します。0では指定した上方向に対して直立し、1では地表法線に完全に合わせます。
Offsetサンプリングした地表法線に沿ってインスタンスを移動します。メッシュが浮いたり埋まったりする場合、小さな正負の値で調整します。
Enable WindこのScatter ObjectでDPT Scatter Windを使用する設定です。割り当てたシェーダーが機能に対応している場合のみ使用できます。対応する草、花などの柔らかいメッシュに有効にします。硬い小道具ではオフにしてください。VCCOREマテリアルは独自の風データを使うため不要です。

Biome LockとPermanent：異なる2つの設定

Biome Lock は、ライブバイオームの変更と遠距離での密度間引きからScatterグループを独立させます。ライブバイオームモディファイアが環境を変更しても、対象オブジェクトの表示数や色を変えたくない場合に使います。以前の Static Scatter を改名した設定です。

Permanent は、生成済みの配置レイアウトを地形シーンとともに保存します。シーンやゲームを再読み込みしても、同じオブジェクトが同じ場所に配置されます。エディターで設定や配置を変更した場合は保存内容を更新できます。樹木、岩、目印となるオブジェクトなど、ロードのたびに配置を再抽選したくないものに適しています。

この2つは独立した設定です。Permanentを有効にしたグループも、Biome Lockがオフならライブバイオームの変化に反応します。一方、Biome Lockだけでは個々の配置位置が永続的に保存されるわけではありません。位置を固定し、ライブバイオームの影響も無視したい場合は両方を有効にしてください。

例：森の木々の位置を固定するには Permanent を有効にします。ライブバイオームの密度や色が変わっても木々を変化させたくない場合だけ Biome Lock も有効にします。冬に消える季節の草にはBiome Lockを使用しません。

岸辺にだけ葦を配置する

  1. ReedsのScatter Objectを作成し、対象を Waterのみにします。
  2. Coverage範囲を例えば 0.15–0.65 にすると、WaterとMudが混ざる岸辺に葦を配置し、被覆率1の純粋なWaterは除外できます。
  3. ペイントした遷移帯の幅と範囲を調整して位置を決め、DensityとSpacingで数と間隔を設定します。

Coverageは対象バイオームの寄与度を合計します。WaterとMudの両方を対象にすると、境界でも合計が1となり、この範囲では除外される場合があります。必要な境界を部分的な被覆率で表すバイオームだけを対象にしてください。Coverageは配置可能な地表を判定し、バイオームごとの Density Multiplier で株数を調整します。

組み込みプリセット、カスタムメッシュ、プレハブ

Mesh Source では組み込みプリセット、カスタムメッシュ、プレハブをGPUインスタンシングのソースとして選択できます。追加のメッシュバリエーションは赤い Remove Mesh Variant ボタンで削除します。

Scatter Objectには複数のMesh Variantを含められます。 Relative Chance は合計を100にする必要のない相対的な選択ウェイトです。配置シードを変えずに組み込みメッシュに変化を付けるには、異なる Shape Seed 値を使います。プリセットの説明はツールチップで確認できます。

組み込みプリセット用途形状の特徴
Grass / Short Grass / Tall Grass草原、地面を覆う短い植生、背の高い草。シーンに適した輪郭を選択してください。近距離・遠距離用ジオメトリによって遠方の描画負荷を抑えます。
Flowers小さな花の群生。シードとカラーランプを組み合わせて変化を付けます。
Lavender直立した紫色の花穂。まとまった花のジオメトリと少数の葉を使い、多数の小花を別々に作るより単純なメッシュにします。
Ferns / Clover / Shrubs葉の多い下草や低木。スケールと間隔で葉の重なりを抑えます。
Reeds湿地や岸辺の植物。初期状態の茎は小さめです。Coverageの帯域とSpacingを組み合わせます。
Pebbles小さな石の集まり。Smoothing Angleで滑らかな陰影か面の際立つ陰影を選べます。
Mushrooms林床の装飾。カラーランプは各生成要素のローカルの高さに沿って適用されます。
Crystals面のはっきりした鉱物の集まり。Smoothing Angleの初期値は0で、鋭い面を保ちます。変更も可能です。
Fallen Branches地面の散乱物。単純化された小枝と地面に沿う形状です。急斜面ではAlignmentとOffsetを確認してください。

シェーディングと表面プロパティ

Crystalsを含むすべての組み込みプリセットには Smoothing Angle: 0–180°があります。0では面がフラットなまま、180では隣接する面の法線をすべてブレンドできます。中間値は穏やかな角だけ滑らかにし、鋭い角を保ちます。照明の見え方が変わりますが、メッシュ形状や地形全体のSmooth / Sharp設定は変わりません。

Vertex Colour Ramp は生成された各要素のローカルな下から上へ評価されます。 Smoothness は0で粗く、1で磨かれた質感になり、新しいバリエーションの初期値は 0.2 です。 Metallic は0～1で金属的な反射を制御します。

生成メッシュではMetallicを UV3.Rに格納します。UV3.GにはSmoothnessの生値ではなく、Smoothnessから導出したDPT独自のスケール/粗さパック値を格納します。カスタムシェーダーではこのデータを適切にデコードする必要があります。

発光するScatter

組み込みバリエーションで Emissive を有効にし、カラーランプのHDR色で明るさ、アルファ値で発光範囲を指定します。DPTは発光バイオームと同様に、その範囲を頂点アルファへパックします。HDR色だけでは発光は有効になりません。マテリアルのEmission設定も適用され、Bloomの見え方はシーンのポストプロセスに依存します。Emissionは光源を生成しません。

カスタムメッシュとプレハブのソース

カスタムScatterのバリエーションでは、インポートしたメッシュまたはプレハブをソースにできます。メッシュを直接指定する場合は、3D Mesh、任意のサブメッシュインデックス、Material、任意のDistant Meshを割り当てます。Distant Meshを指定しない場合は近距離用メッシュを再利用します。

プレハブを指定すると、Scatterシステムはメッシュ、マテリアル、コライダーの定義を抽出し、GPUインスタンシング描画と必要に応じた物理処理に使用します。プレハブはデータのソースであり、表示用インスタンスごとに完全なプレハブGameObjectを生成するわけではありません。これにより、複数パーツを持つ樹木などのインポート済みアセットも、FBXメッシュだけを手作業で指定することなくScatterに利用できます。

カスタムメッシュは元の法線、頂点色、UV3の表面データを保持し、組み込みのShading、Metallic、Smoothness、Emissive設定では書き換えられません。対応するDPT Scatter Windを有効にすると、元のアセットを変更せず、風・バイオームデータを持つランタイム用コピーを作成します。

マテリアルの選択は重要です。 ScatterはGPUインスタンシングを使用します。ソースメッシュのデータに適合するマテリアルを使い、求められた場合はGPU Instancingを有効にしてください。バリエーションのマテリアルが空欄なら、適切な場合に元の地形マテリアルが使用されます。

任意のScatterコライダー

Scatterグループでは、物理的なインタラクションに必要な場合だけコライダーを有効にできます。カスタムプレハブに設定されたコライダー定義は自動的に取得できます。すべての可視インスタンスに物理コライダーを設ける必要はありません。Collider Distance などの距離設定によって、インタラクション領域から一定範囲内に維持するコライダーを制限し、大量配置時のパフォーマンスを管理できます。

プレイヤーの移動を妨げる樹木や大きな岩など、実際に衝突判定が必要なオブジェクトに使用してください。草、花、小さな地表装飾では、特別な必要がなければオフにします。可視メッシュの描画は引き続きGPUインスタンシングで行われますが、コライダーには別途物理処理の負荷がかかります。

例：樹木のプレハブからメッシュ、マテリアル、コライダー情報を取得し、近距離の樹木にコライダーを有効にします。プレイヤーが接触する距離に合わせてCollider Distanceを調整してください。遠くの樹木はGPUインスタンシングで表示したまま、不要な遠距離コライダーは生成しないようにします。

Scatter配置ポイントからパーティクルを放出する

Scatter Outputで Particles または Meshes + Particles を選び、 Particle Effect 1を展開します。組み込みプリセットは、外部スプライトを必要とせず、パーティクルシステム、マテリアル、数学的な形状を生成します。自作ParticleSystemプレハブを使う場合はCustomを選びます。足跡はScatterプリセット一覧ではなく Player Surface Effectsで設定します。

トリガーと放出ポイント

Continuous は表示カメラに近い有効な配置ポイントから放出します。 Player Movement はEnable Scatter Interactionを有効にした移動中のPlayer Surface Effectsコンポーネントが配置ポイント付近を通過すると放出します。インタラクションの半径、高さ、強さを使用し、Scatter Teleport Distanceを超えるテレポートを無視します。メッシュの曲げは任意です。

Meshes + ParticlesはこのScatter Objectのメッシュ配置ポイントを使います。Particlesはメッシュバリエーションなしで独自のポイントを生成します。別のScatter Objectは別のポイントを持ち、他のオブジェクトの草に自動で紐付きません。Emitter Fractionは各エフェクトで使用する配置ポイントの一定割合を選びます。

Emitter FractionとRateを低めから始め、Emission Offset/Rotationを調整してからカメラ距離と上限を設定します。Continuousの編集プレビューにはメインのPreviewとPreview Particles、さらにSceneビューのEffects/Particle Systemsの有効化が必要です。プレビューは初期状態でオフですが、Playモードでの放出には不要です。

プレイヤーの移動に反応させる

  1. 既存の草オブジェクトではMeshes + Particlesを、メッシュ不要のエフェクトではParticlesを使用します。
  2. Grass FlecksまたはPollenを選択し、Emission TriggerをPlayer Movementにします。まずEmitter Fractionを0.2、Rate / Emitterを15、Minimum Movement Speedを0.1にし、必要に応じて負荷上限を下げます。
  3. プレイヤーに Player Surface Effects を追加し、 Enable Scatter Interactionを有効にします。Interaction Origin/Offsetを根元付近に配置し、半径、高さ、強さを調整します。
  4. Playモードで配置ポイントを通過します。停止すると新しい放出も止まります。メッシュも曲げたい場合は、別途Player Interactionと正のBend Distanceを有効にします。

ライブ反応とパーティクルの寿命

ライブバイオームのStrengthとScatter Densityは新規パーティクル放出に乗算されます。0になると新規放出が止まり、既存の粒子は寿命を終えるまで残ります。Biome Lockはこれらの変更から独立して放出します。メッシュのLive Shrinkingはパーティクルの透明度を制御しません。

有効なレイヤーは、配置ポイントごとにGameObjectを作るのではなく、プールされた生成エフェクトまたはCustomプレハブのインスタンスを使います。シミュレーションはワールド空間で実行されます。プレハブが持つ自動放出レート/バーストは無効化され、Scatterエミッターがイベントごとに子システムを駆動し、レイヤーの予算を分配します。

放出の基点は配置トランスフォームに追従します。風やシェーダーによる曲げで、変形後のメッシュ先端へは移動しません。プリセットや出力を変更したりレンダラーを無効にしたりすると、不要なエフェクトが解放されます。プロシージャル生成だけでフレームレートが保証されるわけではなく、大きな半透明粒子の重なりは高コストです。

Scatter配置ポイントからの空間オーディオ

任意のScatter Object内の Scatter Audio を展開します。Meshes、Particles、Meshes + Particlesのどれにも追加できます。同じバイオームと配置ルールに基づく非表示の音ポイントが必要なら Audio Only を選びます。メッシュアセットもパーティクルプレハブも不要です。

  1. Target Biomesを選択し、配置のDensity、Coverage、Slope、Spacingを設定します。
  2. Enable Audio を有効にし、1つ以上の Audio Clipsを割り当てます。新しい音声ごとに有効なクリップがランダムに選択されます。
  3. 空間ループには Audio Trigger → Continuous 、プレイヤーのインタラクションが配置ポイントに届いたときの単発音には Player Movement を選択します。
  4. 音量、ピッチ、距離、Audio Emitter Fraction、音源上限を設定します。移動時のオーディオにはMinimum Movement SpeedとSound Cooldownを調整します。
  5. 有効なAudio Listenerを使いPlayモードでテストします。オーディオに編集モードのプレビューはありません。

滝の水しぶきと霧

滝の下端に手動で配置する着水帯には DPT_WaterfallSplashEmitter を使います。Scatterプロファイルや着水地点ごとのGameObjectを必要とせず、帯全体から共有パーティクルエフェクトを放出します。

有効なコンポーネントはPlayモード中、カメラの範囲内で Emission Rate に従って継続的に放出します。水やプレイヤーとの衝突を待つことはありません。編集時は Preview Particles を有効にします。任意のライブバイオーム・Flow連携によって新規放出を減らしたり止めたりできます。

  1. 滝の根元にGameObjectを作成し、Add Componentから DPT_WaterfallSplashEmitter を追加します。
  2. 初期状態のプロシージャル Waterfall Splash を使うか、別のParticle Presetを選択します。あるいは Custom を選択し、Particle Prefabを表示して自作のエフェクトを割り当てます。
  3. Splash WidthとSplash Depthで着水範囲を覆います。選択オブジェクトのギズモに帯が表示されます。
  4. 上向きの飛沫ではSpray Directionを(0, 1, 0)のままにし、Emission RateとParticle Limitを調整します。
  5. 編集時に表示するにはPreview Particlesを有効にします。
  6. 必要に応じて、後述の水バイオームとFlow速度に連携させます。

着水エフェクトは手動で配置してください。 このコンポーネントは滝の下端を検出したり衝突力を計算したりしません。 Waterfall Projection は水面をアニメーションさせ、このコンポーネントが可視のしぶきと霧を生成します。

連携したしぶきはScatter Densityにも従います。水のスロットでScatter Densityが0なら、Flowが有効でも新規パーティクルを放出しません。独立した放出レートが必要なら連携しないエミッターを使います。

静かな水面では、マテリアルの Lakeモード を選択します。Flowに連携した滝のしぶきはLakeモードで停止しますが、非連携の装飾用エフェクトは独自のレートで継続できます。

プレイヤーに反応する草

対応する草や植物のScatter Objectで Player Interaction を有効にして、プレイヤーに DPT_PlayerSurfaceEffects を追加します。近くのメッシュ先端が根元を固定したままプレイヤーから離れる方向に曲がります。風とは独立して動作し、草の各インスタンスに物理コライダーを用意する必要はありません。

プレイヤーの衝突とインタラクションガイド では設定、半径、高さの許容範囲、曲げ上限、NPC、物理衝突を説明しています。個別の草コライダーを作らず、歩くプレイヤーに草を視覚的に反応させたい場合に使用してください。

距離、LOD、レンダラー設定

Scatter Settingsを展開します。よく使う設定は Distance & LOD と Preview & Shadowsにまとまっています。 Advanced を開くとCell Size、Wind Bounds、タイルごとの上限、Up Mode、Runtime Discoveryを設定できます。配置設定は2つを組にしたコンパクトなスライダーを使い、スケール範囲はX/YではなくMin/Maxと表示されます。 Wind Fade Start と Wind Cutoff は Distance & LOD 内に並んで表示されます。

グループ別の描画距離と影の上書き

各Scatterグループでは、共有の Scatter Settings とは独立して描画距離と影の設定を上書きできます。上書きを無効にすると既存の共有設定を使用し、有効にすると、そのグループだけに異なる表示距離や影の設定を適用できます。

風の設定

DPT Scatter Wind はマテリアルと Scatter Object で制御し、Scatter Settings ではカメラ距離によるフェードも設定できます。 マテリアル 側でシェーダーの風機能を有効にするかを決め、Scatter Object側の Enable Wind でそのオブジェクトがDPT Scatter Wind処理を使うかを決めます。この設定が使用できるのは、割り当てたシェーダーで _DPT_SCATTER_WIND というBoolean Keywordが宣言されている場合だけです。これによってVertex 3D Terrainは対応シェーダーを判別します。

Vertex Terrainマテリアルを使用する

  1. マテリアルの Wind セクションを開き、 Enable Windをオンにします。
  2. 控えめな Wind Strengthを指定します。
  3. Height To Tip をScatterメッシュのオブジェクト空間での高さに近づけます。根元を固定し、先端が最大限動くようにします。
  4. Compass Heading と Vertical Pitchを選びます。
  5. 3D Scatterセクションに戻り、DPT Scatter Windを適用する各Scatter Objectの Enable Wind をオンにします。
  6. 大きく揺れる先端がカメラや視錐台の境界で消える場合は、Scatter Settingsの Wind Bounds を増やします。

小石のような硬いScatterは、同じマテリアルを共有しながらScatter ObjectのEnable Windをオフにできます。

遠くの風を弱めて停止する

  1. 3D Scatter → Scatter Settings → Distance & LOD を開きます。
  2. 動きを弱め始めたいカメラ距離を Wind Fade Start に設定します。
  3. Wind Cutoff に、開始距離より大きい値を設定します。2つの距離の間で風が滑らかに弱まり、停止距離に達すると止まります。
  4. 距離にかかわらず風を続けるには Wind Cutoff を 0 に戻します。停止距離が 0 の間は Wind Fade Start は使われません。

例：Wind Fade Start を 20、Wind Cutoff を 40 にすると、20 メートル以内では風をそのまま適用し、20～40 メートルで弱め、40 メートル以上で停止します。

距離は表示中のカメラから各 Scatter インスタンスの原点までをワールドメートルで測ります。各かたまり全体が同じ割合でフェードします。対応する DPT シェーダーでは、近距離・遠距離メッシュとその影に適用され、CPU と GPU の両方の Scatter 描画に対応します。

この設定が変えるのは風のアニメーションで、描画するオブジェクト数ではありません。描画負荷の調整には Draw Distance、Far Density、影の設定も使います。近くで最も大きく揺れる場合に備え、Wind Bounds には十分な余裕を持たせてください。

距離フェードには現在付属する Vertex Terrain シェーダーを使用してください。カスタムシェーダーには対応する DPT の風距離フェード処理が必要で、風のキーワードを有効にするだけでは追加されません。VCCORE など独自の風システムは、それぞれのマテリアル設定で制御します。

モーションブラーや TAA を使う場合、距離フェードの変化は前フレームのモーションベクトルに含まれないため、カメラがフェード範囲を通過すると再投影の精度が下がる場合があります。

VCCOREマテリアル

VCCOREは独自の風システムを使うため、Scatter Objectの Enable Wind はVCCOREマテリアルでは意図的に利用できません。正常な動作です。モデルに Stylized Color Swapper & Material Optimizerで風をペイントした場合、または風データが作成済みのDPTアセットを使う場合は、Scatter専用の風設定は不要です。VCCOREマテリアル自身の風設定で動きを有効化・調整してください。

自作Shader GraphへDPT Scatter Windを追加する

カスタムシェーダーに独自の風処理があれば、そのまま利用できます。Vertex Terrainシェーダーと同じScatter Wind機能を使いたい場合のみ、次のDPT設定が必要です。

SH_DPT_VCTerrainを開き、以下に示す Scatter Wind ブロックをコピーして自作Shader Graphへ貼り付けます。次にReference名を正確に一致させ、以下のBlackboard項目を追加します。

Blackboard項目型参照名
Wind StrengthFloat_Wind_Strength
Wind DirectionVector 3_Wind_Direction
Height To TipFloat_Height_To_Tip
DPT Scatter WindBoolean Keyword_DPT_SCATTER_WIND
  1. 付属のVertex Terrain Shader GraphからScatter Windブロック全体をコピーして、自作グラフへ貼り付けます。
  2. 上記の4つのBlackboard項目がまだなければ追加します。
  3. Wind Strength、 Wind Direction、 Height To Tip 、 DPT Scatter Wind を参照画像と完全に同じ接続にします。
  4. 最後の DPT Scatter Wind 出力をグラフの Vertex Position 入力に接続します。
  5. グラフを保存し、それを使用するマテリアルをCustom Meshバリエーションへ割り当てます。
  6. そのマテリアルでDPT Scatter Windキーワードを有効にし、Scatter Objectの Enable Wind をオンにします。

ライブバイオームの密度と色への反応

地形表面で使う4つのLive Biome Modifierスロットは、対象バイオームIDに属するScatterも制御できます。これにより季節システムで地面と植生を同時に変化させられます。

Scatter Response設定意味中立値
Scatter Density: 0–1対象バイオームIDに属する生成済みインスタンスのうち、描画する数に倍率を掛けます。1です。0にするとそのバイオームのScatterが非表示になります。通常のライブ変更では配置は保持されます。個体数変化をフェードさせるにはLive Shrinkingを有効にします。
Colour Multiplier対象バイオームIDに属する生成済みScatterの色に乗算します。白。HDR値で色を付けたり明るくしたりできます。

例えば冬のスロットでは、草バイオームの雪のDustingを増やしながらScatter Densityを減らし、Colour Multiplierを淡い霜色へ変えられます。再利用可能な草オブジェクトが森バイオームも対象にしている場合、その森に属するインスタンスは、ライブスロットで森のバイオームIDを対象にしない限り独立しています。

季節の例： 夏はScatter Densityを1、Colour Multiplierを白にします。真冬にはDensityを0.05～0.25程度に減らし、冷たい淡色の倍率を試してください。付属のDynamic Biome Demo Controllerには、Dustingとともにこれらの値を変える冬のアニメーション例があります。

マテリアル設定は 地形マテリアル設定 、コントローラー例は デモとランタイムガイド を参照してください。

ライブ変更時にScatterを縮小する

  1. 3D Scatter → Scatter Settings → Distance & LODを開きます。
  2. Live Shrinking を有効にし、 Fade Range は初期値の0.15から始めます。
  3. Scatterの縮小に対応した付属DPT地形マテリアルを使用し、ライブバイオームの Strength または Scatter Densityをアニメーションさせます。
  4. より滑らかに縮小・再成長させたい場合はFade Rangeを増やします。この値は秒ではなくライブ密度の範囲を表し、時間とイージングはコントローラーが決めます。

Live Shrinkingはライブの個体数が減るにつれメッシュ頂点をインスタンスの根元へ縮め、密度が戻ると元へ成長させます。配置位置を保持し、可視ジオメトリと対応する影の両方に適用されます。アルファクリップのクロスフェードではなく頂点の縮小を使います。

対応するCPU・GPU Scatter経路で動作します。Biome Lockはライブバイオーム変更を無視します。カスタムマテリアルにはDPTの縮小処理への対応が必要で、非対応の場合は従来の表示挙動が保持されます。作成時の配置Densityや再構築はライブ密度アニメーションとは別です。

Transition は近距離/遠距離LODの確率的な遷移帯を制御します。 Live Shrinking はライブバイオームの個体数変化を制御します。パーティクルのフェードは寿命を使い、数学的に描画する足跡には独自のFootprint Lifetime/Fadeがあります。

季節スナップショットと折りたたみ式プロファイル

Dynamic Biome Demo Controller を使って、マテリアルの外観を Environment Profilesとして保存します。マテリアルを編集したら + Capture Current Settings as NEW Profileを選択します。各プロファイルは保存時点のスナップショットです。後からのマテリアル編集は再度キャプチャするまで保存されません。

プロファイルの矢印または名前をクリックすると折りたたみ・展開できます。見出しには名前とシーケンス位置が残り、最初のプロファイルに STARTが表示されます。新規作成したプロファイルは自動展開されます。展開すると Name、 Transition Seconds、イージング、 Channels to Animateを編集でき、キャプチャ、適用、並べ替え、削除も行えます。 Animate To Profile は現在の外観からチェックされたチャンネルをブレンドし、結果を保持します。

スナップショットの変更適用タイミング
ライブモディファイアのTarget Biomes遷移開始時に、追加・置換・削除されたIDを含む遷移先プロファイルのターゲット一覧を適用します。Strength、密度、色などの数値は引き続きアニメーションします。チェックされていないモディファイアスロットは現在の設定を保持します。
開始時にDustingがない場合のDusting Biome ID開始時のDusting Strengthが0、Dustingが無効、またはモディファイアスロットが非アクティブなら、開始時に遷移先のDusting IDを適用します。その後Dusting Strengthを遷移先IDでアニメーションします。
開始時に可視のDustingがある場合のDusting Biome ID開始スロットがアクティブでDustingが有効かつStrengthが0でない場合、元のDusting IDは遷移完了まで維持されます。

これらのルールはシーケンス再生、Edit Mode Preview/スクラブ、Animate To Profileに適用されます。各Live Biome Modifierスロットは最大3つのターゲットバイオームIDを扱えます。一方Scatter ObjectのTarget Biomesには任意の数を設定できます。

春 → 冬 → 春 → 熱波： 水のDusting Strengthが0の春、IceのDustingがある冬、Strengthが0に戻る春、SandのDustingがある熱波を順にキャプチャします。熱波への遷移では最初からSandを選ぶため、先に氷が増えて最後に砂へ切り替わることなく、Strengthとともに砂が増えます。乾季のスナップショットで新たなバイオームを対象にした場合も、遷移開始時からライブモディファイアに加わります。

SceneビューでDustingをペイントする際、赤いDustingプレビューはブラシハンドルより先に描画されるため、選択中のブラシハンドル色がハイライトの上に見えます。

ランタイムScatterとベイク済み地形データ

Scatter配置はメインスレッドで同期的に生成され、描画用にキャッシュされます。読み取り可能な地形メッシュは配置ジオメトリを直接提供します。読み取り不可の地形メッシュでも、Scatter用ジオメトリをベイクした一致する DPT_TerrainSurfaceData アセットを代わりに利用できるため、このランタイム処理では地形のRead/Writeを有効のままにする必要はありません。

  1. ベイク前にScatterプロファイルを割り当てます。
  2. 地形をエディターで編集できる状態で Bake Surface Dataを実行します。Scatterプロファイルが割り当てられていれば、ゲームプレイ用地表情報に加えて配置頂点、法線、三角形、バイオームチャンネルも含まれます。
  3. ベイク済みアセットを各地形ソースの DPT_TerrainSurfaceTarget に割り当てたままにして、ビルドに含めます。
  4. 地形の形状、ペイント、バイオームID、トポロジーを変更したら再ベイクします。ゲームプレイ専用データや古いベイクではScatter配置に不十分です。
  5. 地形のRead/Writeを無効にしたビルドでテストします。レンダラーがScatterジオメトリのベイクを要求したら、新しいデータを用意するか、そのソースメッシュを読み取り可能にしてください。

ベイクした配置配列はメモリを消費します。地形のRead/WriteをオフにしてもScatterデータそのものは消えません。大規模な個体群の生成や再構築には依然としてメインスレッド時間がかかります。この機能で自作カスタムメッシュの要件がなくなるわけではなく、DPT風コピーを作る際には読み取り可能なメッシュチャンネルなどが必要です。

パフォーマンスと実用上の制限

オーディオは配置地点ごとに音声を持つのではなく、再利用できる上限付きの空間音源を使います。Audio Emitter Fraction、Audio Distance、グループのSource Limit、Shared Audio Source Limitを調整してください。プレイヤーの地表パーティクル、足跡、足音は地形検出とバイオーム判定を共有します。足跡はさらに表示範囲カリング、キャッシュしたインスタンスデータ、GPUフェードを使います。実際のゲームカメラと解像度でプロファイルしてください。

  • ScatterはGPUインスタンシングで描画し、プレハブをメッシュ・マテリアルのソースに使用する場合も、描画インスタンスごとにGameObjectを生成しません。
  • 配置は地形メッシュから生成しキャッシュします。通常のカメラ移動やライブ密度の変更では分布を再構築しません。
  • カメラ距離と視錐台カリングはScatterのバッチ/セルに対して行われます。そのためCell Sizeはグループ化負荷とカリング精度の両方に影響します。
  • Biome Lockが無効なグループではFar Densityで遠景の個体数を減らせます。グループ別のRender Distance Overrideを使うと、Scatterグループごとに異なる表示距離を設定できます。
  • グループ別のShadow Overrideを使うと、密集した装飾に不要な影の描画負荷を抑えられます。
  • コライダーは物理処理が必要なグループだけに有効にし、Collider Distanceを可視メッシュの描画距離とは独立して調整してください。
  • Permanentはロード間で保存済みの配置を維持します。Biome Lockは別の設定で、グループがライブバイオームの変更に反応するかどうかを制御します。
  • 大きな地形でDensityを非常に高くすると候補数やインスタンス数の安全上限に達することがあります。上限は最大化の目標ではなく、設定のプロファイリングを促す警告として扱ってください。
  • 何千回も描画するカスタムメッシュはインスタンシングに適したものを使い、不要な頂点・サブメッシュ・マテリアルの複雑さを避けてください。

パーティクルではEmitter Fraction、Rate / Emitter、Particle Distance、Emitter Limit、Particle LimitをメッシュLODとは別に調整します。大きな半透明粒子や重なる霧は粒子数が少なくても高負荷になることがあります。粒子シミュレーションや頂点の曲げは、ベイク済みゲームプレイ地表クエリに影響しません。

Runtime Discoveryは任意なので、安定した地形階層ではPlay中に毎秒全体検索する必要はありません。組み込みバリエーションのシグネチャはプロファイル変更までキャッシュされます。設定済みメッシュキャッシュは有効なレンダラーで使われるものを保持し、再構築後に不要なものを解放します。最後のレンダラーを無効にすると共有Scatterキャッシュをクリアします。プロファイル変更によっては再生成が必要です。

プロファイルの設定が見つからないEnvironment Profileの矢印か名前をクリックして展開します。折りたたみ状態では名前とシーケンス位置だけが表示され、編集・操作項目は内部にあります。

遠距離のScatter密度が高すぎるFar DensityまたはDraw Distanceを下げ、遠距離の密度間引きを使う場合はBiome Lockがオフであることを確認します。距離制御のためだけにTarget BiomeのDensity Multiplierを変更しないでください。
Enable Windがグレーアウトしている割り当てたシェーダーに _DPT_SCATTER_WIND Boolean Keywordが宣言されていないため、Scatter ObjectはDPT Scatter Windを使用できません。Shader GraphへDPT Scatter Wind設定を追加するか、シェーダー独自の風システムを使います。
VCCOREマテリアルでEnable Windがグレーアウトしている仕様どおりです。VCCOREは独自の風データとマテリアル風設定を使うため、DPT Scatter Windの設定は不要です。
対応カスタムDPTシェーダーでも風で動かないマテリアルのDPT Scatter Windキーワード、Scatter ObjectのEnable Windがオンであり、BlackboardのReference名が完全一致し、コピーした風ブロックがVertex Positionへ接続され、Wind Strength / Height To Tipが適切か確認します。
風でオブジェクト全体が不自然に動くEnable Wind、Height To Tip、メッシュのオブジェクト空間の高さ、Wind Strengthを確認します。通常の地形、回転した地形、小惑星に適したUp Modeを使用してください。
カメラから離れると風が止まるScatter Settings → Distance & LOD の Wind Fade Start と Wind Cutoff を確認してください。距離にかかわらず風を続けるには Wind Cutoff を 0 にします。正の停止距離では、遠くの風が意図的に止まります。
風の距離設定がカスタムマテリアルに反映されないシェーダーが DPT の風距離フェードに対応しているか確認してください。独自の風や VCCORE の風は、それぞれのマテリアル設定を使います。風のキーワードだけでは距離フェードは追加されません。
風で揺れる先端が消えるWind Boundsを増やし、描画境界が最大変位を含むようにします。
中立のライブスロットでScatterに色が付くHDR強度0の白はSlot 1を含むすべての4スロットで中立です。スロット対象の重複、他の色倍率、シェーダーのScatter入力を確認します。DustingとScatterの反応は別の処理です。
HDRランプの色が発光しない組み込みバリエーションのEmissiveを有効にし、ランプのアルファとマテリアルのEmission設定を確認します。カスタムメッシュには独自に作成した発光データが必要です。
読み取り不可地形のビルドでScatterが消えるScatterプロファイルを割り当てた状態でSurface Dataを再ベイクしてください。詳しくは ランタイムデータの設定を参照してください。ゲームプレイ専用データには配置ジオメトリがありません。
雪で地形は変わるが草は変わらないScatter Objectがライブスロットと同じバイオームIDを対象にしているか、Scatter Density/Colour Multiplierが中立ではないか、ライブバイオームのマスタースイッチがオンか、Scatter Rendererが同じ互換マテリアルを使っているか確認します。
Scatter Densityを変えてもすぐに反映されないプロファイルの作成時Densityだけでなく、マテリアルのライブScatter Responseを変更しているか確認します。プロファイルのDensityは配置を変えるため再構築が必要な場合があります。ライブScatter Densityは描画する個体数を変えます。
Scatterオーディオが再生されないScatter Audioを有効にして有効なクリップを割り当て、Volume、Emitter Fraction、音源上限、Audio Distanceを確認します。Playモードで有効なAudio Listenerを使ってテストしてください。Player MovementではプレイヤーのEnable Scatter Interactionも必要です。
パーティクルプレビューがGameビューだけに表示されるメインのPreviewとContinuousエフェクトのPreview Particlesを有効にします。SceneビューでEffectsとParticle Systemsをオンにし、提案された場合はツールの表示設定修正を使います。
パーティクルや足跡がピンク色になるConsoleのシェーダーエラーを確認し、現行の共有DPT_ProceduralParticleシェーダーを導入してください。シャドウ関数のシグネチャはインストール済みURPヘッダーに従います。URPとCoreパッケージのバージョンを合わせます。
Scatterプリセットで足跡を探しているPlayer Surface Effects → 地表エフェクトの項目 → Footprintsを使用します。足跡/オーディオのみならParticlesをNoneにし、複数のバイオームを指定するかAdd Allを使います。
