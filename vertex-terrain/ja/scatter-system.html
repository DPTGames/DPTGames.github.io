3D スキャッター システムは、地形アトラスのバイオームデータからインスタンシングされたメッシュやパーティクルの放出位置を直接生成します。スキャッターオブジェクトには、メッシュバリアント、パーティクルレイヤー、任意のオーディオなどを含む再利用可能な配置ルールをまとめられます。バイオームごとに同じ草の設定を作り直す代わりに、1つのオブジェクトへ複数のターゲットバイオームを追加し、必要に応じて対象ごとの密度倍率を指定できます。

スキャッターは草、花、キノコ、石、小道具など、繰り返し配置する地表のディテール向けです。地形メッシュを編集したり、個々のメッシュを別々の GameObject にしたりしません。物理コライダーは任意で距離によって制限でき、表示メッシュは GPU インスタンシングのままです。

スキャッターライブラリの仕組み

スキャッター設定は各バイオームのインスペクターに個別保存されるのではなく、地形アトラスのバイオームライブラリ全体で管理されます。Vertex 3D Terrain ウィンドウの 3D スキャッターセクションからライブラリを作成・編集します。

構成要素役割重要なポイント
スキャッターオブジェクト再利用可能な配置ルール、メッシュやプレハブのバリアント、階層化したパーティクル、任意のコライダー、オーディオ、風・プレイヤーインタラクション設定を保持します。1度設定すれば複数のバイオームに適用できます。必要に応じて バイオーム固定と固定配置 を使用してください。
対象バイオーム選択した 地形アトラスのバイオームが寄与する場所に、対象のスキャッターオブジェクトを生成できます。対象ごとに0～2の 密度倍率 を指定できます。
スキャター出力メッシュ、パーティクル、メッシュ＋パーティクル、音声のみ から選択します。オーディオは別途設定でき、どの出力方式とも併用できます。音声のみ はメッシュやパーティクルを出さずに音の配置位置だけを生成します。
メッシュバリアント内蔵プリセット、インポートしたメッシュ、プレハブのソースと、それぞれの相対的な選択確率を指定します。カスタムプレハブから、インスタンシングに使用するメッシュ、マテリアル、コライダーデータを取得できます。
スキャッター設定シード、バッチ処理、距離、LOD 遷移、遠距離密度、安全上限を制御します。これらはオブジェクトごとではなくスキャッターライブラリで共有されます。
アクティブな地形レンダラー選択した地形ルートにプロファイルを接続し、GPU インスタンシングで描画します。多数のインスタンスを個別の GameObject としてシーンに配置することはありません。

最初のスキャッターオブジェクトを作成する

  1. まず 地形アトラス パイプラインを使用し、地形にバイオームデータがペイントされていることを確認します。
  2. Vertex 3D Terrain ウィンドウで 3D スキャッターを開きます。プロファイルがない場合は スキャッターライブラリ を作成します。
  3. 次に + スキャッターオブジェクトを追加を選び、「草原の草」 などの分かりやすい名前を付けます。
  4. 現在のライブラリのターゲットバイオームから1つ以上のバイオームを選びます。
  5. まず各対象の 密度倍率 を1にします。
  6. 全体の密度 （1平方メートル当たりの株数）、間隔、占有率の範囲、傾斜、スケール、サーフェスへの整列を設定します。
  7. この草の設定ではスキャター出力をメッシュのままにします。メッシュバリアント を追加し、内蔵の 草、インポートメッシュ、プレハブのいずれかを指定します。パーティクルの設定は以下のパーティクル設定を参照してください。
  8. マテリアルを割り当てるか確認し、求められたら GPU Instancing を有効にします。変更後にプレビューが自動更新されない場合はスキャッターを再構築を使って再構築します。

例： 「草原の草」 オブジェクトを1つ作り、青々とした草地 に×1.0、乾燥した草原 に×0.65、森の土壌 に×0.25で適用します。3つのサーフェスで同じ草のメッシュ、カラーランプ、ラフネス、風の設定が使われます。

編集プレビューと地形ツールの更新

Play モード以外で表示するには、プレビューの見出しの横にある 3D スキャッターを使います。新規レンダラーでは初期状態でオフになっており、ランタイム描画には影響しません。有効にすると連動するストローク後に更新ボタンが表示され、初期状態でオンです。地形ツールの操作中は既存の配置を維持し、操作完了時に影響を受けたソースを更新します。オフにすると操作中にも更新されます。

スキャッターのスライダーは指を離した時に変更を適用するため、ドラッグ中の中間値ごとに配置を再生成しません。大規模な再構築は複数のエディター更新に分けて処理され、置換データの準備中も既存の配置を表示できます。

継続 パーティクルでは、エフェクトのパーティクルをプレビューもオンにします。Scene ビューで Effects と Particle Systems を有効にしてください。これらの表示設定がプレビューを隠している場合は修正操作が提示されます。プレイヤーの移動 エフェクトとオーディオは Play モードで確認します。プレビューをアニメーションは風やアニメーション付きマテリアルの表示を継続更新する別のスキャッター設定です。

1つの設定で複数のバイオームを対象にする

1つのスキャッターオブジェクトで、任意の数の 地形アトラスのバイオームを対象にできます。バイオーム選択欄には現在の名前と数値 ID が表示されます。 + ターゲットバイオームを追加でリストを増やします。

設定項目内容例
バイオーム対象のスキャッターオブジェクトを出現させる 地形アトラスのバイオームです。草原、森の土壌 など、現在のライブラリエントリを選びます。
密度倍率：0～2この対象バイオームに限って、オブジェクトの基本密度に倍率を掛けます。1は通常密度、0.5は半分、0はその対象を無効化、2は2倍です。

ペイントされたブレンド部分では、対象バイオームすべての寄与度を合算して評価します。そのため 草と森 の境界でも、同じオブジェクトを連続して配置でき、設定を複製する必要はありません。

採用されたインスタンスには、その位置に寄与した対象バイオームに基づく所有バイオームが記録されます。これにより、ライブバイオームモディファイアが一部の対象バイオームだけを変更した場合、同じ草のオブジェクトでも異なる反応ができます。

配置設定

スキャター出力 の場所： Vertex 3D Terrain ウィンドウで 3D スキャッターを展開し、名前または矢印をクリックして スキャッターオブジェクト を開きます。スキャター出力のドロップダウンはターゲットバイオームのすぐ下、配置の上にあります。ここでメッシュ、パーティクル、またはメッシュ＋パーティクルを選びます。

また、配置内のバイオーム固定はライブバイオーム変更をこのグループに反映するかを決め、固定配置はロード間で保存済みの配置を保持します。プレイヤーの影響を有効にすると、対応メッシュ向けの曲げ距離設定が表示されます。両者の違いはバイオーム固定と固定配置を参照してください。

設定項目内容活用方法
スキャター出力メッシュ は設定済みバリアントを描画し、パーティクル はメッシュバリアントなしで放出位置を生成します。メッシュ＋パーティクル は両者を組み合わせます。既存のオブジェクトでは メッシュ が初期値です。メッシュ＋パーティクル はメッシュバリアントに基づいて配置位置を生成します。
バイオーム固定ライブのスキャッター密度や色合いの変更、遠距離密度の間引きからグループを独立させます。バイオーム効果が変化しても、植生や小道具の見た目を保ちたい場合に便利です。固定配置 による配置保存とは別の機能です。
固定配置シーンやゲームの再ロード後も、保存済みインスタンスの配置を保持します。個々の木や岩など位置を固定したいものに使います。エディターでの編集内容は保存配置へ反映できます。
プレイヤーの影響／曲げ距離散布オブジェクトの反応 が有効な近くの プレイヤーサーフェスエフェクト に反応して、対応メッシュを曲げます。曲げ距離 は先端の最大変位をワールドメートル単位で制限します。草や柔らかい植物で有効にします。詳細はプレイヤーのコリジョンとインタラクションガイドを参照してください。パーティクル のみの出力ではこれらのメッシュ設定は表示されません。
密度：0～100塊/m²対象バイオーム の倍率やライブのランタイム密度を適用する前の基本インスタンス密度です。低めから始め、インスタンス数や遠距離の見え方を確認しながら上げてください。
占有率最小／最大：0～1対象となる ターゲットバイオーム の合計 カバレッジ が指定範囲内の場所だけを配置対象にします。最小値を上げると薄いブレンドを除外できます。最大値を1未満にするとバイオームの完全な内部を除外し、1なら通常の内部配置を維持します。
間隔地形タイル境界をまたぐ場合も含め、同じオブジェクトの株の中心間に必要な最小ワールド距離です。0で制限なしです。値を上げると密集と重なりを減らせますが、最終インスタンス数が 密度 の指定より少なくなる場合があります。中心間の距離なので、大きなメッシュ同士は重なる可能性があります。
最大傾斜：0～90°設定角度より急なサーフェスを除外します。通常、草には岩や崖の瓦礫より低い上限が適しています。
スケール（最小／最大）採用されたインスタンスに適用するランダムな均一スケールの範囲です。急激なサイズ差を避け、自然な変化が得られる適度な範囲にしてください。
位置合わせ：0～1選択した 上方向 と地形法線の間で向きを補間します。0では指定の上方向を基準に直立し、1ではサーフェス法線に完全に合わせます。
オフセット取得したサーフェス法線に沿ってインスタンスを移動します。メッシュが浮く／埋まる場合に、正または負の値で微調整します。
風を有効化このオブジェクトのメッシュに DPT スキャッター風 を適用します。メッシュ と メッシュ＋パーティクル で表示され、使用中のシェーダーが DPT スキャッター風 に対応する場合に選択できます。対応する柔らかいメッシュで有効にします。パーティクルには独立した風に追従設定があります。VCCORE マテリアルでは専用の風設定を使用します。

バイオーム固定と固定配置：異なる2つの設定

バイオーム固定はライブバイオーム変更や遠距離密度の間引きからグループを独立させます。環境のライブ変更時に消えたり、薄くなったり、色が変わったりしてほしくない場合に使います。旧設定名は固定スキャターです。

固定配置は生成済みの配置を地形シーンと一緒に保存し、再ロード後も同じ位置にオブジェクトを配置します。エディターの変更で保存済み配置を更新できます。木、岩、ランドマークなど、位置を保持したい配置に使います。

この2つは独立しています。固定配置のグループでもバイオーム固定を有効にしなければライブバイオーム変更に反応します。同様に、バイオーム固定だけでは個々の配置が保存されるわけではありません。位置とライブ変更からの独立性の両方が必要なら、2つとも有効にしてください。

例： 永続的な森では固定配置で各木の位置を保持します。バイオーム固定は、木がライブ密度や色の変更を無視する必要がある場合だけ追加します。冬に消える季節性の草では バイオーム固定 をオフにしてください。

水辺だけに葦を配置する

  1. 葦 スキャッターオブジェクトを作成し、対象を水 のみにします。
  2. 占有率 の範囲を例えば 0.15–0.65 にすると、水 と 泥 のブレンド部分には葦を配置し、カバレッジ が1の純粋な 水 は除外できます。
  3. ペイントした遷移帯の幅や範囲を調整して帯の位置を決め、密度 と 間隔 で株数と間隔を調整します。

占有率 は対象バイオームすべての合計です。水 と 泥 の両方を対象にすると、遷移部分でも合計が1になり、この範囲では配置されません。必要な水際を示す部分 占有率 を持つ片方のバイオームのみを対象にしてください。占有率 は配置可能なサーフェスを絞り、バイオームごとの密度倍率は配置する株数を変えます。

内蔵プリセット、カスタムメッシュ、プレハブ

メッシュのソースでは、GPU インスタンシングのスキャッターに内蔵プリセット、カスタムメッシュ、プレハブを使用できます。追加したメッシュバリアントは赤いメッシュバリアントを削除ボタンで削除します。

1つのオブジェクトに複数の メッシュバリアント を含められます。相対的な確率は合計100%にする必要のない相対的な選択重みです。配置シードを変えずに内蔵メッシュの形状を変化させるには、異なる形状のシード値を使います。プリセットの説明はツールチップで確認できます。

内蔵プリセット適した用途形状の特徴
草／短い草／背の高い草草原、地表の近くを覆う草、背の高い植生。シーンに合うシルエットを選びます。近距離／遠距離のジオメトリで遠くの描画負荷を抑えます。
花小さな花の群生。シードとカラーランプを組み合わせて変化を付けます。
ラベンダー直立する紫色の花穂。花の塊と少数の葉を使い、小花を大量に独立配置するより単純なメッシュにしています。
シダ／クローバー／低木葉の多い下草や低木。スケールと間隔を調整し、葉の重なりを抑えます。
葦湿地や水辺の植生。初期設定では茎が小さめです。カバレッジ の帯と 間隔 を組み合わせます。
小石小石の群れ。スムージング角度 で滑らかな陰影と角張った陰影を選べます。
キノコ林床のディテール。カラーランプは生成された各要素のローカル高さに沿います。
結晶多面体の鉱物群。鋭い面を保つため スムージング角度 の初期値は0で、変更も可能です。
落ちた枝地面の落枝など。簡略化した小枝を備えた地面向きの形状です。急傾斜では 整列度 と オフセット を確認してください。

シェーディングとサーフェス特性

結晶 を含むすべての内蔵プリセットでスムージング角度：0～180°を使用できます。0では面がフラットなまま、180では隣接面の法線をすべて滑らかにつなげられます。中間値では緩やかな接続だけを平滑化し、鋭いエッジを保ちます。変わるのはライティングであり、シルエットや地形全体の スムーズ／シャープ 設定ではありません。

生成される各要素の頂点カラーランプは、ローカル空間の下から上へ評価されます。スムースネスは0で粗く、1で磨かれた表面になり、新規バリアントの初期値は 0.2 です。メタリックは0～1の金属性を制御します。

生成メッシュは メタリック を UV3.Rに格納します。UV3.G には生の スムースネス ではなく、そこから算出した DPT 独自のスケール／ラフネス値が含まれます。カスタムシェーダーでは適切にデコードする必要があります。

発光スキャッター

内蔵バリアントの発光を有効にし、カラーランプの HDR 色で明るさを、ランプのアルファで発光領域を設定します。DPT は発光バイオームと同様に、その領域を頂点アルファへ格納します。HDR 色だけでは発光が有効になりません。マテリアルの発光設定も適用されます。ブルームはシーンのポストプロセスに依存し、発光メッシュ自体は光源になりません。

カスタムメッシュとプレハブのソース

カスタムバリアントでは、インポートしたメッシュまたはプレハブを使用できます。メッシュの場合は 3D Mesh、任意のサブメッシュ番号、Material、任意の 遠距離メッシュ を指定します。遠距離メッシュ が空なら近距離メッシュを再利用します。

ソースにプレハブを指定すると、GPU インスタンシング描画と任意の物理処理に使用するメッシュ、マテリアル、コライダー情報を抽出します。プレハブはデータの供給元であり、システムは可視インスタンスごとに完全な GameObject を複製しません。木などの複数パーツを持つアセットでも、FBX のメッシュを手動指定せずにインスタンシングできます。

カスタムメッシュの法線、頂点色、UV3 サーフェスデータは元のままです。内蔵のシェーディング、メタリック、滑らかさ、発光 設定では書き換えられません。対応する DPT スキャッター風 を有効にすると、ソースを変えずに風／バイオームデータ付きのランタイムコピーが作成されます。

マテリアルの選択が重要です。 スキャッターは GPU インスタンシングを使います。ソースメッシュのデータと互換性のあるマテリアルを使い、必要に応じて GPU Instancing を有効にしてください。バリアントのマテリアルが空の場合は、適用可能なら元の地形マテリアルが使われます。

任意のスキャッターコライダー

スキャッターグループには物理インタラクション向けの任意のコライダーを追加できます。カスタムプレハブはコライダー定義を自動で提供できますが、表示される全インスタンスに物理判定を付けるのではなく、必要に応じて有効にしてください。コライダーの距離設定で維持する範囲を制限でき、大量配置時の負荷軽減に役立ちます。

木や大きな岩など、衝突判定が必要なものにだけコライダーを使用してください。草、花、見た目だけの地表ディテールでは、本当に必要な場合以外は無効にします。メッシュ描画には引き続き GPU インスタンシングが使われ、コライダーは別の物理負荷です。

例： 木のプレハブからメッシュ、マテリアル、コライダー情報を取得し、近くの木だけコライダーを有効にします。プレイヤーの接近範囲に合わせて距離を設定すれば、遠くの木を描画しつつ不要な物理処理を減らせます。

スキャッター配置からパーティクルを放出する

スキャッター出力 でパーティクルまたはメッシュ＋パーティクルを選び、パーティクルエフェクト 1を展開します。内蔵プリセットは、インポートしたスプライトなしでパーティクルシステム、マテリアル、数学的形状を生成します。ParticleSystem プレハブを使う場合は カスタム を選びます。足跡はプリセット一覧ではなくプレイヤーサーフェスエフェクトで設定します。

トリガーと放出位置

継続は表示カメラの近くで条件を満たす配置位置からパーティクルを放出します。プレイヤーの移動は 散布オブジェクトの反応を有効化 を有効にした プレイヤーサーフェスエフェクト コンポーネントが配置位置の近くを移動したときに放出します。インタラクションの半径、高さ、強さを使い、散布反応のテレポート距離 を超えるテレポートは無視します。メッシュの曲げ表現は任意です。

メッシュ＋パーティクル はそのオブジェクトのメッシュ配置を使用します。パーティクル はメッシュバリアントなしで独自の放出位置を生成します。別のオブジェクトには別の配置位置があり、他の草オブジェクトに自動で取り付くわけではありません。放出位置の割合 で各エフェクトに使用する安定した配置割合を選びます。

パーティクルを風に追従させる

  1. ソースマテリアルの DPT スキャッター風方向と強度を風の設定で調整し、そのマテリアルの風を有効にします。
  2. スキャッターオブジェクト を開き、動かしたいパーティクルエフェクトを展開します。
  3. 次に風に追従を有効にし、風の影響の初期値を 1にします。弱い流れには値を下げ、強い反応には上げてください。
  4. 追加レイヤーにも必要に応じて設定してください。Play モード、または通常の 継続 プレビューで確認します。

パーティクルはマテリアルの風向に沿ってワールド内を流れます。突風は流れる速度を変えますが、生成位置へ引き戻しません。内蔵プリセットと カスタム プレハブの既存の動きを維持しながら作用します。パーティクルノイズ は別の乱流要因です。

スキャッターオブジェクト の風を有効化はメッシュの変形を制御し、パーティクル や 音声のみ 出力では非表示です。パーティクルの動きには メッシュ＋パーティクル の場合も、各エフェクト内の風に追従を使います。2つのスイッチは独立しています。マテリアル側で DPT の風向・強度が有効である必要があり、独自の風や VCCORE の風は自動的にパーティクルの移動へ変換されません。

プレイヤーの移動に反応させる

  1. 既存の草オブジェクトなら メッシュ＋パーティクル、メッシュ不要のエフェクトなら パーティクル を使用します。
  2. 草の切れ端 または 花粉 を選び、放出のトリガー を プレイヤーの移動 にします。最初は 放出位置の割合 0.2、位置ごとの放出数 15、最小移動速度 0.1を使用し、必要に応じて上限を下げます。
  3. プレイヤーにプレイヤーサーフェスエフェクトを追加し、散布オブジェクトの反応を有効化を有効にします。インタラクションの原点/オフセット を根元近くへ置き、半径、高さ、強さを調整します。
  4. Play モードで配置位置の近くを歩きます。停止すると新規放出も止まります。メッシュも曲げたい場合は プレイヤーの影響 と正の 曲げ距離 を別途有効にしてください。

草の根元ではなくプレイヤーの足元のエフェクトにはバイオーム別サーフェスエフェクトを使います。パーティクル、足跡、足音は複数バイオームを対象にする1つのプレイヤーエントリで組み合わせられます。

ライブ反応とパーティクルの寿命

ライブバイオームの 強度 と スキャッター密度 は新規放出に掛け合わされます。0になると放出は停止し、生存パーティクルは寿命まで残ります。バイオーム固定 でこれらの変更から独立させられます。メッシュの ライブ縮小 はパーティクルの透明度を変えません。

各有効レイヤーは配置ごとの GameObject ではなく、プールされた生成エフェクトか カスタム プレハブインスタンスを使用します。シミュレーションはワールド空間です。プレハブ独自の自動 Rate／Burst は無効化され、スキャッターエミッターがイベントごとに通常の子システムを動かし、レイヤー予算を分配します。

放出位置は配置 Transform に追従します。シェーダーによる曲げは放出位置を変形後の先端へ移動させず、風に追従 は放出後に粒子を流します。プリセットや出力を変えたり、レンダラーを無効化すると未使用エフェクトを解放します。プロシージャル生成だけでフレームレートが保証されるわけではなく、重なる透明パーティクルは高負荷になる場合があります。

スキャッター配置からの空間オーディオ

任意の スキャッターオブジェクト 内で散布オーディオを展開します。メッシュ、パーティクル、メッシュ＋パーティクル と併用できます。音声のみを選ぶと、同じバイオーム・配置ルールに従う、見えない音源だけを配置します。メッシュアセットもパーティクルプレハブも不要です。

  1. ターゲットバイオームを選び、配置密度、カバレッジ、傾斜、間隔を設定します。
  2. 次にオーディオを有効化を有効にして、1つ以上のオーディオクリップを割り当てます。新しい音声ごとに、有効なクリップをランダム選択します。
  3. 空間ループ音には音声トリガー → 継続、プレイヤーが配置位置に近づいた際の単発音にはプレイヤーの移動を選びます。
  4. 音量、ピッチ、距離、オーディオ放出点の割合、音源数の上限を設定します。移動時の音には最小移動速度とサウンドのクールダウンも調整します。

滝の水しぶきと霧

滝の下部に手動で配置する着水帯には DPT_WaterfallSplashEmitter を使います。着水帯全体で共通のパーティクルエフェクトを生成するため、配置点ごとの GameObject やスキャッタープロファイルは不要です。

有効なコンポーネントは、Play モード中にカメラの範囲内で放出頻度に従い連続放出します。水やプレイヤーとの衝突は待ちません。編集時はパーティクルをプレビューを有効にできます。任意のライブバイオームや流れの連動で、新規放出を減らす／停止できます。

  1. 滝の根元に GameObject を作成し、コンポーネントを追加から DPT_WaterfallSplashEmitter を追加します。
  2. 初期のプロシージャル滝の水しぶきを使うか、別のパーティクルプリセットを選ぶか、カスタムを選んで独自のパーティクルプレハブを割り当てます。
  3. 水しぶきの幅と奥行きを着水位置に合わせます。選択中のギズモに帯状の範囲が表示されます。
  4. 上向きに飛ばすには水しぶきの方向を (0, 1, 0) のままにし、放出頻度とパーティクル数の上限を調整します。
  5. 編集時に確認するにはパーティクルプレビューを有効にします。
  6. 必要に応じて水バイオームと流速に連動させます。

プレイヤーに反応する草

対応する草や植物のスキャッターオブジェクトでプレイヤーの影響を有効にし、プレイヤーに DPT_PlayerSurfaceEffects を追加します。近くのメッシュの根元は固定されたまま、先端がプレイヤーから離れる方向へ曲がります。風とは独立しており、草の塊ごとに物理コライダーを用意する必要はありません。

設定手順、半径、高さの許容差、曲げ限界、NPC、物理衝突についてはプレイヤーのコリジョンとインタラクションガイドを参照してください。草ごとのコライダーなしでプレイヤーに視覚的に反応させたい場合に役立ちます。

距離、LOD、レンダラー設定

次にスキャッター設定を展開します。よく使う設定は描画距離とLOD、散布の起動設定、プレビューと影にまとめられています。風のフェード開始と停止距離は描画距離とLOD にあります。詳細設定からセルサイズ、風の描画範囲、タイルごとの上限、上方向、実行中の検出を設定できます。配置設定はコンパクトな2値スライダーで、スケール範囲は X/Y ではなく最小／最大で表示されます。

グループ別の描画距離とシャドウ設定の上書き

風の設定

メッシュを動かす DPT スキャッター風は、マテリアルとスキャッターオブジェクトで制御し、共通のスキャッター設定から距離フェードも指定できます。マテリアルがシェーダー側で風を有効にするかを決め、一方、スキャッターオブジェクトの風を有効化は対象が DPT スキャッター風を使うかを決めます。この設定は、割り当てたシェーダーに _DPT_SCATTER_WIND という Boolean Keyword がある場合だけ表示され、Vertex 3D Terrain が対応を検出します。

パーティクルの動きには別の風に追従を使います。パーティクルの移動にスキャッターオブジェクトのメッシュ曲げは不要です。

Vertex Terrain マテリアルを使う

  1. マテリアルの風セクションで風を有効化を有効にします。
  2. 控えめな風の強さを設定します。
  3. 次に先端までの高さをスキャッターメッシュのオブジェクト空間の高さに近づけ、根元を固定しつつ先端を十分に動かします。
  4. 次に方位と上下角度を指定します。
  5. 3D スキャッター に戻り、風を使う各オブジェクトで風を有効化を有効にします。
  6. 強く揺れる先端がカメラや視錐台の端で消える場合は、スキャッター設定の風の描画範囲を増やしてください。

小石のような硬いオブジェクトは同じマテリアルを使いつつ、オブジェクトの風を無効にできます。

遠距離の風をフェード・停止する

  1. 次を開きます： 3D スキャッター → スキャッター設定 → 描画距離とLOD。
  2. 次に風のフェード開始を風の動きを弱め始めるカメラ距離に設定します。
  3. その後風の停止距離により遠い距離を指定します。この2つの値の間で風が滑らかに弱まり、停止距離で完全に止まります。
  4. すべての距離で風を維持するには風の停止距離を再び 0 にします。停止距離が0の場合、フェード開始距離は機能しません。

例： 風のフェード開始距離を 20 、停止距離を 40 にすると、20m以内は風が最大、20～40mで徐々に弱まり、40m以遠で止まります。

距離はカメラから各スキャッターの原点までをワールド単位で測ります。塊全体が一緒にフェードします。対応する DPT シェーダーの近距離／遠距離メッシュとその影に、CPU／GPU いずれの描画経路でも適用されます。

この設定は描画数ではなく風のアニメーションを制御します。描画負荷は描画距離、遠距離の密度、影の設定で調整してください。近距離の強い動きに十分な風の描画範囲を確保します。

距離フェードには最新版の付属 Vertex Terrain シェーダーを使ってください。独自シェーダーには対応する DPT の距離フェード処理が必要で、風キーワードだけでは追加されません。VCCORE など独自の風システムは各マテリアル設定を使います。

モーションブラーや TAA を使う場合、距離フェード変化は前フレームのモーションベクトルに含まれないため、カメラがフェード帯を移動すると再投影精度が下がることがあります。

VCCORE マテリアル

VCCORE には独自の風システムがあるため、スキャッターオブジェクトの風を有効化は意図的に表示されません。これは正常です。 Stylized Color Swapper & Material Optimizerでモデルに風をペイントした場合や、DPT パックのモデルに風データがすでにある場合、スキャッター固有の設定は不要です。VCCORE マテリアルの風設定で有効化・調整してください。

独自シェーダーに風システムがあるなら、それを引き続き使用してください。Vertex Terrain シェーダーと同じスキャッター風を使いたい場合にのみ次の DPT 設定が必要です。

まず SH_DPT_VCTerrainを開き、以下のスキャッター風ブロックを独自の Shader Graph にコピーします。続いて、次の Blackboard 項目を Reference 名を正確に指定して追加します。

Blackboard 項目型Reference
風の強さFloat_Wind_Strength
風向きVector 3_Wind_Direction
先端までの高さFloat_Height_To_Tip
DPT スキャッター風Boolean Keyword_DPT_SCATTER_WIND

  2. 上記4つの Blackboard 項目がなければ追加します。

ライブバイオームの密度と色への反応

地形サーフェスで使う4つのライブバイオームモディファイアスロットは、対象バイオーム ID のスキャッターにも適用できます。地面と植生を季節に合わせて一緒に変化させられます。

スキャッター反応設定意味標準値
スキャッター密度：0～1対象バイオーム ID に属する、生成済みインスタンスの描画割合を掛け算します。1。0では対象バイオームのスキャッターを非表示にします。通常のライブ変更では配置が維持されます。縮小アニメーションにはライブ縮小を有効にします。
カラー倍率対象バイオーム ID に属するインスタンスの生成色に乗算します。白。HDR 値なら色味だけでなく明るさも増やせます。

例えば冬のスロットは、草バイオームの雪のダスティングを強めながら、スキャッター密度を減らし、カラー倍率を淡い霜色にできます。同じ草の設定を森にも適用した場合、森側のバイオーム ID がライブスロットに指定されていなければ、そちらのインスタンスは影響を受けません。

季節の例： 夏はスキャッター密度1、カラー倍率は白にします。真冬には密度を0.05～0.25程度、色を冷たい淡色にしてみてください。付属の動的バイオームデモコントローラーには、ダスティングとともにこれらを変化させる冬のアニメーション例があります。

マテリアルの設定については地形マテリアル設定、コントローラー例についてはデモとランタイムガイドを参照してください。

ライブ変更時にスキャッターを縮小する

  1. 次を開きます： 3D スキャッター → スキャッター設定 → 描画距離とLOD。
  2. 次にライブ縮小を有効にし、フェード範囲の初期値0.15から試します。
  3. スキャッター縮小に対応した付属の DPT 地形マテリアルを使い、ライブバイオームの強度またはスキャッター密度をアニメーションさせます。
  4. フェード範囲を上げると縮小・再成長の変化が緩やかになります。この値は秒数でなくライブ密度範囲の一部です。時間と補間はコントローラーで決まります。

ライブの個体数が減るとメッシュ頂点が各インスタンスの根元へ縮小し、密度が戻ると再成長します。配置位置は変わらず、表示メッシュと対応する影の両方に作用します。アルファクリップによるクロスフェードではなく頂点の縮小です。

対応する CPU／GPU スキャッターで動作します。バイオーム固定はライブ変更を無視します。独自マテリアルには DPT の縮小対応が必要です。非対応マテリアルは従来どおり表示されます。配置密度や再生成はライブ密度アニメーションと独立しています。

切り替え幅は近距離／遠距離 LOD の確率的切り替え帯を制御します。ライブ縮小はライブバイオームの個体数変化を制御します。パーティクルのフェードは寿命、プロシージャルな足跡は独自の寿命／フェード設定に従います。

季節別スナップショットと折りたたみ式プロファイル

マテリアルの外観を動的バイオームデモコントローラーを使って環境プロファイルとして保存できます。マテリアルを編集し、 ＋ 現在の設定を新規プロファイルとしてキャプチャを選んでください。プロファイルはその時点のスナップショットです。以後の変更は再キャプチャするまで反映されません。

プロファイルの矢印や名前をクリックして折りたたみ／展開します。ヘッダーには名前と順番が残り、最初のプロファイルには開始と表示されます。新しくキャプチャしたプロファイルは自動展開されます。展開すると名前、遷移時間（秒）、イージング、アニメーション対象チャンネルを編集でき、キャプチャ、適用、並べ替え、削除もできます。プロファイルへアニメーションはチェックしたチャンネルを現在の外観から補間し、結果を保持します。

起動時の準備とロード画面

次を開きます： 3D スキャッター → スキャッター設定 → 散布の起動設定。または散布の起動設定セクションを DPT_ScatterRenderer のインスペクターから使用します。設定は地形ルートごとのレンダラーに保存されるため、ルートごとに異なる起動方法を選べます。

配置生成はメインスレッド上で、エディター更新やゲームフレームに分割して実行します。単一フレームで完了する必要はありませんが、大きなメッシュでは複数フレーム以上の準備が必要な場合があります。通常は配置パスの完了後に描画され、対応する GPU アップロードは段階的に公開されます。カメラ移動だけで分布は再生成されません。

準備：バックグラウンド通常のバックグラウンド生成ペースを使用します。既存・新規レンダラーの初期値です。スキャッターが徐々に表示されてもよい場合や、ロードシーケンスでゲーム開始を待てる場合に使用します。
準備：周辺を準備起動カメラの起動時の範囲内にあるソースの配置とメッシュアップロードを、高めの起動時作業量で準備します。他のソースはバックグラウンドで継続します。プレイヤー操作を開始する前に、開始地点周辺の植生を準備したい場合に使用します。
準備：すべて準備すべての有効なソースメッシュの配置とアップロードが完了するまで待ちます。準備中は起動時の作業量を使用します。小さなシーンや、ゲーム開始前にすべてのソースを準備したい場合に向いています。
フレーム予算（ms）：1～50フレームごとに共有する準備時間の目標です。初期値4ms。値を上げると早く完了しますが、他のゲームシステムに使えるフレーム時間が減ります。

起動時の範囲周辺を準備の場合に表示。初期値50m。開始カメラから各ソースメッシュのバウンドまでの距離で判定します。大きなソースが半径に交差する場合、ソース全体の配置パスが必要です。セルサイズは配置作業を細かく分割しません。
起動キャッシュを使用初期状態ではオフ。一致するエディターでベイクした初期配置を復元して、候補生成を省きます。作り込んだシーンの初期配置作業を減らします。以下の手順でベイクして保存します。

これらの予算は共有の準備時間の目標であり、Unity の個々の処理を必ず上限以下に収めるものではありません。複数のレンダラーでは予算を足し合わせず、要求された最大値を共有します。起動時の準備は最初の領域に対して一度完了し、カメラ移動のたびにゲームを停止しません。

準備機能だけではロード画面を作成したり、プレイヤーを自動停止したりしません。 周辺を準備／すべて準備では起動時に追加作業を行い、準備完了のシグナルを取得できます。シーンを見せる時点やプレイヤーの操作開始はゲーム側で決めます。植生ロード中に空の地形を見せたくない場合は、以下のロード画面との連携を使用してください。

任意の起動キャッシュをベイクする

  1. 最初の地形形状、ペイント済みバイオーム、スキャッター配置設定を完成させます。
  2. 有効なレンダラーで起動キャッシュをベイクを選択します。ベイクは複数回のエディター更新に分けて実行されます。
  3. ベイクが完了し、キャッシュされた配置数／ソース数が表示されるまで進めます。ベイクを中止では、以前に完了したキャッシュを保持したまま新しいベイクを中止できます。
  4. 次に起動キャッシュを使用を有効にし、シーンを保存してベイク済み配置を保持します。
  5. Play モードで試します。配置を変更してキャッシュしたい場合は、再ベイクして再度保存します。

キャッシュはプロファイル値、参照アセット、ソース形状、ペイント済みチャンネル、マテリアル／Transform、関連する上方向参照が一致する場合のみ使用されます。欠損・古い・無効なデータは通常生成へ戻ります。保存データの削除にはキャッシュを削除を使用してください。

キャッシュはシーン保存データとランタイムの配置メモリを増やします。候補生成を減らせますが、ソース形状の確認、バッチング、最小間隔、GPU アップロードには時間がかかります。任意の機能であり、初回フレームで即表示を保証するものではありません。

機能目的
起動キャッシュ入力が一致する場合の初期配置を高速化します。通常の風、ライブバイオーム、グループ設定は引き続き使用できます。
固定配置グループの位置をロード間で保持します。個々の木やランドマークを固定したい場合に使用します。
バイオーム固定ライブバイオームの密度・色の変化や遠距離の間引きに従うかを制御します。
サーフェスデータをベイク読み取り不可メッシュでのランタイム判定と配置に使う地形形状・バイオーム情報を保存します。起動配置キャッシュとは別です。詳しくはランタイム地形データを参照してください。

ゲームのロード画面を連携させる

ロード用コルーチンは PrepareStartup(camera) の完了を待ってから画面を隠し、プレイヤー操作を有効にできます。ロード画面の裏でゲーム用カメラを無効にする場合は、そのカメラを明示的に渡してください。準備中はレンダラーを有効に保ちます。

// Inside your existing loading coroutine, with player control disabled:
yield return scatterRenderer.PrepareStartup(gameplayCamera);
// Now hide the loading screen and enable player control.

PrepareStartup(camera) は選択された周辺を準備／すべて準備の領域を使用します。バックグラウンド設定で明示的に呼ぶと、有効な全ソースを対象とします。ロード時に必要な各レンダラーで呼んでください。

完了状態には IsStartupReady 、0～1の進捗には StartupProgress を使います。進捗は配置・アップロードの完了段階を数えるもので、残り秒数の予測ではありません。起動完了状態は保持されますが、再度 PrepareStartup(camera) を呼ぶと新しい要求が始まります。準備は Time.timeScale = 0でも進みます。無効なレンダラーは待機を終了するため、植生が必要ならレンダラーの有効状態も確認してください。

準備完了が示すのはスキャッター配置とメッシュインスタンスのアップロードです。パーティクル／音声のウォームアップ、シェーダーコンパイル、外部シーンやアセットのロードは別途継続する場合があります。必要ならゲーム全体のロード手順に含めてください。

森の入口の例： 周辺を準備を選び、起動時の範囲50、フレーム予算4ms、起動予算12msから試し、 PrepareStartup(gameplayCamera) を待ってからプレイヤーを操作可能にします。一致する起動キャッシュで配置作業を減らせます。個々の木の固定には独立した固定配置設定を使います。

ランタイムスキャッターとベイク済み地形データ

スキャッター配置はメインスレッドで複数回の更新・フレームに分割して準備され、描画用にキャッシュされます。任意の起動キャッシュで一致する初期配置を復元でき、起動時の準備では作業量と準備完了状態を制御します。読み取り可能な地形メッシュは配置形状を直接提供します。読み取り不可のメッシュでは、代わりにスキャッター形状をベイクした DPT_TerrainSurfaceData アセットを使えるため、ランタイムで地形の Read/Write を有効にしておく必要はありません。

  1. ベイクする前にスキャッタープロファイルを割り当てます。
  2. エディターで地形を編集可能なうちにサーフェスデータをベイクを実行します。プロファイルを割り当てていれば、ゲーム用サーフェス情報に加え、配置用頂点、法線、三角形、バイオームチャンネルも含まれます。
  3. ベイク済みアセットを各地形ソースの DPT_TerrainSurfaceTarget へ割り当て、ビルドに含めます。
  4. 地形形状、ペイント、バイオーム ID、トポロジーを変更したら再ベイクします。ゲームプレイ用のみ、または古いベイクではスキャッター配置に使用できません。
  5. 地形の Read/Write を無効にしたビルドで確認してください。レンダラーが形状のベイクを要求する場合は新しいデータを提供するか、ソースメッシュを読み取り可能にします。

ベイク済みの配置用配列にはメモリが必要です。Read/Write を無効にしてもスキャッターデータ自体はなくなりません。大量生成・再生成には、フレームに分割されたメインスレッド処理時間がかかります。サーフェスデータのベイクだけでは生成済みの個体配置は保存されません。また、DPT 風用コピー作成時に必要な読み取り可能チャンネルなど、カスタムメッシュ固有の要件も残ります。

パフォーマンスと実用上の制限

オーディオは配置点ごとの音源ではなく、再利用できる上限付きの空間音源を使います。オーディオ放出割合、距離、グループ音源上限、共有上限を調整してください。プレイヤーのサーフェスパーティクル、足跡、足音は地形判定とバイオーム照合を共有し、足跡にはカメラ／距離カリング、キャッシュされたインスタンスデータ、GPU フェードも使われます。実際のゲームカメラと解像度で計測してください。

  • プレハブからメッシュとマテリアルを取得する場合でも、表示インスタンスごとに GameObject を作るのではなく GPU インスタンシング描画を使います。
  • 配置は地形メッシュから生成され、キャッシュされます。通常のカメラ移動やライブ密度変更では再生成されません。
  • カメラ距離・視錐台カリングはバッチ／セルに対して行います。セルサイズはグループ化負荷とカリング精度を変えますが、ソース全体の配置処理量は減りません。巨大なソースメッシュは準備に時間がかかることがあります。
  • 次の起動予算と準備完了の仕組みで、バックグラウンド表示かロード画面中の準備かを選びます。一致する起動キャッシュは保存データとメモリを使う代わりに生成負荷を減らせます。
  • バイオーム固定されていないグループでは、遠距離の密度で簡易メッシュへの切り替えに加えて個体数も減らせます。グループ別の描画距離上書きにより、異なる表示範囲を指定できます。
  • グループ別シャドウ上書きで、密集する装飾スキャッターの不要な影描画を省けます。
  • 物理衝突が必要なグループだけコライダーを有効にし、その距離は描画距離と別に調整します。
  • 固定配置はロード間の位置を保持し、バイオーム固定はライブ変更への追従を個別に制御します。
  • 広い地形で密度を上げすぎると候補数やインスタンス数の安全上限に達します。上限は増やす目標ではなく、計測して設定を見直すための警告です。
  • 数千回描画するカスタムメッシュでは、不要な頂点、サブメッシュ、マテリアルの複雑さを避け、インスタンシングに適した構成にしてください。

パーティクルは放出点割合、放出率、距離、放出位置の上限、粒子上限をメッシュ LOD と別に調整します。透明粒子や重なる霧は少数でも高負荷の場合があります。シミュレーションと頂点の曲げ表現はゲームプレイ用のベイク済み地表判定を変更しません。

実行中の検出はオプトインなので、安定した地形階層を Play 中に毎秒全検索する必要はありません。内蔵バリアントのシグネチャはプロファイル変更までキャッシュされます。使われているメッシュを保持し、再生成後には古いエントリを解放します。最後のレンダラーを無効にすると共有キャッシュも消去されます。プロファイル変更で再生成が必要になる場合はあります。

スキャッターのトラブルシューティング

症状確認する順番
Play モード開始後、植生が遅れて表示される大きなソースメッシュの準備には複数フレーム以上かかる場合があります。準備方法、起動時の範囲、作業予算を確認し、一致する起動キャッシュの使用を検討してください。ロード画面中に PrepareStartup(camera) を呼んでからプレイヤー操作を開始します。密度、ソースメッシュの大きさ、配置予算も確認してください。セルサイズだけを変更してもソース全体の配置時間は短くなりません。
起動キャッシュが使われていない起動キャッシュを有効にしてベイクを完了し、シーンを保存します。地形形状、ペイント、プロファイル・参照、ソース Transform の変更でデータが無効化され、通常生成へ戻る場合があります。編集後は再ベイクし、読み取り可能な形状か最新サーフェスデータを用意します。
起動準備の待機が終わらないレンダラーを有効に保ち、特に周辺を準備の場合は使用するカメラを指定します。無効なゲームカメラでも PrepareStartup(camera) に明示的に渡してください。レンダラーの更新を許可し、大きなソース作業や繰り返し編集・再生成の状態を確認します。Time.timeScale = 0 でも準備は続きます。
準備完了なのにパーティクルやシェーダーがまだ読み込まれている準備完了シグナルは配置とメッシュインスタンスのアップロードだけを対象とします。粒子・音声のウォームアップ、シェーダーコンパイル、外部ロードには別途完了判定が必要です。
パーティクルが表示されないスキャター出力をパーティクルまたはメッシュ＋パーティクルにし、プリセットを選びます。カスタムならパーティクルプレハブを割り当てます。ターゲットバイオーム、配置密度、放出点割合、放出率、カメラ距離、ライブ密度を確認します。プレイヤーの移動時はスキャッターへのインタラクションが有効な移動中のコンポーネントが必要で、メッシュの曲げは任意です。Scene ビューでは通常のプレビューに加えてパーティクルプレビューも有効にします。
ライブ密度が0になってもパーティクルが漂い続ける既存の粒子は設定された寿命を終えるまで残ります。内蔵の寿命はプロシージャルプリセットで決まります。別の持続時間にするにはカスタムプレハブの Start Lifetime を短くしてください。ライブ倍率は新規放出のみを制御します。
滝のしぶきが予期せず止まるパーティクルの距離、ライブバイオーム追従、地形マテリアル、バイオーム ID、ライブ強度、スキャッター密度を確認します。流速追従を使う場合は流れが有効で速度が0以外かを確認してください。湖モードでは新規放出が意図的に止まります。
草がプレイヤーに反応しない次のプレイヤーインタラクションの確認項目：グループのスイッチ、曲げ距離、対応シェーダー、インタラクション中心、半径、高さ許容差を確認します。
スキャッターが表示されない地形アトラス モード、スキャッターライブラリ、ターゲットバイオーム、基本密度、対象密度倍率、占有率の最小／最大、最大傾斜、マテリアル、プレビューを確認し、スキャッターを再構築します。
間違ったバイオームにスキャッターが出る対象バイオームの名前／IDを確認し、設定後に地形ライブラリの順番を変更していないか調べます。重複または意図しない対象を削除します。
バイオームの境目が空きすぎる占有率範囲の両端と対象密度倍率を確認します。占有率は全対象バイオームの合計です。水辺の帯には水と泥を両方ではなく、水だけを対象にします。
塊が重なりすぎる間隔を増やし、スケール最小／最大を確認します。間隔は同じオブジェクト内の中心間距離で、外形全体や別のオブジェクトとの間隔ではありません。最終個体数が減ることもあります。
湖の中央にスキャッターが出る水だけを対象とし、占有率最大値を1より小さくします。葦を生やしたい場所に水と泥の緩やかな遷移帯をペイントしてください。
一部のバイオームだけ草が多すぎるオブジェクト全体を複製するのではなく、その対象の密度倍率を下げます。
カスタムメッシュ／プレハブが描画されない選択したメッシュ／プレハブのソース、抽出メッシュとマテリアル、サブメッシュの割り当て、GPU インスタンシング対応を確認します。マテリアルがカスタムメッシュのデータに対応しているかも確認します。
シーンやゲームのロードごとに配置が変わる対象グループで固定配置を有効にし、地形シーンに配置を保存してください。バイオーム固定だけでは位置は保存されません。
季節の密度・色変更を無視するグループがある対象グループのバイオーム固定が有効か確認します。ライブ変更へ反応させる場合は無効にしてください。固定配置はそのまま有効で構いません。
スキャッターオブジェクトが想定どおり衝突しないグループのコライダーが有効か、使用するプレハブに適切なコライダーがあるか、コライダー距離がインタラクション範囲を覆うか確認します。遠距離の表示インスタンスすべてに物理コライダーが必要なわけではありません。
グループが近すぎる距離で消える／遠すぎる距離まで描画される共通描画距離とグループの描画距離上書きの両方を確認します。グループ固有の値は全体設定と異なる場合があります。
グループの影が消える／影の負荷が高すぎるグループ別シャドウ上書きとレンダラー全体の影の投射／受け取りを確認します。
LOD 境界でスキャッターが突然変わる切り替え幅幅を増やし、適切な遠距離メッシュ／内蔵プリセットがあるかを確認します。近／遠のシルエットとスケールも比較します。
季節変化でスキャッターが突然消える距離と LOD のライブ縮小を有効にしてフェード範囲を調整します。DPT スキャッターフェード対応のマテリアルを使い、反応させたいグループでバイオーム固定を無効にします。配置を再生成するのではなく、ライブ強度かスキャッター密度をアニメーションさせてください。
熱波への遷移で砂に切り替わる前に氷が増える間に入る春プロファイルでは水のダスティング強度0を保存し、熱波ではダスティング ID を砂として保存します。開始強度が0なら遷移先 ID を開始時に選び、見える強度が残っていれば終了まで以前の ID を保持します。
新たに対象にした乾季バイオームが反応しない更新した対象リストを遷移先プロファイルにキャプチャし、モディファイアスロットがアニメーション対象チャンネルに含まれるか確認します。対象リストは遷移開始時に適用されますが、既存のスナップショットは編集後に自動更新されません。
プロファイルの設定が見つからない環境プロファイルの矢印または名前をクリックして展開します。折りたたみ状態では名前と順番だけが表示され、編集・操作ボタンは内部にあります。
Visual Studio ではインスタンシング宣言に警告が出るが Unity はコンパイルできる更新済みの DPT スキャッターインスタンシング include を使用します。Unity 固有マクロをガードし、単体 HLSL エディター向けフォールバック宣言も提供します。実際のシェーダーコンパイルエラーは Unity Console で別に確認してください。
遠距離のスキャッターが密集しすぎる遠距離の密度または描画距離を下げます。遠距離間引きを使う場合はバイオーム固定がオフか確認します。バイオームごとの密度倍率を距離専用の設定として使わないでください。
パーティクル出力の風設定を探している各パーティクルエフェクトの風に追従を使用します。グループの風を有効にするボタンはメッシュ用で、パーティクルおよび音声のみでは非表示です。
風に追従してもパーティクルが動かない対象エフェクトで風に追従を有効にし、風の影響を正の値にします。マテリアルでは DPT 風が有効、強度が0より大きいこと、方向が有効であることが必要です。プレビュー／放出の条件を満たしているか確認します。独自の風や VCCORE の風は別システムです。
風を有効にする設定がグレー表示される割り当てたシェーダーに _DPT_SCATTER_WIND Boolean Keyword が宣言されていないため、このオブジェクトでは DPT スキャッター風を使用できません。Shader Graph に DPT スキャッター風の設定を追加するか、独自シェーダーの風システムを使用してください。
VCCORE マテリアルで風を有効にできない正常です。VCCORE は独自の風データとマテリアル設定を使うため、DPT スキャッター風の設定は不要です。
DPT 対応の独自シェーダーなのに動かないマテリアルの DPT スキャッター風 キーワードとオブジェクトの風が有効か、Blackboard の Reference 名が一致するか、コピーした風ブロックが Vertex Position に接続されているか、風の強さと先端までの高さが適切か確認します。
風でオブジェクト全体が不自然に動く風を有効にする設定、先端までの高さ、メッシュのオブジェクト空間の高さ、風の強さを確認します。通常の地形、回転地形、小惑星に合う上方向を選んでください。
カメラが離れると風が止まるスキャッター設定 → 描画距離とLOD の風フェード開始・停止距離を確認します。すべての距離で風を維持するには停止距離を0にします。正の値なら意図的に遠距離で停止します。
独自マテリアルに風の距離設定が反映されないシェーダーが DPT の風距離フェードに対応しているか確認してください。独自の風や VCCORE はそれぞれのマテリアル設定を使用し、風キーワードだけでは対応できません。
風で揺れる先端が消える風の描画範囲を増やし、予想される最大変位を描画バウンド内に収めます。
中立のライブスロットがスキャッターを色付けするHDR 強度0の白は、スロット1を含む4つすべてで中立です。重複した対象スロット、他の色の乗数、シェーダーのスキャッター入力を確認してください。ダスティングとスキャッター反応は別処理です。
HDR ランプ色が光らない内蔵バリアントのエミッシブを有効にし、ランプのアルファとマテリアルの発光設定を確認します。カスタムメッシュは独自の発光データが必要です。
Read/Write 無効の地形でビルドするとスキャッターが消えるスキャッタープロファイルを割り当ててサーフェスデータを再ベイクします。ランタイムデータの設定を参照してください。ゲーム用のみのデータには配置形状がありません。
雪で地面は変化するが草は変わらないスキャッターオブジェクトの対象バイオーム ID がライブスロットと同じか、密度／カラー倍率が中立のままではないか、ライブバイオームのメインスイッチがオンか、レンダラーが同じ対応マテリアルを使っているか確認します。
スキャッター密度を変更してもすぐに反映されないプロファイルの編集用密度ではなく、マテリアルのライブスキャッター反応を変更しているか確認します。プロファイル密度は配置を変更し再生成が必要な場合がありますが、ライブ密度は描画する個体数を変更します。
スキャッターオーディオが鳴らない散布オーディオを有効にし、有効なクリップを割り当て、音量、放出割合、音源上限、距離を確認します。Audio Listener が有効な Play モードで試してください。プレイヤーの移動時はプレイヤーの散布オブジェクトの反応も必要です。
パーティクルプレビューが Game ビューにしか出ないメインプレビューと継続エフェクトのパーティクルプレビューを有効にします。Scene ビューで Effects と Particle Systems を有効にし、必要ならツールが提示する表示オプション修正を使用します。
パーティクルや足跡がピンクになるConsole のシェーダーエラーを確認し、最新版の共有 DPT_ProceduralParticle シェーダーを導入してください。シャドウ関数のシグネチャはインストールされた URP ヘッダーに従います。URP／Core パッケージのバージョンを揃えます。
スキャッタープリセットに足跡が見つからないプレイヤーサーフェスエフェクトのエントリ → 足跡を使用します。足跡・音声だけならパーティクルなしを選び、複数の対象バイオームを割り当てるか、すべて追加を使います。
