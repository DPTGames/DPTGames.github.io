デモ・ランタイムガイド

付属のコンポーネントを試し、地形の地表情報を自分のゲームプレイに使います。

小さい画面では、幅の広い表を横にスクロールするとすべての列を読めます。

デモのコンポーネントでは、地形の確認、ライブマテリアル効果の実験、物理レイキャストが返すバイオームの検証ができます。参考にして変更できる例であり、完成したキャラクター制御、天候、足音システムではありません。

デモを試すだけならコードを書く必要はありません。後半の連携例は、地表情報を自分のゲームプレイに使いたい開発者向けです。

デモを試し、各部品を確認する

  1. Assets/DPTGames/Vertex_Terrain/VertexTerrain_Demo/VertexTerrain_DemoScene.unity を開きます。
  2. 地形の Renderer、マテリアル、ライブラリを確認し、その地表の ID を調べます。
  3. Dynamic Biome Demo Controller を探し、Play モードに入る前にマテリアル、対象 ID、有効なシミュレーションを確認します。
  4. Play モードでデモカメラを動かし、塗られた地表を確認します。
  5. 効果が分かるよう、マテリアルのシミュレーションは一つずつ試します。
  6. Surface Raycast Tester で ID と名前を確認します。一種類だけの場所と、混ざった境界で見た目を比較します。
コンポーネント・アセット役割自分のゲームに必要か
Dynamic Biome Demo Controller地形マテリアルにライブ設定を書き込み、例のアニメーションを動かします。任意です。天候やゲームのルールに合わせて独自制御を作れます。
Surface Raycast Tester物理ヒットと、その場所のバイオームを表示します。任意の検証ツールです。ゲーム側から同じ問い合わせ API を直接使えます。
Terrain Demo Camera確認用の自由移動カメラです。任意です。自分のプレイヤーやカメラに置き換えられます。
Terrain Surface Dataベイクした三角形とバイオームの対応です。付属の三角形ベースの問い合わせに必要です。
Terrain Surface TargetRenderer とベイクしたデータを結び、問い合わせを処理します。付属の問い合わせで認識したい地形に使います。

Dynamic Biome Demo Controller

オブジェクトに DPT → Dynamic Biome Demo Controller を追加し、Terrain Material を指定します。未指定の場合、同じオブジェクトの Renderer から共有マテリアルを取得できます。Renderer のない空オブジェクトでは、明示的なマテリアル参照が必要です。

このコントローラーは、渡されたマテリアルを編集します。専用インスタンスを自動作成するわけではありません。一つの地形だけ独立させたい場合は、別のマテリアルを使います。

Pull、Push、同期の違い

項目・操作変更の向き用途
Pull Settings From Materialマテリアル → コンポーネント。マテリアルで作った設定を取り込みます。対応するスロットの値は置き換わります。
Push Settings To Materialコンポーネント → マテリアル。現在のコンポーネント設定を適用します。先にマテリアルを指定・取得してください。対応するマテリアル設定を置き換えます。
Pull From Material On PlayPlay モード開始時、既存のライブ設定が検出された場合に取り込みます。初期状態は有効です。予想と違う場合は、取り込み後のコンポーネントを確認します。
Sync In Edit ModePlay モード外でのコンポーネントの編集を、マテリアルへ反映します。初期状態は無効です。マテリアルを直接調整中は無効にし、コンポーネントを基準にする場合は有効にします。
Enable Dynamic BiomesPush 時に、マテリアル全体のライブスイッチを設定します。各スロットの Active と合わせて使います。全体を有効にしても Slot 1 が強制的に有効になるわけではありません。

Pull と Push はコンポーネントのコンテキストメニューから使えます。実行中は、シミュレーションが有効な間、継続して Push します。すべて無効なら、自分のスクリプトでフィールドを変えても毎フレーム反映されません。変更後に PushMaterialProperties() を呼びます。

分かりやすい進め方：マテリアル側で設定を仕上げ、Pull で取り込んでから、今後どちらを基準にするか決めます。シミュレーションや編集モード同期が動く間に、両方を繰り返し編集しないようにします。

四つのスロットを設定する

各スロットは最大三つの ID を対象にできます。Slot 1 は二つのデモアニメーションが使うスロットで、常時有効という特別なルールはありません。コンポーネントの初期 ID はデモ用です。自分のライブラリに同じ地表があるとは限りません。

項目意味最初の値の目安
Active / Target Biome IDs影響を与える既存の地表を選びます。試すスロットだけを有効にし、自分の ID を指定します。無効化は Active を使います。−1 は無効化 ID ではありません。
Weight Multiplier：0～5塗られた混合内で、対象地表の寄与を変えます。1 は重みを維持します。塗っていないバイオームを追加することはできません。
Smoothness / Normal / Parallax：0～3対象地表の各反応に掛ける倍率です。1 は元の反応です。1 付近の小さな変更から試します。
Emissive：0～10元の発光の倍率です。1 は維持です。模様の発光には、元の地表に発光情報が必要です。
Flowテクスチャの動き、方向、速さ、往復を指定します。遅い正の速度から始めます。負なら逆方向、0 は静止です。
Dusting上に重ねるバイオーム、強さ、上向きの傾斜しきい値を指定します。下地をスロットの対象にし、雪・ほこりを重ねる ID にします。地形には先にマスクを塗ります。

重み、流れ、傾斜、マスクの詳しい意味は、地形マテリアル設定を参照してください。デモには Waterfall Projection の項目がなく、Push するとマテリアルのフラグを解除することがあります。

デモアニメーションが実際に変えるもの

シミュレーション実際の動作必要な準備
Winter SnowstormSlot 1 のダスティングを有効にし、強さを 0～1.8 で変化させます。Slot 1 の重み自体は動かしません。Slot 1 を有効にし、受け側の ID と雪の ID、地形のマスクを設定します。Weather Cycle Speed が周期の速さです。
River LevelSlot 1 の重み倍率を 0～2.5 で変化させます。対象の川バイオームを含む混合を塗ります。地表の寄与を変えるもので、水位や形状は変えません。
Emissive PulseSlot 4 を有効にし、発光倍率を 0.5～8.5 で変化させます。Slot 4 で発光バイオームを対象にします。Pulse Speed は周期の速さ、Bloom は別の設定です。

周期の速度は、正弦波のデモの時間変化を調整します。物理的な天候の長さや、流れの速さではありません。一つずつ試して理解してから、意図を持って組み合わせてください。

Play モード中に無効にすると、Slot 1 の重みとダスティング強さ、Slot 4 の発光倍率は開始時の値へ戻ります。変更したすべてのフラグ、ID、マテリアル設定が戻るわけではありません。既知の基準を残し、実験後のマテリアルを比較します。

Surface Raycast Tester

レイキャストは、Unity に「この線上にどのコライダーがあるか」を問い合わせます。テスターはヒットを表示し、次に地形の Surface Target にバイオームを問い合わせます。二つは別の処理です。コライダーに当たっても、サーフェスデータがあるとは限りません。

自分の地形にプローブを置く

  1. 小さなテスト地形を塗り、メッシュを保存します。
  2. ベイクするメッシュと同じ三角形配置の MeshCollider を用意します。
  3. 地形ツールの Bake Surface Data を使います。
  4. 適切な地形オブジェクトに DPT → Terrain Surface Target があり、ベイクした Surface Data が指定されていることを確認します。Renderer も必要です。
  5. 地形の上に別の空オブジェクトを作り、DPT → Surface Raycast Tester を追加します。
  6. Downward Probe、十分な Max Ray Distance、地形のコライダーを含むレイヤーマスクを指定します。
  7. Scene Gizmos か Game HUD を有効にし、対象、三角形番号、ID、名前を確認します。異なる地表間でプローブを動かして比較します。
設定意味よくある間違い
Downward Probeオブジェクトからワールド下方向に飛ばします。惑星の重力方向には自動追従しません。向きを合わせた前方レイや独自のレイを使います。
Transform Forwardオブジェクトのローカル前方、+Z に飛ばします。地形と反対を向いている場合があります。回転させ、ギズモの線を確認します。
Mouse Cursorメインカメラからポインター方向へ飛ばします。エディターでは Scene ビューのカメラを代わりに使えます。適したカメラが必要です。使えるカメラがなければ下向きのレイに戻ります。
Max Ray Distance：1～500ヒットできる最大距離です。高い位置の短いレイは届きません。除外したレイヤーは距離を伸ばしても検出できません。
Raycast Layersヒットするコライダーのレイヤーです。別のコライダーが先に当たる場合があります。検証中は地形専用のマスクが便利です。
Override Surface Data当たった対象の Surface Target の代わりに、指定したベイクを直接読みます。通常のライブ問い合わせでは空にします。指定したデータは静的で、ヒットしたメッシュと一致する必要があります。無関係な地形に同じデータを使うと誤った結果になります。
Scene GizmosScene ビューにプローブとヒットを表示します。Unity 側のギズモ表示も確認します。
Game HUDGame ビューにヒット結果を表示します。検証用の表示で、プレイヤー向けの操作 UI ではありません。
Log Clicks To Console左クリック時に現在のヒットを記録します。クリックしても、下向きプローブがポインターのレイに変わるわけではありません。

結果の読み方

Hit Object はレイを受けたコライダー、Triangle Index は参照する三角形番号です。Biome ID と Name が地表の結果、Hit Point、Normal、Distance は交点、法線、距離です。

当たっているのにバイオームが不明なら、Surface Target とデータを確認します。BoxCollider や SphereCollider は、この三角形ベースの処理で一致した地形 MeshCollider の代わりにはなりません。負の値など無効な三角形番号を、有効な問い合わせとして扱わないでください。

Terrain Demo Camera

確認用カメラに DPT → Terrain Demo Camera を追加します。自由移動とマウス視点操作ができます。歩行の物理、衝突回避、接地、惑星の重力は提供しません。

入力動作
W / A / S / Dカメラ基準で前、左、後ろ、右へ移動します。
Spaceワールド上方向へ移動します。
Ctrl または Cワールド下方向へ移動します。
右マウスボタンを押すマウスで見回します。
Shift を押す移動速度に倍率を掛けて高速移動します。

Movement Speed は通常の速度、Fast Multiplier は Shift の倍率、Mouse Sensitivity は視点の感度です。操作表示は、覚える間に便利です。小さな形状の確認では遅く、大きな地形を移動するときは速くします。

確認用カメラには衝突制御がないため、地形を通り抜けます。橋、洞窟、階段を実際に移動できるかは、自分のゲームプレイ用コントローラーで確認します。

サーフェスデータをゲームプレイに使う

基本の流れは、地形を塗る → サーフェスデータをベイクする → 地形に関連付ける → 一致するコライダーへレイを飛ばす → ID を読む → ゲーム側の反応を選ぶです。

ベイクしたアセットは、ライブの重み変更に使う候補 ID と重みを含め、三角形ごとの代表的な地表情報を記録します。Surface Target は、その情報とマテリアルの現在の修正を読みます。一回のヒットに一つの ID を返すもので、テクスチャ全体や見えているすべての素材の一覧を返すものではありません。

小さな連携例

以下を TerrainSurfaceProbe.cs として保存し、テスト地形の上のオブジェクトに追加します。地形のレイヤーと距離を設定し、コンポーネントのメニューの Read Surface で一回問い合わせます。Console 出力は例です。ゲームに組み込むときは、自分の音、パーティクル、移動設定の参照に置き換えてください。

using UnityEngine;
using DPT.VertexTerrain;

public class TerrainSurfaceProbe : MonoBehaviour
{
    public LayerMask terrainLayers = ~0;
    public float distance = 2f;

    [ContextMenu("Read Surface")]
    public void ReadSurface()
    {
        if (!Physics.Raycast(transform.position, Vector3.down,
                out RaycastHit hit, distance, terrainLayers))
        {
            Debug.Log("指定距離内にコライダーがありません。");
            return;
        }

        if (hit.triangleIndex < 0)
        {
            Debug.Log("このコライダーには有効な地形の三角形番号がありません。");
            return;
        }

        if (DPT_TerrainSurfaceTarget.TryGetHitBiome(
                hit, out int biomeID, out string biomeName))
        {
            Debug.Log($"地表: {biomeName} (ID {biomeID})");
            // biomeID を使って、ゲーム側の処理を選びます。
        }
        else
        {
            Debug.Log("当たった対象に地形のサーフェスデータがありません。");
        }
    }
}

足音では、足音が発生するタイミングに、足やキャラクターの適した位置から問い合わせます。返った ID を、自分の音・効果の表に対応させます。ライブラリ変更後はその表も更新してください。名前は確認に便利ですが、問い合わせが返す数値はライブラリの ID です。

惑星や独自の重力では、例のワールド下方向を、自分のゲームの局所的な重力方向に置き換えます。このスクリプトで、その方向が自動推定されるわけではありません。

再ベイクするタイミング

  • ゲームプレイで問い合わせる場所を塗り直した後。
  • バイオームの追加、削除、並べ替えにより、データで使う ID が変わった後。
  • 分割、削除、トンネル生成、簡略化などで三角形が変わった後。
  • その他の形状変更により、ベイクや代表的な地表情報に影響した後。
  • 簡略化した LOD コライダーなど、別のコライダーメッシュへ切り替えたとき。

通常の対応するライブ倍率は、問い合わせ時に読まれるため、毎回塗り直したり三角形データを作り直したりする必要はありません。ただし、候補はベイク済みのものです。古いベイクから、新しく塗った情報を読み出すことはできません。

問い合わせは見た目とどこまで一致するか

付属の問い合わせは代表的な地表の選択に役立ちますが、シェーダーが描く画素を完全に取得するものではありません。すべての境界や雪の領域で、カーソル下の見た目と正確に一致すると考えず、自分のゲームの要件で確認します。

状況問い合わせの動作ゲームプレイへの影響
一つの三角形に複数の地表一つの代表 ID を返します。静的ベイクは被覆・優先度のルール、ライブは保存した候補の重みを使います。非常に小さな領域や境界では、位置ごとに別の ID が返るとは限りません。
高さで混ざる細部画素単位の高さ・細部のブレンドをすべて再現しません。局所的な見た目と、三角形の代表地表が異なる場合があります。
ライブの重み変更マテリアルの倍率で、ベイクした候補を再評価します。ベイクにない、新しく塗った候補は選べません。
ダスティングワールド上方向の傾斜と強さで簡略判定します。塗ったマスクは含みません。見た目の被覆がない場所でも、雪などの ID が返ることがあります。移動や足音に使う前に確認します。
テスターの Override Surface Dataベイクしたアセットを直接読みます。Surface Target のライブ評価を通りません。通常のライブ処理を試す場合は解除します。
別のコライダーのトポロジー三角形番号はコライダーのもので、描画メッシュとは限りません。ベイクをその三角形順序に合わせる必要があります。簡略化した LOD2 に、別の元メッシュの対応をそのまま使わないでください。

正確な小領域、局所重力に合う雪、画素単位の被覆がゲームに必要なら、そのルール用の問い合わせを作り、検証してください。付属コンポーネントは、ここで説明した制約を持つ出発点です。

実行時・デモの問題

症状確認すること
デモコントローラーが何も変えないマテリアル、全体とスロットの有効状態、現在の ID を確認し、Push します。変更できる元の寄与があるかも確認します。
Play 開始時にコンポーネントの値が変わるPull From Material On Play が既存設定を取り込むことがあります。どちらを基準にするか先に決めます。
マテリアルの編集がすぐ戻るSync In Edit Mode と実行中のシミュレーションを確認します。設定中は一方を基準にします。
スクリプトで値を変えても見た目が変わらないシミュレーションがない場合、変更後に PushMaterialProperties を呼びます。マテリアル参照も確認します。
雪嵐を動かしても雪がないSlot 1 の Active、下地の ID、雪の ID、マスク、傾斜を確認します。アニメーションは強さを変え、ダスティングを有効にするだけです。
River Level で水位が上がらないSlot 1 の塗られた重みを変える例です。水メッシュや物理的な高さは変えません。
ヒットしてもバイオームが出ないレイヤー、Surface Target、ベイクを確認します。一致する MeshCollider と有効な三角形番号が必要です。
名前や ID が違う不適切な Override を解除し、再ベイクします。ID とコライダーの順序を確認し、混合境界より先に一種類の地表で試します。
惑星でレイが外れるDownward Probe はワールド下方向です。地表に向けた Transform Forward や、ゲームの重力に合うレイを使います。
複数の地形が一緒に変わる共有マテリアルを編集している場合があります。別々の動作には独立したマテリアルを使います。
デモカメラが橋を通り抜ける衝突制御がありません。実際の地形コライダーとゲーム用キャラクターで移動を試します。

サポート

相談するときは、期待した結果、使った項目、実際に起きたことを説明してください。Unity のバージョン、選択したパイプライン、関連する設定のスクリーンショットも添えます。実行時の問い合わせの問題では、コライダーの種類と、最後にサーフェスデータをベイクした時期も記載してください。
